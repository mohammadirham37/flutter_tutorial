Hive hanya mengerti tipe dasar seperti String, int, bool, List, dan Map. Agar Hive bisa menyimpan objek Mahasiswa, kita perlu memberi "kamus terjemahan" yang disebut TypeAdapter: bagaimana objek ditulis menjadi byte (write) dan bagaimana byte dibaca kembali menjadi objek (read).

Buat file lib/models/mahasiswa_adapter.dart:

📄 lib/models/mahasiswa_adapter.dart

import 'package:hive_ce/hive_ce.dart';

import 'mahasiswa_model.dart';

/// TypeAdapter memberi tahu Hive cara menyimpan (write)
/// dan membaca (read) objek Mahasiswa dalam bentuk biner.
///
/// ATURAN PENTING:
/// 1. typeId harus unik per class (0 - 223).
/// 2. Urutan read HARUS sama persis dengan urutan write.
class MahasiswaAdapter extends TypeAdapter<Mahasiswa> {
  @override
  final int typeId = 0;

  @override
  Mahasiswa read(BinaryReader reader) {
    return Mahasiswa(
      id: reader.readString(),
      nim: reader.readString(),
      nama: reader.readString(),
      prodi: reader.readString(),
      semester: reader.readInt(),
    );
  }

  @override
  void write(BinaryWriter writer, Mahasiswa obj) {
    writer.writeString(obj.id);
    writer.writeString(obj.nim);
    writer.writeString(obj.nama);
    writer.writeString(obj.prodi);
    writer.writeInt(obj.semester);
  }
}

Cara kerja adapter

Bayangkan Hive menulis data ke file seperti menulis di satu baris panjang tanpa nama kolom. Saat menyimpan Siti Aminah, isi file kira-kira seperti ini:

[typeId 0] "1731300000000" "22010100" "Siti Aminah" "Informatika" 3
            └─ id ──────┘  └─ nim ─┘  └─ nama ────┘ └─ prodi ───┘ └ semester
  • typeId = 0: Hive menulis angka ini di depan setiap objek. Saat membaca, Hive melihat angka 0 lalu tahu harus memakai MahasiswaAdapter. Setiap class yang punya adapter wajib memakai typeId berbeda (0 sampai 223).
  • write menulis kelima field secara berurutan: id, nim, nama, prodi (semuanya writeString), lalu semester (writeInt).
  • read membaca dengan urutan dan tipe yang sama persis. Karena tidak ada nama kolom, satu-satunya penanda field adalah urutannya.

⚠️ Dua aturan yang tidak boleh dilanggar

  1. Urutan read = urutan write. Jika write menulis nim lalu nama, tetapi read membaca nama lalu nim, data akan tertukar. Jika tipenya berbeda (misalnya readInt untuk data yang ditulis writeString), aplikasi akan crash saat membuka box.
  2. Jangan mengubah typeId setelah ada data tersimpan. Data lama tercatat dengan id 0; jika adapter diganti menjadi 1, Hive tidak menemukan adapter untuk data lama.

Jika selama latihan Anda terlanjur mengubah urutan field dan aplikasi crash, cara tercepat adalah uninstall aplikasi dari emulator agar file box lama terhapus, lalu jalankan ulang. Cara aman menambah field tanpa menghapus data dibahas di Modul 11 section 5 (byte versi).
