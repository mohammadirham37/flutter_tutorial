MahasiswaController adalah inti aplikasi. Semua yang "berpikir" ada di sini: menyimpan daftar mahasiswa sebagai state reaktif, menyaring pencarian, membuka form tambah/edit, memvalidasi input, menyimpan, dan menghapus. View cukup menampilkan isi controller dan memanggil method-nya.

Buat file lib/controllers/mahasiswa_controller.dart. File ini paling panjang, jadi salin utuh dulu lalu baca penjelasan per bagian di bawahnya:

📄 lib/controllers/mahasiswa_controller.dart

import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../models/mahasiswa_model.dart';
import '../routes/app_routes.dart';
import '../services/hive_service.dart';

/// CONTROLLER: penghubung antara View dan Model.
/// Menyimpan state (reaktif) dan berisi seluruh logika CRUD.
class MahasiswaController extends GetxController {
  final HiveService _service = HiveService();

  // ------------------ STATE REAKTIF ------------------
  final mahasiswaList = <Mahasiswa>[].obs;
  final keyword = ''.obs;
  final selectedProdi = 'Informatika'.obs;

  final List<String> daftarProdi = const [
    'Informatika',
    'Sistem Informasi',
    'Teknik Komputer',
    'Data Science',
  ];

  // ------------------ STATE FORM ------------------
  final formKey = GlobalKey<FormState>();
  final nimC = TextEditingController();
  final namaC = TextEditingController();
  final semesterC = TextEditingController();

  /// null  -> mode TAMBAH
  /// berisi id -> mode EDIT
  String? editingId;
  bool get isEdit => editingId != null;

  /// Data yang ditampilkan (sudah difilter pencarian).
  List<Mahasiswa> get filteredList {
    final q = keyword.value.toLowerCase();
    if (q.isEmpty) return mahasiswaList;
    return mahasiswaList
        .where((m) =>
            m.nama.toLowerCase().contains(q) || m.nim.contains(q))
        .toList();
  }

  @override
  void onInit() {
    super.onInit();
    loadData();
  }

  // ------------------ READ ------------------
  void loadData() {
    final data = _service.getAll()
      ..sort((a, b) => a.nama.toLowerCase().compareTo(b.nama.toLowerCase()));
    mahasiswaList.assignAll(data);
  }

  // ------------------ NAVIGASI KE FORM ------------------
  void openAddForm() {
    editingId = null;
    nimC.clear();
    namaC.clear();
    semesterC.clear();
    selectedProdi.value = daftarProdi.first;
    Get.toNamed(AppRoutes.form);
  }

  void openEditForm(Mahasiswa mhs) {
    editingId = mhs.id;
    nimC.text = mhs.nim;
    namaC.text = mhs.nama;
    semesterC.text = mhs.semester.toString();
    selectedProdi.value = mhs.prodi;
    Get.toNamed(AppRoutes.form);
  }

  // ------------------ CREATE & UPDATE ------------------
  Future<void> save() async {
    if (!formKey.currentState!.validate()) return;

    final nim = nimC.text.trim();

    // Cegah NIM ganda
    final nimSudahAda =
        mahasiswaList.any((m) => m.nim == nim && m.id != editingId);
    if (nimSudahAda) {
      Get.snackbar('Gagal', 'NIM $nim sudah terdaftar',
          snackPosition: SnackPosition.BOTTOM);
      return;
    }

    final mhs = Mahasiswa(
      id: editingId ?? DateTime.now().millisecondsSinceEpoch.toString(),
      nim: nim,
      nama: namaC.text.trim(),
      prodi: selectedProdi.value,
      semester: int.parse(semesterC.text.trim()),
    );

    if (isEdit) {
      await _service.update(mhs);
    } else {
      await _service.create(mhs);
    }

    final pesan = isEdit ? 'Data berhasil diperbarui' : 'Data berhasil ditambahkan';
    loadData();
    tutup(); // kembali ke halaman daftar
    Get.snackbar('Sukses', pesan, snackPosition: SnackPosition.BOTTOM);
  }

  // ------------------ DELETE ------------------
  Future<void> confirmDelete(Mahasiswa mhs) async {
    final yakin = await Get.dialog<bool>(
      AlertDialog(
        title: const Text('Hapus Data'),
        content: Text('Yakin ingin menghapus ${mhs.nama}?'),
        actions: [
          TextButton(
            onPressed: () => tutup(false),
            child: const Text('Batal'),
          ),
          FilledButton(
            onPressed: () => tutup(true),
            child: const Text('Hapus'),
          ),
        ],
      ),
    );

    if (yakin == true) {
      await _service.delete(mhs.id);
      loadData();
      Get.snackbar('Terhapus', '${mhs.nama} telah dihapus',
          snackPosition: SnackPosition.BOTTOM);
    }
  }

  // ------------------ HELPER NAVIGASI ------------------
  /// Menutup halaman / dialog paling atas (opsional membawa [result]).
  ///
  /// Kenapa tidak memakai Get.back()? Pada GetX 4.x, jika masih ada
  /// snackbar yang tampil, Get.back() HANYA menutup snackbar tersebut,
  /// sehingga halaman form / dialog tidak tertutup. Get.key adalah
  /// navigator milik GetMaterialApp, jadi pop() selalu menutup route.
  void tutup<T>([T? result]) => Get.key.currentState?.pop<T>(result);

  // ------------------ VALIDATOR ------------------
  String? validateNim(String? v) {
    if (v == null || v.trim().isEmpty) return 'NIM wajib diisi';
    if (int.tryParse(v.trim()) == null) return 'NIM harus berupa angka';
    if (v.trim().length < 8) return 'NIM minimal 8 digit';
    return null;
  }

  String? validateNama(String? v) {
    if (v == null || v.trim().isEmpty) return 'Nama wajib diisi';
    return null;
  }

  String? validateSemester(String? v) {
    final s = int.tryParse(v?.trim() ?? '');
    if (s == null) return 'Semester wajib berupa angka';
    if (s < 1 || s > 14) return 'Semester antara 1 - 14';
    return null;
  }

  @override
  void onClose() {
    nimC.dispose();
    namaC.dispose();
    semesterC.dispose();
    super.onClose();
  }
}

Bagian 1: State reaktif

final mahasiswaList = <Mahasiswa>[].obs;   // RxList<Mahasiswa>
final keyword = ''.obs;                     // RxString
final selectedProdi = 'Informatika'.obs;    // RxString

Akhiran .obs mengubah nilai biasa menjadi nilai yang bisa "diamati". Setiap Obx di View yang membaca nilai ini akan otomatis dibangun ulang saat nilainya berubah. Ingat cara membaca dan mengubahnya:

  • keyword.value = 'budi' untuk RxString/RxInt (pakai .value).
  • mahasiswaList.assignAll(data) untuk RxList (mengganti seluruh isi list sekaligus dan memicu satu kali rebuild).

daftarProdi tidak diberi .obs karena isinya tidak pernah berubah.

Bagian 2: State form

formKey dan tiga TextEditingController disimpan di controller (bukan di View) agar isi form bisa diisi dari controller saat mode edit, dan dibaca saat save(). Variabel editingId menentukan mode form:

editingIdisEditJudul formTombolSaat disimpan
nullfalseTambah MahasiswaSimpanid baru dibuat, _service.create()
berisi idtrueEdit MahasiswaPerbaruiid lama dipakai, _service.update()

Dengan cara ini satu halaman form dipakai untuk tambah sekaligus edit.

Bagian 3: filteredList (pencarian)

Getter ini mengembalikan seluruh data jika kata kunci kosong, atau hanya data yang nama (huruf kecil) atau NIM-nya mengandung kata kunci. Karena getter ini membaca keyword.value dan mahasiswaList, Obx di View yang memanggilnya akan rebuild setiap kali pengguna mengetik atau data berubah. Pencarian dilakukan di memori, jadi hasilnya instan.

Bagian 4: Siklus hidup onInit dan onClose

  • onInit() dijalankan sekali saat controller pertama kali dibuat. Di sini kita memanggil loadData() sehingga daftar langsung terisi saat aplikasi dibuka.
  • onClose() dijalankan saat controller dihapus dari memori. Di sini TextEditingController di-dispose() agar tidak bocor memori (sama seperti dispose() pada StatefulWidget).

Bagian 5: READ dengan loadData()

Mengambil semua data dari HiveService, mengurutkannya berdasarkan nama tanpa membedakan huruf besar/kecil, lalu memasukkannya ke mahasiswaList. Tanda .. (cascade) berarti "panggil sort pada list yang sama, lalu kembalikan list-nya". Method ini dipanggil ulang setiap kali data berubah, sehingga mahasiswaList selalu sama dengan isi box.

Bagian 6: Membuka form

  • openAddForm() mengosongkan editingId dan semua field, mengembalikan prodi ke pilihan pertama, lalu pindah ke route /form.
  • openEditForm(mhs) mengisi editingId dan semua field dengan data mahasiswa yang dipilih (semester diubah ke teks dengan toString()), lalu pindah ke /form.

Karena isi field disiapkan sebelum pindah halaman, form langsung tampil terisi saat dibuka.

Bagian 7: CREATE & UPDATE dengan save()

  1. formKey.currentState!.validate() menjalankan semua validator di form. Jika ada yang gagal, pesan merah muncul di bawah field dan fungsi berhenti.
  2. Cek NIM ganda: any(...) mencari mahasiswa lain dengan NIM yang sama. Syarat m.id != editingId penting: saat mengedit, data milik sendiri tidak dihitung sebagai duplikat.
  3. Membuat objek Mahasiswa. Saat tambah, id dibuat dari DateTime.now().millisecondsSinceEpoch (jumlah milidetik sejak 1970), cukup unik untuk satu perangkat. Saat edit, id lama dipakai agar put menimpa data yang sama.
  4. await create atau update, lalu loadData() agar daftar ikut berubah.
  5. tutup() kembali ke halaman daftar, lalu Get.snackbar menampilkan pesan sukses.

Perhatikan bahwa variabel pesan dihitung sebelum menutup form. Ini kebiasaan baik: ambil semua nilai yang dibutuhkan dulu, baru pindah halaman.

Bagian 8: DELETE dengan confirmDelete()

Get.dialog<bool>(...) menampilkan dialog dan menunggu sampai dialog ditutup. Tombol Batal menutup dengan nilai false, tombol Hapus dengan nilai true. Jika pengguna mengetuk area di luar dialog, hasilnya null. Karena itu pengecekannya yakin == true, bukan sekadar if (yakin). Setelah yakin, data dihapus, daftar dimuat ulang, dan snackbar ditampilkan.

Bagian 9: Helper tutup()

void tutup<T>([T? result]) => Get.key.currentState?.pop<T>(result);

Kenapa tidak memakai Get.back() seperti biasa? Pada GetX 4.x, jika masih ada snackbar yang tampil (misalnya snackbar "NIM sudah terdaftar"), Get.back() hanya menutup snackbar tersebut dan halaman form tetap terbuka. Pengguna merasa tombolnya tidak bekerja. Get.key adalah navigator milik GetMaterialApp, sehingga pop() selalu menutup halaman atau dialog paling atas. Parameter result dipakai dialog hapus untuk mengirim true/false.

ℹ️ Controller ini mengimpor material.dart

Di Modul 08 dan 11 dianjurkan agar controller tidak mengimpor material.dart supaya mudah di-unit-test. Proyek ini sengaja mengambil jalan yang lebih praktis untuk pemula: GlobalKey<FormState>, TextEditingController, dan AlertDialog ditaruh di controller sehingga View menjadi sangat tipis dan semua logika ada di satu tempat. Untuk proyek besar, Anda bisa memindahkan bagian form dan dialog ke View, lalu controller hanya menerima data bersih seperti simpan(nim, nama, prodi, semester). Keduanya tetap MVC; yang berbeda hanya seberapa tipis View-nya.
