Ringkasan modul

  • Model (Mahasiswa) adalah data murni; TypeAdapter mengajari Hive cara menulis dan membaca objek tersebut dengan urutan field yang sama.
  • HiveService menjadi satu-satunya pintu ke database: put untuk create dan update, values untuk read, delete untuk delete.
  • MahasiswaController menyimpan state reaktif (.obs), memvalidasi, mencegah NIM ganda, menyimpan, menghapus, dan memanggil loadData() setelah setiap perubahan.
  • View (GetView) hanya menampilkan state lewat Obx dan meneruskan klik ke controller. View tidak pernah menyentuh Hive.
  • Binding + Routes membuat controller otomatis dan memungkinkan navigasi memakai nama.
  • Hive harus diinisialisasi dengan urutan: ensureInitialized → initFlutter → registerAdapter → openBox → runApp.

ℹ️ Selanjutnya

Pola yang sama (model, service, controller, view) dipakai lagi di Modul 13-14. Bedanya, di sana sumber data utama adalah Supabase dan Hive dipakai sebagai cache offline. Jika Anda paham proyek ini, Anda sudah memegang separuh kerangka proyek besar tersebut.
