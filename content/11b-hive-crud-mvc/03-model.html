Kita mulai dari lapisan paling bawah: Model. Model adalah class Dart biasa yang mendeskripsikan bentuk satu data mahasiswa. Class ini tidak tahu apa-apa tentang tampilan, GetX, maupun Hive.

Buat file baru lib/models/mahasiswa_model.dart, lalu salin kode berikut:

📄 lib/models/mahasiswa_model.dart

/// MODEL: representasi data Mahasiswa.
/// Class ini murni berisi data (tidak tahu soal UI maupun GetX).
class Mahasiswa {
  final String id;
  final String nim;
  final String nama;
  final String prodi;
  final int semester;

  Mahasiswa({
    required this.id,
    required this.nim,
    required this.nama,
    required this.prodi,
    required this.semester,
  });

  /// Membuat salinan objek dengan sebagian field yang diubah.
  Mahasiswa copyWith({
    String? nim,
    String? nama,
    String? prodi,
    int? semester,
  }) {
    return Mahasiswa(
      id: id,
      nim: nim ?? this.nim,
      nama: nama ?? this.nama,
      prodi: prodi ?? this.prodi,
      semester: semester ?? this.semester,
    );
  }
}

Penjelasan kode

FieldTipeKeterangan
idStringPenanda unik setiap data. Dipakai sebagai key di box Hive. Dibuat otomatis oleh controller, pengguna tidak pernah melihatnya.
nimStringNomor induk mahasiswa. Disimpan sebagai teks (bukan int) karena NIM bisa diawali angka 0 dan tidak pernah dihitung.
namaStringNama lengkap.
prodiStringProgram studi, dipilih dari dropdown.
semesterintSemester 1 sampai 14. Bertipe angka agar mudah dibandingkan dan divalidasi.
  • Semua field final: setelah objek dibuat, isinya tidak bisa diubah. Objek seperti ini disebut immutable. Keuntungannya, data tidak bisa berubah diam-diam dari tempat lain sehingga bug lebih mudah dilacak.
  • required di constructor memaksa semua field diisi. Lupa mengisi satu field langsung menjadi error saat kompilasi, bukan saat aplikasi berjalan.
  • copyWith: karena objek tidak bisa diubah, cara "mengedit" adalah membuat salinan dengan sebagian field diganti. Field yang tidak dikirim (null) memakai nilai lama berkat operator ??. Perhatikan bahwa id sengaja tidak bisa diganti, karena id adalah identitas data.

Contoh penggunaan copyWith (dipakai di unit test section 12):

final budi = Mahasiswa(
  id: '1', nim: '220101001', nama: 'Budi', prodi: 'Informatika', semester: 5,
);

final budiBaru = budi.copyWith(nama: 'Budi Santoso', semester: 6);
// budiBaru.id    -> '1'            (tetap)
// budiBaru.nim   -> '220101001'    (tetap)
// budiBaru.nama  -> 'Budi Santoso' (diganti)
// budiBaru.semester -> 6           (diganti)
// budi.nama      -> 'Budi'         (objek lama tidak berubah)

ℹ️ Kenapa model tidak memakai anotasi Hive?

Di Modul 11 Anda melihat dua cara: TypeAdapter manual dan adapter hasil generate (@GenerateAdapters). Proyek ini memakai cara manual agar model tetap bersih dan Anda melihat sendiri bagaimana Hive menyimpan data. Kode Hive-nya dipisah ke file adapter di section berikutnya.
