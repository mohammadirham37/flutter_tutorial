HiveService adalah satu-satunya class yang berbicara langsung dengan Hive. Controller cukup memanggil create, getAll, update, atau delete tanpa perlu tahu nama box maupun cara Hive bekerja.

Buat file lib/services/hive_service.dart:

📄 lib/services/hive_service.dart

import 'package:hive_ce/hive_ce.dart';

import '../models/mahasiswa_model.dart';

/// Lapisan akses data (bagian dari MODEL pada MVC).
/// Semua operasi CRUD ke Hive dikumpulkan di sini,
/// sehingga Controller tidak perlu tahu detail database.
class HiveService {
  static const String boxName = 'mahasiswa_box';

  Box<Mahasiswa> get _box => Hive.box<Mahasiswa>(boxName);

  // READ
  List<Mahasiswa> getAll() => _box.values.toList();

  // CREATE (key = id mahasiswa)
  Future<void> create(Mahasiswa mhs) => _box.put(mhs.id, mhs);

  // UPDATE (put dengan key yang sama akan menimpa data lama)
  Future<void> update(Mahasiswa mhs) => _box.put(mhs.id, mhs);

  // DELETE
  Future<void> delete(String id) => _box.delete(id);
}

_box.values.toList()READ: semua objek Mahasiswa di box dalam bentuk List.
_box.put(mhs.id, mhs)CREATE: menyimpan objek dengan key = id. Jika key belum ada, data baru dibuat.
_box.put(mhs.id, mhs) (lagi)UPDATE: kode yang sama! Jika key sudah ada, put menimpa data lama. Inilah alasan id dipakai sebagai key.
_box.delete(id)DELETE: menghapus data berdasarkan key.

💡 Kenapa create dan update dipisah kalau isinya sama?

Supaya kode controller terbaca jelas: _service.create(mhs) dan _service.update(mhs) langsung memberi tahu maksudnya. Jika suatu saat penyimpanan diganti ke Supabase (Modul 12), create menjadi insert dan update menjadi update. Cukup isi HiveService yang diubah, controller dan view tidak perlu disentuh.

ℹ️ Future<void>

put dan delete menulis ke file sehingga butuh waktu sesaat. Keduanya mengembalikan Future, dan controller memanggilnya dengan await agar data benar-benar tersimpan sebelum daftar dimuat ulang. Sebaliknya getAll() sinkron karena Hive menyimpan salinan isi box di memori.
