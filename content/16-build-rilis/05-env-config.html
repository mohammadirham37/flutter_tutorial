Contoh singkat sering menulis URL dan key Supabase langsung di main.dart. Proyek Modul 13-14 sudah memakai cara yang dibahas di sini, jadi bagian ini merangkum dan memperdalamnya. Begitu kode di-push ke GitHub publik, kunci itu ikut terbaca semua orang. Bagian ini memindahkan konfigurasi ke file terpisah yang tidak masuk git, lalu menyuntikkannya saat build dengan --dart-define-from-file.

Konsep: konstanta saat kompilasi

Flag --dart-define mengirim pasangan kunci-nilai ke compiler. Kode Dart membacanya dengan String.fromEnvironment:

flutter run --dart-define=APP_ENV=dev --dart-define=SUPABASE_URL=https://abcdefghijkl.supabase.co

Menulis banyak --dart-define tentu merepotkan. Flutter menyediakan --dart-define-from-file yang membaca semua nilai dari satu file JSON (atau .env).

Langkah 1: file konfigurasi per lingkungan

📄 config/dev.json (TIDAK di-commit)

{
  "SUPABASE_URL": "https://abcdefghijkl.supabase.co",
  "SUPABASE_PUBLISHABLE_KEY": "sb_publishable_xxxxxxxxxxxxxxxx",
  "APP_ENV": "dev",
  "ENABLE_LOG": true
}

📄 config/prod.json (TIDAK di-commit)

{
  "SUPABASE_URL": "https://abcdefghijkl.supabase.co",
  "SUPABASE_PUBLISHABLE_KEY": "sb_publishable_xxxxxxxxxxxxxxxx",
  "APP_ENV": "prod",
  "ENABLE_LOG": false
}

Agar anggota kelompok tahu kunci apa saja yang dibutuhkan, commit file contoh tanpa nilai asli:

📄 config/example.json (di-commit)

{
  "SUPABASE_URL": "https://ISI_PROJECT_ID.supabase.co",
  "SUPABASE_PUBLISHABLE_KEY": "ISI_PUBLISHABLE_KEY_DARI_DASHBOARD",
  "APP_ENV": "dev",
  "ENABLE_LOG": true
}

Lalu tambahkan ke .gitignore di root proyek:

📄 .gitignore (tambahkan di bagian bawah)

# Konfigurasi rahasia
/config/*.json
!/config/example.json

Baris ! berarti pengecualian: semua file JSON di config/ diabaikan kecuali example.json.

Langkah 2: class Env

📄 lib/config/env.dart

// lib/config/env.dart
class Env {
  // Nilai diisi saat build lewat --dart-define atau --dart-define-from-file.
  // WAJIB const, karena nilainya ditanam ke aplikasi saat kompilasi.
  static const supabaseUrl = String.fromEnvironment('SUPABASE_URL');
  static const supabaseKey = String.fromEnvironment('SUPABASE_PUBLISHABLE_KEY');
  static const appEnv = String.fromEnvironment('APP_ENV', defaultValue: 'dev');
  static const enableLog = bool.fromEnvironment('ENABLE_LOG');

  static bool get isProduction => appEnv == 'prod';

  /// false jika aplikasi dijalankan tanpa --dart-define-from-file.
  static bool get isConfigured => supabaseUrl.isNotEmpty && supabaseKey.isNotEmpty;
}
  • String.fromEnvironment dan bool.fromEnvironment harus dipanggil sebagai const. Dokumentasi Dart hanya menjamin nilainya terbaca dalam konteks const; tanpa const, nilainya bisa kosong, terutama di build release.
  • Nilai JSON true/false dibaca dengan bool.fromEnvironment; angka dengan int.fromEnvironment.
  • defaultValue dipakai jika kunci tidak ada di file.

Langkah 3: memakai Env di main.dart

📄 lib/main.dart

// lib/main.dart
import 'package:flutter/material.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

import 'config/env.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // Lupa --dart-define-from-file? Tampilkan pesan yang jelas, jangan crash.
  if (!Env.isConfigured) {
    runApp(const ConfigErrorApp());
    return;
  }

  await Supabase.initialize(
    url: Env.supabaseUrl,
    publishableKey: Env.supabaseKey,
  );
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Catatan Kuliah',
      // Pita "DEBUG" hanya muncul jika bukan build produksi
      debugShowCheckedModeBanner: !Env.isProduction,
      home: Scaffold(
        appBar: AppBar(title: const Text('Catatan Kuliah')),
        body: Center(child: Text('Lingkungan: ${Env.appEnv}')),
      ),
    );
  }
}

class ConfigErrorApp extends StatelessWidget {
  const ConfigErrorApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      home: Scaffold(
        body: Center(
          child: Padding(
            padding: EdgeInsets.all(24),
            child: Column(
              mainAxisSize: MainAxisSize.min,
              children: [
                Icon(Icons.settings_suggest, size: 64, color: Colors.orange),
                SizedBox(height: 16),
                Text(
                  'Konfigurasi Supabase belum diisi',
                  style: TextStyle(fontSize: 18, fontWeight: FontWeight.bold),
                ),
                SizedBox(height: 8),
                Text(
                  'Jalankan dengan:\n'
                  'flutter run --dart-define-from-file=config/dev.json',
                  textAlign: TextAlign.center,
                ),
              ],
            ),
          ),
        ),
      ),
    );
  }
}

Jika aplikasi dijalankan tanpa file konfigurasi (misalnya menekan tombol Run tanpa launch.json), pengguna melihat pesan jelas, bukan crash misterius dari Supabase:

Dijalankan tanpa --dart-define-from-file: ConfigErrorApp tampil

Langkah 4: menjalankan dan mem-build

# Pengembangan
flutter run --dart-define-from-file=config/dev.json

# Build rilis dengan konfigurasi produksi
flutter build apk --split-per-abi --dart-define-from-file=config/prod.json

# Juga bisa memakai file .env (format KUNCI=nilai)
flutter run --dart-define-from-file=.env

Agar tombol Run/Debug di VS Code otomatis memakai file konfigurasi, isi .vscode/launch.json seperti di Modul 15 bagian 2 ("args": ["--dart-define-from-file=config/dev.json"]).

ℹ️ Apakah key Supabase jadi rahasia?

Tidak sepenuhnya. Nilai --dart-define ditanam ke dalam APK, sehingga orang yang membongkar APK masih bisa menemukannya. Tujuan langkah ini adalah tidak menyebarkan kunci lewat GitHub dan memudahkan berganti project dev/prod. Keamanan data Supabase tetap bergantung pada Row Level Security (Modul 12). Publishable/anon key memang dirancang boleh berada di aplikasi klien; yang tidak boleh sama sekali masuk ke aplikasi adalah service_role/secret key.

⚠️ Kesalahan umum

  • Menulis final url = String.fromEnvironment('SUPABASE_URL'); tanpa const. Di build release, nilainya bisa kosong.
  • Lupa menambahkan flag saat flutter build. APK jadi tidak bisa login. Simpan perintah build di README agar tidak lupa.
  • Sudah terlanjur commit key ke GitHub, lalu hanya menghapus file di commit berikutnya. Key tetap ada di riwayat git. Buat ulang (rotate) key di dashboard Supabase.
  • Memasukkan service_role key ke aplikasi agar “RLS tidak mengganggu”. Siapa pun yang membongkar APK bisa membaca dan menghapus seluruh database.
