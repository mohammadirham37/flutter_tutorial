Android melindungi fitur sensitif (internet, kamera, lokasi, notifikasi) dengan permission. Aplikasi harus mendeklarasikan permission di AndroidManifest.xml; sebagian juga harus diminta langsung kepada pengguna saat aplikasi berjalan.

Jebakan nomor satu: permission INTERNET

Aplikasi Catatan Kuliah berjalan lancar di emulator, tetapi setelah APK release dipasang di HP, login Supabase selalu gagal. Kenapa? Proyek Flutter punya tiga file manifest:

android/app/src/
├── debug/AndroidManifest.xml     # dipakai saat flutter run (debug)
├── profile/AndroidManifest.xml   # dipakai saat --profile
└── main/AndroidManifest.xml      # dipakai SEMUA mode, termasuk release

Manifest debug bawaan sudah berisi permission INTERNET (dibutuhkan untuk hot reload), sedangkan manifest main tidak. Jadi aplikasi bisa mengakses internet saat debug, tetapi tidak saat release. Isi manifest debug bawaan:

📄 android/app/src/debug/AndroidManifest.xml (bawaan flutter create)

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- The INTERNET permission is required for development. Specifically,
         the Flutter tool needs it to communicate with the running application
         to allow setting breakpoints, to provide hot reload, etc.
    -->
    <uses-permission android:name="android.permission.INTERNET"/>
</manifest>

Solusinya, tambahkan permission di manifest main, di luar tag <application>:

📄 android/app/src/main/AndroidManifest.xml (potongan)

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- Wajib untuk Supabase, REST API, gambar dari internet -->
    <uses-permission android:name="android.permission.INTERNET"/>

    <application
        android:label="Catatan Kuliah"
        android:name="${applicationName}"
        android:icon="@mipmap/ic_launcher">
        ...
    </application>
</manifest>

Contoh manifest untuk aplikasi capstone yang memakai kamera dan lokasi (misalnya aplikasi pengaduan sarana kampus):

📄 android/app/src/main/AndroidManifest.xml (potongan)

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.INTERNET"/>
    <uses-permission android:name="android.permission.ACCESS_NETWORK_STATE"/>
    <uses-permission android:name="android.permission.CAMERA"/>
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>
    <uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>

    <!-- Kamera tidak wajib: aplikasi tetap bisa dipasang di perangkat tanpa kamera -->
    <uses-feature android:name="android.hardware.camera" android:required="false"/>

    <application ...>
        ...
    </application>
</manifest>

Permission “berbahaya” (kamera, lokasi, notifikasi) juga harus diminta saat runtime. Package seperti image_picker dan geolocator biasanya sudah menampilkan dialog izin sendiri. Untuk kontrol penuh, gunakan package permission_handler dan ikuti petunjuk konfigurasinya di pub.dev.

iOS: alasan penggunaan di Info.plist

iOS tidak memakai daftar permission, tetapi mewajibkan kalimat alasan untuk setiap fitur sensitif. Tanpa kalimat ini aplikasi langsung tertutup saat meminta izin, dan App Store menolak aplikasi.

📄 ios/Runner/Info.plist (potongan)

<key>NSCameraUsageDescription</key>
<string>Kamera dipakai untuk memotret fasilitas yang rusak.</string>
<key>NSLocationWhenInUseUsageDescription</key>
<string>Lokasi dipakai untuk menandai posisi laporan di peta kampus.</string>

⚠️ Kesalahan umum

  • Menambahkan INTERNET hanya di manifest debug, atau menaruh <uses-permission> di dalam tag <application>.
  • Meminta permission yang tidak dipakai. Play Console akan menanyakan alasannya, dan pengguna jadi curiga.
  • Tidak menangani kasus pengguna menolak izin. Tampilkan pesan dan jalan alternatif, jangan biarkan aplikasi crash.
