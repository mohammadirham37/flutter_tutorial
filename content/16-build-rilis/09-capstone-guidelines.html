🏆 Ketentuan Capstone Project (Bobot 35% Nilai Akhir)

Mahasiswa secara berkelompok (2-3 orang) atau mandiri membangun satu aplikasi mobile lengkap yang menyelesaikan permasalahan nyata di lingkungan kampus atau masyarakat. Capstone adalah tempat menggabungkan semua materi: widget dan layout (Modul 03-06), navigasi (07), Provider (08), API dan penyimpanan (09-12), arsitektur proyek (13-14), testing (15), dan rilis (16).

Boleh memakai arsitektur Catatan Kuliah sebagai dasar

Anda diizinkan dan disarankan memakai struktur proyek Modul 13-14 sebagai kerangka: AuthProvider + AuthGate untuk login Supabase, pola Repository dengan remote data source (Supabase) dan cache Hive, serta Provider untuk state halaman. Syaratnya:

  • Domain aplikasi harus berbeda dari catatan kuliah (tabel, model, dan halaman baru, bukan sekadar mengganti judul).
  • Minimal dua entitas data yang saling berhubungan (misalnya laporan dan kategori, atau produk dan pesanan), bukan hanya satu tabel.
  • Sebutkan di README bagian mana yang diadaptasi dari modul.

Struktur folder yang direkomendasikan:

lib/
├── main.dart              # inisialisasi Env, Supabase, Hive, MultiProvider
├── config/env.dart        # konfigurasi --dart-define-from-file
├── models/                # class data + fromJson/toJson
├── data/                  # data source (Supabase, Hive) dan repository
├── providers/             # AuthProvider dan provider fitur
├── pages/                 # satu file per halaman
├── widgets/               # widget yang dipakai ulang
└── utils/                 # validator, formatter, konstanta
test/
├── unit/                  # validator, model, provider
├── mock/                  # fake data source
└── widget/                # halaman login, daftar, form

Pilihan tema proyek

  1. Sistem Pengaduan Sarana Kampus: laporan fasilitas rusak dengan foto kamera, kategori, dan status penanganan (baru, diproses, selesai).
  2. Marketplace UMKM Mahasiswa: katalog produk, keranjang belanja (Provider), riwayat pesanan per pengguna.
  3. Perpustakaan & Peminjaman Buku: pencarian buku via REST API publik, daftar pinjaman di Supabase, bookmark offline.
  4. Layanan Akademik: jadwal kuliah, pengajuan surat izin online, pengingat tugas.
  5. Tema bebas dengan persetujuan dosen paling lambat minggu ke-2 periode capstone.

## Fitur
- Register, login, logout (Supabase Auth), sesi tersimpan
- CRUD laporan + kategori (tabel berelasi, RLS aktif)
- Cache offline dengan Hive
- Unggah foto ke Supabase Storage (bonus)

## Arsitektur
UI (pages, widgets) -> Provider -> Repository -> Data source (Supabase / Hive).
Diadaptasi dari proyek Catatan Kuliah Modul 13-14: AuthGate, AuthProvider,
pola NoteRepository (diganti menjadi LaporanRepository).

| kategori | id, nama                                        |
| laporan  | id, user_id, kategori_id, judul, status, foto   |

## Menjalankan Proyek
1. `flutter pub get`
2. Salin `config/example.json` menjadi `config/dev.json`, isi URL dan key Supabase
3. `flutter run --dart-define-from-file=config/dev.json`

## Testing
```bash
flutter test            # 14 test, semua lulus
flutter test --coverage
```

## Build Rilis
```bash
flutter build apk --split-per-abi --obfuscate \
  --split-debug-info=build/symbols --dart-define-from-file=config/prod.json
```

⚠️ Kesalahan umum capstone

  • Satu anggota mengerjakan semuanya dan anggota lain hanya membuat slide. Riwayat commit akan terlihat.
  • Mematikan RLS di Supabase agar “tidak error”. Ini mengurangi nilai integrasi data secara signifikan.
  • Hanya menguji di emulator debug, lalu APK release gagal login saat presentasi (lupa permission INTERNET atau lupa --dart-define-from-file).
  • Meng-commit config/dev.json berisi key asli. Rotasi key di dashboard Supabase jika sudah terlanjur.
  • Mulai mengerjakan di minggu ke-5. Ikuti timeline; demo progres minggu ke-4 adalah titik pemeriksaan wajib.
