Android hanya mau memasang APK yang ditandatangani secara digital. Selama ini Flutter diam-diam memakai debug key yang sama untuk semua developer di dunia. Untuk rilis, Anda butuh kunci sendiri (keystore) yang menjadi bukti bahwa update aplikasi benar-benar berasal dari Anda.

Konsep: kenapa tanda tangan penting?

  • Android hanya mengizinkan update jika APK baru ditandatangani dengan kunci yang sama dengan APK yang sudah terpasang.
  • Jika keystore hilang, Anda tidak bisa lagi memperbarui aplikasi yang sudah dibagikan (kecuali memakai Play App Signing, lihat bagian 8).
  • Jika keystore bocor, orang lain bisa membuat “update” palsu atas nama Anda.

Langkah 1: membuat keystore dengan keytool

keytool sudah tersedia bersama JDK yang dipasang Android Studio. Jalankan dari folder root proyek:

# macOS / Linux: simpan di android/app/
keytool -genkey -v -keystore android/app/upload-keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias upload

# Windows (PowerShell), satu baris:
keytool -genkey -v -keystore android\app\upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload

Jika muncul keytool: command not found, pakai keytool bawaan Android Studio. Lokasinya bisa dilihat dengan flutter doctor -v pada baris Java binary at, lalu ganti java dengan keytool pada path tersebut.

Langkah 2: file android/key.properties

Gradle membaca password dari file terpisah agar tidak tertulis di build.gradle.kts:

📄 android/key.properties

storePassword=password_keystore_anda
keyPassword=password_key_anda
keyAlias=upload
# Relatif terhadap folder android/app/
storeFile=upload-keystore.jks

Periksa android/.gitignore. Proyek dari flutter create versi terbaru sudah mengabaikan file-file ini:

📄 android/.gitignore (bawaan, bagian bawah)

# Remember to never publicly share your keystore.
# See https://flutter.dev/to/reference-keystore
key.properties
**/*.keystore
**/*.jks

Pastikan dengan perintah berikut. Jika file muncul di daftar “Untracked files”, berarti belum diabaikan:

git status --ignored android/ | grep -E "key.properties|jks"
# hasil yang benar: kedua file muncul di bagian "Ignored files"

Langkah 3: konfigurasi signing di build.gradle.kts

Proyek Flutter baru memakai Kotlin DSL (build.gradle.kts). Berikut file lengkap hasil flutter create versi terbaru yang sudah ditambah konfigurasi signing. Bagian yang Anda tambahkan: dua baris import di paling atas, blok pembacaan key.properties, blok signingConfigs, dan isi buildTypes.

📄 android/app/build.gradle.kts

import java.io.FileInputStream
import java.util.Properties

plugins {
    id("com.android.application")
    // The Flutter Gradle Plugin must be applied after the Android and Kotlin Gradle plugins.
    id("dev.flutter.flutter-gradle-plugin")
}

// Baca android/key.properties (jika ada)
val keystoreProperties = Properties()
val keystorePropertiesFile = rootProject.file("key.properties")
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(FileInputStream(keystorePropertiesFile))
}

android {
    namespace = "id.ac.unsoed.catatan_kuliah"
    compileSdk = flutter.compileSdkVersion
    ndkVersion = flutter.ndkVersion

    compileOptions {
        sourceCompatibility = JavaVersion.VERSION_17
        targetCompatibility = JavaVersion.VERSION_17
    }

    defaultConfig {
        // TODO: Specify your own unique Application ID (https://developer.android.com/studio/build/application-id.html).
        applicationId = "id.ac.unsoed.catatan_kuliah"
        // You can update the following values to match your application needs.
        // For more information, see: https://flutter.dev/to/review-gradle-config.
        minSdk = flutter.minSdkVersion
        targetSdk = flutter.targetSdkVersion
        // Uses the version code from pubspec.yaml. When using split APKs, 1000 * ABI_VERSION
        // is added automatically by Flutter. (https://developer.android.com/studio/build/configure-apk-splits#configure-APK-versions)
        // You can force using the value of versionCode by specifying the `-P force-version-code-ignoring-abi=true`
        // flag during build.
        versionCode = flutter.versionCode
        versionName = flutter.versionName
    }

    signingConfigs {
        create("release") {
            if (keystorePropertiesFile.exists()) {
                keyAlias = keystoreProperties["keyAlias"] as String
                keyPassword = keystoreProperties["keyPassword"] as String
                storeFile = file(keystoreProperties["storeFile"] as String)
                storePassword = keystoreProperties["storePassword"] as String
            }
        }
    }

    buildTypes {
        release {
            signingConfig = if (keystorePropertiesFile.exists()) {
                signingConfigs.getByName("release")
            } else {
                // Belum ada key.properties: pakai debug key agar
                // `flutter run --release` tetap bisa dicoba
                signingConfigs.getByName("debug")
            }
        }
    }
}

kotlin {
    compilerOptions {
        jvmTarget = org.jetbrains.kotlin.gradle.dsl.JvmTarget.JVM_17
    }
}

flutter {
    source = "../.."
}

Penjelasan:

  • import harus di baris paling atas, sebelum blok plugins. Di Kotlin script, import di tengah file menyebabkan error kompilasi Gradle.
  • rootProject.file("key.properties") menunjuk ke android/key.properties, sedangkan file(...) di dalam blok android relatif terhadap android/app/. Itu sebabnya storeFile=upload-keystore.jks cukup ditulis nama filenya.
  • Pemeriksaan keystorePropertiesFile.exists() membuat proyek tetap bisa di-build oleh anggota kelompok yang tidak memegang keystore (APK-nya memakai debug key). Tanpa pemeriksaan ini, flutter run biasa pun gagal di komputer mereka.
  • Bagian lain (compileSdk, versionCode, blok kotlin) biarkan sesuai bawaan proyek Anda. Versi Flutter yang berbeda bisa menghasilkan isi bawaan yang sedikit berbeda.

Jika proyek Anda masih memakai build.gradle (Groovy, proyek lama), ikuti panduan resmi: docs.flutter.dev/deployment/android.

Langkah 4: memastikan APK benar-benar memakai kunci rilis

Setelah build (bagian 7), periksa sertifikat APK dengan apksigner dari Android SDK build-tools:

# macOS (sesuaikan versi build-tools di komputer Anda)
~/Library/Android/sdk/build-tools/<versi>/apksigner verify --print-certs \
  build/app/outputs/flutter-apk/app-arm64-v8a-release.apk
# Benar: memakai keystore Anda
V2 Signer: certificate DN: CN=Budi Santoso, OU=Informatika, O=UNSOED, L=Purwokerto, ST=Jawa Tengah, C=ID

# Salah: masih debug key (key.properties tidak terbaca)
V2 Signer: certificate DN: C=US, O=Android, CN=Android Debug

💡 Backup keystore

Simpan salinan upload-keystore.jks beserta password-nya di tempat aman di luar laptop (password manager, Google Drive pribadi yang tidak dibagikan). Laptop rusak tanpa backup keystore berarti aplikasi Anda tidak bisa di-update lagi di luar Play App Signing.

⚠️ Kesalahan umum

  • Meng-commit key.properties atau file .jks ke GitHub publik.
  • Menulis path Windows dengan backslash tunggal di key.properties (C:\Users\budi\key.jks). Gunakan garis miring biasa (C:/Users/budi/key.jks) atau simpan keystore di android/app/ dan tulis nama filenya saja.
  • Lupa mengganti signingConfig di buildTypes.release, sehingga APK rilis tetap memakai debug key.
  • Membuat keystore baru setiap kali build. Satu aplikasi = satu keystore selamanya.
