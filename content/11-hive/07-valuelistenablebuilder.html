Kalau data di box berubah, bagaimana UI ikut berubah? Kamu bisa saja memanggil setState setelah setiap put, tetapi Hive menyediakan cara yang lebih rapi: box.listenable() yang dipasangkan dengan widget ValueListenableBuilder.

Konsep

  • box.listenable() (dari hive_ce_flutter) menghasilkan ValueListenable<Box> yang memberi kabar setiap ada put, add, delete, atau clear.
  • ValueListenableBuilder menjalankan ulang fungsi builder-nya setiap kabar itu datang.
  • Hasilnya: cukup tulis ke box, dan UI akan menyesuaikan sendiri. Tidak perlu setState.
ValueListenableBuilder<Box<String>>(
  valueListenable: Hive.box<String>('tugas_cepat').listenable(),
  builder: (context, box, child) {
    return Text('Jumlah tugas: ${box.length}');
  },
)

Contoh lengkap: daftar Tugas Cepat

📄 lib/main.dart

// lib/main.dart
import 'package:flutter/material.dart';
import 'package:hive_ce_flutter/hive_ce_flutter.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Hive.initFlutter();
  await Hive.openBox<String>('tugas_cepat');
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const TugasScreen(),
    );
  }
}

class TugasScreen extends StatefulWidget {
  const TugasScreen({super.key});

  @override
  State<TugasScreen> createState() => _TugasScreenState();
}

class _TugasScreenState extends State<TugasScreen> {
  // Box sudah dibuka di main(), di sini cukup diambil
  final Box<String> _box = Hive.box<String>('tugas_cepat');
  final _controller = TextEditingController();

  @override
  void dispose() {
    _controller.dispose();
    super.dispose();
  }

  void _tambah() {
    final teks = _controller.text.trim();
    if (teks.isEmpty) return;
    _box.add(teks); // TIDAK perlu setState: UI ikut berubah sendiri
    _controller.clear();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Tugas Cepat')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(12),
            child: Row(
              children: [
                Expanded(
                  child: TextField(
                    controller: _controller,
                    decoration: const InputDecoration(
                      hintText: 'Tulis tugas...',
                      border: OutlineInputBorder(),
                    ),
                    onSubmitted: (_) => _tambah(),
                  ),
                ),
                const SizedBox(width: 8),
                FilledButton(onPressed: _tambah, child: const Text('Tambah')),
              ],
            ),
          ),
          Expanded(
            // Builder ini dijalankan ulang setiap isi box berubah
            child: ValueListenableBuilder<Box<String>>(
              valueListenable: _box.listenable(),
              builder: (context, box, _) {
                if (box.isEmpty) {
                  return const Center(child: Text('Belum ada tugas'));
                }
                final keys = box.keys.toList();
                return ListView.builder(
                  itemCount: keys.length,
                  itemBuilder: (context, index) {
                    final key = keys[index];
                    return ListTile(
                      leading: CircleAvatar(child: Text('${index + 1}')),
                      title: Text(box.get(key) ?? ''),
                      trailing: IconButton(
                        icon: const Icon(Icons.delete_outline),
                        onPressed: () => box.delete(key),
                      ),
                    );
                  },
                );
              },
            ),
          ),
        ],
      ),
    );
  }
}
Box masih kosong
Setelah menambah tugas: list langsung diperbarui tanpa setState

Penjelasan:

  • _box.add(teks) di _tambah() tidak diikuti setState. Builder tetap dijalankan ulang karena mendengarkan box.
  • Di dalam builder kita memakai box.keys.toList(), lalu menghapus berdasarkan key (box.delete(key)), bukan index. Ingat bagian 3: key dari add() terus naik dan tidak ikut bergeser saat ada yang dihapus.
  • setState masih wajar dipakai untuk state UI lain yang bukan isi box, misalnya teks di TextField.

Hanya mendengarkan key tertentu

Jika widget hanya peduli pada satu atau dua key, berikan parameter keys agar widget tidak ikut di-rebuild saat key lain berubah:

ValueListenableBuilder<Box>(
  valueListenable: Hive.box('pengaturan').listenable(keys: ['tema_gelap']),
  builder: (context, box, _) {
    final gelap = box.get('tema_gelap', defaultValue: false) as bool;
    return Icon(gelap ? Icons.dark_mode : Icons.light_mode);
  },
)

💡 Kapan cukup ValueListenableBuilder, kapan butuh Provider?

ValueListenableBuilder sangat praktis untuk layar sederhana yang langsung menampilkan isi box. Ketika ada logika tambahan (validasi, pencarian, pengurutan, gabungan beberapa sumber data), lebih rapi jika logika itu dipindah ke repository dan Provider. Itu topik bagian berikutnya.
