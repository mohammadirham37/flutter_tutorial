Menulis adapter manual untuk banyak model cukup melelahkan dan rawan salah urutan. hive_ce_generator bisa membuatkan adapter secara otomatis. Bagian ini bersifat lanjutan (opsional); pastikan kamu sudah paham bagian 5 dulu.

Langkah 1: Pasang generator

flutter create rak_buku
cd rak_buku
flutter pub add hive_ce hive_ce_flutter
flutter pub add dev:hive_ce_generator dev:build_runner

Awalan dev: menaruh package di dev_dependencies, karena generator hanya dipakai saat development dan tidak ikut ke APK.

Langkah 2: Model biasa, tanpa anotasi

📄 lib/models/buku.dart

// lib/models/buku.dart  (class biasa, tanpa anotasi apa pun)
class Buku {
  final String isbn;
  final String judul;
  final int tahun;
  final List<String> penulis;

  Buku({
    required this.isbn,
    required this.judul,
    required this.tahun,
    required this.penulis,
  });
}

Langkah 3: Daftarkan model di satu file @GenerateAdapters

Cara yang direkomendasikan hive_ce saat ini adalah anotasi @GenerateAdapters. Semua model yang ingin dibuatkan adapter cukup didaftarkan di satu tempat; model tidak perlu ditempeli @HiveType dan @HiveField seperti di tutorial hive lama.

📄 lib/hive/hive_adapters.dart

// lib/hive/hive_adapters.dart
import 'package:hive_ce/hive_ce.dart';

import '../models/buku.dart';

part 'hive_adapters.g.dart';

@GenerateAdapters([AdapterSpec<Buku>()])
class HiveAdapters {}

Langkah 4: Jalankan build_runner

dart run build_runner build --delete-conflicting-outputs

Tiga file baru akan muncul di folder lib/hive/:

FileIsi
hive_adapters.g.dartKelas BukuAdapter hasil generate
hive_adapters.g.yamlCatatan typeId dan indeks tiap field. Wajib ikut di-commit ke Git, karena dipakai agar indeks tidak berubah saat model diubah.
hive_registrar.g.dartExtension Hive.registerAdapters() untuk mendaftarkan semua adapter sekaligus

Dan potongan BukuAdapter yang dibuat otomatis. Perhatikan bahwa setiap nilai diawali nomor indeks field (writeByte(0), writeByte(1), ...). Karena itu field baru bisa ditambahkan tanpa merusak data lama.

// GENERATED CODE - DO NOT MODIFY BY HAND

part of 'hive_adapters.dart';

// **************************************************************************
// AdaptersGenerator
// **************************************************************************

class BukuAdapter extends TypeAdapter<Buku> {
  @override
  final typeId = 0;

  @override
  Buku read(BinaryReader reader) {
    final numOfFields = reader.readByte();
    final fields = <int, dynamic>{
      for (int i = 0; i < numOfFields; i++) reader.readByte(): reader.read(),
    };
    return Buku(
      isbn: fields[0] as String,
      judul: fields[1] as String,
      tahun: (fields[2] as num).toInt(),
      penulis: (fields[3] as List).cast<String>(),
    );
  }

  @override
  void write(BinaryWriter writer, Buku obj) {
    writer
      ..writeByte(4)
      ..writeByte(0)
      ..write(obj.isbn)
      ..writeByte(1)
      ..write(obj.judul)
      ..writeByte(2)
      ..write(obj.tahun)
      ..writeByte(3)
      ..write(obj.penulis);
  }

  @override
  int get hashCode => typeId.hashCode;

  @override
  bool operator ==(Object other) =>
      identical(this, other) ||
      other is BukuAdapter &&
          runtimeType == other.runtimeType &&
          typeId == other.typeId;
}

📄 lib/hive/hive_registrar.g.dart (dibuat otomatis, jangan diedit)

import 'package:hive_ce/hive_ce.dart';

extension HiveRegistrar on HiveInterface {
  void registerAdapters() {
    registerAdapter(BukuAdapter());
  }

  void registerAdapters() {
    registerAdapter(BukuAdapter());
  }

Langkah 5: Pakai di main.dart

📄 lib/main.dart

// lib/main.dart
import 'package:flutter/material.dart';
import 'package:hive_ce_flutter/hive_ce_flutter.dart';

import 'models/buku.dart';
import 'hive/hive_registrar.g.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Hive.initFlutter();

  // Satu baris mendaftarkan SEMUA adapter hasil generate
  Hive.registerAdapters();

  final box = await Hive.openBox<Buku>('buku_box');
  if (box.isEmpty) {
    await box.add(Buku(
      isbn: '978-602-1',
      judul: 'Belajar Flutter',
      tahun: 2024,
      penulis: ['Andi', 'Siti'],
    ));
    await box.add(Buku(
      isbn: '978-602-2',
      judul: 'Struktur Data dengan Dart',
      tahun: 2023,
      penulis: ['Budi'],
    ));
  }

  runApp(const BukuApp());
}

class BukuApp extends StatelessWidget {
  const BukuApp({super.key});

  @override
  Widget build(BuildContext context) {
    final daftar = Hive.box<Buku>('buku_box').values.toList();
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        appBar: AppBar(title: const Text('Rak Buku (codegen)')),
        body: ListView(
          children: [
            for (final b in daftar)
              ListTile(
                leading: const Icon(Icons.menu_book),
                title: Text(b.judul),
                subtitle: Text('${b.penulis.join(', ')} • ${b.tahun}'),
              ),
          ],
        ),
      ),
    );
  }
}
Objek Buku (termasuk List penulis) tersimpan memakai adapter hasil generate

Saat model berubah

  • Tambah field: tambahkan di kelas, jalankan lagi build_runner. Field baru mendapat indeks berikutnya (lihat nextIndex di file yaml). Untuk data lama, field baru bernilai null, jadi buat field baru nullable atau beri nilai default di constructor.
  • Hapus field: hapus dari kelas lalu generate ulang. Indeksnya tidak akan dipakai ulang.
  • Tambah model baru: tambahkan AdapterSpec<ModelBaru>() ke daftar @GenerateAdapters.

ℹ️ Bagaimana dengan @HiveType dan @HiveField?

Gaya lama (anotasi @HiveType(typeId: 0) di kelas dan @HiveField(0) di setiap field, ditambah part 'buku.g.dart';) masih didukung hive_ce_generator agar proyek lama tetap jalan. Untuk proyek baru, gunakan @GenerateAdapters karena model tetap bersih dan indeks dikelola otomatis lewat file yaml.
