Package sensors_plus dari Flutter Community menyediakan stream untuk akselerometer, user accelerometer, giroskop, magnetometer, dan barometer di Android dan iOS. Bagian ini membahas pemasangan, konfigurasi platform, nama API terbaru, dan cara menangani perangkat yang tidak punya sensor.

Pemasangan

flutter pub add sensors_plus

Versi terbaru package ini membutuhkan Android Gradle Plugin, Gradle wrapper, dan Kotlin yang cukup baru (lihat bagian Requirements di README pub.dev). Proyek yang dibuat dengan flutter create versi stabil terkini sudah memenuhinya. Jika proyek lamamu gagal build setelah menambah package ini, perbarui versi plugin Gradle di android/settings.gradle.kts dan android/gradle/wrapper/gradle-wrapper.properties.

Konfigurasi Android

Akselerometer, giroskop, magnetometer, dan barometer tidak memerlukan izin apa pun di Android. Tidak ada dialog izin yang muncul, sehingga tidak ada alur "izin ditolak" seperti kamera atau lokasi (Modul 17). Ada dua tambahan opsional di android/app/src/main/AndroidManifest.xml:

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- Opsional: tetap bisa dipasang di HP tanpa kompas,
         tapi Play Store tahu aplikasi ini memakai sensor tersebut -->
    <uses-feature android:name="android.hardware.sensor.accelerometer"
                  android:required="false" />
    <uses-feature android:name="android.hardware.sensor.compass"
                  android:required="false" />

    <!-- Hanya jika butuh lebih dari 200 Hz (Android 12+). Jarang perlu. -->
    <!-- <uses-permission android:name="android.permission.HIGH_SAMPLING_RATE_SENSORS" /> -->

    <application ...>

android:required="true" membuat aplikasi tersembunyi di Play Store untuk HP yang tidak punya sensor tersebut. Pakai true hanya jika aplikasimu sama sekali tidak berguna tanpa sensor itu.

Konfigurasi iOS

README sensors_plus mewajibkan kunci NSMotionUsageDescription di ios/Runner/Info.plist. Tanpa kunci ini aplikasi akan crash saat mengakses data gerak (paling terasa saat membaca barometer).

<key>NSMotionUsageDescription</key>
<string>Aplikasi memakai sensor gerak untuk kompas dan waterpass.</string>

Daftar fungsi stream

Gunakan fungsi yang menerima samplingPeriod. Getter lama seperti accelerometerEvents masih ada tetapi sudah deprecated.

FungsiTipe eventFieldSumber di Android / iOS
accelerometerEventStream()AccelerometerEventx, y, z (m/s²), timestampTYPE_ACCELEROMETER / CMAccelerometer
userAccelerometerEventStream()UserAccelerometerEventx, y, z (m/s², tanpa gravitasi)TYPE_LINEAR_ACCELERATION / userAcceleration dari device motion
gyroscopeEventStream()GyroscopeEventx, y, z (rad/s)TYPE_GYROSCOPE / CMGyro
magnetometerEventStream()MagnetometerEventx, y, z (µT)TYPE_MAGNETIC_FIELD / CMMagnetometer
barometerEventStream()BarometerEventpressure (hPa)TYPE_PRESSURE / CMAltimeter

Semua fungsi menerima parameter bernama samplingPeriod bertipe Duration, defaultnya SensorInterval.normalInterval (200 ms). Di iOS, periode barometer tidak bisa diatur. Di web, periode diabaikan, dan magnetometer serta barometer tidak tersedia.

Contoh kecil: membaca akselerometer

Pola dasarnya sama dengan stream di Modul 02: listen di initState, simpan StreamSubscription, lalu cancel di dispose.

📄 lib/main.dart

// lib/main.dart
import 'dart:async';

import 'package:flutter/material.dart';
import 'package:flutter/services.dart';
import 'package:sensors_plus/sensors_plus.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const AkselerometerPage(),
    );
  }
}

class AkselerometerPage extends StatefulWidget {
  const AkselerometerPage({super.key});

  @override
  State<AkselerometerPage> createState() => _AkselerometerPageState();
}

class _AkselerometerPageState extends State<AkselerometerPage> {
  StreamSubscription<AccelerometerEvent>? _langganan;
  AccelerometerEvent? _event;
  String? _error;

  @override
  void initState() {
    super.initState();
    _langganan =
        accelerometerEventStream(samplingPeriod: SensorInterval.uiInterval)
            .listen(
              (event) {
                setState(() => _event = event);
              },
              onError: (Object e) {
                // Android mengirim PlatformException kode NO_SENSOR
                // jika perangkat tidak punya sensor ini.
                final pesan = e is PlatformException
                    ? '${e.code}: ${e.details ?? e.message}'
                    : e.toString();
                setState(() => _error = pesan);
              },
              cancelOnError: true,
            );
  }

  @override
  void dispose() {
    _langganan?.cancel(); // WAJIB: hentikan sensor saat halaman ditutup
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final event = _event;
    return Scaffold(
      appBar: AppBar(title: const Text('Akselerometer')),
      body: Center(
        child: _error != null
            ? Text(
                'Sensor tidak tersedia\n$_error',
                textAlign: TextAlign.center,
              )
            : event == null
            ? const CircularProgressIndicator()
            : Column(
                mainAxisSize: MainAxisSize.min,
                children: [
                  Text('x: ${event.x.toStringAsFixed(2)} m/s²'),
                  Text('y: ${event.y.toStringAsFixed(2)} m/s²'),
                  Text('z: ${event.z.toStringAsFixed(2)} m/s²'),
                ],
              ),
      ),
    );
  }
}
  • accelerometerEventStream(samplingPeriod: SensorInterval.uiInterval) meminta data sekitar 15 kali per detik.
  • onError dipanggil jika sensor tidak ada. Di Android, plugin mengirim PlatformException dengan code NO_SENSOR dan details berisi pesan seperti "It seems that your device has no Accelerometer sensor". Di iOS, kode error-nya UNAVAILABLE.
  • cancelOnError: true menghentikan langganan setelah error pertama. Sensor yang tidak ada tidak akan tiba-tiba muncul, jadi tidak ada gunanya terus mendengarkan.
  • _langganan?.cancel() di dispose adalah baris paling penting. Tanpa ini, sensor tetap aktif setelah halaman ditutup, baterai terkuras, dan setState dipanggil pada widget yang sudah dibuang.

Coba letakkan HP mendatar di meja: z mendekati 9,8. Tegakkan HP: kini y yang mendekati 9,8. Miringkan ke kanan: x menjadi negatif karena sisi kanan turun.

Bagaimana dengan "izin" sensor?

Untuk empat sensor di atas, "alur izin" diganti dengan alur ketersediaan:

  1. Tersedia: data mengalir ke onData, tampilkan seperti biasa.
  2. Tidak tersedia (HP murah tanpa giroskop/magnetometer, simulator iOS, browser): onError terpanggil. Tampilkan pesan yang jelas dan nonaktifkan fitur yang bergantung pada sensor itu, tetapi biarkan fitur lain tetap berjalan.
  3. Data belum datang: tampilkan indikator memuat. Jangan menganggap nilai awal 0 sebagai data asli.

ℹ️ Sensor yang butuh izin

Penghitung langkah (step counter) dan pengenalan aktivitas memerlukan izin ACTIVITY_RECOGNITION di Android dan izin Motion & Fitness di iOS. Fitur tersebut tidak disediakan sensors_plus, dan alur izinnya mengikuti pola permission_handler di Modul 17.

⚠️ Satu sensor, satu stream bersama

Di Android dan iOS, sensors_plus membuat satu broadcast stream per sensor dan menyimpannya. Memanggil accelerometerEventStream() dua kali dengan samplingPeriod berbeda akan mengubah periode untuk semua pendengar. Tentukan satu periode per sensor di satu tempat (nanti di SensorService, bagian 7).
