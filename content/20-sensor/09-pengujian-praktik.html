Aplikasi sensor sulit diuji karena datanya berasal dari dunia fisik. Bagian ini membahas tiga lapis pengujian: unit test untuk rumus, emulator Android dengan sensor virtual, dan HP fisik. Setelah itu ada daftar praktik terbaik dan kesalahan umum.

1. Unit test untuk rumus

Karena semua rumus sudah dipisah ke file Dart murni, kita bisa mengujinya tanpa sensor sama sekali. Caranya: berikan vektor buatan yang hasilnya bisa kita hitung sendiri. Ganti kompas_kampus dengan nama proyekmu (lihat name: di pubspec.yaml).

📄 test/rumus_sensor_test.dart

// test/rumus_sensor_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:kompas_kampus/models/vektor3.dart';
import 'package:kompas_kampus/utils/filter_sensor.dart';
import 'package:kompas_kampus/utils/kompas_math.dart';
import 'package:kompas_kampus/utils/waterpass_math.dart';

void main() {
  group('headingDerajat (HP mendatar, layar ke atas)', () {
    // Medan magnet contoh: 30 µT mendatar ke utara, 20 µT ke bawah.
    test('sisi atas HP menghadap utara = 0°', () {
      expect(headingDerajat(0, 0, 9.81, 0, 30, -20), closeTo(0, 0.001));
    });
    test('sisi atas HP menghadap timur = 90°', () {
      // Utara sekarang ada di sebelah kiri HP (sumbu -x)
      expect(headingDerajat(0, 0, 9.81, -30, 0, -20), closeTo(90, 0.001));
    });
    test('sisi atas HP menghadap barat = 270°', () {
      expect(headingDerajat(0, 0, 9.81, 30, 0, -20), closeTo(270, 0.001));
    });
    test('data tidak valid menghasilkan null', () {
      expect(headingDerajat(0, 0, 0, 0, 30, -20), isNull); // jatuh bebas
    });
  });

  test('bearing kiblat dari Jakarta sekitar 295°', () {
    expect(bearingDerajat(-6.2, 106.8, 21.4225, 39.8262), closeTo(295, 1));
  });

  test('selisihSudut memilih arah terpendek', () {
    expect(selisihSudut(350, 10), closeTo(20, 1e-9));
    expect(selisihSudut(10, 350), closeTo(-20, 1e-9));
  });

  test('kemiringan: sisi kanan terangkat 30° → sudutX = 30', () {
    // gravitasi terbagi ke sumbu x (sin 30°) dan z (cos 30°)
    final k = hitungKemiringan(const Vektor3(4.905, 0, 8.4957));
    expect(k.sudutX, closeTo(30, 0.01));
    expect(k.sudutY, closeTo(0, 0.01));
    expect(k.datar(), isFalse);
  });

  test('guncangan hanya dihitung sekali dalam jeda', () {
    final d = DeteksiGuncangan();
    final t0 = DateTime(2025);
    const keras = Vektor3(30, 0, 0); // sekitar 3 g
    expect(d.proses(keras, t0), isTrue);
    expect(d.proses(keras, t0.add(const Duration(milliseconds: 100))), isFalse);
    expect(d.proses(keras, t0.add(const Duration(seconds: 1))), isTrue);
    expect(d.proses(const Vektor3(0, 0, 9.81), t0), isFalse); // diam = 1 g
  });
}

flutter test test/rumus_sensor_test.dart
  • HP mendatar dengan sisi atas ke utara: akselerometer (0, 0, 9.81), medan magnet mengarah ke +y (dan sedikit ke bawah). Heading harus 0°.
  • HP diputar menghadap timur: utara sekarang di kiri HP, sehingga medan magnet mengarah ke -x. Heading harus 90°.
  • Sisi kanan diangkat 30°: gravitasi terbagi menjadi 9,81 × sin 30° = 4,905 di x dan 9,81 × cos 30° ≈ 8,4957 di z.
  • Test seperti ini menangkap kesalahan tanda (misalnya atan2(ny, ey) yang tertukar) sebelum kamu sempat memutar-mutar HP.

2. Emulator Android: Virtual sensors

Android Emulator menyediakan sensor virtual. Buka Extended Controls (tombol ⋯ di panel samping emulator), lalu pilih Virtual sensors:

  • Tab Device Pose: putar model HP 3D dengan menyeret, atau atur slider rotasi (Yaw, Pitch, Roll pada versi emulator terbaru). Akselerometer, giroskop, dan magnetometer ikut berubah sesuai pose. Cocok untuk menguji waterpass (ubah Pitch/Roll) dan kompas (ubah Yaw: piringan harus berputar berlawanan arah). Mode Move menggeser posisi HP untuk menghasilkan percepatan.
  • Tab Additional sensors: mengatur nilai sensor lingkungan secara langsung, termasuk medan magnet (µT) dan tekanan udara (hPa). Coba isi medan magnet dengan nilai besar (misalnya 150 µT) untuk memunculkan peringatan kalibrasi.

Batasan emulator:

  • Guncangan sulit ditiru. Deteksi guncangan paling mudah diuji lewat unit test dan HP fisik.
  • Data emulator terlalu bersih (tanpa derau), sehingga efek low-pass filter dan gangguan hard/soft iron tidak terlihat.
  • Simulator iOS tidak punya sensor gerak sama sekali. Stream akan mengirim error, dan kamu bisa memanfaatkannya untuk menguji tampilan "sensor tidak tersedia". Pengujian iOS yang sebenarnya harus di iPhone fisik.

3. HP fisik

Pengujian akhir selalu di HP fisik. Untuk kompas, bandingkan hasilnya dengan aplikasi kompas bawaan atau panah arah di Google Maps. Untuk waterpass, letakkan HP di permukaan yang diketahui datar, misalnya lantai keramik. Jika hasilnya bukan 0°, wajar. Akselerometer HP punya offset kecil dari pabrik, dan beberapa aplikasi waterpass menyediakan tombol "kalibrasi nol" yang menyimpan offset tersebut lalu menguranginya dari hasil berikutnya.

Praktik terbaik

  1. Selalu batalkan langganan di dispose() atau onClose(). Dokumentasi Android mengingatkan bahwa sistem tidak mematikan sensor otomatis saat layar padam.
  2. Matikan sensor saat aplikasi di background dengan AppLifecycleListener (atau WidgetsBindingObserver), lalu nyalakan lagi saat kembali. Sejak Android 9, aplikasi di background memang tidak menerima event sensor kontinu, jadi tidak ada gunanya membiarkan langganan tetap hidup.
  3. Pilih sampling period terbesar yang masih cukup. uiInterval untuk tampilan, gameInterval hanya jika perlu respons cepat. Hindari fastestInterval.
  4. Pisahkan laju data dari laju gambar. Filter memproses setiap sampel, tetapi UI cukup diperbarui 10 sampai 20 kali per detik.
  5. Selalu pasang onError dan rancang UI untuk sensor yang tidak ada. Matikan fitur yang bergantung padanya, jangan seluruh aplikasi.
  6. Kunci orientasi layar untuk aplikasi yang memetakan sensor ke tampilan (kompas, waterpass, game kemiringan).
  7. Pisahkan rumus ke file Dart murni supaya bisa diuji tanpa perangkat.
  8. Beri tahu pengguna jika data meragukan: medan magnet tidak wajar, HP terlalu miring, atau data belum datang.
