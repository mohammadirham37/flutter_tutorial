Tabel bisa dibuat lewat Table Editor dengan klik-klik, tetapi di praktikum ini kita memakai SQL Editor. Perintah SQL bisa disimpan, dibagikan, dan dijalankan ulang persis sama. Kebiasaan ini juga yang dipakai tim profesional (disebut migration).

Membuka SQL Editor

  1. Di sidebar dashboard klik SQL Editor.
  2. Klik New query (atau ikon +).
  3. Tempel SQL, lalu klik Run (atau Ctrl/Cmd + Enter).
  4. Hasil atau pesan error muncul di panel bawah. "Success. No rows returned" artinya perintah berhasil.

Tabel pertama: mata_kuliah

create table public.mata_kuliah (
  id bigint generated always as identity primary key,
  kode text not null unique,
  nama text not null,
  sks int not null default 3 check (sks between 1 and 6),
  semester int not null check (semester between 1 and 8),
  created_at timestamptz not null default now()
);

Kita bedah baris demi baris:

  • public.mata_kuliah: tabel dibuat di schema public. Hanya tabel di schema ini yang bisa diakses lewat API dari Flutter.
  • bigint generated always as identity primary key: id berupa angka yang naik otomatis (1, 2, 3, ...). Kita tidak perlu mengirim id saat insert.
  • text not null unique: kode wajib diisi dan tidak boleh ada yang sama. Insert kode ganda akan ditolak dengan error 23505.
  • default 3: jika kolom tidak dikirim saat insert, nilainya otomatis 3.
  • check (sks between 1 and 6): database menolak nilai di luar rentang (error 23514). Validasi di database adalah lapis pertahanan terakhir, meskipun form Flutter juga sudah memvalidasi.
  • timestamptz not null default now(): waktu dibuat terisi otomatis dalam UTC dengan zona waktu.

Relasi ke tabel user (auth.users)

Supabase menyimpan akun hasil register di tabel auth.users (schema auth, dikelola Supabase, tidak bisa diakses langsung lewat API). Tabel milik kita cukup menyimpan id user sebagai foreign key:

create table public.contoh_milik_user (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null default auth.uid()
    references auth.users (id) on delete cascade,
  isi text not null
);
  • default auth.uid(): saat insert dari aplikasi, user_id otomatis terisi id user yang sedang login. Aplikasi tidak perlu mengirimnya.
  • on delete cascade: jika akun user dihapus, semua barisnya ikut terhapus.

💡 Membersihkan tabel latihan

Tabel contoh_uuid dan contoh_milik_user hanya untuk latihan. Hapus dengan drop table public.contoh_uuid, public.contoh_milik_user;

⚠️ Tabel baru tanpa RLS = terbuka untuk siapa saja

Tabel yang dibuat lewat SQL tidak otomatis dilindungi. Selama RLS belum aktif, siapa pun yang memegang publishable key bisa membaca dan mengubah isinya (dashboard akan memberi label peringatan UNRESTRICTED). Sebaliknya, jika RLS aktif tetapi belum ada policy, hasil query dari aplikasi selalu kosong. Section berikutnya membahas cara mengatur keduanya dengan benar.
