Supabase Auth mengurus register, login, penyimpanan sesi, dan perpanjangan token secara otomatis. Di section ini kita mengenal method-method dasarnya. Implementasi lengkap dengan UI dikerjakan di Modul 13.

Pengaturan di dashboard

  1. Buka Authentication → Sign In / Providers. Pastikan provider Email aktif (default sudah aktif).
  2. Perhatikan opsi Confirm email:
    • ON (default): setelah register, user harus mengeklik link di email sebelum bisa login. signUp mengembalikan session == null.
    • OFF: user langsung login setelah register. signUp mengembalikan session yang valid. Cocok untuk latihan di kelas.
  3. Daftar user yang sudah register bisa dilihat di Authentication → Users.

⚠️ Batas pengiriman email

Layanan email bawaan Supabase hanya untuk percobaan dan dibatasi beberapa email per jam. Jika satu kelas register bersamaan dengan Confirm email ON, sebagian akan mendapat error over_email_send_rate_limit. Untuk praktikum, matikan Confirm email. Untuk aplikasi produksi, pasang SMTP sendiri di Authentication → Emails → SMTP Settings.

1. Register: signUp

Future<void> daftar() async {
  final AuthResponse res = await supabase.auth.signUp(
    email: 'budi@mhs.unsoed.ac.id',
    password: 'rahasia123',
    data: {'full_name': 'Budi Santoso'}, // disimpan di user metadata
  );

  final User? user = res.user; // akun yang baru dibuat
  final Session? session = res.session; // null jika wajib konfirmasi email
  debugPrint('User: ${user?.id}, langsung login: ${session != null}');
}
  • data disimpan sebagai user metadata (di database bernama kolom raw_user_meta_data). Di Modul 13 kita memakai trigger untuk menyalin full_name ke tabel profiles.
  • Password minimal 6 karakter (default Supabase). Jika kurang, muncul AuthException dengan code weak_password.

2. Login dan logout

Future<void> masuk() async {
  final res = await supabase.auth.signInWithPassword(
    email: 'budi@mhs.unsoed.ac.id',
    password: 'rahasia123',
  );
  debugPrint('Halo ${res.user?.email}');
}

Future<void> keluar() async {
  await supabase.auth.signOut();
}

Setelah login berhasil, semua query database berikutnya otomatis membawa token user. RLS pun mengenali siapa yang meminta data melalui auth.uid(), tanpa kode tambahan.

3. Mengecek sesi saat ini

void cekSesi() {
  // Sesi disimpan otomatis di perangkat oleh supabase_flutter,
  // jadi setelah aplikasi ditutup dan dibuka lagi user tetap login.
  final Session? session = supabase.auth.currentSession;
  final User? user = supabase.auth.currentUser;

  if (session == null) {
    debugPrint('Belum login');
  } else {
    debugPrint('Login sebagai ${user!.email}');
    debugPrint('Nama: ${user.userMetadata?['full_name']}');
  }
}

4. Mendengarkan perubahan status login

StreamSubscription<AuthState> dengarkanAuth() {
  return supabase.auth.onAuthStateChange.listen((AuthState data) {
    final AuthChangeEvent event = data.event;
    final Session? session = data.session;

    switch (event) {
      case AuthChangeEvent.initialSession:
        debugPrint('Aplikasi dibuka, sesi awal: ${session != null}');
      case AuthChangeEvent.signedIn:
        debugPrint('Berhasil login');
      case AuthChangeEvent.signedOut:
        debugPrint('Sudah logout');
      case AuthChangeEvent.tokenRefreshed:
        debugPrint('Token diperbarui otomatis');
      default:
        debugPrint('Event lain: ${event.name}');
    }
  });
}
// Jangan lupa: subscription.cancel() di dispose() jika dipakai di widget.
EventKapan terjadi
initialSessionSelalu menjadi event pertama saat stream didengarkan. Berisi sesi tersimpan (atau null).
signedInSetelah login/register berhasil (dan sesi aktif).
signedOutSetelah signOut() atau sesi tidak valid lagi.
tokenRefreshedToken akses diperpanjang otomatis (kira-kira setiap jam).
userUpdatedData user diubah lewat updateUser().
passwordRecoveryUser membuka link reset password.

Stream inilah kunci navigasi otomatis: ada sesi = tampilkan Home, tidak ada sesi = tampilkan Login. Pola ini disebut AuthGate dan dibangun di Modul 13.

ℹ️ Di mana sesi disimpan?

supabase_flutter menyimpan sesi di penyimpanan lokal perangkat (berbasis SharedPreferences, Modul 10). Karena itu user tetap login walaupun aplikasi ditutup, dan token diperbarui otomatis selama aplikasi berjalan.

⚠️ Register dengan email yang sudah terdaftar

Jika Confirm email ON, Supabase tidak melempar error saat email sudah terdaftar. Ia mengembalikan user "palsu" agar penyerang tidak bisa menebak email siapa saja yang terdaftar (user enumeration). Jika Confirm email OFF, error user_already_exists akan muncul.
