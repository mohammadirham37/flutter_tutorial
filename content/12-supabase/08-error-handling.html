Request ke internet pasti suatu saat gagal, entah karena sinyal hilang, server menolak, atau data tidak valid. Aplikasi yang baik menampilkan pesan yang jelas, bukan layar merah atau loading tanpa akhir.

Tiga jenis kegagalan

JenisException di DartContoh penyebab
Database menolakPostgrestExceptionRLS, UNIQUE dilanggar, CHECK gagal, tabel tidak ada
Auth menolakAuthException (dan turunannya)password salah, email belum dikonfirmasi, email sudah terdaftar
Jaringan gagalSocketException, ClientException, TimeoutException, AuthRetryableFetchExceptiontidak ada internet, DNS gagal, server terlalu lama

Menangani PostgrestException

Future<String> tambahDenganPenangananError() async {
  try {
    await supabase.from('mata_kuliah').insert({
      'kode': 'INF301', // sudah ada -> melanggar UNIQUE
      'nama': 'Duplikat',
      'semester': 5,
    });
    return 'Berhasil disimpan';
  } on PostgrestException catch (e) {
    // e.code berisi kode error PostgreSQL / PostgREST
    switch (e.code) {
      case '23505':
        return 'Kode mata kuliah sudah dipakai.';
      case '23514':
        return 'Data melanggar aturan CHECK (misalnya SKS di luar 1-6).';
      case '42501':
        return 'Ditolak oleh Row Level Security. Apakah Anda sudah login?';
      default:
        return 'Kesalahan database: ${e.message}';
    }
  } on TimeoutException {
    return 'Server terlalu lama merespons.';
  } catch (e) {
    // Biasanya SocketException / ClientException: tidak ada internet.
    return 'Tidak dapat terhubung ke server.';
  }
}
  • on PostgrestException catch (e) hanya menangkap error dari database. Properti pentingnya: e.message, e.code, e.details, dan e.hint.
  • catch (e) paling bawah menangkap sisanya, biasanya masalah jaringan.
  • Urutan on ... catch penting: yang paling spesifik ditulis di atas.

Menangani AuthException

Future<String?> loginDenganPenangananError(
  String email,
  String password,
) async {
  try {
    await supabase.auth.signInWithPassword(email: email, password: password);
    return null; // null = sukses
  } on AuthRetryableFetchException {
    return 'Tidak ada koneksi internet.';
  } on AuthException catch (e) {
    // e.code: 'invalid_credentials', 'email_not_confirmed', dst.
    if (e.code == 'invalid_credentials') return 'Email atau password salah.';
    if (e.code == 'email_not_confirmed') return 'Konfirmasi email dulu.';
    return e.message;
  }
}

AuthRetryableFetchException adalah turunan AuthException yang dilempar saat request Auth gagal karena jaringan. Karena merupakan turunan, ia harus ditangkap sebelum on AuthException.

💡 Di mana sebaiknya try-catch ditulis?

Jangan menyebar try-catch di setiap widget. Di proyek Modul 13–14, error ditangkap di Provider, diterjemahkan menjadi pesan Bahasa Indonesia, lalu UI cukup menampilkan pesannya. Dengan begitu tampilan tetap bersih dan logika error terkumpul di satu tempat.

⚠️ Jangan menelan error

catch (e) {} yang kosong membuat bug tidak terlihat: data tidak tersimpan dan user tidak tahu kenapa. Minimal tampilkan SnackBar atau tulis debugPrint(e.toString()) saat pengembangan.
