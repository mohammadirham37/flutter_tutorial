Kasus nyata pertama: pengguna memilih tema Terang, Gelap, atau Ikuti Sistem, dan pilihan itu harus tetap berlaku ketika aplikasi dibuka lagi. Kita gabungkan SharedPreferences dengan GetX dan pola MVC (Modul 08): service membaca/menulis preferensi, controller menyimpan tema yang sedang aktif, dan view menampilkan pilihannya.

Konsep

  1. GetMaterialApp (sama seperti MaterialApp) punya parameter themeMode (ThemeMode.light, .dark, .system).
  2. Enum tidak bisa disimpan langsung, jadi simpan namanya (ThemeMode.dark.name = 'dark'), lalu ubah kembali dengan ThemeMode.values.byName('dark').
  3. Tema harus sudah diketahui sebelum layar pertama tampil agar tidak "berkedip" dari terang ke gelap. Karena itu preferensi dibaca di main() sebelum runApp memakai SharedPreferencesWithCache.

Contoh Kecil: Enum ke String dan Sebaliknya

import 'package:flutter/material.dart';

void contohEnum() {
  const mode = ThemeMode.dark;
  final String disimpan = mode.name; // 'dark'
  final ThemeMode dibaca = ThemeMode.values.byName(disimpan); // ThemeMode.dark
  print('$disimpan -> $dibaca');
}

Struktur File

lib/
├── main.dart                      (membaca prefs, mendaftarkan controller, View pengaturan)
├── services/
│   └── theme_service.dart         (akses SharedPreferences)
└── controllers/
    └── theme_controller.dart      (state tema yang reaktif)

Langkah 1: ThemeService (Akses Data)

Service adalah satu-satunya class yang tahu kunci 'theme_mode' dan cara mengubah enum menjadi string. Service tidak memakai GetX dan tidak memakai widget; dari Flutter ia hanya mengambil tipe enum ThemeMode.

📄 lib/services/theme_service.dart

import 'package:flutter/material.dart' show ThemeMode;
import 'package:shared_preferences/shared_preferences.dart';

class ThemeService {
  static const kunciTema = 'theme_mode';

  final SharedPreferencesWithCache _prefs;
  ThemeService(this._prefs);

  /// Dibaca sinkron dari cache, jadi tidak perlu loading.
  ThemeMode baca() {
    final nama = _prefs.getString(kunciTema);
    if (nama == null) return ThemeMode.system;
    try {
      return ThemeMode.values.byName(nama);
    } on ArgumentError {
      return ThemeMode.system; // nilai rusak/tidak dikenal
    }
  }

  Future<void> simpan(ThemeMode mode) => _prefs.setString(kunciTema, mode.name);
}

Langkah 2: ThemeController

📄 lib/controllers/theme_controller.dart

import 'package:flutter/material.dart' show ThemeMode;
import 'package:get/get.dart';

import '../services/theme_service.dart';

class ThemeController extends GetxController {
  // Nilai awal langsung diambil dari service (sudah ada di cache)
  ThemeController(this._service) : _mode = _service.baca().obs;

  final ThemeService _service;
  final Rx<ThemeMode> _mode;

  ThemeMode get mode => _mode.value;

  Future<void> setMode(ThemeMode mode) async {
    if (mode == _mode.value) return;
    _mode.value = mode; // UI berubah seketika
    await _service.simpan(mode); // lalu disimpan
  }
}

Penjelasan: Rx<ThemeMode> adalah versi reaktif dari enum. Karena nilai awalnya dibaca di constructor, tema sudah benar sejak frame pertama. import ... show ThemeMode menegaskan bahwa controller hanya butuh tipe enum, bukan widget Material.

Langkah 3: Baca Preferensi Sebelum runApp

📄 lib/main.dart

// Pastikan sudah: flutter pub add shared_preferences get
import 'package:flutter/material.dart';
import 'package:get/get.dart';
import 'package:shared_preferences/shared_preferences.dart';

import 'controllers/theme_controller.dart';
import 'services/theme_service.dart';

Future<void> main() async {
  // Wajib sebelum memakai plugin di main()
  WidgetsFlutterBinding.ensureInitialized();

  final prefs = await SharedPreferencesWithCache.create(
    cacheOptions: const SharedPreferencesWithCacheOptions(
      allowList: {ThemeService.kunciTema},
    ),
  );

  Get.put(ThemeController(ThemeService(prefs)), permanent: true);
  runApp(const TemaApp());
}

class TemaApp extends StatelessWidget {
  const TemaApp({super.key});

  @override
  Widget build(BuildContext context) {
    final themeC = Get.find<ThemeController>();
    // Obx membangun ulang GetMaterialApp setiap kali mode berubah
    return Obx(() => GetMaterialApp(
          debugShowCheckedModeBanner: false,
          theme: ThemeData(colorSchemeSeed: Colors.indigo, brightness: Brightness.light),
          darkTheme: ThemeData(colorSchemeSeed: Colors.indigo, brightness: Brightness.dark),
          themeMode: themeC.mode,
          home: const PengaturanView(),
        ));
  }
}

class PengaturanView extends GetView<ThemeController> {
  const PengaturanView({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Pengaturan Tampilan')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          Text('Tema aplikasi', style: Theme.of(context).textTheme.titleMedium),
          const SizedBox(height: 12),
          Obx(() => SegmentedButton<ThemeMode>(
                segments: const [
                  ButtonSegment(value: ThemeMode.light, icon: Icon(Icons.light_mode), label: Text('Terang')),
                  ButtonSegment(value: ThemeMode.dark, icon: Icon(Icons.dark_mode), label: Text('Gelap')),
                  ButtonSegment(value: ThemeMode.system, icon: Icon(Icons.phone_android), label: Text('Sistem')),
                ],
                selected: {controller.mode},
                onSelectionChanged: (pilihan) => controller.setMode(pilihan.first),
              )),
          const SizedBox(height: 24),
          Card(
            child: Obx(() => ListTile(
                  leading: const Icon(Icons.info_outline),
                  title: Text('Mode tersimpan: ${controller.mode.name}'),
                  subtitle: const Text('Tutup lalu buka aplikasi: tema tetap sama.'),
                )),
          ),
        ],
      ),
    );
  }
}

Penjelasan:

  • WidgetsFlutterBinding.ensureInitialized() wajib dipanggil karena kita memakai plugin (SharedPreferencesWithCache.create) sebelum runApp.
  • Objek prefs dioper ke ThemeService, lalu service dioper ke ThemeController lewat constructor. Tidak ada class yang membuat dependency-nya sendiri, sehingga mudah diganti saat testing.
  • Get.put(..., permanent: true) dipanggil sebelum runApp, sehingga TemaApp dan PengaturanView bisa langsung memakai Get.find. Tema dipakai sepanjang umur aplikasi, jadi controller-nya dibuat permanen.
  • Obx di TemaApp membaca themeC.mode; saat pengguna memilih segmen lain, GetMaterialApp dibangun ulang dengan themeMode baru.
  • SegmentedButton adalah komponen Material 3 untuk memilih satu dari beberapa opsi.

💡 Alternatif: Get.changeThemeMode

GetX juga menyediakan Get.changeThemeMode(ThemeMode.dark) untuk mengganti tema tanpa Obx. Di kursus ini kita memakai Obx agar alurnya sama dengan state lain: nilai di controller berubah, View yang membacanya ikut berubah. Dengan begitu tema yang tampil selalu sama dengan yang tersimpan di controller.

⚠️ Kesalahan Umum

  • Lupa WidgetsFlutterBinding.ensureInitialized(): muncul error Binding has not yet been initialized.
  • Membaca tema di initState layar pertama: tampilan sempat terang sebentar lalu berubah gelap (flicker).
  • Menyimpan mode.toString() ('ThemeMode.dark') lalu membacanya dengan byName: gagal. Pakai .name.
  • Memanggil Get.find<ThemeController>() sebelum Get.put: error "ThemeController" not found.
  • Lupa menambahkan kunci ke allowList: SharedPreferencesWithCache melempar error saat kunci dipakai.
