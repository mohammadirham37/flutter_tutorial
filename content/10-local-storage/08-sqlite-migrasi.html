Aplikasi terus berkembang. Di versi 2 kamu ingin menambah kolom prioritas pada tabel tugas. Masalahnya, pengguna lama sudah punya database versi 1 berisi data penting. Kita tidak boleh menghapusnya; kita harus memigrasi struktur tabel. Inilah fungsi version dan onUpgrade.

Konsep: Kapan Callback Dipanggil?

Kondisi di HP penggunaCallback yang berjalan
Aplikasi baru dipasang (file belum ada)onCreate(db, versiTerbaru)
File ada, versinya lebih kecil dari versiononUpgrade(db, versiLama, versiBaru)
File ada, versinya lebih besar (aplikasi di-downgrade)onDowngrade (jika diisi)
Setiap kali database dibuka, sebelum yang lainonConfigure(db)
Setiap kali database selesai dibukaonOpen(db)

Contoh Kecil: Menambah Kolom di Versi 2

import 'package:sqflite/sqflite.dart';

Future<Database> buka(String path) {
  return openDatabase(
    path,
    version: 2, // naik dari 1 ke 2
    onCreate: (db, version) async {
      // Pengguna BARU langsung mendapat struktur terbaru
      await db.execute('''
        CREATE TABLE tugas (
          id INTEGER PRIMARY KEY AUTOINCREMENT,
          judul TEXT NOT NULL,
          prioritas INTEGER NOT NULL DEFAULT 0
        )
      ''');
    },
    onUpgrade: (db, oldVersion, newVersion) async {
      // Pengguna LAMA (versi 1) cukup ditambah kolomnya, data tetap aman
      if (oldVersion < 2) {
        await db.execute('ALTER TABLE tugas ADD COLUMN prioritas INTEGER NOT NULL DEFAULT 0');
      }
    },
  );
}

Aturan emas: onCreate selalu membuat struktur terbaru, sedangkan onUpgrade berisi langkah perubahan dari setiap versi lama.

Pola Migrasi Bertahap

Pengguna bisa melompat versi (dari 1 langsung ke 3). Karena itu tulis setiap langkah dengan if (oldVersion < N) yang berurutan, bukan if (oldVersion == N).

📄 lib/data/migrasi_database.dart

import 'package:path/path.dart';
import 'package:sqflite/sqflite.dart';

/// Riwayat skema:
///  v1: tabel tugas (id, judul)
///  v2: + kolom prioritas
///  v3: + tabel catatan
class MigrasiDatabase {
  static const int versiSkema = 3;
  static Database? _db;

  static Future<Database> get database async => _db ??= await _open();

  static Future<Database> _open() async {
    final path = join(await getDatabasesPath(), 'migrasi_demo.db');
    return openDatabase(
      path,
      version: versiSkema,
      onConfigure: (db) async {
        // Aktifkan foreign key setiap kali dibuka (dipakai di section Relasi)
        await db.execute('PRAGMA foreign_keys = ON');
      },
      onCreate: (db, version) async {
        // Struktur TERBARU untuk pengguna baru
        await db.execute('''
          CREATE TABLE tugas (
            id INTEGER PRIMARY KEY AUTOINCREMENT,
            judul TEXT NOT NULL,
            prioritas INTEGER NOT NULL DEFAULT 0
          )
        ''');
        await _buatTabelCatatan(db);
      },
      onUpgrade: (db, oldVersion, newVersion) async {
        if (oldVersion < 2) {
          await db.execute(
            'ALTER TABLE tugas ADD COLUMN prioritas INTEGER NOT NULL DEFAULT 0',
          );
        }
        if (oldVersion < 3) {
          await _buatTabelCatatan(db);
        }
      },
    );
  }

  static Future<void> _buatTabelCatatan(Database db) async {
    await db.execute('''
      CREATE TABLE catatan (
        id INTEGER PRIMARY KEY AUTOINCREMENT,
        isi TEXT NOT NULL,
        dibuat TEXT NOT NULL
      )
    ''');
  }

  /// Daftar kolom suatu tabel, untuk melihat hasil migrasi
  static Future<List<String>> kolom(String tabel) async {
    final db = await database;
    final info = await db.rawQuery('PRAGMA table_info($tabel)');
    return info.map((r) => '${r['name']} (${r['type']})').toList();
  }
}

Penjelasan: fungsi _buatTabelCatatan dipakai di dua tempat (onCreate dan onUpgrade) sehingga definisi tabel tidak ditulis dua kali. PRAGMA table_info adalah perintah SQLite untuk melihat struktur tabel.

Contoh Lengkap: Melihat Struktur Database

📄 lib/main.dart

// Pastikan sudah: flutter pub add sqflite path, dan membuat lib/data/migrasi_database.dart
import 'package:flutter/material.dart';
import 'package:sqflite/sqflite.dart'; // untuk db.getVersion()

import 'data/migrasi_database.dart';

void main() => runApp(const MaterialApp(home: StrukturScreen()));

class StrukturScreen extends StatefulWidget {
  const StrukturScreen({super.key});

  @override
  State<StrukturScreen> createState() => _StrukturScreenState();
}

class _StrukturScreenState extends State<StrukturScreen> {
  // Future disimpan sekali agar query tidak diulang setiap rebuild
  late final Future<Map<String, List<String>>> _future = _muat();

  Future<Map<String, List<String>>> _muat() async {
    final db = await MigrasiDatabase.database;
    return {
      'Versi skema': ['${await db.getVersion()}'],
      'Tabel tugas': await MigrasiDatabase.kolom('tugas'),
      'Tabel catatan': await MigrasiDatabase.kolom('catatan'),
    };
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Hasil Migrasi')),
      body: FutureBuilder(
        future: _future,
        builder: (context, snapshot) {
          if (snapshot.hasError) return Center(child: Text('${snapshot.error}'));
          if (!snapshot.hasData) return const Center(child: CircularProgressIndicator());
          return ListView(
            padding: const EdgeInsets.all(16),
            children: [
              for (final entry in snapshot.data!.entries)
                Card(
                  child: ListTile(
                    title: Text(entry.key),
                    subtitle: Text(entry.value.join('\n')),
                  ),
                ),
            ],
          );
        },
      ),
    );
  }
}
Versi skema 3 dengan kolom dan tabel terbaru

Coba eksperimen: ubah versiSkema menjadi 1 dan hapus bagian yang belum ada di v1, jalankan (setelah uninstall), lalu kembalikan ke 3 tanpa uninstall. Data lama tetap ada, dan kolom/tabel baru muncul.

💡 Fase Belajar vs Produksi

Saat masih belajar dan belum ada pengguna, cara paling cepat setelah mengubah onCreate adalah uninstall aplikasi (atau Clear storage) lalu jalankan ulang. Setelah aplikasi dirilis, jangan lakukan itu: selalu naikkan version dan tulis onUpgrade.

⚠️ Kesalahan Umum

  • Mengubah CREATE TABLE tanpa menaikkan version: pengguna lama mendapat error no such column.
  • Hot reload/hot restart tidak membuat ulang database. Perubahan skema baru terlihat setelah migrasi atau uninstall.
  • Menulis if (oldVersion == 1): pengguna yang melompat dari v1 ke v3 tidak mendapat langkah v2 → v3.
  • Menurunkan nomor version: memicu onDowngrade atau error. Nomor versi hanya boleh naik.
  • SQLite hanya mendukung sebagian ALTER TABLE (tambah/ganti nama kolom). Untuk mengubah tipe kolom, buat tabel baru, salin data, hapus tabel lama.
