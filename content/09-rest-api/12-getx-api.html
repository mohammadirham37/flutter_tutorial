FutureBuilder cocok untuk satu layar sederhana. Namun jika data yang sama dipakai banyak layar (daftar, detail, form) dan bisa berubah (tambah/hapus), simpan data di controller GetX (Modul 08). Controller menyimpan tiga hal: isLoading, pesan error, dan data. View cukup membaca ketiganya di dalam Obx.

Posisi Setiap File dalam Pola MVC

Lapisan dari section 9 tetap dipakai. Dalam pola MVC, ApiClient dan PostRepository berperan sebagai service (akses data); kita cukup menambahkan controller dan view.

Arah ketergantungan tetap satu arah: View → Controller → Repository → ApiClient. Controller tidak tahu soal http, dan View tidak tahu soal URL.

Langkah 1: Controller

Pasang package: flutter pub add get. Controller menerima PostRepository lewat constructor, sehingga saat testing bisa diganti FakePostRepository.

📄 lib/controllers/post_controller.dart

import 'package:get/get.dart';

import '../models/post.dart';
import '../repositories/post_repository.dart';

class PostController extends GetxController {
  PostController(this._repo);
  final PostRepository _repo;

  // State privat yang reaktif
  final _posts = <Post>[].obs;
  final _isLoading = false.obs;
  final _error = RxnString(); // String? yang reaktif

  // Getter publik read-only untuk View
  List<Post> get posts => List.unmodifiable(_posts);
  bool get isLoading => _isLoading.value;
  String? get error => _error.value;

  @override
  void onInit() {
    super.onInit();
    fetchPosts(); // data pertama diambil saat controller dibuat
  }

  Future<void> fetchPosts() async {
    _isLoading.value = true; // View langsung menampilkan loading
    _error.value = null;
    try {
      _posts.assignAll(await _repo.getAll());
    } catch (e) {
      _error.value = e.toString();
    } finally {
      _isLoading.value = false; // View menampilkan data atau error
    }
  }

  /// Optimistic delete: hapus dulu dari layar, kembalikan jika server gagal.
  Future<bool> deletePost(Post post) async {
    final index = _posts.indexOf(post);
    _posts.removeAt(index);
    try {
      await _repo.delete(post.id!);
      return true;
    } catch (e) {
      _posts.insert(index, post); // rollback
      return false;
    }
  }
}

Penjelasan:

  • Tidak ada pemanggilan manual seperti update(). Setiap kali .value pada _isLoading/_error diubah, atau isi _posts berubah (assignAll, removeAt, insert), semua Obx yang membacanya otomatis dibangun ulang.
  • onInit() adalah tempat yang tepat untuk request pertama: dipanggil sekali saat controller dibuat oleh Get.put.
  • finally memastikan isLoading kembali false, baik request berhasil maupun gagal.
  • Pada deletePost kita memakai pola optimistic update: item langsung hilang sehingga aplikasi terasa cepat, lalu dikembalikan jika server menolak. Controller hanya mengembalikan bool; yang menampilkan SnackBar adalah View.
  • Controller tidak mengimpor material.dart dan tidak memegang BuildContext, sehingga bisa di-unit-test tanpa widget (Modul 15).

Langkah 2: View

View di-extend dari GetView<PostController>, sehingga properti controller otomatis berisi hasil Get.find<PostController>().

📄 lib/views/post_list_view.dart

import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/post_controller.dart';

class PostListView extends GetView<PostController> {
  const PostListView({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Obx(() => Text('Post (${controller.posts.length})'))),
      body: Obx(() {
        // 1. Loading
        if (controller.isLoading) {
          return const Center(child: CircularProgressIndicator());
        }
        // 2. Error
        if (controller.error != null) {
          return Center(
            child: Column(
              mainAxisSize: MainAxisSize.min,
              children: [
                Text(controller.error!),
                const SizedBox(height: 12),
                FilledButton(
                  onPressed: controller.fetchPosts,
                  child: const Text('Coba Lagi'),
                ),
              ],
            ),
          );
        }
        // 3. Data
        final posts = controller.posts;
        return RefreshIndicator(
          onRefresh: controller.fetchPosts,
          child: ListView.builder(
            itemCount: posts.length,
            itemBuilder: (context, i) {
              final post = posts[i];
              return Dismissible(
                key: ValueKey(post.id),
                direction: DismissDirection.endToStart,
                background: Container(
                  color: Colors.red,
                  alignment: Alignment.centerRight,
                  padding: const EdgeInsets.only(right: 20),
                  child: const Icon(Icons.delete, color: Colors.white),
                ),
                onDismissed: (_) async {
                  final messenger = ScaffoldMessenger.of(context);
                  final ok = await controller.deletePost(post);
                  messenger.showSnackBar(SnackBar(
                    content: Text(ok ? 'Post ${post.id} dihapus' : 'Gagal menghapus, data dikembalikan'),
                  ));
                },
                child: ListTile(
                  leading: CircleAvatar(child: Text('${post.id}')),
                  title: Text(post.title, maxLines: 1, overflow: TextOverflow.ellipsis),
                  subtitle: Text(post.body, maxLines: 1, overflow: TextOverflow.ellipsis),
                ),
              );
            },
          ),
        );
      }),
    );
  }
}

Langkah 3: Daftarkan Controller di main.dart

📄 lib/main.dart

// Butuh: flutter pub add http get
// File: models/post.dart, core/api_exception.dart, core/api_client.dart,
//       repositories/post_repository.dart, controllers/post_controller.dart,
//       views/post_list_view.dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

import 'core/api_client.dart';
import 'controllers/post_controller.dart';
import 'repositories/post_repository.dart';
import 'views/post_list_view.dart';

void main() {
  final repo = RemotePostRepository(
    ApiClient(baseUrl: 'https://jsonplaceholder.typicode.com'),
  );
  Get.put(PostController(repo)); // onInit() langsung memanggil fetchPosts()
  runApp(const GetMaterialApp(home: PostListView()));
}
Data berhasil dimuat: daftar post dari PostController

Penjelasan:

  • Get.put(PostController(repo)) dipanggil sebelum runApp, sehingga controller sudah ada ketika PostListView memanggil Get.find (lewat GetView).
  • Obx di judul AppBar hanya membaca posts.length, jadi hanya judul yang dibangun ulang ketika jumlah post berubah. Obx di body membaca isLoading, error, dan posts.
  • Urutan pengecekan loading → error → data menjamin hanya satu kondisi yang tampil.
  • Di dalam callback (onPressed, onRefresh, onDismissed) cukup panggil controller.method(), tanpa Obx.
  • ScaffoldMessenger.of(context) disimpan ke variabel sebelum await, sehingga aman dipakai setelahnya.
  • Geser item ke kiri untuk menghapus. Karena JSONPlaceholder selalu menjawab sukses, rollback hanya terlihat jika internet dimatikan.

⚠️ Kesalahan Umum

  • Memanggil fetchPosts() di dalam build(): request dikirim ulang setiap kali layar dibangun. Panggil di onInit() controller.
  • Lupa Get.put sebelum View dibuka: muncul error "PostController" not found. You need to call "Get.put(PostController())".
  • Mengganti list dengan _posts = hasil: variabel final tidak bisa diisi ulang, dan list reaktifnya hilang. Pakai _posts.assignAll(hasil).
  • Obx yang tidak membaca satu pun nilai reaktif: GetX melempar error improper use of a GetX. Pastikan getter seperti controller.isLoading dibaca di dalam fungsi Obx, bukan di luar.
  • Menampilkan SnackBar atau dialog dari controller. Biarkan controller mengembalikan hasil (bool/pesan), lalu View yang bereaksi.
