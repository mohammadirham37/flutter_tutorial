Jaringan itu tidak bisa diandalkan: sinyal hilang di dalam lift, server kampus down saat KRS-an, atau URL salah ketik. Aplikasi yang baik tidak crash dan memberi pesan yang dimengerti pengguna. Di section ini kita mengenali jenis-jenis kegagalan dan cara menanganinya satu per satu.

Dua Jenis Kegagalan

JenisContohBagaimana terdeteksi
Request sampai, tetapi server menolak404, 401, 500Tidak ada exception! Harus cek response.statusCode.
Tidak ada internet / host salahMode pesawat, DNS gagalSocketException / http.ClientException
Server terlalu lamaServer lambat, sinyal lemahTimeoutException (jika memakai .timeout())
Response bukan JSON yang diharapkanHalaman HTML errorFormatException / TypeError

Langkah 1: Cek Status Code

import 'package:http/http.dart' as http;

Future<String> ambil() async {
  final response = await http.get(Uri.parse('https://jsonplaceholder.typicode.com/posts/9999'));

  // http TIDAK melempar error untuk 404, jadi kita cek sendiri
  if (response.statusCode >= 200 && response.statusCode < 300) {
    return response.body;
  }
  throw Exception('Server membalas ${response.statusCode}');
}

Langkah 2: Tangkap Exception dengan try/catch dan on

Klausa on NamaException catch (e) menangkap jenis error tertentu. Urutannya dari yang paling spesifik ke paling umum.

import 'dart:async'; // TimeoutException
import 'dart:io'; // SocketException (tidak tersedia di web)

import 'package:http/http.dart' as http;

Future<String> ambilDenganPenanganan() async {
  try {
    final response = await http
        .get(Uri.parse('https://jsonplaceholder.typicode.com/posts/1'))
        .timeout(const Duration(seconds: 10)); // batas waktu 10 detik
    return 'Status ${response.statusCode}';
  } on SocketException {
    return 'Tidak ada koneksi internet.';
  } on TimeoutException {
    return 'Server terlalu lama merespons. Coba lagi.';
  } on http.ClientException catch (e) {
    return 'Gagal menghubungi server: ${e.message}';
  } catch (e) {
    return 'Terjadi kesalahan tak terduga: $e';
  }
}

ℹ️ SocketException vs ClientException

Di Android/iOS, error koneksi dari package http berbentuk ClientException yang juga merupakan SocketException, sehingga kedua klausa di atas bisa menangkapnya. Di Flutter Web, dart:io tidak berfungsi dan error koneksi hanya berupa http.ClientException. Karena itu selalu sediakan klausa http.ClientException.

Langkah 3: Exception Buatan Sendiri

Agar UI cukup menampilkan satu pesan yang ramah, ubah semua jenis error menjadi satu class ApiException:

📄 lib/services/api_exception.dart

class ApiException implements Exception {
  final String message;
  final int? statusCode;

  const ApiException(this.message, {this.statusCode});

  // Menerjemahkan status code menjadi pesan yang dimengerti pengguna
  factory ApiException.fromStatus(int code) {
    final pesan = switch (code) {
      400 => 'Data yang dikirim tidak valid.',
      401 => 'Sesi berakhir, silakan login ulang.',
      403 => 'Anda tidak punya akses ke data ini.',
      404 => 'Data tidak ditemukan.',
      422 => 'Validasi gagal, periksa kembali isian.',
      >= 500 => 'Server sedang bermasalah. Coba beberapa saat lagi.',
      _ => 'Terjadi kesalahan (kode $code).',
    };
    return ApiException(pesan, statusCode: code);
  }

  @override
  String toString() => message; // agar Text('$error') langsung rapi
}

Contoh Lengkap: Simulator Error

Aplikasi ini punya tombol untuk memicu setiap jenis kegagalan: sukses, 404, host tidak ada, dan timeout (endpoint httpbin /delay/5 butuh 5 detik, sedangkan batas kita 2 detik). Coba juga nyalakan mode pesawat di emulator.

📄 lib/main.dart

// Pastikan sudah: flutter pub add http, dan membuat lib/services/api_exception.dart
import 'dart:async';
import 'dart:convert';
import 'dart:io';

import 'package:flutter/material.dart';
import 'package:http/http.dart' as http;

import 'services/api_exception.dart';

/// Satu fungsi GET yang mengubah semua jenis kegagalan menjadi ApiException.
Future<dynamic> getJson(String url, {Duration timeout = const Duration(seconds: 10)}) async {
  try {
    final res = await http.get(Uri.parse(url)).timeout(timeout);
    if (res.statusCode < 200 || res.statusCode >= 300) {
      throw ApiException.fromStatus(res.statusCode);
    }
    return jsonDecode(res.body);
  } on SocketException {
    throw const ApiException('Tidak ada koneksi internet. Periksa Wi-Fi atau data seluler.');
  } on TimeoutException {
    throw const ApiException('Koneksi lambat, server tidak merespons tepat waktu.');
  } on http.ClientException {
    throw const ApiException('Gagal menghubungi server.');
  } on FormatException {
    throw const ApiException('Format data dari server tidak dikenali.');
  }
}

void main() => runApp(const MaterialApp(home: ErrorDemoScreen()));

class ErrorDemoScreen extends StatefulWidget {
  const ErrorDemoScreen({super.key});

  @override
  State<ErrorDemoScreen> createState() => _ErrorDemoScreenState();
}

class _ErrorDemoScreenState extends State<ErrorDemoScreen> {
  String _pesan = 'Pilih skenario.';
  bool _sukses = true;
  bool _loading = false;

  Future<void> _coba(String url, {Duration timeout = const Duration(seconds: 10)}) async {
    setState(() => _loading = true);
    try {
      final data = await getJson(url, timeout: timeout);
      _sukses = true;
      _pesan = 'Berhasil: ${(data as Map)['title']}';
    } on ApiException catch (e) {
      _sukses = false;
      _pesan = e.statusCode == null ? e.message : '${e.message} (HTTP ${e.statusCode})';
    }
    if (mounted) setState(() => _loading = false);
  }

  @override
  Widget build(BuildContext context) {
    const base = 'https://jsonplaceholder.typicode.com';
    return Scaffold(
      appBar: AppBar(title: const Text('Simulasi Error Jaringan')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          FilledButton(onPressed: () => _coba('$base/posts/1'), child: const Text('Sukses (200)')),
          FilledButton.tonal(onPressed: () => _coba('$base/posts/9999'), child: const Text('Tidak ditemukan (404)')),
          FilledButton.tonal(
            onPressed: () => _coba('https://host-tidak-ada.invalid/data'),
            child: const Text('Host salah / offline'),
          ),
          FilledButton.tonal(
            onPressed: () => _coba('https://httpbin.org/delay/5', timeout: const Duration(seconds: 2)),
            child: const Text('Timeout (2 detik)'),
          ),
          const SizedBox(height: 24),
          if (_loading)
            const Center(child: CircularProgressIndicator())
          else
            Card(
              color: _sukses ? Colors.green.shade50 : Colors.red.shade50,
              child: ListTile(
                leading: Icon(
                  _sukses ? Icons.check_circle : Icons.error_outline,
                  color: _sukses ? Colors.green : Colors.red,
                ),
                title: Text(_pesan),
              ),
            ),
        ],
      ),
    );
  }
}

Penjelasan: fungsi getJson adalah satu-satunya tempat yang tahu soal SocketException, TimeoutException, dan status code. UI hanya perlu menangkap ApiException dan menampilkan message. Pola ini akan kita pakai lagi di service/repository layer.

⚠️ Kesalahan Umum

  • Hanya memakai try/catch tanpa mengecek status code, sehingga response 500 dianggap sukses lalu jsonDecode gagal dengan pesan membingungkan.
  • Menampilkan e.toString() mentah kepada pengguna (ClientException with SocketException: Failed host lookup...). Terjemahkan menjadi kalimat yang ramah.
  • Tidak memberi .timeout(): tanpa batas waktu, spinner bisa berputar sangat lama.
  • Menelan error diam-diam: catch (e) {} tanpa pesan apa pun membuat pengguna dan programmer sama-sama bingung.
