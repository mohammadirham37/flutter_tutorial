Hampir semua aplikasi modern (Gojek, Tokopedia, SIA kampus) tidak menyimpan seluruh datanya di HP. Data diambil dari server lewat internet. Cara paling umum untuk "mengobrol" dengan server adalah REST API yang berjalan di atas protokol HTTP. Sebelum menulis kode Flutter, pahami dulu bahasa percakapannya.

Client, Server, Request, Response

Aplikasi Flutter berperan sebagai client. Client mengirim request (permintaan) ke server, lalu server membalas dengan response (jawaban). Satu request selalu dibalas satu response.

  Aplikasi Flutter (client)                        Server (backend)
  ─────────────────────────                        ────────────────
  GET /posts/1   ───────────── request ──────────>
                 <──────────── response ──────────  200 OK + data JSON

Setiap request terdiri dari 4 bagian utama:

  1. Method: apa yang ingin dilakukan (ambil, buat, ubah, hapus).
  2. URL: alamat data yang dituju.
  3. Header: informasi tambahan (format data, token login).
  4. Body: isi data yang dikirim (biasanya JSON). Request GET dan DELETE umumnya tidak punya body.

Response juga punya status code (angka hasil), header, dan body.

Anatomi URL

https://jsonplaceholder.typicode.com/posts/1/comments?_limit=5&_sort=id
└─┬─┘   └────────────┬────────────┘└───────┬────────┘└───────┬───────┘
scheme            host / base URL        path          query parameter

- Base URL : https://jsonplaceholder.typicode.com  (alamat server)
- Endpoint : /posts/1/comments                     (sumber data yang dituju)
- Path param: 1                                     (id post yang spesifik)
- Query    : _limit=5 dan _sort=id                  (filter tambahan, dipisah &)

REST memakai kata benda untuk URL (/posts, /users) dan method HTTP sebagai kata kerjanya:

Status Code

Status code adalah angka 3 digit yang memberi tahu hasil request. Digit pertama menunjukkan kelompoknya:

KodeNamaArti untuk aplikasi
200OKBerhasil (GET, PUT, PATCH, DELETE).
201CreatedData baru berhasil dibuat (POST).
204No ContentBerhasil, tetapi body kosong (sering untuk DELETE).
400Bad RequestData yang dikirim salah format / tidak valid.
401UnauthorizedBelum login atau token salah/kedaluwarsa.
403ForbiddenSudah login, tetapi tidak punya hak akses.
404Not FoundURL atau data dengan id tersebut tidak ada.
422Unprocessable EntityValidasi gagal (mis. email sudah dipakai).
500Internal Server ErrorServer sedang bermasalah, bukan salah aplikasi.
503Service UnavailableServer sedang down / maintenance.

💡 Cara Mudah Mengingat

2xx = sukses, 4xx = kesalahan dari sisi client (aplikasi kita), 5xx = kesalahan dari sisi server. Di kode, cek sukses dengan statusCode >= 200 && statusCode < 300.

Contoh Kode: Menyusun URL dengan Kelas Uri

Di Dart, URL disimpan sebagai objek Uri. Ada dua cara membuatnya. Uri.parse cocok untuk URL sederhana, sedangkan Uri.https lebih aman untuk query parameter karena karakter khusus (spasi, &) otomatis di-encode.

📄 lib/contoh_uri.dart

// Jalankan dengan: dart run lib/contoh_uri.dart
void main() {
  // Cara 1: Uri.parse dari string utuh
  final uri1 = Uri.parse('https://jsonplaceholder.typicode.com/posts/1');
  print(uri1.host); // jsonplaceholder.typicode.com
  print(uri1.path); // /posts/1

  // Cara 2: Uri.https(host, path, queryParameters)
  final uri2 = Uri.https(
    'jsonplaceholder.typicode.com',
    '/posts',
    {'userId': '1', '_limit': '5'}, // nilai query WAJIB String
  );
  print(uri2); // https://jsonplaceholder.typicode.com/posts?userId=1&_limit=5

  // Karakter khusus otomatis di-encode
  final uri3 = Uri.https('example.com', '/cari', {'q': 'flutter & dart'});
  print(uri3); // https://example.com/cari?q=flutter+%26+dart

  // Menambah query ke Uri yang sudah ada
  final uri4 = uri1.replace(queryParameters: {'lang': 'id'});
  print(uri4); // https://jsonplaceholder.typicode.com/posts/1?lang=id
}

Penjelasan: nilai di queryParameters harus bertipe String, jadi angka ditulis '1' bukan 1. Bagian uri3 memperlihatkan alasan memakai Uri.https: tanda & di dalam kata kunci pencarian berubah menjadi %26 sehingga tidak dianggap pemisah query.

⚠️ Kesalahan Umum

  • Menulis host dengan https:// di Uri.https('https://example.com', ...). Argumen pertama hanya host, tanpa scheme.
  • Mengirim angka di queryParameters ({'page': 1}) sehingga error tipe. Ubah menjadi '1' atau 1.toString().
  • Menganggap status 404 akan melempar exception. Package http tidak melempar error untuk 4xx/5xx; kita sendiri yang wajib mengecek statusCode.
  • Memakai GET untuk mengirim data sensitif lewat query (mis. password). Data di URL tercatat di log server; kirim lewat body POST.
