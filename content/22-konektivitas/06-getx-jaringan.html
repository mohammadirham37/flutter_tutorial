Contoh di bagian 2 menaruh semua logika di dalam State sebuah halaman. Di aplikasi nyata, status jaringan dibutuhkan banyak halaman sekaligus: banner di beranda, tombol simpan di form, dan logika muat ulang di controller data. Karena itu kita pindahkan ke pola MVC GetX (Modul 08): ConnectivityService membungkus plugin, NetworkController menyimpan state .obs global, dan View cukup membaca dengan Obx.

Langkah 1: Service

📄 lib/services/connectivity_service.dart

import 'dart:async';
import 'dart:io';

import 'package:connectivity_plus/connectivity_plus.dart';

/// Satu-satunya kelas yang menyentuh connectivity_plus.
class ConnectivityService {
  ConnectivityService({
    Connectivity? connectivity,
    this.hostUji = 'example.com',
  }) : _connectivity = connectivity ?? Connectivity();

  final Connectivity _connectivity;

  /// Host yang di-lookup untuk memastikan internet benar-benar jalan.
  /// Di proyek nyata, pakai domain server Anda sendiri (misal domain Supabase).
  final String hostUji;

  /// true jika ada antarmuka jaringan (WiFi/seluler/ethernet/VPN) aktif.
  Stream<bool> get perubahanJaringan =>
      _connectivity.onConnectivityChanged.map(_adaJaringan);

  Future<bool> adaJaringan() async =>
      _adaJaringan(await _connectivity.checkConnectivity());

  /// Cek internet sungguhan dengan lookup DNS ringan (maks 5 detik).
  Future<bool> cekInternet() async {
    try {
      final hasil = await InternetAddress.lookup(hostUji)
          .timeout(const Duration(seconds: 5));
      return hasil.isNotEmpty && hasil.first.rawAddress.isNotEmpty;
    } on SocketException {
      return false;
    } on TimeoutException {
      return false;
    }
  }

  static bool _adaJaringan(List<ConnectivityResult> hasil) =>
      !hasil.contains(ConnectivityResult.none);
}

Service tidak mengimpor GetX. Konstruktornya menerima Connectivity opsional, sehingga di unit test (Modul 15) Anda bisa menyuntikkan objek palsu. Parameter hostUji membuat domain yang dicek bisa diganti, misalnya domain proyek Supabase Anda.

Langkah 2: Controller dengan worker debounce

📄 lib/controllers/network_controller.dart

import 'dart:async';

import 'package:get/get.dart';

import '../services/connectivity_service.dart';

class NetworkController extends GetxController {
  NetworkController(this._service);

  final ConnectivityService _service;

  final _online = true.obs; // anggap online sampai terbukti sebaliknya
  final _memeriksa = false.obs;
  final _jumlahPerubahan = 0.obs; // pemicu debounce

  StreamSubscription<bool>? _subscription;
  Worker? _debounceWorker;

  bool get online => _online.value;
  bool get memeriksa => _memeriksa.value;

  /// Dipakai controller lain untuk memasang worker ever().
  RxBool get statusOnline => _online;

  @override
  void onInit() {
    super.onInit();
    // 1. Setiap event jaringan hanya menaikkan penghitung
    _subscription = _service.perubahanJaringan.listen((_) {
      _jumlahPerubahan.value++;
    });
    // 2. debounce: tunggu 2 detik tenang, baru periksa internet sungguhan.
    //    WiFi yang naik-turun cepat tidak memicu banyak request.
    _debounceWorker = debounce<int>(
      _jumlahPerubahan,
      (_) => periksa(),
      time: const Duration(seconds: 2),
    );
    periksa(); // status awal
  }

  Future<void> periksa() async {
    if (_memeriksa.value) return; // hindari pemeriksaan ganda
    _memeriksa.value = true;
    try {
      final adaJaringan = await _service.adaJaringan();
      _online.value = adaJaringan && await _service.cekInternet();
    } finally {
      _memeriksa.value = false;
    }
  }

  @override
  void onClose() {
    _subscription?.cancel();
    _debounceWorker?.dispose();
    super.onClose();
  }
}
  • Kenapa debounce? Saat HP berpindah dari WiFi ke data seluler, stream bisa memancarkan beberapa event dalam satu detik (WiFi putus, seluler naik, VPN tersambung ulang). Tanpa jeda, kita mengirim beberapa lookup sekaligus. debounce (Modul 08) menunggu sampai tidak ada perubahan selama 2 detik, baru menjalankan periksa() sekali.
  • _jumlahPerubahan dinaikkan setiap event. Worker GetX hanya bereaksi jika nilai Rx berubah. Jika kita menyimpan bool, perpindahan WiFi → seluler (true → true) tidak akan memicu worker, padahal internetnya perlu dicek ulang.
  • statusOnline membuka RxBool agar controller lain bisa memasang ever() padanya. View tetap memakai getter online.
  • onClose() membatalkan StreamSubscription dan membuang worker. Untuk controller permanent: true method ini praktis tidak dipanggil, tetapi kebiasaan membersihkan tetap penting agar kode aman jika suatu saat controller dipasang per halaman.
  • Nilai awal true: lebih baik menganggap online lalu dikoreksi dalam sedetik, daripada menampilkan banner offline yang berkedip setiap aplikasi dibuka.

Langkah 3: Banner offline

📄 lib/widgets/banner_offline.dart

import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/network_controller.dart';

/// Banner tipis yang muncul hanya saat offline.
class BannerOffline extends GetView<NetworkController> {
  const BannerOffline({super.key});

  @override
  Widget build(BuildContext context) {
    final skema = Theme.of(context).colorScheme;
    return Obx(() {
      if (controller.online) return const SizedBox.shrink();
      return Material(
        color: skema.errorContainer,
        child: ListTile(
          dense: true,
          leading: Icon(Icons.cloud_off, color: skema.onErrorContainer),
          title: Text(
            'Kamu sedang offline. Data dari cache.',
            style: TextStyle(color: skema.onErrorContainer),
          ),
          trailing: controller.memeriksa
              ? const SizedBox(
                  width: 20,
                  height: 20,
                  child: CircularProgressIndicator(strokeWidth: 2),
                )
              : TextButton(
                  onPressed: controller.periksa,
                  child: const Text('Coba lagi'),
                ),
        ),
      );
    });
  }
}

Sinkronisasi ulang otomatis di proyek Catatan Kuliah (Modul 14)

Di Modul 14, NoteRepository memakai strategi network first, cache fallback: jika server tidak bisa dihubungi, data diambil dari cache Hive dan NotesController.isOffline bernilai true. Masalahnya, saat internet kembali, daftar catatan tetap menampilkan data cache sampai pengguna menarik layar (pull-to-refresh). Dengan NetworkController, controller catatan bisa bereaksi sendiri.

Tambahkan tiga file dari langkah 1–3 ke proyek Modul 14, lalu tambahkan kode berikut di dalam class NotesController (jangan lupa import 'network_controller.dart'; di bagian atas file):

📄 lib/controllers/notes_controller.dart (tambahan)

// ...field dan getter lama tetap seperti di Modul 14...

// Tambahan Modul 22
final NetworkController _network = Get.find<NetworkController>();
Worker? _sinkronWorker;

@override
void onInit() {
  super.onInit();
  _sinkronWorker = ever<bool>(_network.statusOnline, (online) {
    // Hanya muat ulang jika: kembali online, data di layar dari cache,
    // dan tidak sedang memuat.
    if (online && isOffline && !isLoading) {
      loadNotes();
    }
  });
}

@override
void onClose() {
  _sinkronWorker?.dispose();
  super.onClose();
}

Lalu daftarkan NetworkController sebelum NotesController di main(), karena NotesController memanggil Get.find saat dibuat:

📄 lib/main.dart (bagian pendaftaran controller)

// 4. Daftarkan controller global
Get.put(
  NetworkController(
    // cek ke server sendiri, bukan ke domain umum
    ConnectivityService(hostUji: Uri.parse(Env.supabaseUrl).host),
  ),
  permanent: true,
);
Get.put(AuthController(authService), permanent: true);
Get.put(NotesController(repository), permanent: true);
  • ever() dipanggil setiap statusOnline berubah. Karena perubahan sudah disaring oleh debounce di NetworkController, loadNotes() tidak akan terpanggil bertubi-tubi.
  • Tiga syarat sebelum memuat ulang: kembali online, data di layar berasal dari cache (isOffline), dan tidak sedang loading. Jika data sudah segar, tidak ada request sia-sia. Sebelum login, isOffline masih false, jadi tidak ada request tanpa sesi.
  • loadNotes() memakai repository yang sama. Jika berhasil, cache Hive ikut diperbarui dan isOffline kembali false, sehingga OfflineBanner Modul 14 hilang sendiri.
  • Di HomeView, Anda juga bisa menonaktifkan tombol tambah catatan saat Get.find<NetworkController>().online bernilai false, karena operasi tulis di Modul 14 memang wajib online.

💡 Lebih jauh: antrean tulis offline

Pola di atas adalah sinkronisasi baca. Jika ingin pengguna bisa menambah catatan saat offline, simpan operasi ke box Hive terpisah (misalnya antrean_tulis) berisi jenis operasi dan datanya, tampilkan catatan itu dengan tanda "belum terkirim", lalu di dalam worker ever yang sama kirim antrean satu per satu ke Supabase saat online kembali. Hapus item dari antrean hanya setelah server menjawab sukses.

⚠️ Kesalahan umum

  • Memakai ever tanpa menyimpan Worker: worker tetap hidup setelah controller dihapus. Simpan dan panggil dispose() di onClose().
  • Memanggil Get.find<NetworkController>() sebelum Get.put: error "NetworkController not found". Urutan pendaftaran di main() penting.
  • Menganggap banner offline berarti request pasti gagal (atau sebaliknya). Tetap tangani error di setiap request, karena status bisa berubah di tengah request.
