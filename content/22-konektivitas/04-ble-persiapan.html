Untuk BLE kita memakai flutter_blue_plus, package BLE paling lengkap untuk Flutter (Android, iOS, macOS, Linux, web, Windows). Sebelum bisa memindai, ada empat hal yang harus beres: lisensi package, konfigurasi platform, izin runtime, dan status adapter Bluetooth.

1. Perhatikan lisensinya

Berbeda dengan sebagian besar package yang berlisensi BSD/MIT, flutter_blue_plus versi 2 ke atas memakai FlutterBluePlus License:

  • Gratis untuk penggunaan pribadi, organisasi nirlaba, dan institusi pendidikan. Tugas kuliah dan praktikum termasuk di sini.
  • Berbayar (Commercial License) untuk penggunaan oleh perusahaan atau individu yang mencari keuntungan, misalnya aplikasi pesanan klien atau produk startup.

Lisensi ini terlihat langsung di kode: method connect() wajib diberi parameter license. Untuk materi kuliah kita isi License.nonprofit. Changelog package juga menyebutkan bahwa proses build Android mengirim "license ping" berisi nama package dan nama aplikasi. Baca file LICENSE.md di repositori package sebelum memakainya di proyek komersial. Jika suatu saat Anda membuat produk berbayar, anggarkan lisensinya atau pertimbangkan alternatif lain yang lisensinya cocok.

2. Instalasi

flutter pub add flutter_blue_plus
flutter pub add permission_handler device_info_plus get

⚠️ Pasang flutter_blue_plus lebih dulu, terpisah

Saat modul ini ditulis, versi terbaru connectivity_plus dan network_info_plus memakai dependensi Linux (dbus) yang bertabrakan dengan dependensi Linux flutter_blue_plus 2.x. Jika semua package ditambahkan dalam satu perintah, pub bisa diam-diam memilih flutter_blue_plus 1.x yang lama (tanpa parameter license), sehingga kode di modul ini error No named parameter with the name 'license'. Pasang flutter_blue_plus lebih dulu, baru package lain, agar pub yang menyesuaikan versi package jaringan. Periksa hasilnya dengan flutter pub deps | grep flutter_blue_plus: angka depannya harus 2 atau lebih.

device_info_plus dipakai untuk mengetahui versi Android (API level), karena izin yang diminta berbeda antara Android 11 ke bawah dan Android 12 ke atas.

3. Konfigurasi Android

Sejak Android 12 (API 31), Bluetooth punya izin sendiri yang di layar disebut "Perangkat di sekitar" (Nearby devices). Sebelum Android 12, memindai BLE justru membutuhkan izin lokasi, karena hasil scan bisa dipakai menebak posisi pengguna. Manifest berikut mengikuti README flutter_blue_plus versi "tanpa lokasi":

📄 android/app/src/main/AndroidManifest.xml

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- Aplikasi memakai BLE. required="false" agar tetap bisa
         dipasang di HP tanpa BLE (fitur BLE dimatikan di aplikasi) -->
    <uses-feature android:name="android.hardware.bluetooth_le" android:required="false" />

    <!-- Android 12+ : izin "Perangkat di sekitar" -->
    <uses-permission android:name="android.permission.BLUETOOTH_SCAN"
        android:usesPermissionFlags="neverForLocation" />
    <uses-permission android:name="android.permission.BLUETOOTH_CONNECT" />

    <!-- Android 11 ke bawah -->
    <uses-permission android:name="android.permission.BLUETOOTH" android:maxSdkVersion="30" />
    <uses-permission android:name="android.permission.BLUETOOTH_ADMIN" android:maxSdkVersion="30" />
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" android:maxSdkVersion="30" />

    <!-- Android 9 ke bawah -->
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" android:maxSdkVersion="28" />

    <application ...>
        ...
    </application>
</manifest>
  • neverForLocation adalah janji kepada sistem bahwa hasil scan tidak dipakai untuk menentukan lokasi. Imbalannya, di Android 12+ aplikasi tidak perlu izin lokasi untuk scan. Konsekuensinya, sebagian paket iklan (misalnya beacon/iBeacon) bisa disaring oleh sistem. Jika aplikasi memang butuh lokasi dari BLE, hapus flag ini, deklarasikan ACCESS_FINE_LOCATION tanpa maxSdkVersion, dan panggil startScan(androidUsesFineLocation: true).
  • maxSdkVersion="30" membuat izin lama hanya berlaku di Android 11 ke bawah, sehingga pengguna Android 12+ tidak dimintai izin lokasi.
  • Jika proyek Anda sudah punya ACCESS_FINE_LOCATION tanpa maxSdkVersion (misalnya dari bagian 3 atau Modul 19), pertahankan deklarasi yang tanpa batas itu. Jangan menulis izin yang sama dua kali dengan atribut berbeda.
  • minSdk: flutter_blue_plus butuh minimal API 21. Nilai bawaan flutter.minSdkVersion di android/app/build.gradle.kts proyek Flutter baru sudah di atas itu, jadi biasanya tidak perlu diubah.

4. Konfigurasi iOS

📄 ios/Runner/Info.plist

<key>NSBluetoothAlwaysUsageDescription</key>
<string>Bluetooth dipakai untuk memindai dan membaca sensor di laboratorium.</string>

Di iOS, dialog izin Bluetooth muncul otomatis saat flutter_blue_plus pertama kali dipakai. Jika pengguna menolak, adapterState bernilai unauthorized. Karena izin tidak diminta lewat permission_handler, makro Podfile untuk Bluetooth tidak dibutuhkan.

5. Alur izin runtime (Android)

Fungsi berikut memilih izin yang tepat berdasarkan versi Android, lalu mengembalikan tiga kemungkinan hasil seperti di Modul 17.

📄 lib/services/izin_bluetooth.dart

import 'dart:io';

import 'package:device_info_plus/device_info_plus.dart';
import 'package:permission_handler/permission_handler.dart';

enum HasilIzin { diberikan, ditolak, ditolakPermanen }

/// Meminta izin yang dibutuhkan untuk scan dan connect BLE.
Future<HasilIzin> mintaIzinBluetooth() async {
  if (!Platform.isAndroid) {
    // iOS: dialog izin Bluetooth muncul otomatis saat plugin pertama
    // kali memakai Bluetooth. Status ditolak terbaca dari adapterState.
    return HasilIzin.diberikan;
  }

  final android = await DeviceInfoPlugin().androidInfo;
  final daftarIzin = android.version.sdkInt >= 31
      // Android 12 (API 31) ke atas: izin "Perangkat di sekitar"
      ? [Permission.bluetoothScan, Permission.bluetoothConnect]
      // Android 11 ke bawah: scan BLE dianggap bisa melacak lokasi
      : [Permission.locationWhenInUse];

  final hasil = await daftarIzin.request();
  final semuaStatus = hasil.values;

  if (semuaStatus.every((s) => s.isGranted)) return HasilIzin.diberikan;
  if (semuaStatus.any((s) => s.isPermanentlyDenied)) {
    return HasilIzin.ditolakPermanen;
  }
  return HasilIzin.ditolak;
}
  • sdkInt >= 31: Android 12 ke atas meminta bluetoothScan dan bluetoothConnect. Keduanya tampil sebagai satu dialog "Izinkan aplikasi menemukan, menghubungkan, dan menentukan posisi relatif perangkat di sekitar?".
  • Android 11 ke bawah meminta locationWhenInUse. Di versi ini, Permission.bluetoothScan selalu dilaporkan diberikan (selama izin BLUETOOTH lama ada di manifest), sehingga kalau kita hanya memeriksa izin itu, tanpa izin lokasi scan akan berjalan tetapi tidak menemukan apa-apa.
  • daftarIzin.request() meminta beberapa izin sekaligus dan mengembalikan Map<Permission, PermissionStatus>.
  • Untuk ditolak permanen, tampilkan tombol yang memanggil openAppSettings(). Contoh lengkapnya ada di studi kasus bagian 7.

6. Status adapter dan menyalakan Bluetooth

Izin sudah ada, tetapi Bluetooth mungkin dimatikan pengguna. FlutterBluePlus.adapterState adalah stream status adapter: unknown, unavailable, unauthorized, turningOn, on, turningOff, atau off.

import 'dart:async';
import 'dart:io';

import 'package:flutter/foundation.dart';
import 'package:flutter_blue_plus/flutter_blue_plus.dart';

Future<void> contohAdapter() async {
  // 1. Apakah HP punya Bluetooth LE? (emulator: false)
  if (await FlutterBluePlus.isSupported == false) {
    debugPrint('Perangkat ini tidak mendukung Bluetooth LE');
    return;
  }

  // 2. Dengarkan status adapter (on, off, unauthorized, ...)
  final StreamSubscription<BluetoothAdapterState> sub = FlutterBluePlus
      .adapterState
      .listen((state) {
        debugPrint('Adapter: $state');
      });

  // 3. Android saja: minta pengguna menyalakan Bluetooth
  if (Platform.isAndroid) {
    try {
      await FlutterBluePlus.turnOn();
    } on FlutterBluePlusException catch (e) {
      debugPrint('Pengguna menolak menyalakan Bluetooth: ${e.description}');
    }
  }

  // 4. Tunggu sampai benar-benar menyala
  await FlutterBluePlus.adapterState
      .where((s) => s == BluetoothAdapterState.on)
      .first;

  await sub.cancel();
}
  • FlutterBluePlus.isSupported bernilai false jika perangkat tidak punya BLE, termasuk di Android Emulator.
  • turnOn() hanya ada di Android. Sistem menampilkan dialog "Aplikasi ingin mengaktifkan Bluetooth". Jika pengguna menolak, muncul FlutterBluePlusException. Di iOS aplikasi tidak boleh menyalakan Bluetooth, jadi cukup tampilkan pesan agar pengguna menyalakannya dari Pusat Kontrol.
  • Status awal di iOS biasanya unknown sesaat sebelum menjadi on. Jangan langsung menampilkan error saat melihat unknown.
  • Simpan StreamSubscription dari adapterState dan batalkan saat tidak dipakai, sama seperti stream lain.

⚠️ Android 11 ke bawah: lokasi HP juga harus menyala

Selain izin lokasi, Android versi lama mewajibkan layanan lokasi (saklar Lokasi di panel cepat) menyala agar scan BLE menemukan perangkat. Jika di HP lama daftar hasil scan selalu kosong, minta pengguna menyalakan lokasi.
