connectivity_plus hanya tahu "sedang memakai WiFi". Untuk detailnya (nama jaringan, alamat IP, gateway) kita memakai network_info_plus. Contoh pemakaian di kampus: presensi yang hanya boleh dilakukan dari WiFi kelas, atau aplikasi lab yang mencari server ESP32 di subnet yang sama.

Kenapa nama WiFi butuh izin lokasi?

Nama dan BSSID WiFi bisa dipakai untuk menebak lokasi seseorang (database lokasi titik akses WiFi sudah ada di mana-mana). Karena itu, sejak Android 10 (API 29), aplikasi baru bisa membaca SSID jika memenuhi semua syarat berikut:

  • Punya izin ACCESS_FINE_LOCATION yang sudah diberikan pengguna.
  • Layanan lokasi HP sedang menyala (Setelan → Lokasi).
  • Di Android 12 ke atas, punya izin ACCESS_NETWORK_STATE (sudah dibawa package).

Package ini sengaja tidak menambahkan izin lokasi ke manifest, jadi kita tambahkan sendiri.

Konfigurasi Android

📄 android/app/src/main/AndroidManifest.xml

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />

    <application ...>
        ...
    </application>
</manifest>

Konfigurasi iOS

Di iOS 13 ke atas, nama WiFi hanya diberikan kepada aplikasi yang punya izin lokasi (atau yang mengatur WiFi/VPN sendiri). Tambahkan kunci berikut, lalu aktifkan capability Access WiFi Information di Xcode (Runner → Signing & Capabilities). Di iOS Simulator nilainya selalu null.

📄 ios/Runner/Info.plist

<key>NSLocationWhenInUseUsageDescription</key>
<string>Lokasi dibutuhkan untuk membaca nama WiFi kelas saat presensi.</string>

Karena kita memakai permission_handler, iOS juga butuh makro izin di ios/Podfile (lihat Modul 17). Tanpa makro, permintaan izin lokasi di iOS langsung dianggap ditolak. Untuk Permission.locationWhenInUse makronya:

📄 ios/Podfile (di dalam blok post_install)

config.build_settings['GCC_PREPROCESSOR_DEFINITIONS'] ||= [
  '$(inherited)',
  'PERMISSION_LOCATION_WHENINUSE=1',
]

Contoh lengkap: membaca info WiFi dengan alur izin

📄 lib/main.dart

import 'package:flutter/material.dart';
import 'package:network_info_plus/network_info_plus.dart';
import 'package:permission_handler/permission_handler.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const InfoWifiPage(),
    );
  }
}

class InfoWifiPage extends StatefulWidget {
  const InfoWifiPage({super.key});

  @override
  State<InfoWifiPage> createState() => _InfoWifiPageState();
}

class _InfoWifiPageState extends State<InfoWifiPage> {
  final NetworkInfo _info = NetworkInfo();

  String? _ssid;
  String? _ip;
  String? _gateway;
  String _pesan = 'Tekan tombol untuk membaca info WiFi.';
  bool _izinDitolakPermanen = false;

  Future<void> _bacaInfo() async {
    // 1. SSID termasuk data lokasi, jadi minta izin lokasi dulu
    final status = await Permission.locationWhenInUse.request();
    if (!mounted) return;

    if (status.isPermanentlyDenied) {
      setState(() {
        _izinDitolakPermanen = true;
        _pesan =
            'Izin lokasi ditolak permanen. Buka pengaturan aplikasi '
            'untuk mengizinkannya.';
      });
      return;
    }

    // 2. IP dan gateway tidak butuh izin lokasi, tetap bisa dibaca
    final ip = await _info.getWifiIP();
    final gateway = await _info.getWifiGatewayIP();
    final ssid = status.isGranted ? await _info.getWifiName() : null;
    if (!mounted) return;

    setState(() {
      _izinDitolakPermanen = false;
      _ip = ip;
      _gateway = gateway;
      _ssid = ssid == null ? null : _bersihkanKutip(ssid);
      _pesan = status.isGranted
          ? 'Info WiFi berhasil dibaca.'
          : 'Izin lokasi ditolak, nama WiFi tidak bisa ditampilkan.';
    });
  }

  /// Android mengembalikan SSID dengan tanda kutip: "Kampus-WiFi"
  String _bersihkanKutip(String ssid) {
    if (ssid.length >= 2 && ssid.startsWith('"') && ssid.endsWith('"')) {
      return ssid.substring(1, ssid.length - 1);
    }
    return ssid;
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Info WiFi')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          Text(_pesan),
          const SizedBox(height: 12),
          ListTile(
            leading: const Icon(Icons.wifi),
            title: const Text('Nama WiFi (SSID)'),
            subtitle: Text(_ssid ?? '-'),
          ),
          ListTile(
            leading: const Icon(Icons.lan),
            title: const Text('Alamat IP perangkat'),
            subtitle: Text(_ip ?? '-'),
          ),
          ListTile(
            leading: const Icon(Icons.router),
            title: const Text('Gateway (router)'),
            subtitle: Text(_gateway ?? '-'),
          ),
          const SizedBox(height: 12),
          FilledButton.icon(
            onPressed: _bacaInfo,
            icon: const Icon(Icons.search),
            label: const Text('Baca info WiFi'),
          ),
          if (_izinDitolakPermanen)
            TextButton(
              onPressed: openAppSettings,
              child: const Text('Buka pengaturan aplikasi'),
            ),
        ],
      ),
    );
  }
}

Penjelasan baris penting

  • Tiga cabang hasil izin (pola Modul 17): diberikan → baca SSID; ditolak → tetap tampilkan IP dan gateway, beri tahu bahwa SSID butuh izin; ditolak permanen → dialog tidak akan muncul lagi, jadi tampilkan tombol openAppSettings.
  • IP dan gateway tetap dibaca walaupun izin ditolak. Jangan mengunci seluruh fitur hanya karena satu data butuh izin.
  • _bersihkanKutip: Android mengembalikan SSID dengan tanda kutip, misalnya "Kampus-WiFi". Ini perilaku sistem operasi yang terdokumentasi, bukan bug package, jadi bersihkan sebelum ditampilkan atau dibandingkan.
  • if (!mounted) return; setelah request() dan setelah membaca info, karena keduanya await.

⚠️ SSID null atau <unknown ssid> padahal izin sudah diberikan

Penyebab paling sering: layanan lokasi HP mati. Izin aplikasi dan saklar lokasi sistem adalah dua hal berbeda. Di emulator Android, SSID biasanya terbaca sebagai AndroidWifi setelah izin diberikan dan lokasi dinyalakan.

ℹ️ SSID bukan bukti kehadiran yang kuat

Siapa pun bisa membuat hotspot dengan nama "Kampus-WiFi". Untuk presensi berbasis WiFi, gabungkan SSID dengan BSSID titik akses yang terdaftar, lokasi GPS (Modul 19), dan validasi di server. Jangan mengandalkan satu pemeriksaan di sisi aplikasi.
