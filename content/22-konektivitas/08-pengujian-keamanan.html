Membuat sensor tiruan dengan nRF Connect

Jika tidak punya sensor BLE, pakai HP kedua sebagai peripheral. Aplikasi gratis nRF Connect for Mobile (Nordic Semiconductor) bisa memindai sekaligus berpura-pura menjadi perangkat BLE. Fitur server GATT paling lengkap ada di versi Android. Nama menu bisa sedikit berbeda antar versi, tetapi langkahnya kira-kira seperti ini:

  1. Di HP kedua, buka nRF Connect → menu → Configure GATT server. Tambahkan service Battery Service (0x180F) berisi characteristic Battery Level (0x2A19) dengan properti Read dan Notify, lalu isi nilai awal, misalnya 90 (0x5A).
  2. Buka tab Advertiser, buat paket iklan baru yang connectable dan berisi Complete Local Name, lalu nyalakan.
  3. Di HP pertama, jalankan aplikasi studi kasus dan scan. Nama HP kedua muncul. Connect, lalu ubah nilai Battery Level di nRF Connect untuk melihat notify bekerja.

nRF Connect juga berguna sebagai pembanding. Jika nRF Connect di HP yang sama tidak menemukan perangkat Anda, masalahnya ada di perangkat atau pengaturan HP, bukan di kode Flutter. Alternatif lain adalah papan ESP32 dengan contoh sketch BLE server bawaan Arduino IDE.

Keamanan BLE

BLE dirancang untuk kemudahan, bukan kerahasiaan. Siapa pun di dekat Anda dengan aplikasi seperti nRF Connect bisa melihat iklan perangkat, dan jika tidak ada pengamanan, bisa connect dan membaca characteristic yang sama.

  • Iklan (advertising) selalu terbuka. Jangan menaruh data pribadi (NIM, nama lengkap, token) di nama perangkat atau data iklan.
  • Koneksi tanpa pairing tidak terenkripsi. Untuk data sensitif, peripheral sebaiknya mewajibkan pairing/bonding sehingga characteristic hanya bisa dibaca setelah link terenkripsi. Saat aplikasi mengakses characteristic yang dilindungi, sistem operasi menampilkan dialog pairing. Di Android, flutter_blue_plus juga menyediakan createBond(). Pilih metode pairing dengan PIN atau perbandingan angka (LE Secure Connections), bukan "Just Works" yang tidak melindungi dari penyadap aktif.
  • Jangan percaya data dari perangkat. Validasi panjang dan rentang nilai (misalnya baterai harus 0–100) sebelum dipakai atau dikirim ke server. Perangkat palsu bisa memakai nama yang sama dengan sensor asli.
  • Perintah tulis yang berbahaya (membuka kunci pintu lab, mengubah konfigurasi) perlu autentikasi di tingkat aplikasi, misalnya tantangan-jawaban dengan kunci rahasia per perangkat, bukan sekadar menulis byte 0x01.
  • Data yang disimpan di HP (misalnya kunci perangkat atau riwayat bacaan) disimpan di flutter_secure_storage atau box Hive terenkripsi (Modul 11), bukan di file biasa.
  • Privasi pengguna: hasil scan BLE dan nama WiFi bisa dipakai untuk melacak lokasi. Minta izin hanya saat fitur dipakai, jelaskan alasannya di teks izin, dan jangan mengirim daftar perangkat sekitar ke server tanpa persetujuan.

ℹ️ Rangkuman alur aman

Izin diminta tepat waktu → adapter dicek → scan dengan timeout → connect → discover → baca/tulis dengan validasi → disconnect saat selesai. Untuk jaringan: status radio untuk UX, cek internet untuk kepastian, dan penanganan error di setiap request.
