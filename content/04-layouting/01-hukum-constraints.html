Untuk menguasai layouting Flutter tanpa frustrasi menghadapi galat overflow, setiap mahasiswa wajib menghafal prinsip dasar yang dirumuskan oleh tim inti Flutter:

📜 Tiga Aturan Emas Layout Flutter:

  1. Constraints go down: Widget induk (Parent) memberikan batasan (minimum & maksimum lebar serta tinggi) kepada widget anak (Child).
  2. Sizes go up: Widget anak memutuskan ukurannya sendiri berdasarkan batasan yang diberikan induknya, lalu melaporkan ukurannya kembali ke Parent.
  3. Parent sets position: Widget induk menentukan posisi letak (koordinat x, y) widget anak di layar.

Analogi: pembagian kamar kos

Pemilik kos (induk) berkata: "Lemarimu boleh lebarnya 50 sampai 120 cm." Kamu (anak) memilih lemari 100 cm dan melapor ke pemilik. Pemilik yang menentukan lemari itu ditaruh di pojok mana. Kamu tidak bisa memilih lemari 200 cm, dan kamu tidak bisa menentukan sendiri posisinya.

Apa itu constraints?

Constraints (BoxConstraints) adalah empat angka: minWidth, maxWidth, minHeight, maxHeight.

JenisArtinyaContoh pemberi
Tight (ketat)min = max. Anak harus berukuran tepat segitu.Layar penuh dari runApp, SizedBox(width: 100, height: 100), Expanded
Loose (longgar)min = 0, max = sekian. Anak bebas sekecil apa pun asal tidak melebihi max.Center, Align, Scaffold.body
Unbounded (tak terbatas)max = tak hingga (double.infinity) di satu arah.Arah utama Row/Column, ListView, SingleChildScrollView

Contoh 1: Container yang "tidak patuh"

Pemula sering heran kenapa kode di bawah menghasilkan kotak merah sepenuh layar, padahal ukurannya sudah ditulis 100 x 100:

import 'package:flutter/material.dart';

// Langsung di runApp: layar memberi constraint TIGHT seukuran layar.
// Container dipaksa sebesar layar, width/height 100 diabaikan.
void main() {
  runApp(Container(width: 100, height: 100, color: Colors.red));
}
Container 100 x 100 dipaksa memenuhi layar

Solusinya: beri induk yang memberikan constraint longgar, misalnya Center. Center berkata "kamu boleh sekecil apa pun, maksimal selebar layar", sehingga Container bisa memilih 100 x 100.

import 'package:flutter/material.dart';

void main() {
  runApp(
    Center(
      child: Container(width: 100, height: 100, color: Colors.red),
    ),
  );
}
Di dalam Center, Container bisa berukuran 100 x 100

Contoh lengkap: melihat constraints dengan LayoutBuilder

LayoutBuilder memberi kita akses ke constraints yang diterima dari induk. Contoh ini menampilkan constraints di beberapa situasi agar aturan di atas terlihat nyata.

📄 lib/main.dart

// lib/main.dart — salin SELURUH kode ini untuk menggantikan isi lib/main.dart
import 'package:flutter/material.dart';

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      home: Scaffold(
        appBar: AppBar(title: const Text('Melihat Constraints')),
        body: SingleChildScrollView(
          padding: const EdgeInsets.all(16),
          child: Column(
            crossAxisAlignment: CrossAxisAlignment.stretch,
            children: [
              const Text('1. Di dalam SizedBox 200 x 80 (tight):'),
              // Center mencegah stretch dari Column memaksa lebar penuh
              const Center(
                child: SizedBox(width: 200, height: 80, child: InfoConstraints()),
              ),
              const SizedBox(height: 16),
              const Text('2. Di dalam Center di kotak 120 px (loose):'),
              const SizedBox(
                height: 120,
                child: Center(child: InfoConstraints()),
              ),
              const SizedBox(height: 16),
              const Text('3. Di dalam ConstrainedBox (min 100, max 250):'),
              Center(
                // ConstrainedBox tidak punya konstruktor const
                child: ConstrainedBox(
                  constraints: const BoxConstraints(
                    minWidth: 100,
                    maxWidth: 250,
                    minHeight: 50,
                    maxHeight: 100,
                  ),
                  child: const InfoConstraints(),
                ),
              ),
              const SizedBox(height: 16),
              const Text('4. Di dalam Row (lebar tak terbatas):'),
              const Row(children: [InfoConstraints(lebar: 220)]),
            ],
          ),
        ),
      ),
    );
  }
}

/// Menampilkan constraints yang diterima dari induknya.
class InfoConstraints extends StatelessWidget {
  final double? lebar;

  const InfoConstraints({super.key, this.lebar});

  @override
  Widget build(BuildContext context) {
    return LayoutBuilder(
      builder: (context, constraints) {
        String fmt(double v) => v == double.infinity ? '∞' : v.toStringAsFixed(0);
        return Container(
          width: lebar,
          padding: const EdgeInsets.all(8),
          color: Colors.amber.shade200,
          child: Text(
            'lebar: ${fmt(constraints.minWidth)} - ${fmt(constraints.maxWidth)}\n'
            'tinggi: ${fmt(constraints.minHeight)} - ${fmt(constraints.maxHeight)}',
            style: const TextStyle(fontSize: 12),
          ),
        );
      },
    );
  }
}
Constraints yang diterima widget di empat situasi

Penjelasan hasil

  • Kotak 1: lebar 200 - 200, tinggi 80 - 80. Constraint ketat, anak tidak punya pilihan. Kenapa SizedBox perlu dibungkus Center? Column memakai CrossAxisAlignment.stretch yang memberi constraint ketat selebar layar. Tanpa Center, width: 200 diabaikan dan kotak menjadi selebar layar (coba hapus Center-nya).
  • Kotak 2: lebar 0 - (lebar layar), tinggi 0 - 120. Center melonggarkan constraint sehingga kotak kuning hanya seukuran teksnya.
  • Kotak 3: ConstrainedBox menambahkan batas minimum dan maksimum sendiri.
  • Kotak 4: lebar 0 - ∞. Di dalam Row, anak menerima lebar tak terbatas. Karena itu kita wajib memberi lebar: 220; tanpa batas, widget yang ingin "selebar mungkin" akan error. Ini akar dari banyak error layout yang dibahas di section Overflow.

⚠️ Kesalahan umum

  • Mengira width/height selalu dipatuhi. Ukuran hanya permintaan; jika constraint induk ketat, permintaan itu diabaikan.
  • Menaruh widget "serakah" di ruang tak terbatas, misalnya ListView di dalam Column tanpa Expanded, atau TextField di dalam Row tanpa Expanded. Hasilnya error "unbounded height/width".
  • Mengharapkan anak menentukan posisinya sendiri. Posisi diatur oleh induk (lewat alignment, mainAxisAlignment, Positioned, dan lain-lain).
