Di banyak bahasa, error paling sering adalah memakai nilai yang ternyata kosong (null), dikenal sebagai NullPointerException. Dart 3 menerapkan Sound Null Safety: secara default, semua tipe tidak boleh null, dan compiler memaksa kita menangani kemungkinan null sebelum program dijalankan.

Tipe non-nullable vs nullable

void main() {
  String nama = 'Ayu';
  // nama = null; // ERROR: String tidak boleh null

  String? nomorHp; // tanda ? artinya boleh null, nilai awalnya null
  print(nama.length); // Output: 3
  print(nomorHp); // Output: null
  // print(nomorHp.length); // ERROR: nomorHp mungkin null

  nomorHp = '08123456789';
  print(nomorHp.length); // Output: 11
}

Setelah nomorHp diisi String, Dart tahu nilainya pasti tidak null, sehingga nomorHp.length diizinkan. Kemampuan ini disebut type promotion.

Memakai ?., ??, dan ??=

String? cariEmail(String nim) {
  final data = {'H1D023001': 'ayu@mhs.unsoed.ac.id'};
  return data[nim]; // null jika nim tidak terdaftar
}

void main() {
  String? email1 = cariEmail('H1D023001');
  String? email2 = cariEmail('H1D099999');

  print(email1?.toUpperCase()); // Output: AYU@MHS.UNSOED.AC.ID
  print(email2?.toUpperCase()); // Output: null
  print(email2 ?? 'Email belum terdaftar'); // Output: Email belum terdaftar
  print(email2?.length ?? 0); // Output: 0

  email2 ??= 'default@unsoed.ac.id';
  print(email2); // Output: default@unsoed.ac.id
}

email2?.length ?? 0 adalah kombinasi yang sangat umum: "ambil panjangnya jika ada, jika tidak pakai 0".

Type promotion dengan pengecekan null

int hitungPanjang(String? teks) {
  if (teks == null) {
    return 0;
  }
  // Di sini Dart tahu teks pasti tidak null
  return teks.length;
}

class Profil {
  String? bio;
}

void cetakBio(Profil p) {
  // if (p.bio != null) print(p.bio.length); // ERROR: field tidak dipromosikan
  final bio = p.bio; // salin ke variabel lokal dulu
  if (bio != null) {
    print('Panjang bio: ${bio.length}');
  } else {
    print('Bio kosong');
  }
}

void main() {
  print(hitungPanjang(null)); // Output: 0
  print(hitungPanjang('Flutter')); // Output: 7

  cetakBio(Profil()); // Output: Bio kosong
  cetakBio(Profil()..bio = 'Suka Dart'); // Output: Panjang bio: 9
}

Promotion berjalan untuk variabel lokal dan parameter. Untuk field class yang publik dan bisa diubah, Dart tidak bisa menjamin nilainya tetap sama di antara pengecekan dan pemakaian, sehingga trik "salin ke variabel lokal" sangat sering dipakai.

Operator !: gunakan dengan hati-hati

void main() {
  Map<String, int> nilai = {'Ayu': 90};

  int nilaiAyu = nilai['Ayu']!; // kita YAKIN kunci 'Ayu' ada
  print(nilaiAyu); // Output: 90

  // int nilaiBudi = nilai['Budi']!;
  // CRASH saat runtime: Null check operator used on a null value

  int nilaiBudi = nilai['Budi'] ?? 0; // cara yang aman
  print(nilaiBudi); // Output: 0
}

! mematikan perlindungan null safety. Gunakan hanya jika Anda benar-benar yakin nilainya tidak null. Dalam banyak kasus, ?? atau pengecekan if adalah pilihan yang lebih aman.

late pada field class

class KoneksiDatabase {
  late String namaDb; // belum ada nilai saat objek dibuat

  void buka(String nama) {
    namaDb = nama;
    print('Database $namaDb dibuka');
  }
}

void main() {
  final db = KoneksiDatabase();
  // print(db.namaDb); // CRASH: LateInitializationError, belum diisi
  db.buka('kampus.db'); // Output: Database kampus.db dibuka
  print(db.namaDb); // Output: kampus.db
}

Di Flutter, late biasa dipakai untuk controller yang dibuat di initState(), misalnya late TextEditingController _namaController;.

Null-aware pada List dan Map

List<String>? ambilDaftar(bool ada) => ada ? ['Dart', 'Flutter'] : null;

void main() {
  final daftar = ambilDaftar(false);
  print(daftar?.length); // Output: null
  print(daftar?[0]); // Output: null
  print(daftar?.isEmpty ?? true); // Output: true

  final daftar2 = ambilDaftar(true);
  print(daftar2?[1]); // Output: Flutter
}

⚠️ Kesalahan umum

  • Menaburkan ! di mana-mana agar error compiler hilang. Error-nya hanya pindah menjadi crash saat aplikasi dipakai.
  • Membuat semua variabel nullable (String?) "supaya aman". Justru sebaliknya: jadikan non-nullable sebisa mungkin, dan nullable hanya untuk data yang memang bisa tidak ada.
  • Memakai late lalu lupa mengisinya, sehingga muncul LateInitializationError.
