Program yang baik tidak langsung "mati" ketika terjadi masalah, seperti input yang salah, data rusak, atau server tidak merespons. Dart menyediakan try, catch, on, finally, dan throw untuk menangani situasi tersebut dengan rapi.

try dan catch

void main() {
  try {
    int angka = int.parse('12a'); // melempar FormatException
    print('Angka: $angka'); // baris ini dilewati
  } catch (e) {
    print('Terjadi error: ${e.runtimeType}');
  }
  print('Program tetap berjalan');
  // Output:
  // Terjadi error: FormatException
  // Program tetap berjalan
}

Begitu terjadi error di dalam try, sisa baris di blok itu dilewati dan eksekusi melompat ke catch. Setelah itu, program berlanjut normal. Tanpa try/catch, program akan berhenti dengan pesan Unhandled exception.

on, catch, finally, dan throw

double bagi(int a, int b) {
  if (b == 0) {
    throw ArgumentError('Pembagi tidak boleh nol');
  }
  return a / b;
}

void main() {
  for (final input in ['10', 'x', '0']) {
    try {
      final b = int.parse(input);
      print('100 / $b = ${bagi(100, b)}');
    } on FormatException {
      print('"$input" bukan angka');
    } on ArgumentError catch (e) {
      print('Argumen salah: ${e.message}');
    } finally {
      print('-- selesai memproses "$input"');
    }
  }
  // Output:
  // 100 / 10 = 10.0
  // -- selesai memproses "10"
  // "x" bukan angka
  // -- selesai memproses "x"
  // Argumen salah: Pembagi tidak boleh nol
  // -- selesai memproses "0"
}
  • on TipeError menangkap jenis error tertentu saja. Tambahkan catch (e) jika butuh objek error-nya.
  • finally selalu dijalankan, baik terjadi error maupun tidak. Cocok untuk menutup koneksi atau mematikan indikator loading.
  • throw melempar error secara sengaja ketika kondisi tidak valid.
  • catch (e, stackTrace) memberikan parameter kedua berisi jejak pemanggilan, berguna untuk debugging.

Membuat Exception sendiri

Exception kustom membuat jenis error lebih jelas dan bisa membawa data tambahan. Cukup buat class yang meng-implements Exception.

class SaldoTidakCukupException implements Exception {
  final double saldo;
  final double diminta;

  SaldoTidakCukupException(this.saldo, this.diminta);

  @override
  String toString() => 'SaldoTidakCukupException: saldo $saldo, diminta $diminta';
}

class Dompet {
  double saldo;
  Dompet(this.saldo);

  void bayar(double jumlah) {
    if (jumlah <= 0) {
      throw ArgumentError.value(jumlah, 'jumlah', 'harus lebih dari 0');
    }
    if (jumlah > saldo) {
      throw SaldoTidakCukupException(saldo, jumlah);
    }
    saldo -= jumlah;
  }
}

void main() {
  final dompet = Dompet(50000);
  try {
    dompet.bayar(20000);
    print('Bayar 20000 berhasil, sisa ${dompet.saldo}');
    dompet.bayar(40000);
    print('Baris ini tidak dijalankan');
  } on SaldoTidakCukupException catch (e) {
    print(e);
    print('Kurang: ${e.diminta - e.saldo}');
  }
  // Output:
  // Bayar 20000 berhasil, sisa 30000.0
  // SaldoTidakCukupException: saldo 30000.0, diminta 40000.0
  // Kurang: 10000.0
}

rethrow: mencatat lalu meneruskan error

int bacaNilai(String input) {
  try {
    return int.parse(input);
  } on FormatException {
    print('[log] input tidak valid: $input');
    rethrow; // lempar ulang ke pemanggil
  }
}

void main() {
  try {
    bacaNilai('sembilan');
  } catch (e) {
    print('Ditangani di main: ${e.runtimeType}');
  }
  // Output:
  // [log] input tidak valid: sembilan
  // Ditangani di main: FormatException
}

rethrow berguna ketika sebuah fungsi ingin mencatat error (logging) tetapi keputusan penanganannya, misalnya menampilkan pesan ke pengguna, tetap diserahkan ke pemanggil.

Exception vs Error

ExceptionError
ArtiKondisi tidak normal yang bisa diantisipasiBug di dalam kode
ContohFormatException, TimeoutException, gagal koneksiRangeError, TypeError, LateInitializationError
SikapTangkap dan tangani (tampilkan pesan, coba lagi)Perbaiki kodenya, jangan ditangkap diam-diam

⚠️ Kesalahan umum

  • catch (e) {} kosong: error "ditelan" sehingga bug sulit dilacak. Minimal cetak atau catat error-nya.
  • Menangkap semua error dengan catch padahal yang diharapkan hanya satu jenis. Gunakan on TipeException agar lebih spesifik.
  • Melempar String (throw 'gagal'). Hal ini memang diizinkan, tetapi lebih baik melempar objek Exception agar bisa ditangkap berdasarkan tipenya.
