Jalankan SQL berikut di SQL Editor

📄 supabase/setup.sql

create table if not exists public.notes (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null default auth.uid() references auth.users (id) on delete cascade,
  title text not null check (char_length(title) between 1 and 100),
  content text not null default '',
  category text not null default 'Kuliah'
    check (category in ('Kuliah', 'Tugas', 'Ujian', 'Lainnya')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index if not exists notes_user_id_idx on public.notes (user_id);

alter table public.notes enable row level security;

drop policy if exists "User melihat catatannya sendiri" on public.notes;
create policy "User melihat catatannya sendiri"
on public.notes for select
to authenticated
using ((select auth.uid()) = user_id);

drop policy if exists "User menambah catatannya sendiri" on public.notes;
create policy "User menambah catatannya sendiri"
on public.notes for insert
to authenticated
with check ((select auth.uid()) = user_id);

drop policy if exists "User mengubah catatannya sendiri" on public.notes;
create policy "User mengubah catatannya sendiri"
on public.notes for update
to authenticated
using ((select auth.uid()) = user_id)
with check ((select auth.uid()) = user_id);

drop policy if exists "User menghapus catatannya sendiri" on public.notes;
create policy "User menghapus catatannya sendiri"
on public.notes for delete
to authenticated
using ((select auth.uid()) = user_id);

create or replace function public.set_updated_at()
returns trigger
language plpgsql
set search_path = ''
as $$
begin
  new.updated_at = now();
  return new;
end;
$$;

drop trigger if exists notes_set_updated_at on public.notes;
create trigger notes_set_updated_at
  before update on public.notes
  for each row execute procedure public.set_updated_at();

Penjelasan

  • user_id ... default auth.uid(): aplikasi tidak perlu mengirim user_id saat insert. Database mengisinya dari token login. Ini juga lebih aman karena user tidak bisa "menitipkan" catatan atas nama orang lain, sebab policy with check akan menolaknya.
  • check (category in (...)): database hanya menerima empat kategori, sama dengan daftar di model Dart.
  • create index ... (user_id): setiap query difilter RLS berdasarkan user_id. Index membuat filter itu tetap cepat walaupun tabel berisi ribuan catatan.
  • Empat policy (select, insert, update, delete) semuanya memakai syarat yang sama: (select auth.uid()) = user_id.
  • Trigger set_updated_at dijalankan before update, sehingga nilai new.updated_at diganti now() sebelum baris disimpan. Aplikasi tidak perlu (dan tidak bisa salah) mengirim waktu.

Uji RLS dari dua akun

  1. Buka Table Editor → notes dan pastikan tabel ada dengan label RLS aktif (bukan UNRESTRICTED).
  2. Setelah aplikasi selesai, buat dua akun berbeda dan masing-masing menulis catatan.
  3. Login bergantian: setiap akun hanya boleh melihat catatannya sendiri. Di Table Editor (mode admin) semua catatan tetap terlihat.

⚠️ Jangan lewati RLS

Jika lupa enable row level security, aplikasi tetap "berjalan normal", tetapi semua user bisa membaca catatan semua orang lewat API. Kesalahan ini tidak terlihat saat diuji dengan satu akun, jadi selalu uji dengan dua akun.
