NoteRepository adalah "satu pintu" untuk data catatan. Provider cukup memanggil repository.getNotes() tanpa perlu tahu apakah data datang dari Supabase atau dari cache Hive.

Strategi: network first, cache fallback

getNotes()
   │
   ├─▶ remote.fetchNotes()  (maks 10 detik)
   │       │
   │       ├─ sukses ──────────▶ local.saveNotes(data) ──▶ NotesResult(data, fromCache: false)
   │       │
   │       ├─ PostgrestException ──▶ rethrow  (server MENJAWAB tapi menolak:
   │       │                                    RLS, tabel tidak ada → harus diperbaiki)
   │       │
   │       └─ error lain ─────▶ local.getNotes() ──▶ NotesResult(cache, fromCache: true)
   │          (SocketException,                      → UI menampilkan banner "mode offline"
   │           ClientException,
   │           TimeoutException)

import 'dart:async';

import 'package:supabase_flutter/supabase_flutter.dart';

import '../models/note.dart';
import 'note_local_data_source.dart';
import 'note_remote_data_source.dart';

/// Hasil pengambilan daftar catatan.
class NotesResult {
  const NotesResult(this.notes, {required this.fromCache});

  final List<Note> notes;

  /// true jika server tidak bisa dihubungi dan data diambil dari Hive.
  final bool fromCache;
}

/// Satu pintu untuk semua data catatan. Provider tidak perlu tahu
/// apakah data berasal dari Supabase atau dari cache Hive.
class NoteRepository {
  NoteRepository({
    required this.remote,
    required this.local,
    this.timeout = const Duration(seconds: 10),
  });

  final NoteRemoteDataSource remote;
  final NoteLocalDataSource local;
  final Duration timeout;

  /// Ambil dari server lalu simpan ke cache. Jika gagal karena jaringan,
  /// kembalikan isi cache (mode offline).
  Future<NotesResult> getNotes() async {
    try {
      final notes = await remote.fetchNotes().timeout(timeout);
      await local.saveNotes(notes);
      return NotesResult(notes, fromCache: false);
    } on PostgrestException {
      // Server menjawab tapi menolak (misalnya RLS / tabel tidak ada).
      // Ini bukan masalah jaringan, jadi teruskan errornya.
      rethrow;
    } catch (_) {
      // SocketException, ClientException, TimeoutException, dll.
      return NotesResult(local.getNotes(), fromCache: true);
    }
  }

  Future<Note> addNote({
    required String title,
    required String content,
    required String category,
  }) async {
    final note = await remote
        .createNote(title: title, content: content, category: category)
        .timeout(timeout);
    await local.saveNote(note);
    return note;
  }

  Future<Note> updateNote(Note note) async {
    final updated = await remote.updateNote(note).timeout(timeout);
    await local.saveNote(updated);
    return updated;
  }

  Future<void> deleteNote(String id) async {
    await remote.deleteNote(id).timeout(timeout);
    await local.deleteNote(id);
  }

  Future<void> clearCache() => local.clear();
}

Membedah NoteRepository

  • NotesResult membungkus dua informasi: daftar catatan dan asal datanya. Tanpa flag fromCache, UI tidak bisa menampilkan banner offline.
  • .timeout(timeout): tanpa batas waktu, request di jaringan yang sangat lambat bisa menggantung lama. Setelah 10 detik muncul TimeoutException dan kita beralih ke cache.
  • on PostgrestException { rethrow; } ditulis sebelum catch (_). Error dari database bukan masalah koneksi, sehingga tidak boleh disembunyikan dengan data cache. Kalau disembunyikan, Anda tidak akan sadar policy RLS salah.
  • Operasi tulis (addNote, updateNote, deleteNote) wajib online. Urutannya: server dulu, cache kemudian. Jika server gagal, exception diteruskan dan cache tidak berubah, sehingga cache tidak pernah berisi data yang tidak ada di server.
  • Field remote dan local bertipe class konkret, tetapi tetap bisa diganti di test karena Dart mengizinkan class Palsu implements NoteRemoteDataSource.

ℹ️ Kenapa tidak memakai package connectivity?

Status "Wi-Fi tersambung" tidak menjamin internet benar-benar bisa dipakai (misalnya Wi-Fi kampus yang belum login portal). Cara paling jujur adalah langsung mencoba request: jika gagal karena jaringan, kita tahu sedang offline.

💡 Batasan desain ini

Mode offline di proyek ini bersifat baca saja. Menambah atau mengubah catatan saat offline akan gagal dengan pesan yang jelas. Antrean penulisan offline (offline queue) dibahas sebagai ide pengembangan di section terakhir.
