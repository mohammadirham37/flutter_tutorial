NotesController adalah C (Controller) pada pola MVC untuk fitur catatan. Ia memegang semua state halaman catatan: daftar catatan, status loading, mode offline, pesan error, kata kunci pencarian, dan filter kategori. Controller ini hanya berbicara dengan NoteRepository dan tidak mengenal widget sama sekali.

import 'dart:async';

import 'package:get/get.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

import '../data/note_repository.dart';
import '../models/note.dart';

class NotesController extends GetxController {
  NotesController(this._repository);

  final NoteRepository _repository;

  // State privat yang reaktif (.obs). Setiap perubahan otomatis
  // memberi tahu Obx yang membacanya.
  final _notes = <Note>[].obs;
  final _isLoading = false.obs;
  final _isOffline = false.obs;
  final _errorMessage = RxnString();
  final _query = ''.obs;
  final _categoryFilter = RxnString(); // null = semua kategori

  bool get isLoading => _isLoading.value;
  bool get isOffline => _isOffline.value;
  String? get errorMessage => _errorMessage.value;
  String get query => _query.value;
  String? get categoryFilter => _categoryFilter.value;
  bool get hasNotes => _notes.isNotEmpty;

  /// Daftar yang ditampilkan di layar setelah difilter pencarian & kategori.
  List<Note> get visibleNotes {
    final q = _query.value.toLowerCase();
    final kategori = _categoryFilter.value;
    return _notes.where((note) {
      final cocokKategori = kategori == null || note.category == kategori;
      final cocokCari =
          q.isEmpty ||
          note.title.toLowerCase().contains(q) ||
          note.content.toLowerCase().contains(q);
      return cocokKategori && cocokCari;
    }).toList();
  }

  Note? findById(String id) {
    for (final note in _notes) {
      if (note.id == id) return note;
    }
    return null;
  }

  /// Memuat catatan (dipanggil saat HomeView dibuka & saat pull-to-refresh).
  Future<void> loadNotes() async {
    _isLoading.value = true;
    _errorMessage.value = null;

    try {
      final result = await _repository.getNotes();
      _notes.assignAll(result.notes);
      _isOffline.value = result.fromCache;
    } catch (e) {
      _errorMessage.value = _friendlyError(e);
    } finally {
      _isLoading.value = false;
    }
  }

  /// Mengembalikan null jika berhasil, atau pesan error jika gagal.
  Future<String?> addNote({
    required String title,
    required String content,
    required String category,
  }) async {
    try {
      final note = await _repository.addNote(
        title: title,
        content: content,
        category: category,
      );
      _notes.insert(0, note);
      _isOffline.value = false;
      return null;
    } catch (e) {
      return _friendlyError(e);
    }
  }

  Future<String?> updateNote(Note note) async {
    try {
      final updated = await _repository.updateNote(note);
      _notes.removeWhere((n) => n.id == updated.id);
      _notes.insert(0, updated); // yang baru diubah naik ke atas
      _isOffline.value = false;
      return null;
    } catch (e) {
      return _friendlyError(e);
    }
  }

  /// Optimistic delete: hapus dari layar dulu, baru kirim ke server.
  /// Jika server gagal, catatan dikembalikan ke posisi semula (rollback).
  Future<String?> deleteNote(Note note) async {
    final index = _notes.indexWhere((n) => n.id == note.id);
    if (index == -1) return null;

    _notes.removeAt(index); // UI langsung diperbarui

    try {
      await _repository.deleteNote(note.id);
      return null;
    } catch (e) {
      _notes.insert(index, note); // rollback, UI ikut diperbarui
      return _friendlyError(e);
    }
  }

  void setQuery(String value) => _query.value = value;

  void setCategoryFilter(String? category) => _categoryFilter.value = category;

  /// Dipanggil saat logout: kosongkan state dan cache Hive.
  Future<void> clear() async {
    _notes.clear();
    _query.value = '';
    _categoryFilter.value = null;
    _errorMessage.value = null;
    _isOffline.value = false;
    await _repository.clearCache();
  }

  String _friendlyError(Object e) {
    if (e is PostgrestException) {
      if (e.code == '42501') {
        return 'Akses ditolak oleh Row Level Security. Periksa policy tabel notes.';
      }
      if (e.code == '42P01' || e.code == 'PGRST205') {
        return 'Tabel notes belum dibuat. Jalankan SQL di Supabase.';
      }
      return 'Kesalahan database: ${e.message}';
    }
    if (e is TimeoutException) {
      return 'Server terlalu lama merespons. Coba lagi.';
    }
    return 'Tidak dapat terhubung ke server. Periksa koneksi internet.';
  }
}

Polanya sama dengan Modul 08: state disimpan sebagai field privat yang reaktif (.obs, RxnString() untuk nilai yang boleh null), lalu dibuka lewat getter publik yang hanya-baca. View tidak bisa mengubah state secara langsung. Satu-satunya jalan adalah memanggil method controller seperti setQuery atau deleteNote.

Karena setiap getter membaca .value dari sebuah Rx, Obx yang memanggil getter tersebut otomatis "berlangganan" ke Rx itu. Kita tidak perlu memanggil apa pun untuk memberi tahu UI. Mengubah _isLoading.value atau memanggil _notes.insert(...) sudah cukup.

Pencarian dan filter tanpa query ulang

visibleNotes dihitung dari data di memori. Mengetik di kolom pencarian tidak mengirim request ke server, sehingga hasilnya instan dan tetap berfungsi saat offline. Untuk ratusan catatan cara ini lebih dari cukup. Untuk data sangat besar, gunakan .ilike() di server (Modul 12).

visibleNotes adalah getter biasa, bukan Rx. Getter ini membaca tiga Rx sekaligus (_notes, _query, _categoryFilter), jadi Obx yang memanggilnya akan rebuild bila salah satu dari ketiganya berubah. Data turunan seperti ini sebaiknya dihitung lewat getter, bukan disimpan sebagai state terpisah yang harus disinkronkan.

Optimistic delete dengan rollback

user geser catatan ──▶ konfirmasi "Hapus"
                         │
                         ▼
   1. simpan index, _notes.removeAt(index)   ← RxList memberi tahu Obx, UI langsung berubah
                         │
   2. await repository.deleteNote(id)
            │                         │
         sukses                     gagal (offline / RLS)
            │                         │
         selesai          3. _notes.insert(index, note)   ← kembalikan ke posisi semula
                                                          ← Obx rebuild, catatan muncul lagi
                             return pesan error           ← View menampilkan SnackBar

Disebut optimistic karena kita "optimis" server akan berhasil, sehingga UI diperbarui duluan. Keuntungannya, aplikasi terasa instan. Konsekuensinya, kita wajib menyediakan rollback jika ternyata gagal.

Untuk tambah dan edit kita memakai cara sebaliknya (pessimistic): tunggu server, baru perbarui list. Alasannya, id dan tanggal catatan baru berasal dari database.

Kontrak nilai kembali: Future<String?>

addNote, updateNote, dan deleteNote mengembalikan null jika sukses atau String pesan error jika gagal. Controller tidak menampilkan SnackBar sendiri. View yang memanggilnya cukup menulis:

final error = await Get.find<NotesController>().addNote(
  title: 'Basis Data',
  content: 'Normalisasi sampai 3NF',
  category: 'Kuliah',
);
if (error == null) {
  // sukses: tampilkan SnackBar lalu Get.back()
} else {
  // tampilkan error di SnackBar
}

GetX sebenarnya menyediakan Get.snackbar yang bisa dipanggil dari mana saja, termasuk dari controller. Di kursus ini kita sengaja tidak melakukannya. Controller yang tidak menyentuh UI bisa diuji dengan unit test biasa tanpa widget (section 10).

Menerjemahkan error

_friendlyError mengubah exception menjadi kalimat untuk user: 42501 (RLS menolak), 42P01/PGRST205 (tabel belum dibuat), TimeoutException, dan selain itu dianggap masalah koneksi.

Kapan loadNotes() dipanggil?

Di Modul 08 kita memuat data awal di onInit(). Untuk NotesController cara itu tidak cocok. Controller ini didaftarkan sekali di main() (section 9), yaitu sebelum user login, dan onInit() hanya berjalan satu kali seumur aplikasi. Jika memuat di onInit(), request dikirim tanpa sesi login dan tidak dikirim ulang setelah user berganti akun. Karena itu loadNotes() dipanggil oleh HomeView setiap kali halaman itu dibuat, yaitu setiap kali user berhasil login (section 7).

⚠️ Kesalahan umum

  • Membuka _notes langsung lewat getter publik: View bisa mengubah list tanpa lewat controller. Di sini View hanya menerima visibleNotes, yaitu list baru hasil where().toList().
  • Mengganti list dengan _notes = [...]: field final tidak bisa diganti, dan kalaupun bisa, Obx masih mendengarkan RxList yang lama. Gunakan assignAll, insert, removeAt, atau clear agar RxList yang sama memberi tahu Obx.
  • Lupa .value: _isLoading = true adalah error kompilasi, sedangkan membaca _query tanpa .value menghasilkan objek RxString, bukan teks.
  • Mengimpor material.dart atau menyimpan BuildContext di controller: controller jadi sulit diuji. Biarkan View yang menampilkan SnackBar dan bernavigasi.
