Jalankan aplikasi lalu ikuti tujuh skenario di bawah secara berurutan. Setiap skenario menguji satu bagian kode dan sebaiknya dicek juga di dashboard Supabase, supaya Anda melihat bahwa data benar-benar tersimpan di cloud.

flutter run --dart-define-from-file=env.json

Skenario 1: Validasi dan login gagal

  1. Aplikasi terbuka di halaman login, karena belum ada user yang login dan AuthMiddleware mengalihkan dari / ke /login.
  2. Tekan Masuk dengan form kosong. Pesan "Email wajib diisi" dan "Password wajib diisi" muncul.
  3. Isi email yang belum terdaftar dan password sembarang, lalu tekan Masuk. Tombol sempat berputar, lalu muncul snackbar "Email atau password salah."

Skenario 2: Register

  1. Tekan Belum punya akun? Daftar. Email yang tadi diketik ikut terisi.
  2. Isi password dan isi Ulangi Password dengan nilai berbeda. Pesan "Konfirmasi password tidak sama" muncul.
  3. Samakan kedua password lalu tekan Daftar. Aplikasi langsung membuka halaman daftar yang masih kosong, dengan tulisan "Masuk sebagai ...".
  4. Cek di dashboard: buka Authentication → Users. Akun baru Anda ada di sana.

Skenario 3: Create dan NIM ganda

  1. Tambahkan tiga mahasiswa: Budi Santoso (220101001, Informatika, 5), Siti Aminah (220102015, Sistem Informasi, 3), Andi Pratama (220103007, Informatika, 7).
  2. Daftar tampil urut A-Z: Andi, Budi, Siti.
  3. Coba tambah lagi dengan NIM 220101001. Snackbar "NIM 220101001 sudah terdaftar" muncul dan form tidak tertutup.
  4. Cek di dashboard: buka Table Editor → mahasiswa. Ada tiga baris, dan kolom user_id pada ketiganya sama dengan id akun Anda di menu Users.

Skenario 5: Sesi tersimpan

  1. Tutup aplikasi sepenuhnya (geser dari daftar aplikasi terbaru), lalu buka lagi dari ikon di HP.
  2. Aplikasi langsung membuka halaman daftar tanpa meminta login, dan datanya tetap ada.

Ini terjadi karena Supabase.initialize memulihkan sesi yang tersimpan, sehingga AuthMiddleware menganggap user sudah login.

Skenario 6: Logout dan bukti RLS

  1. Tekan ikon Keluar di AppBar, lalu pilih Keluar. Aplikasi kembali ke halaman login.
  2. Daftarkan akun kedua dengan email lain. Halaman daftar kosong, walaupun di Table Editor ada data milik akun pertama. Inilah kerja RLS.
  3. Dengan akun kedua, tambahkan mahasiswa dengan NIM 220101001 (sama dengan Budi milik akun pertama). Penyimpanan berhasil, karena constraint-nya unique (user_id, nim), bukan unique (nim).
  4. Logout, lalu login lagi dengan akun pertama. Hanya data milik akun pertama yang tampil.

Skenario 7: Tanpa internet

  1. Aktifkan mode pesawat di HP atau emulator, lalu tutup dan buka ulang aplikasi.
  2. Halaman daftar menampilkan "Tidak dapat terhubung ke server. Periksa internet." dan tombol Coba Lagi. Aplikasi tetap berada di halaman daftar karena sesi tersimpan di HP.
  3. Matikan mode pesawat, lalu tekan Coba Lagi. Data kembali tampil.

ℹ️ Supabase vs Hive saat offline

Versi Hive dari Modul 11B tetap jalan tanpa internet, sedangkan versi ini tidak. Itulah tukar-tambahnya: data di cloud bisa diakses dari banyak HP dan aman per akun, tetapi butuh koneksi. Modul 14 menunjukkan cara menggabungkan keduanya, yaitu Supabase sebagai sumber utama dan Hive sebagai cache offline.
