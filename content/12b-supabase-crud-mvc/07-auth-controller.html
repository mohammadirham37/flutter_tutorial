AuthController adalah "otak" halaman login dan register. Polanya sama persis dengan MahasiswaController di Modul 11B: state reaktif (.obs), TextEditingController dan formKey disimpan di controller, validator, lalu method yang dipanggil tombol.

Buat file lib/controllers/auth_controller.dart. Salin utuh dulu, lalu baca penjelasan per bagian di bawahnya:

📄 lib/controllers/auth_controller.dart

import 'dart:async';

import 'package:flutter/material.dart';
import 'package:get/get.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

import '../routes/app_routes.dart';
import '../services/auth_service.dart';

/// CONTROLLER untuk login, register, dan logout.
class AuthController extends GetxController {
  AuthController(this._authService);

  final AuthService _authService;

  // ------------------ STATE REAKTIF ------------------
  final isLoading = false.obs;
  final hidePassword = true.obs;

  // ------------------ STATE FORM ------------------
  // Login dan register punya form sendiri-sendiri, karena saat halaman
  // register dibuka, halaman login masih ada di bawahnya.
  final loginFormKey = GlobalKey<FormState>();
  final registerFormKey = GlobalKey<FormState>();
  final emailC = TextEditingController();
  final passwordC = TextEditingController();
  final regEmailC = TextEditingController();
  final regPasswordC = TextEditingController();
  final regKonfirmasiC = TextEditingController();

  StreamSubscription<AuthState>? _authSub;

  bool get isLoggedIn => _authService.currentUser != null;
  String get email => _authService.currentUser?.email ?? '';

  @override
  void onInit() {
    super.onInit();
    // Jika sesi berakhir (logout, token kedaluwarsa, akun dihapus),
    // kembalikan pengguna ke halaman login dari halaman mana pun.
    _authSub = _authService.authStateChanges.listen((data) {
      if (data.event == AuthChangeEvent.signedOut) {
        Get.offAllNamed(AppRoutes.login);
      }
    });
  }

  // ------------------ LOGIN ------------------
  Future<void> login() async {
    if (!loginFormKey.currentState!.validate()) return;

    isLoading.value = true;
    try {
      await _authService.signIn(
        email: emailC.text.trim(),
        password: passwordC.text,
      );
      passwordC.clear();
      Get.offAllNamed(AppRoutes.home);
    } on AuthException catch (e) {
      _tampilkanError(_pesanAuth(e));
    } catch (e) {
      _tampilkanError('Tidak dapat terhubung ke server. Periksa internet.');
    } finally {
      isLoading.value = false;
    }
  }

  // ------------------ REGISTER ------------------
  void openRegister() {
    regEmailC.text = emailC.text.trim();
    regPasswordC.clear();
    regKonfirmasiC.clear();
    Get.toNamed(AppRoutes.register);
  }

  Future<void> register() async {
    if (!registerFormKey.currentState!.validate()) return;

    isLoading.value = true;
    try {
      final res = await _authService.signUp(
        email: regEmailC.text.trim(),
        password: regPasswordC.text,
      );

      if (res.session != null) {
        // "Confirm email" dimatikan: user langsung login.
        Get.offAllNamed(AppRoutes.home);
        Get.snackbar(
          'Berhasil',
          'Akun dibuat, selamat datang!',
          snackPosition: SnackPosition.BOTTOM,
        );
      } else {
        // "Confirm email" aktif: user harus klik link di email dulu.
        emailC.text = regEmailC.text.trim();
        tutup(); // kembali ke halaman login
        Get.snackbar(
          'Cek email Anda',
          'Klik link verifikasi di email, lalu login.',
          snackPosition: SnackPosition.BOTTOM,
          duration: const Duration(seconds: 5),
        );
      }
    } on AuthException catch (e) {
      _tampilkanError(_pesanAuth(e));
    } catch (e) {
      _tampilkanError('Tidak dapat terhubung ke server. Periksa internet.');
    } finally {
      isLoading.value = false;
    }
  }

  // ------------------ LOGOUT ------------------
  Future<void> confirmLogout() async {
    final yakin = await Get.dialog<bool>(
      AlertDialog(
        title: const Text('Keluar'),
        content: const Text('Yakin ingin keluar dari akun ini?'),
        actions: [
          TextButton(onPressed: () => tutup(false), child: const Text('Batal')),
          FilledButton(
            onPressed: () => tutup(true),
            child: const Text('Keluar'),
          ),
        ],
      ),
    );
    if (yakin == true) {
      // Tidak perlu navigasi di sini: listener di onInit menerima event
      // signedOut lalu membuka halaman login.
      await _authService.signOut();
    }
  }

  // ------------------ HELPER ------------------
  /// Menutup halaman / dialog paling atas (sama seperti di Modul 11B).
  void tutup<T>([T? result]) => Get.key.currentState?.pop<T>(result);

  void _tampilkanError(String pesan) {
    Get.snackbar('Gagal', pesan, snackPosition: SnackPosition.BOTTOM);
  }

  /// Menerjemahkan kode error Supabase Auth ke bahasa Indonesia.
  String _pesanAuth(AuthException e) {
    if (e is AuthRetryableFetchException) {
      return 'Tidak dapat terhubung ke server. Periksa internet.';
    }
    switch (e.code) {
      case 'invalid_credentials':
        return 'Email atau password salah.';
      case 'email_not_confirmed':
        return 'Email belum diverifikasi. Buka link di inbox Anda.';
      case 'user_already_exists':
      case 'email_exists':
        return 'Email sudah terdaftar. Silakan login.';
      case 'weak_password':
        return 'Password terlalu lemah (minimal 6 karakter).';
      case 'email_address_invalid':
        return 'Alamat email ditolak server.';
      case 'over_email_send_rate_limit':
      case 'over_request_rate_limit':
        return 'Terlalu banyak percobaan. Tunggu beberapa menit.';
    }
    return e.message;
  }

  // ------------------ VALIDATOR ------------------
  String? validateEmail(String? v) {
    final text = v?.trim() ?? '';
    if (text.isEmpty) return 'Email wajib diisi';
    if (!RegExp(r'^[^@\s]+@[^@\s]+\.[^@\s]+$').hasMatch(text)) {
      return 'Format email tidak valid';
    }
    return null;
  }

  String? validatePassword(String? v) {
    if (v == null || v.isEmpty) return 'Password wajib diisi';
    if (v.length < 6) return 'Password minimal 6 karakter';
    return null;
  }

  String? validateKonfirmasi(String? v) {
    if (v == null || v.isEmpty) return 'Ulangi password wajib diisi';
    if (v != regPasswordC.text) return 'Konfirmasi password tidak sama';
    return null;
  }

  @override
  void onClose() {
    _authSub?.cancel();
    emailC.dispose();
    passwordC.dispose();
    regEmailC.dispose();
    regPasswordC.dispose();
    regKonfirmasiC.dispose();
    super.onClose();
  }
}

Bagian 1: Constructor dan state

AuthController(this._authService);

final isLoading = false.obs;     // tombol menampilkan loading
final hidePassword = true.obs;   // ikon mata: sembunyikan/tampilkan password

AuthService diterima lewat constructor (didaftarkan di main.dart). isLoading bernilai true selama menunggu jawaban server. Selama itu tombol dinonaktifkan supaya tidak ditekan dua kali.

Bagian 2: Dua form terpisah

Login dan register punya GlobalKey<FormState> dan TextEditingController sendiri-sendiri. Alasannya, saat halaman register dibuka dengan Get.toNamed, halaman login masih ada di bawahnya. Satu GlobalKey tidak boleh dipakai dua widget sekaligus, karena Flutter akan menampilkan error Duplicate GlobalKey detected.

Bagian 3: Mendengarkan perubahan status login di onInit

_authSub = _authService.authStateChanges.listen((data) {
  if (data.event == AuthChangeEvent.signedOut) {
    Get.offAllNamed(AppRoutes.login);
  }
});

Setiap kali Supabase memancarkan event signedOut, aplikasi pindah ke halaman login dan seluruh halaman lain dihapus dari tumpukan. Event ini muncul saat pengguna menekan Keluar, dan juga saat sesi tidak bisa diperpanjang lagi (misalnya akun dihapus admin). Jadi kita cukup menulis navigasi ke login di satu tempat ini. StreamSubscription disimpan di _authSub agar bisa dihentikan di onClose.

Bagian 4: login()

  1. Validasi form. Jika ada field yang salah, berhenti.
  2. isLoading.value = true sehingga tombol berubah menjadi indikator loading.
  3. Panggil signIn. Jika berhasil, password dikosongkan lalu Get.offAllNamed(AppRoutes.home) membuka halaman daftar dan membuang halaman login dari tumpukan. Akibatnya tombol Back di halaman daftar menutup aplikasi, bukan kembali ke login.
  4. Jika gagal, AuthException ditangkap dan diterjemahkan menjadi pesan berbahasa Indonesia oleh _pesanAuth. Error lain (misalnya tidak ada internet) ditangkap oleh catch (e) umum.
  5. finally selalu dijalankan, baik berhasil maupun gagal, sehingga loading pasti dimatikan.

Bagian 5: register() dan dua kemungkinan hasil

Pengaturan Confirm emailIsi res.sessionYang dilakukan aplikasi
Mati (praktikum)Berisi sesi, user langsung loginBuka halaman daftar + snackbar "Akun dibuat"
Aktif (produksi)null, user harus verifikasi emailKembali ke login, email terisi otomatis, snackbar "Cek email Anda"

openRegister() menyalin email yang sudah diketik di halaman login ke halaman register, supaya pengguna tidak perlu mengetik ulang.

Bagian 6: confirmLogout()

Menampilkan dialog konfirmasi seperti dialog hapus di Modul 11B. Jika pengguna memilih Keluar, cukup panggil signOut(). Kita tidak memanggil Get.offAllNamed di sini, karena listener di Bagian 3 akan menerima event signedOut lalu membuka halaman login.

Bagian 7: Menerjemahkan error

Supabase mengirim kode error dalam bahasa Inggris, misalnya invalid_credentials. _pesanAuth mengubahnya menjadi kalimat yang dipahami pengguna:

Kode dari SupabasePesan di aplikasi
invalid_credentialsEmail atau password salah.
email_not_confirmedEmail belum diverifikasi. Buka link di inbox Anda.
user_already_exists / email_existsEmail sudah terdaftar. Silakan login.
weak_passwordPassword terlalu lemah (minimal 6 karakter).
over_request_rate_limitTerlalu banyak percobaan. Tunggu beberapa menit.
AuthRetryableFetchExceptionTidak dapat terhubung ke server. Periksa internet.

ℹ️ Kenapa "Email atau password salah", bukan "Email tidak terdaftar"?

Supabase sengaja tidak memberi tahu mana yang salah. Jika aplikasi bilang "email tidak terdaftar", penyerang bisa menebak-nebak email mana saja yang punya akun. Pesan yang samar justru lebih aman.
