Sebelum menulis kode Flutter, kita siapkan dulu "gudang data" di Supabase: satu tabel mahasiswa yang dikunci dengan Row Level Security (RLS), sehingga setiap akun hanya bisa membaca dan mengubah datanya sendiri.

Langkah 1: Siapkan project Supabase

Jika belum punya project, buat dulu di supabase.com/dashboard seperti di Modul 12 section 2. Lalu catat dua nilai yang nanti diisi ke env.json:

NilaiTempat mencarinyaContoh bentuk
Project URLTombol Connect di bagian atas dashboard, atau Project Settings → Data APIhttps://abcdefghijkl.supabase.co
Publishable keyProject Settings → API Keyssb_publishable_xxxxxxxx

⚠️ Jangan pakai secret key

Di halaman API Keys juga ada secret key (sb_secret_..., dulu bernama service_role). Key ini mengabaikan semua RLS, jadi tidak boleh dimasukkan ke aplikasi mobile. Aplikasi cukup memakai publishable key, karena keamanannya dijaga oleh RLS.

Langkah 2: Buat tabel dan RLS lewat SQL Editor

Buka SQL Editor → New query, tempel seluruh SQL di bawah, lalu klik Run. Simpan juga SQL ini di proyek sebagai supabase/setup.sql sebagai dokumentasi. SQL ini aman dijalankan ulang karena memakai if not exists dan drop policy if exists.

📄 supabase/setup.sql

-- 1. Tabel mahasiswa: setiap baris dimiliki satu user (user_id)
create table if not exists public.mahasiswa (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null default auth.uid()
    references auth.users (id) on delete cascade,
  nim text not null,
  nama text not null,
  prodi text not null,
  semester int not null check (semester between 1 and 14),
  created_at timestamptz not null default now(),
  unique (user_id, nim)
);

-- 2. Izinkan user yang login memakai tabel ini lewat API
grant select, insert, update, delete on public.mahasiswa to authenticated;

-- 3. Kunci tabel dengan Row Level Security
alter table public.mahasiswa enable row level security;

-- 4. Policy: user hanya boleh menyentuh baris miliknya sendiri
drop policy if exists "Lihat data sendiri" on public.mahasiswa;
create policy "Lihat data sendiri"
on public.mahasiswa for select
to authenticated
using ((select auth.uid()) = user_id);

drop policy if exists "Tambah data sendiri" on public.mahasiswa;
create policy "Tambah data sendiri"
on public.mahasiswa for insert
to authenticated
with check ((select auth.uid()) = user_id);

drop policy if exists "Ubah data sendiri" on public.mahasiswa;
create policy "Ubah data sendiri"
on public.mahasiswa for update
to authenticated
using ((select auth.uid()) = user_id)
with check ((select auth.uid()) = user_id);

drop policy if exists "Hapus data sendiri" on public.mahasiswa;
create policy "Hapus data sendiri"
on public.mahasiswa for delete
to authenticated
using ((select auth.uid()) = user_id);

-- 5. Index agar filter berdasarkan user_id tetap cepat
create index if not exists mahasiswa_user_id_idx on public.mahasiswa (user_id);

Jika berhasil, di bagian bawah muncul tulisan Success. No rows returned.

Penjelasan per bagian

KodePenjelasan
id uuid primary key default gen_random_uuid()Id dibuat otomatis oleh database berupa teks acak unik, misalnya 3f2b9c1e-.... Aplikasi tidak perlu membuat id sendiri seperti di Hive.
user_id uuid not null default auth.uid()Pemilik baris. auth.uid() adalah id user yang sedang login, dan karena menjadi nilai default, aplikasi tidak perlu mengirim user_id saat insert.
references auth.users (id) on delete cascadeRelasi ke tabel user milik Supabase. Jika akun dihapus, semua data mahasiswa miliknya ikut terhapus.
check (semester between 1 and 14)Validasi di sisi database. Walaupun validasi di aplikasi terlewat, database tetap menolak semester 0 atau 20.
unique (user_id, nim)NIM tidak boleh ganda dalam satu akun. Akun berbeda boleh punya NIM yang sama.
grant ... to authenticatedMemberi izin dasar ke role authenticated (user yang sudah login) untuk memakai tabel lewat API. Pada sebagian project baru, izin ini tidak diberikan otomatis, jadi kita tulis secara eksplisit.
enable row level securityMengunci tabel. Setelah baris ini, tidak ada yang bisa membaca atau menulis kecuali diizinkan oleh policy.
Empat create policySatu policy untuk setiap operasi (select, insert, update, delete). Semuanya memakai syarat yang sama: auth.uid() = user_id, artinya hanya baris milik sendiri.
using (...) vs with check (...)using menyaring baris lama yang boleh dilihat/diubah/dihapus. with check memeriksa baris baru hasil insert/update, sehingga user tidak bisa menyisipkan data atas nama orang lain.
(select auth.uid())Dibungkus select supaya Postgres cukup menghitungnya sekali per query, bukan sekali per baris. Hasilnya sama, tetapi lebih cepat.
create index ... (user_id)Karena setiap query difilter berdasarkan user_id, index membuat pencarian tetap cepat walaupun datanya banyak.

ℹ️ Kenapa query di Flutter tidak perlu .eq('user_id', ...)?

Karena RLS sudah menyaring di server. Saat Budi menjalankan select(), Postgres otomatis menambahkan syarat "hanya baris dengan user_id milik Budi". Ini juga lebih aman: walaupun ada yang mengubah kode aplikasi, data akun lain tetap tidak bisa diambil.

Langkah 3: Matikan "Confirm email" (khusus praktikum)

Secara bawaan, Supabase mengirim email verifikasi setelah register, dan akun baru belum bisa login sebelum link di email diklik. Untuk praktikum di kelas, fitur ini kita matikan supaya register langsung login dan tidak terkena batas pengiriman email.

  1. Di sidebar kiri, buka Authentication (ikon gembok).
  2. Di bagian CONFIGURATION, klik Sign In / Providers (nomor 1 pada gambar). Jangan tertukar dengan menu Emails di bagian NOTIFICATIONS, karena menu itu hanya mengatur isi template email.
  3. Pada kotak User Signups, matikan toggle Confirm email (nomor 2) sampai berwarna abu-abu.
  4. Klik Save changes (nomor 3).
Authentication → Sign In / Providers → matikan Confirm email → Save changes

Pastikan juga Allow new users to sign up tetap aktif (hijau). Jika dimatikan, register akan selalu gagal.

💡 Untuk aplikasi sungguhan

Di aplikasi produksi, Confirm email sebaiknya diaktifkan agar orang tidak bisa mendaftar memakai email orang lain. Kode di modul ini sudah menangani kedua kondisi: jika Confirm email aktif, setelah register aplikasi kembali ke halaman login dan menampilkan pesan "Cek email Anda".

Langkah 4: Cek hasilnya

  1. Buka Table Editor. Tabel mahasiswa harus muncul dan isinya masih kosong.
  2. Buka Authentication → Policies. Pada tabel mahasiswa harus ada empat policy: Lihat, Tambah, Ubah, dan Hapus data sendiri. RLS harus berstatus aktif (enabled).
