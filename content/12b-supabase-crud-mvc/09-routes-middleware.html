Aplikasi sekarang punya empat halaman, dan dua di antaranya (daftar dan form) hanya boleh dibuka setelah login. Di section ini kita menambah route baru, membuat middleware sebagai penjaga, dan memperbarui binding.

1. Nama route

Ganti isi lib/routes/app_routes.dart:

📄 lib/routes/app_routes.dart

/// Daftar nama route aplikasi.
abstract class AppRoutes {
  static const login = '/login';
  static const register = '/register';
  static const home = '/';
  static const form = '/form';
}

Route home tetap '/' (halaman daftar) seperti di Modul 11B. Ada dua route baru: /login dan /register.

2. Middleware: satpam di depan halaman

Middleware adalah kode yang dijalankan GetX sebelum sebuah halaman dibuka. Di sini kita memakainya untuk menolak pengguna yang belum login. Buat file lib/middlewares/auth_middleware.dart:

📄 lib/middlewares/auth_middleware.dart

import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/auth_controller.dart';
import '../routes/app_routes.dart';

/// "Satpam" route: dipasang pada halaman yang wajib login.
/// Jika user belum login, GetX diarahkan ke halaman login.
class AuthMiddleware extends GetMiddleware {
  @override
  RouteSettings? redirect(String? route) {
    final auth = Get.find<AuthController>();
    if (auth.isLoggedIn) return null; // boleh lanjut
    return const RouteSettings(name: AppRoutes.login);
  }
}
  • redirect dipanggil setiap kali route yang memakai middleware ini akan dibuka.
  • Mengembalikan null berarti "silakan lewat".
  • Mengembalikan RouteSettings(name: AppRoutes.login) berarti "jangan buka halaman ini, buka halaman login".
  • Get.find<AuthController>() bisa dipakai karena AuthController sudah didaftarkan di main.dart sebelum aplikasi berjalan.

ℹ️ Kenapa tidak cukup menyembunyikan tombol?

Halaman bisa dibuka dari banyak jalan: initialRoute, Get.toNamed, atau tombol Back. Dengan middleware, aturannya ditulis sekali di route, jadi semua jalan itu terjaga. Ingat juga bahwa keamanan data yang sesungguhnya tetap ada di RLS. Middleware hanya mengatur tampilan agar pengguna tidak melihat halaman kosong yang gagal memuat data.

3. Binding

Ganti isi lib/bindings/mahasiswa_binding.dart:

📄 lib/bindings/mahasiswa_binding.dart

import 'package:get/get.dart';

import '../controllers/mahasiswa_controller.dart';

/// Binding: mendaftarkan MahasiswaController sebelum halaman daftar dibuka.
/// MahasiswaService sudah didaftarkan di main(), tinggal diambil Get.find().
class MahasiswaBinding extends Bindings {
  @override
  void dependencies() {
    Get.lazyPut<MahasiswaController>(() => MahasiswaController(Get.find()));
  }
}

Bedanya dengan Modul 11B hanya pada MahasiswaController(Get.find()). Controller sekarang meminta service lewat constructor, dan Get.find() mengambil MahasiswaService yang sudah didaftarkan di main.dart. Dart bisa menebak tipe yang dicari dari parameter constructor, jadi Get.find() tidak perlu ditulis Get.find<MahasiswaService>().

4. Pemetaan route

Ganti isi lib/routes/app_pages.dart:

📄 lib/routes/app_pages.dart

import 'package:get/get.dart';

import '../bindings/mahasiswa_binding.dart';
import '../middlewares/auth_middleware.dart';
import '../views/login_view.dart';
import '../views/mahasiswa_form_view.dart';
import '../views/mahasiswa_list_view.dart';
import '../views/register_view.dart';
import 'app_routes.dart';

/// Pemetaan route -> halaman (+ binding + middleware).
class AppPages {
  static final pages = [
    GetPage(name: AppRoutes.login, page: () => const LoginView()),
    GetPage(name: AppRoutes.register, page: () => const RegisterView()),
    GetPage(
      name: AppRoutes.home,
      page: () => const MahasiswaListView(),
      binding: MahasiswaBinding(),
      middlewares: [AuthMiddleware()],
    ),
    GetPage(
      name: AppRoutes.form,
      page: () => const MahasiswaFormView(),
      middlewares: [AuthMiddleware()],
    ),
  ];
}
RouteHalamanBindingMiddleware
/loginLoginView--
/registerRegisterView--
/MahasiswaListViewMahasiswaBindingAuthMiddleware
/formMahasiswaFormView-AuthMiddleware
  • Halaman login dan register tidak butuh binding, karena AuthController sudah ada sejak main.dart.
  • MahasiswaBinding tetap dipasang hanya di route home, dengan alasan yang sama seperti Modul 11B: halaman form memakai controller yang sama dengan halaman daftar.

💡 Bonus: data tidak tercampur antar-akun

Saat logout, Get.offAllNamed(AppRoutes.login) menutup halaman daftar. GetX ikut menghapus MahasiswaController dari memori karena halaman yang memakainya sudah tidak ada. Ketika akun lain login, controller dibuat baru dan onInit memuat data milik akun tersebut. Jadi daftar milik akun sebelumnya tidak sempat terlihat.

Coba jalankan: middleware menjaga halaman

app_pages.dart di atas belum bisa dipakai karena view-nya baru dibuat di section 10 dan 11. Untuk mencoba middleware sekarang, kita pasang AuthMiddleware pada halaman sederhana. Ganti seluruh isi lib/main.dart dengan:

📄 lib/main.dart (sementara)

// lib/main.dart (SEMENTARA) — mencoba AuthMiddleware sebagai penjaga route.
// Jalankan: flutter run --dart-define-from-file=env.json
import 'package:flutter/material.dart';
import 'package:get/get.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

import 'config/env.dart';
import 'controllers/auth_controller.dart';
import 'middlewares/auth_middleware.dart';
import 'routes/app_routes.dart';
import 'services/auth_service.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();
  await Supabase.initialize(
    url: Env.supabaseUrl,
    publishableKey: Env.supabaseKey,
  );
  Get.put(AuthService(Supabase.instance.client), permanent: true);
  Get.put(AuthController(Get.find()), permanent: true);
  runApp(const CobaMiddlewareApp());
}

class CobaMiddlewareApp extends StatelessWidget {
  const CobaMiddlewareApp({super.key});

  @override
  Widget build(BuildContext context) {
    return GetMaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo, useMaterial3: true),
      // Selalu mencoba membuka home. Middleware yang memutuskan.
      initialRoute: AppRoutes.home,
      getPages: [
        GetPage(name: AppRoutes.login, page: () => const DemoLoginPage()),
        GetPage(
          name: AppRoutes.home,
          page: () => const DemoRahasiaPage(),
          middlewares: [AuthMiddleware()],
        ),
      ],
    );
  }
}

class DemoLoginPage extends GetView<AuthController> {
  const DemoLoginPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Login (dialihkan middleware)')),
      body: Form(
        key: controller.loginFormKey,
        child: ListView(
          padding: const EdgeInsets.all(16),
          children: [
            TextFormField(
              controller: controller.emailC,
              validator: controller.validateEmail,
              decoration: const InputDecoration(labelText: 'Email'),
            ),
            TextFormField(
              controller: controller.passwordC,
              validator: controller.validatePassword,
              obscureText: true,
              decoration: const InputDecoration(labelText: 'Password'),
            ),
            const SizedBox(height: 16),
            Obx(
              () => FilledButton(
                onPressed: controller.isLoading.value ? null : controller.login,
                child: const Text('Masuk'),
              ),
            ),
          ],
        ),
      ),
    );
  }
}

class DemoRahasiaPage extends GetView<AuthController> {
  const DemoRahasiaPage({super.key});

Belum login: dialihkan ke login

Jalankan dengan flutter run --dart-define-from-file=env.json:

  1. Jika masih login, Halaman Wajib Login langsung terbuka. Middleware mengembalikan null (boleh lewat).
  2. Tekan ikon keluar lalu pilih Keluar. Aplikasi pindah ke halaman login.
  3. Hentikan aplikasi lalu jalankan lagi. initialRoute tetap AppRoutes.home, tetapi yang terbuka adalah halaman Login (dialihkan middleware). Inilah kerja redirect.
  4. Login. Karena login() memanggil Get.offAllNamed(AppRoutes.home) dan sekarang isLoggedIn bernilai true, middleware mengizinkan halaman rahasia terbuka.
  • Bandingkan dengan contoh section 7: di sana initialRoute memilih sendiri lewat auth.isLoggedIn ? ... : .... Sekarang initialRoute selalu home, dan aturan "wajib login" cukup ditulis sekali di middlewares: [AuthMiddleware()].
  • Halaman login tidak diberi middleware. Jika diberi, pengguna yang belum login akan dialihkan ke login terus-menerus tanpa henti.
