💡 Cara melihat error asli dari Supabase

Pesan di snackbar sengaja disederhanakan. Untuk melihat detailnya saat debugging, tambahkan sementara debugPrint('$e'); di dalam catch, lalu lihat terminal tempat flutter run berjalan. Log di sisi server bisa dilihat di dashboard pada menu Logs.

Ringkasan modul

  • Berkat pola MVC, memindahkan database dari Hive ke Supabase hampir hanya mengubah lapisan Model: HiveService diganti MahasiswaService, dan model mendapat fromJson/toJson. View daftar dan form nyaris tidak berubah.
  • Akses ke cloud bersifat async dan bisa gagal, sehingga controller perlu state isLoading, isSaving, dan errorMessage dengan pola try / catch / finally.
  • Row Level Security dengan syarat auth.uid() = user_id membuat setiap akun hanya bisa melihat dan mengubah datanya sendiri. Aplikasi tidak perlu memfilter user_id, dan publishable key aman dipasang di aplikasi.
  • AuthService + AuthController menangani register, login, dan logout. Sesi tersimpan otomatis, jadi pengguna tidak perlu login ulang.
  • AuthMiddleware menjaga route yang wajib login, dan listener onAuthStateChange mengembalikan pengguna ke halaman login saat sesi berakhir.
  • Service yang disuntikkan lewat constructor dan Get.put bisa diganti versi palsu saat testing, sehingga flutter test berjalan tanpa internet.

Langkah selanjutnya: Modul 13 dan 14 membangun proyek "Catatan Kuliah" yang lebih besar dengan pola yang sama, ditambah tabel profil, mode offline dengan cache Hive, dan fitur yang lebih lengkap.
