Kita mulai dari lapisan paling bawah, lalu naik ke atas: konfigurasi → service → provider → UI. Di section ini kita membuat tiga file yang tidak bergantung pada widget sama sekali.

File 1: lib/config/env.dart

Membaca URL dan key yang disuntikkan lewat --dart-define-from-file=env.json (Modul 12 section 4).

📄 lib/config/env.dart

/// Konfigurasi Supabase yang dibaca saat build lewat --dart-define.
///
/// Jalankan aplikasi dengan:
///   flutter run --dart-define-from-file=env.json
class Env {
  static const String supabaseUrl = String.fromEnvironment('SUPABASE_URL');
  static const String supabasePublishableKey = String.fromEnvironment(
    'SUPABASE_PUBLISHABLE_KEY',
  );

  /// true jika kedua nilai sudah diisi.
  static bool get isConfigured =>
      supabaseUrl.isNotEmpty && supabasePublishableKey.isNotEmpty;
}

File 2: lib/utils/validators.dart

Validator dipakai oleh form Login dan Register. Kita kumpulkan di satu tempat agar aturannya konsisten (misalnya minimal 6 karakter mengikuti aturan default Supabase).

📄 lib/utils/validators.dart

/// Kumpulan validator untuk TextFormField.
/// Setiap fungsi mengembalikan null jika valid, atau pesan error jika tidak.
class Validators {
  static String? fullName(String? value) {
    final text = value?.trim() ?? '';
    if (text.isEmpty) return 'Nama lengkap wajib diisi';
    if (text.length < 3) return 'Nama minimal 3 karakter';
    return null;
  }

  static String? email(String? value) {
    final text = value?.trim() ?? '';
    if (text.isEmpty) return 'Email wajib diisi';
    final pola = RegExp(r'^[^@\s]+@[^@\s]+\.[^@\s]+$');
    if (!pola.hasMatch(text)) return 'Format email tidak valid';
    return null;
  }

  static String? password(String? value) {
    final text = value ?? '';
    if (text.isEmpty) return 'Password wajib diisi';
    if (text.length < 6) return 'Password minimal 6 karakter';
    return null;
  }
}
  • Setiap validator mengembalikan null jika valid, atau String pesan error jika tidak valid. Ini kontrak validator pada TextFormField (Modul 05).
  • Method dibuat static sehingga bisa langsung dipasang sebagai tear-off: validator: Validators.email.
  • Regex email sengaja dibuat sederhana. Validasi sesungguhnya tetap dilakukan Supabase (error email_address_invalid).

File 3: lib/services/auth_service.dart

AuthService adalah satu-satunya class yang memanggil supabase.auth. Class lain cukup memakai service ini.

📄 lib/services/auth_service.dart

import 'package:supabase_flutter/supabase_flutter.dart';

/// Lapisan paling bawah untuk urusan autentikasi.
/// Hanya class ini yang berbicara langsung dengan Supabase Auth.
class AuthService {
  AuthService(this._client);

  final SupabaseClient _client;

  GoTrueClient get _auth => _client.auth;

  /// Stream yang memancarkan event setiap status login berubah
  /// (initialSession, signedIn, signedOut, tokenRefreshed, ...).
  Stream<AuthState> get authStateChanges => _auth.onAuthStateChange;

  Session? get currentSession => _auth.currentSession;

  User? get currentUser => _auth.currentUser;

  /// Mendaftarkan akun baru. Nama lengkap dikirim sebagai metadata
  /// (raw_user_meta_data) dan nanti disalin trigger ke tabel profiles.
  Future<AuthResponse> signUp({
    required String fullName,
    required String email,
    required String password,
  }) {
    return _auth.signUp(
      email: email,
      password: password,
      data: {'full_name': fullName},
    );
  }

  Future<AuthResponse> signIn({
    required String email,
    required String password,
  }) {
    return _auth.signInWithPassword(email: email, password: password);
  }

  Future<void> signOut() => _auth.signOut();
}

Penjelasan:

  • Constructor menerima SupabaseClient (dependency injection), bukan memanggil Supabase.instance.client di dalam class. Dengan begitu kita bisa mengganti client saat testing.
  • authStateChanges meneruskan stream onAuthStateChange. Stream ini yang nanti didengarkan oleh AuthGate.
  • signUp(... data: {'full_name': fullName}): nama lengkap dikirim sebagai metadata, lalu trigger handle_new_user (section 3) menyalinnya ke tabel profiles.
  • Method mengembalikan Future<AuthResponse> apa adanya. Penanganan error bukan tugas service, melainkan tugas provider di section berikutnya.

ℹ️ Kenapa tidak langsung memanggil Supabase dari widget?

Bisa saja, dan untuk demo kecil itu wajar. Tetapi jika suatu hari Anda pindah ke Firebase atau backend kampus sendiri, Anda hanya perlu mengganti isi AuthService. Provider dan semua layar tidak perlu disentuh.
