Bagaimana aplikasi tahu harus menampilkan Login atau Home? Kita tidak memakai Get.off atau Navigator.pushReplacement setelah login. Sebagai gantinya, satu widget bernama AuthGate mengamati status login di AuthController (yang mendengarkan stream onAuthStateChange) dan memilih halaman secara otomatis.

Kenapa AuthGate lebih baik daripada navigasi manual?

SituasiNavigasi manualAuthGate (reaktif)
Login berhasilHarus memanggil Get.off(...) / pushReplacement ke HomeOtomatis pindah ke Home
LogoutHarus Get.offAll(...) / pushAndRemoveUntil ke LoginOtomatis kembali ke Login
Aplikasi dibuka ulang, sesi masih adaPerlu cek manual di splash screenLangsung ke Home (event initialSession)
Sesi kedaluwarsa / dicabutSering terlupaOtomatis ke Login (event signedOut)

File 5: lib/views/auth_gate.dart

📄 lib/views/auth_gate.dart

import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/auth_controller.dart';
import 'home_view.dart';
import 'login_view.dart';

/// "Penjaga pintu" aplikasi: mengamati status login di AuthController
/// lalu memilih halaman yang tepat secara otomatis.
class AuthGate extends GetView<AuthController> {
  const AuthGate({super.key});

  @override
  Widget build(BuildContext context) {
    return Obx(() {
      // currentSession dibaca di dalam Obx, jadi setiap kali sesi berubah
      // (signedIn, signedOut, ...) builder ini dijalankan ulang.
      if (controller.currentSession == null) {
        return const LoginView();
      }
      return const HomeView();
    });
  }
}
  • extends GetView<AuthController>: GetView adalah StatelessWidget yang punya getter controller, isinya sama dengan Get.find<AuthController>(). Cocok untuk halaman yang hanya memakai satu controller.
  • Obx(() { ... }) membaca controller.currentSession. Karena getter itu membaca _session.value, Obx otomatis mendaftar sebagai pendengar dan dibangun ulang setiap kali sesi berubah.
  • Tidak perlu StatefulWidget, initState, atau StreamBuilder. Langganan stream sudah diurus AuthController di onInit dan dibatalkan di onClose, sehingga tidak ada risiko berlangganan ulang di setiap build.
  • Sesi awal diisi dari currentSession di onInit, sehingga user yang sudah login tidak melihat layar Login "berkedip" sesaat ketika aplikasi dibuka.
  • Setiap event (signedIn, signedOut, tokenRefreshed, ...) membawa session terbaru, jadi cukup cek currentSession == null.

Untuk menguji alur login, kita buat Home sederhana yang menampilkan nama dan email user serta tombol keluar. File ini akan diganti seluruhnya di Modul 14.

📄 lib/views/home_view.dart

import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/auth_controller.dart';

/// HomeView sementara untuk Bagian 1. Di Modul 14 file ini diganti
/// dengan daftar catatan lengkap.
class HomeView extends GetView<AuthController> {
  const HomeView({super.key});

  Future<void> _logout() async {
    await controller.signOut();
    // Tidak perlu navigasi: AuthGate otomatis menampilkan LoginView.
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(
        title: const Text('Catatan Kuliah'),
        actions: [
          IconButton(
            tooltip: 'Keluar',
            icon: const Icon(Icons.logout),
            onPressed: _logout,
          ),
        ],
      ),
      body: Center(
        child: Padding(
          padding: const EdgeInsets.all(24),
          child: Obx(() {
            final user = controller.currentUser;
            return Column(
              mainAxisSize: MainAxisSize.min,
              children: [
                const Icon(Icons.verified_user, size: 72, color: Colors.green),
                const SizedBox(height: 16),
                Text(
                  'Halo, ${controller.displayName}!',
                  style: Theme.of(context).textTheme.headlineSmall,
                  textAlign: TextAlign.center,
                ),
                const SizedBox(height: 8),
                Text('Login sebagai ${user?.email ?? '-'}'),
                const SizedBox(height: 4),
                SelectableText(
                  'User ID: ${user?.id ?? '-'}',
                  style: Theme.of(context).textTheme.bodySmall,
                  textAlign: TextAlign.center,
                ),
                const SizedBox(height: 24),
                const Text(
                  'Autentikasi berhasil. Daftar catatan dibuat di Modul 14.',
                  textAlign: TextAlign.center,
                ),
                const SizedBox(height: 24),
                OutlinedButton.icon(
                  onPressed: _logout,
                  icon: const Icon(Icons.logout),
                  label: const Text('Keluar'),
                ),
              ],
            );
          }),
        ),
      ),
    );
  }
}
  • extends GetView<AuthController> menyediakan getter controller (hasil Get.find), sama seperti di AuthGate.
  • Hanya bagian yang membaca data user yang dibungkus Obx. AppBar tidak bergantung pada state, jadi tidak perlu ikut dibangun ulang.
  • Perhatikan _logout: setelah signOut() tidak ada navigasi sama sekali (tidak ada Get.offAll atau Navigator). Stream memancarkan signedOut, AuthController mengosongkan sesi, lalu Obx di AuthGate menampilkan LoginView.

File 7: lib/main.dart (versi Bagian 1)

📄 lib/main.dart

import 'package:flutter/material.dart';
import 'package:get/get.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

import 'config/env.dart';
import 'controllers/auth_controller.dart';
import 'services/auth_service.dart';
import 'views/auth_gate.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  if (!Env.isConfigured) {
    runApp(const ConfigErrorApp());
    return;
  }

  await Supabase.initialize(
    url: Env.supabaseUrl,
    publishableKey: Env.supabasePublishableKey,
  );

  // Daftarkan controller global SEBELUM runApp. permanent: true membuat
  // AuthController tidak pernah dihapus selama aplikasi berjalan.
  Get.put(
    AuthController(AuthService(Supabase.instance.client)),
    permanent: true,
  );

  runApp(const CatatanKuliahApp());
}

class CatatanKuliahApp extends StatelessWidget {
  const CatatanKuliahApp({super.key});

  @override
  Widget build(BuildContext context) {
    return GetMaterialApp(
      title: 'Catatan Kuliah',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(
        colorScheme: ColorScheme.fromSeed(seedColor: Colors.indigo),
      ),
      home: const AuthGate(),
    );
  }
}

/// Ditampilkan jika aplikasi dijalankan tanpa --dart-define-from-file.
class ConfigErrorApp extends StatelessWidget {
  const ConfigErrorApp({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      debugShowCheckedModeBanner: false,
      home: Scaffold(
        body: Center(
          child: Padding(
            padding: EdgeInsets.all(24),
            child: Text(
              'SUPABASE_URL / SUPABASE_PUBLISHABLE_KEY belum diisi.\n\n'
              'Jalankan dengan:\n'
              'flutter run --dart-define-from-file=env.json',
              textAlign: TextAlign.center,
            ),
          ),
        ),
      ),
    );
  }
}
  • if (!Env.isConfigured): jika lupa --dart-define-from-file, aplikasi menampilkan petunjuk yang jelas, bukan error membingungkan dari Supabase.
  • AuthService(Supabase.instance.client) dibuat sesudah initialize selesai, lalu disuntikkan ke constructor AuthController.
  • Get.put(..., permanent: true) sebelum runApp mendaftarkan AuthController sebagai controller global. Saat itu juga onInit dijalankan sehingga langganan status login sudah aktif sebelum layar pertama tampil. permanent: true mencegah GetX menghapus controller ini ketika halaman ditutup. Di Modul 14, NotesController didaftarkan di tempat yang sama.
  • GetMaterialApp menggantikan MaterialApp agar fitur GetX seperti Get.to dan Get.back (dipakai di LoginView dan RegisterView) bisa berjalan. Parameter lain (title, theme, home) tetap sama.
  • ConfigErrorApp cukup memakai MaterialApp biasa karena tidak memakai controller maupun navigasi GetX.
