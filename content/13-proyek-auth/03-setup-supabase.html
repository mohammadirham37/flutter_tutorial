Aplikasi kita butuh tempat menyimpan data tambahan tentang user, misalnya nama lengkap. Tabel auth.users dikelola Supabase dan tidak bisa diakses langsung dari aplikasi, sehingga pola yang lazim adalah membuat tabel public.profiles yang barisnya dibuat otomatis oleh trigger setiap kali ada user baru.

Alur data saat register

Flutter: auth.signUp(email, password, data: {'full_name': 'Fikri Ramadhan'})
   │
   ▼
auth.users  ← baris baru, raw_user_meta_data = {"full_name": "Fikri Ramadhan"}
   │  (trigger on_auth_user_created: AFTER INSERT)
   ▼
public.profiles ← (id = id user baru, full_name = 'Fikri Ramadhan')

Langkah 1: Jalankan SQL berikut di SQL Editor

Buka SQL Editor → New query, tempel seluruh SQL di bawah, lalu klik Run. SQL ini aman dijalankan ulang karena memakai if not exists, drop ... if exists, dan create or replace.

📄 supabase/setup.sql

create table if not exists public.profiles (
  id uuid primary key references auth.users (id) on delete cascade,
  full_name text,
  created_at timestamptz not null default now()
);

alter table public.profiles enable row level security;

drop policy if exists "User melihat profilnya sendiri" on public.profiles;
create policy "User melihat profilnya sendiri"
on public.profiles for select
to authenticated
using ((select auth.uid()) = id);

drop policy if exists "User mengubah profilnya sendiri" on public.profiles;
create policy "User mengubah profilnya sendiri"
on public.profiles for update
to authenticated
using ((select auth.uid()) = id)
with check ((select auth.uid()) = id);

create or replace function public.handle_new_user()
returns trigger
language plpgsql
security definer
set search_path = ''
as $$
begin
  insert into public.profiles (id, full_name)
  values (new.id, new.raw_user_meta_data ->> 'full_name');
  return new;
end;
$$;

drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute procedure public.handle_new_user();

Penjelasan per bagian

KodePenjelasan
id uuid primary key references auth.users (id)id profil sama dengan id user (relasi satu-satu). on delete cascade: profil ikut terhapus jika akun dihapus.
enable row level securityMengunci tabel. Tanpa policy, tidak ada yang bisa membaca.
Policy select/update dengan (select auth.uid()) = idUser hanya bisa membaca dan mengubah profilnya sendiri. Tidak ada policy INSERT karena insert dilakukan oleh trigger, bukan oleh aplikasi.
returns triggerFungsi khusus yang dipanggil oleh trigger. Variabel new berisi baris yang baru dimasukkan ke auth.users.
security definerFungsi berjalan dengan hak pembuat fungsi (admin), bukan hak user. Ini perlu karena pada saat register user belum login, dan RLS profiles akan menolaknya.
set search_path = ''Praktik keamanan untuk fungsi security definer: semua nama tabel harus ditulis lengkap (public.profiles) sehingga tidak bisa "dibelokkan" ke tabel lain.
new.raw_user_meta_data ->> 'full_name'Operator ->> mengambil nilai dari kolom JSON sebagai teks. Isinya berasal dari parameter data di signUp().
after insert on auth.users for each rowTrigger dijalankan sekali untuk setiap user baru.

⚠️ Trigger error = register gagal

Jika fungsi trigger error (misalnya salah ketik nama tabel), seluruh proses register ikut dibatalkan dan aplikasi menerima pesan Database error saving new user. Jika itu terjadi, buka Logs → Postgres di dashboard untuk melihat detail error-nya.

Langkah 2: Atur konfirmasi email

  1. Buka Authentication → Sign In / Providers → Email.
  2. Untuk praktikum di kelas, matikan Confirm email agar register langsung login dan tidak terkena batas pengiriman email.
  3. Aplikasi yang kita buat tetap mendukung kedua mode: jika Confirm email aktif, RegisterScreen menampilkan dialog "Cek email Anda".

Langkah 3: Verifikasi

Setelah aplikasi selesai (section 8), register satu akun lalu buka Table Editor → profiles. Harus ada satu baris dengan full_name sesuai yang Anda isi. Akun yang sama juga terlihat di Authentication → Users.
