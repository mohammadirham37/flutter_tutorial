Sebelum menulis kode, kita sepakati dulu "denah rumah"-nya. Arsitektur yang rapi membuat kode mudah diuji, mudah dicari saat error, dan mudah dikembangkan.

Lapisan (layer) aplikasi: pola MVC dengan GetX

Proyek ini memakai pola MVC yang sudah dikenalkan di Modul 08: View menampilkan, Controller mengelola state dan logika, Model + lapisan data mengurus penyimpanan. Lapisan data dipecah lagi menjadi service (Auth) dan repository (catatan).

┌─────────────────────────────────────────────────────────────┐
│ VIEW (views/, widgets/)                                     │
│  LoginView, RegisterView, HomeView, NoteFormView            │
│  → hanya menampilkan state & meneruskan aksi user           │
└───────────────▲───────────────────────────┬─────────────────┘
     Obx (rebuild otomatis)                 │ controller.method()
┌───────────────┴───────────────────────────▼─────────────────┐
│ CONTROLLER (controllers/)                                   │
│  AuthController, NotesController (GetxController)           │
│  → isLoading, errorMessage, daftar data (.obs), pesan ramah │
└───────────────────────────┬─────────────────────────────────┘
                            │ memanggil
┌───────────────────────────▼─────────────────────────────────┐
│ DATA (services/, data/) + MODEL (models/)                   │
│  AuthService ─────────────▶ Supabase Auth                   │
│  NoteRepository ─┬─▶ NoteRemoteDataSource ─▶ Supabase (Postgres)
│                  └─▶ NoteLocalDataSource  ─▶ Hive (cache)   │
└─────────────────────────────────────────────────────────────┘
LapisanBoleh tahu tentangTidak boleh tahu tentang
ViewController, model, widgetSupabase, Hive, SQL
ControllerService/Repository, model, jenis exception, package:getWidget, BuildContext, SnackBar, navigasi
Service/RepositorySupabase client, Hive box, modelController, View, GetX

Aturan sederhananya: panah hanya ke bawah (View → Controller → Service → Model). Karena NoteRepository tidak mengenal View maupun GetX, kita bisa mengujinya dengan unit test tanpa emulator (dilakukan di Modul 14). Controller pun tidak menampilkan SnackBar atau berpindah halaman sendiri; ia cukup mengembalikan hasil (bool, enum, atau pesan error), lalu View yang memutuskan reaksinya.

ℹ️ Bagaimana View mendapatkan controller?

Lewat dependency injection GetX. Di main() kita mendaftarkan controller sekali dengan Get.put(AuthController(AuthService(...)), permanent: true). Halaman mana pun lalu mengambilnya dengan Get.find<AuthController>() atau dengan extends GetView<AuthController>. Service disuntikkan lewat constructor controller, sehingga saat testing kita bisa memberi service palsu.

  hive_ce_flutter: ^x.y.z

mkdir -p lib/config lib/models lib/services lib/data lib/controllers lib/views lib/widgets lib/utils
