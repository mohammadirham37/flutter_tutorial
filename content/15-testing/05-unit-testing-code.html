Debugging mencari bug yang sudah terjadi. Testing mencegah bug yang akan terjadi. Dengan test otomatis, setiap kali Anda mengubah kode, cukup jalankan satu perintah untuk memastikan fitur lama tidak rusak (regresi).

Struktur folder test

Semua test berada di folder test/ dan nama filenya wajib diakhiri _test.dart. Biasakan struktur folder test meniru folder lib/:

catatan_kuliah/
├── lib/
│   ├── utils/ipk.dart
│   ├── utils/validators.dart
│   └── models/keranjang_krs.dart
└── test/
    ├── unit/ipk_test.dart
    ├── unit/validators_test.dart
    └── unit/keranjang_krs_test.dart

Package flutter_test sudah otomatis ada di dev_dependencies proyek baru, jadi tidak perlu dipasang.

Test pertama: fungsi hitungIpk

Agar mudah diuji, letakkan logika di file terpisah di lib/, bukan di dalam widget:

📄 lib/utils/ipk.dart

// lib/utils/ipk.dart
double hitungIpk(List<int> bobot, List<int> sks) {
  if (bobot.length != sks.length) {
    throw ArgumentError('Jumlah bobot dan SKS harus sama');
  }
  if (bobot.isEmpty) return 0.0;

  var totalBobot = 0;
  var totalSks = 0;
  for (var i = 0; i < bobot.length; i++) {
    totalBobot += bobot[i] * sks[i];
    totalSks += sks[i];
  }
  return double.parse((totalBobot / totalSks).toStringAsFixed(2));
}

String predikat(double ipk) {
  if (ipk >= 3.51) return 'Dengan Pujian';
  if (ipk >= 3.01) return 'Sangat Memuaskan';
  if (ipk >= 2.76) return 'Memuaskan';
  return 'Cukup';
}

Lalu tulis test-nya. Ganti catatan_kuliah pada import dengan nama proyek Anda (baris name: di pubspec.yaml).

📄 test/unit/ipk_test.dart

// test/unit/ipk_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:catatan_kuliah/utils/ipk.dart';

void main() {
  group('hitungIpk', () {
    test('menghitung IPK normal dengan benar', () {
      // Arrange: siapkan data
      final bobot = [4, 4, 3, 4]; // A, A, B, A
      final sks = [3, 3, 3, 3];

      // Act: jalankan fungsi yang diuji
      final hasil = hitungIpk(bobot, sks);

      // Assert: periksa hasilnya
      expect(hasil, 3.75);
    });

    test('daftar kosong menghasilkan 0.0', () {
      expect(hitungIpk([], []), 0.0);
    });

    test('SKS berbeda ikut menjadi bobot', () {
      // (4 x 4 + 2 x 2) / 6 = 3.33
      expect(hitungIpk([4, 2], [4, 2]), 3.33);
    });
  });

  group('predikat', () {
    test('IPK 3.75 berpredikat Dengan Pujian', () {
      expect(predikat(3.75), 'Dengan Pujian');
    });

    test('batas bawah tiap predikat', () {
      expect(predikat(3.51), 'Dengan Pujian');
      expect(predikat(3.01), 'Sangat Memuaskan');
      expect(predikat(2.76), 'Memuaskan');
      expect(predikat(2.0), 'Cukup');
    });
  });
}

Penjelasan:

  • test('deskripsi', () { ... }) mendefinisikan satu kasus uji. Tulis deskripsi sebagai kalimat yang menjelaskan perilaku, karena kalimat inilah yang muncul saat test gagal.
  • expect(nilaiAktual, nilaiHarapan) adalah inti test. Jika keduanya berbeda, test gagal.
  • group() mengelompokkan test yang berkaitan. Nama grup ditambahkan di depan nama test pada laporan.
  • Pola Arrange-Act-Assert: siapkan data, jalankan fungsi, periksa hasil. Pola ini membuat test mudah dibaca.

setUp dan tearDown

Jika beberapa test membutuhkan objek yang sama, jangan membuatnya sekali di luar lalu dipakai bersama, karena perubahan di satu test akan bocor ke test lain. Gunakan setUp() yang dijalankan ulang sebelum setiap test.

📄 lib/models/keranjang_krs.dart

// lib/models/keranjang_krs.dart
class MataKuliah {
  final String kode;
  final String nama;
  final int sks;

  const MataKuliah(this.kode, this.nama, this.sks);
}

class KeranjangKrs {
  static const batasSks = 24;
  final List<MataKuliah> _items = [];

  List<MataKuliah> get items => List.unmodifiable(_items);
  int get totalSks => _items.fold(0, (total, mk) => total + mk.sks);

  void tambah(MataKuliah mk) {
    if (_items.any((item) => item.kode == mk.kode)) {
      throw StateError('${mk.nama} sudah ada di KRS');
    }
    if (totalSks + mk.sks > batasSks) {
      throw StateError('Total SKS melebihi $batasSks');
    }
    _items.add(mk);
  }

  void hapus(String kode) => _items.removeWhere((mk) => mk.kode == kode);

  void kosongkan() => _items.clear();
}

📄 test/unit/keranjang_krs_test.dart

// test/unit/keranjang_krs_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:catatan_kuliah/models/keranjang_krs.dart';

void main() {
  late KeranjangKrs keranjang;

  const mobile = MataKuliah('IF301', 'Pemrograman Mobile', 3);
  const basdat = MataKuliah('IF205', 'Basis Data', 4);

  // Dijalankan SEBELUM setiap test: keranjang selalu baru dan kosong
  setUp(() {
    keranjang = KeranjangKrs();
  });

  test('keranjang baru kosong', () {
    expect(keranjang.items, isEmpty);
    expect(keranjang.totalSks, 0);
  });

  test('menambah mata kuliah menambah total SKS', () {
    keranjang.tambah(mobile);
    keranjang.tambah(basdat);

    expect(keranjang.items, hasLength(2));
    expect(keranjang.totalSks, 7);
  });

  test('menghapus mata kuliah berdasarkan kode', () {
    keranjang.tambah(mobile);
    keranjang.hapus('IF301');

    expect(keranjang.items, isEmpty);
  });

  test('daftar items tidak bisa diubah dari luar', () {
    expect(() => keranjang.items.add(mobile), throwsUnsupportedError);
  });
}
  • late KeranjangKrs keranjang; dideklarasikan di luar, lalu diisi ulang di setUp. Test kedua tidak terpengaruh mata kuliah yang ditambahkan di test lain.
  • tearDown() adalah kebalikannya: dijalankan setelah setiap test, misalnya untuk menutup box Hive atau menghapus file sementara.
  • setUpAll()/tearDownAll() dijalankan sekali saja untuk seluruh file, cocok untuk pekerjaan mahal seperti membuka database tes.

Matcher: cara membandingkan yang lebih ekspresif

Argumen kedua expect bisa berupa nilai biasa atau matcher. Matcher membuat test lebih mudah dibaca dan pesan gagalnya lebih jelas.

📄 test/unit/matchers_test.dart

// test/unit/matchers_test.dart
import 'package:flutter_test/flutter_test.dart';

void main() {
  test('contoh matcher yang sering dipakai', () {
    final nilai = [80, 90, 75];
    const nama = 'Pemrograman Mobile';

    expect(nilai.length, equals(3)); // sama dengan 3
    expect(nilai, contains(90)); // list berisi 90
    expect(nilai, hasLength(3)); // panjang list 3
    expect(nilai, isNot(contains(100))); // TIDAK berisi 100
    expect(nama, startsWith('Pemrograman'));
    expect(nama, contains('Mobile'));
    expect(nama, isA<String>()); // bertipe String
    expect(0.1 + 0.2, closeTo(0.3, 0.0001)); // untuk angka desimal
    expect(85, greaterThan(80));
    expect(85, inInclusiveRange(80, 100));
    expect(<String>[], isEmpty);
    expect(nilai, everyElement(greaterThanOrEqualTo(75)));
    expect(nilai, orderedEquals([80, 90, 75]));
    expect(nilai, unorderedEquals([75, 80, 90]));
  });
}
MatcherLulus jika
equals(x) atau langsung xNilai sama dengan x (list dibandingkan isinya)
isTrue, isFalse, isNull, isNotNullSesuai namanya
isEmpty, isNotEmpty, hasLength(n)Untuk String, List, Map
contains(x)String memuat teks / List memuat elemen
isA<T>()Objek bertipe T
closeTo(x, delta)Angka desimal mendekati x
greaterThan, lessThan, inInclusiveRangePerbandingan angka
isNot(m)Kebalikan matcher m
throwsA(m), throwsArgumentError, throwsStateErrorFungsi melempar error (bagian berikutnya)

Contoh nyata: menguji validator form login

Validator yang dipakai form login di Modul 13 sebaiknya diletakkan di file sendiri agar bisa diuji tanpa UI:

📄 lib/utils/validators.dart

// lib/utils/validators.dart
final _polaEmail = RegExp(r'^[^@\s]+@[^@\s]+\.[^@\s]+$');

String? validasiEmail(String? value) {
  if (value == null || value.trim().isEmpty) return 'Email wajib diisi';
  if (!_polaEmail.hasMatch(value.trim())) return 'Format email tidak valid';
  return null;
}

String? validasiPassword(String? value) {
  if (value == null || value.isEmpty) return 'Password wajib diisi';
  if (value.length < 8) return 'Password minimal 8 karakter';
  return null;
}

📄 test/unit/validators_test.dart

// test/unit/validators_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:catatan_kuliah/utils/validators.dart';

void main() {
  group('validasiEmail', () {
    test('email kosong ditolak', () {
      expect(validasiEmail(''), 'Email wajib diisi');
      expect(validasiEmail(null), 'Email wajib diisi');
      expect(validasiEmail('   '), 'Email wajib diisi');
    });

    test('format salah ditolak', () {
      expect(validasiEmail('budi'), 'Format email tidak valid');
      expect(validasiEmail('budi@kampus'), 'Format email tidak valid');
    });

    test('email benar lolos (mengembalikan null)', () {
      expect(validasiEmail('budi@mhs.unsoed.ac.id'), isNull);
    });
  });

  group('validasiPassword', () {
    test('kurang dari 8 karakter ditolak', () {
      expect(validasiPassword('abc123'), contains('minimal 8'));
    });

    test('8 karakter atau lebih lolos', () {
      expect(validasiPassword('rahasia123'), isNull);
    });
  });
}

Perhatikan bahwa setiap aturan diuji dari dua sisi: kasus positif (input benar lolos) dan kasus negatif (input salah ditolak). Juga uji kasus batas: string berisi spasi saja, nilai null, panjang tepat 8 karakter.

⚠️ Kesalahan umum

  • Nama file tidak diakhiri _test.dart, sehingga flutter test tidak menemukannya.
  • Import memakai path relatif ke lib/ (import '../../lib/utils/ipk.dart'). Selalu gunakan package:nama_proyek/....
  • Membandingkan double dengan ==: 0.1 + 0.2 tidak sama persis dengan 0.3. Gunakan closeTo.
  • Satu test menguji terlalu banyak hal. Jika gagal, Anda sulit tahu bagian mana yang salah. Lebih baik banyak test kecil.
  • Test saling bergantung (test B hanya lulus jika test A dijalankan dulu). Gunakan setUp agar setiap test mulai dari kondisi bersih.
