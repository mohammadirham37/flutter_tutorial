Bug yang paling murah adalah bug yang tertangkap sebelum aplikasi dijalankan. Dart menyediakan analyzer yang membaca kode Anda dan melaporkan error, peringatan, dan saran gaya penulisan (lint). Biasakan menjalankan flutter analyze sebelum commit dan sebelum mengumpulkan tugas.

Menjalankan flutter analyze

# Dari folder root proyek
flutter analyze

# Hanya folder tertentu
flutter analyze lib/pages

Misalkan ada kode “gaya lama” seperti ini:

import 'package:flutter/material.dart';

class Contoh extends StatelessWidget {
  Contoh({Key? key}) : super(key: key);

  @override
  Widget build(BuildContext context) {
    var judul = 'Catatan';
    print(judul);
    return Container(
      child: Text(judul),
    );
  }
}

Hasil flutter analyze (output asli):

info • Constructors in '@immutable' classes should be declared as 'const' • lib/contoh.dart:4:3 • prefer_const_constructors_in_immutables
info • Parameter 'key' could be a super parameter • lib/contoh.dart:4:3 • use_super_parameters
info • Don't invoke 'print' in production code. Try using a logging framework • lib/contoh.dart:9:5 • avoid_print
info • Unnecessary instance of 'Container' • lib/contoh.dart:10:12 • avoid_unnecessary_containers

4 issues found.

Setiap baris berisi: tingkat (error, warning, info), pesan, lokasi (file:baris:kolom), dan nama aturan. Nama aturan bisa dicari di dart.dev/tools/linter-rules untuk penjelasan lengkap dan contoh.

Memperbaiki otomatis dengan dart fix

Banyak lint bisa diperbaiki otomatis. Lihat dulu apa yang akan diubah, baru terapkan:

# Pratinjau perubahan
dart fix --dry-run

# Terapkan semua perbaikan
dart fix --apply

# Rapikan format (indentasi, spasi, koma)
dart format lib test

Pada contoh di atas, dart fix --apply mengubah konstruktor menjadi const Contoh({super.key});. Lint avoid_print dan avoid_unnecessary_containers harus Anda perbaiki sendiri (ganti dengan debugPrint dan hapus Container).

Mengatur aturan di analysis_options.yaml

Proyek baru dari flutter create sudah memakai paket flutter_lints. Anda bisa menambah aturan yang lebih ketat atau menaikkan tingkat suatu aturan:

📄 analysis_options.yaml

include: package:flutter_lints/flutter.yaml

analyzer:
  errors:
    # Naikkan avoid_print dari info menjadi error
    avoid_print: error
  exclude:
    - "**/*.g.dart" # file hasil generator (misalnya adapter Hive)
    - build/**
    - android/**
    - ios/**
    - web/**
    - windows/**
    - macos/**
    - linux/**

linter:
  rules:
    prefer_single_quotes: true      # pakai 'kutip satu'
    prefer_final_locals: true       # variabel lokal yang tidak diubah wajib final
    always_declare_return_types: true
    unawaited_futures: true         # Future yang lupa di-await akan ditandai

Aturan unawaited_futures sangat berguna untuk aplikasi Supabase/Hive: ia menandai pemanggilan seperti repository.addNote(...) yang lupa diberi await, sehingga error-nya tidak tertangkap oleh try/catch.

Mengabaikan lint secara sengaja

Kadang ada alasan kuat untuk melanggar aturan. Abaikan hanya di baris itu dan tulis alasannya:

// Skrip seeding data hanya dijalankan developer dari terminal
// ignore: avoid_print
void cetakRingkasan(int jumlah) => print('Berhasil membuat $jumlah catatan');

Jangan menulis // ignore_for_file: di atas file hanya agar daftar issue terlihat bersih.

⚠️ Kesalahan umum

  • Mengabaikan semua info karena “cuma saran”. Lint seperti use_build_context_synchronously menandai bug sungguhan (memakai context setelah await tanpa cek mounted).
  • Menghapus baris include: package:flutter_lints/flutter.yaml agar warning hilang.
  • Menjalankan dart fix --apply tanpa commit terlebih dahulu. Jika hasilnya tidak sesuai, Anda tidak bisa kembali dengan mudah.
