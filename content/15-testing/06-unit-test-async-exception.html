Kode aplikasi nyata penuh dengan Future (ambil data dari Supabase, baca Hive) dan error (input tidak valid, koneksi putus). Bagian ini membahas cara menguji keduanya.

1. Menguji Future

Cara paling mudah: jadikan fungsi test async, lalu await hasilnya seperti di kode biasa. Alternatifnya, gunakan matcher completion().

📄 test/unit/async_test.dart

// test/unit/async_test.dart
import 'package:flutter_test/flutter_test.dart';

Future<String> ambilNamaMahasiswa(String nim) async {
  await Future.delayed(const Duration(milliseconds: 100));
  if (nim.isEmpty) throw ArgumentError('NIM kosong');
  return 'Budi Santoso';
}

Stream<int> hitungMundur(int dari) async* {
  for (var i = dari; i >= 0; i--) {
    yield i;
  }
}

void main() {
  test('cara 1: async/await di dalam test', () async {
    final nama = await ambilNamaMahasiswa('H1D021001');
    expect(nama, 'Budi Santoso');
  });

  test('cara 2: matcher completion', () {
    expect(ambilNamaMahasiswa('H1D021001'), completion('Budi Santoso'));
  });

  test('Future yang gagal diuji dengan expectLater + throwsA', () async {
    await expectLater(
      ambilNamaMahasiswa(''),
      throwsA(isA<ArgumentError>()),
    );
  });

  test('Stream mengeluarkan nilai berurutan', () {
    expect(hitungMundur(3), emitsInOrder([3, 2, 1, 0, emitsDone]));
  });
}

Penjelasan:

  • Cara 1 (async/await) paling mudah dibaca dan paling sering dipakai.
  • Cara 2 completion(x): test menunggu Future selesai lalu membandingkan hasilnya dengan x.
  • Untuk Future yang gagal, gunakan await expectLater(future, throwsA(...)). Kata await penting: tanpa itu test bisa selesai sebelum Future-nya gagal.
  • emitsInOrder menguji Stream: nilai apa saja yang keluar dan urutannya. emitsDone memastikan Stream sudah ditutup.

2. Menguji exception pada fungsi biasa

Test juga harus memastikan kode menolak input yang salah. Kuncinya: bungkus pemanggilan dengan () => agar expect yang menjalankan fungsinya dan menangkap error.

📄 test/unit/exception_test.dart

// test/unit/exception_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:catatan_kuliah/models/keranjang_krs.dart';
import 'package:catatan_kuliah/utils/ipk.dart';

void main() {
  test('hitungIpk melempar ArgumentError jika panjang list beda', () {
    // Bungkus pemanggilan dengan () => supaya error ditangkap oleh expect
    expect(() => hitungIpk([4, 3], [3]), throwsArgumentError);
  });

  test('menambah matkul yang sama dua kali melempar StateError', () {
    final keranjang = KeranjangKrs();
    const mk = MataKuliah('IF301', 'Pemrograman Mobile', 3);
    keranjang.tambah(mk);

    expect(() => keranjang.tambah(mk), throwsStateError);
  });

  test('pesan error melebihi 24 SKS bisa diperiksa', () {
    final keranjang = KeranjangKrs();
    for (var i = 0; i < 6; i++) {
      keranjang.tambah(MataKuliah('MK$i', 'Matkul $i', 4)); // 24 SKS
    }

    expect(
      () => keranjang.tambah(const MataKuliah('MK9', 'Matkul 9', 2)),
      throwsA(
        isA<StateError>().having(
          (e) => e.message,
          'message',
          contains('melebihi 24'),
        ),
      ),
    );
  });
}
  • throwsArgumentError, throwsStateError, throwsUnsupportedError, throwsException adalah matcher siap pakai untuk tipe error umum.
  • throwsA(isA<StateError>()) adalah bentuk umumnya, bisa dipakai untuk class exception buatan sendiri, misalnya throwsA(isA<AuthException>()).
  • .having((e) => e.message, 'message', contains(...)) memeriksa isi properti error. Berguna jika satu fungsi bisa melempar beberapa pesan berbeda.

Perbedaan kecil yang sering membuat bingung

3. Ringkasan pola test async dan error

Yang diujiPola
Future berhasilexpect(await f(), hasil)
Future gagalawait expectLater(f(), throwsA(isA<E>()))
Fungsi biasa melempar errorexpect(() => f(), throwsA(isA<E>()))
Streamexpect(stream, emitsInOrder([a, b, emitsDone]))
Fungsi TIDAK melempar errorexpect(() => f(), returnsNormally)

⚠️ Kesalahan umum

  • Lupa async pada fungsi test padahal di dalamnya ada await (error kompilasi), atau lupa await pada expectLater (test lulus palsu).
  • Memakai Future.delayed berdetik-detik di kode yang diuji. Test jadi lambat. Pada widget test, waktu bisa “dipercepat” dengan tester.pump(Duration).
  • Menguji fungsi yang langsung memanggil Supabase. Test menjadi lambat, butuh internet, dan mengotori database. Solusinya ada di bagian berikutnya: fake dan mock.
