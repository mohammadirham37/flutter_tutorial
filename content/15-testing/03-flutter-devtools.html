Flutter DevTools adalah kumpulan alat diagnostik berbasis web yang terhubung ke aplikasi yang sedang berjalan. Jika debugPrint dan breakpoint adalah “kaca pembesar”, DevTools adalah “ruang kontrol” yang menampilkan widget tree, waktu render tiap frame, lalu lintas jaringan, dan pemakaian memori.

1. Inspector: memeriksa widget tree dan layout

Inspector menampilkan pohon widget yang benar-benar sedang dirender. Fitur yang paling sering dipakai:

  • Select Widget Mode: klik ikon panah, lalu sentuh elemen di emulator. Inspector melompat ke widget tersebut dan VS Code membuka baris kodenya.
  • Layout Explorer: untuk Row/Column, menampilkan ukuran setiap anak, flex, dan alignment. Sangat membantu saat memperbaiki RenderFlex overflow.
  • Show Guidelines (debug paint): menggambar garis batas, padding, dan baseline semua widget di layar.

Debug paint juga bisa diaktifkan lewat kode, berguna jika DevTools belum terbuka:

📄 lib/main.dart

import 'package:flutter/material.dart';
import 'package:flutter/rendering.dart';

void main() {
  debugPaintSizeEnabled = true; // tampilkan garis batas semua widget
  runApp(
    const MaterialApp(
      home: Scaffold(
        body: Padding(
          padding: EdgeInsets.all(24),
          child: Row(
            children: [
              Icon(Icons.book),
              SizedBox(width: 8),
              Expanded(child: Text('Garis biru = batas widget')),
            ],
          ),
        ),
      ),
    ),
  );
}
debugPaintSizeEnabled: setiap widget digambar dengan garis batas, padding, dan arah layout

Jangan lupa menghapus baris debugPaintSizeEnabled = true setelah selesai.

2. Performance: mencari jank

Layar 60 Hz menggambar 60 frame per detik, artinya setiap frame punya jatah sekitar 16 ms. Jika satu frame butuh lebih lama, animasi terlihat patah-patah (jank). Penyebab paling umum: pekerjaan berat di dalam build().

// SALAH: perhitungan berat di dalam build() -> frame macet (jank)
int hitungPrimaSampai(int batas) {
  var jumlah = 0;
  for (var n = 2; n <= batas; n++) {
    var prima = true;
    for (var d = 2; d * d <= n; d++) {
      if (n % d == 0) {
        prima = false;
        break;
      }
    }
    if (prima) jumlah++;
  }
  return jumlah;
}

class StatistikSalah extends StatelessWidget {
  const StatistikSalah({super.key});

  @override
  Widget build(BuildContext context) {
    final jumlah = hitungPrimaSampai(5000000); // dihitung ulang tiap rebuild!
    return Text('Ada $jumlah bilangan prima');
  }
}

Di tab Performance, frame-frame yang lambat tampil sebagai batang merah. Klik batang tersebut untuk melihat bahwa hitungPrimaSampai menghabiskan ratusan milidetik di thread UI. Perbaikannya, pindahkan perhitungan ke isolate lain dengan Isolate.run dan simpan Future-nya di initState:

// BENAR: jalankan di isolate lain, hasilnya ditampilkan lewat FutureBuilder
class StatistikBenar extends StatefulWidget {
  const StatistikBenar({super.key});

  @override
  State<StatistikBenar> createState() => _StatistikBenarState();
}

class _StatistikBenarState extends State<StatistikBenar> {
  // Future dibuat SEKALI di initState, bukan di build()
  late final Future<int> _hasil;

  @override
  void initState() {
    super.initState();
    _hasil = Isolate.run(() => hitungPrimaSampai(5000000));
  }

  @override
  Widget build(BuildContext context) {
    return FutureBuilder<int>(
      future: _hasil,
      builder: (context, snapshot) {
        if (!snapshot.hasData) return const CircularProgressIndicator();
        return Text('Ada ${snapshot.data} bilangan prima');
      },
    );
  }
}

Ukur performa dengan mode profile, bukan debug. Mode debug sengaja lambat karena banyak pemeriksaan tambahan, sehingga hasilnya menyesatkan.

# Mode profile hanya berjalan di HP fisik atau emulator, tidak di web debug
flutter run --profile

Sebagai alternatif cepat tanpa DevTools, aktifkan grafik performa langsung di atas aplikasi:

class AppDenganOverlay extends StatelessWidget {
  const AppDenganOverlay({super.key});

  @override
  Widget build(BuildContext context) {
    return const MaterialApp(
      // Menampilkan grafik waktu frame (UI & raster) di atas aplikasi
      showPerformanceOverlay: true,
      home: Scaffold(body: Center(child: Text('Cek grafik di atas'))),
    );
  }
}
Performance overlay: grafik atas = thread raster (GPU), grafik bawah = thread UI. Garis horizontal menandai kelipatan 16 ms; penanda frame terbaru hijau jika di bawah batas dan merah jika melewatinya.

3. Network: memeriksa request HTTP

Tab Network mencatat setiap request yang dibuat dengan package:http, dio, maupun client Supabase. Untuk tiap request Anda bisa melihat:

  • Method dan URL lengkap (apakah query ?select=* sudah benar?).
  • Status code: 200 sukses, 401 belum login / token kedaluwarsa, 404 URL salah, 500 error server.
  • Header request (apakah header Authorization terkirim?) dan body response (JSON yang benar-benar dikirim server).
  • Durasi: request yang butuh 3 detik akan terasa lambat bagi pengguna.

Saat Catatan Kuliah gagal memuat data, buka tab ini sebelum menebak-nebak. Jika status 200 tetapi daftar tetap kosong, masalahnya ada di parsing JSON atau RLS, bukan koneksi.

4. Memory: mencari memory leak

Memory leak terjadi jika objek yang sudah tidak dipakai tetap tersimpan di RAM. Di Flutter, penyebab paling umum adalah controller yang tidak di-dispose():

class HalamanCari extends StatefulWidget {
  const HalamanCari({super.key});

  @override
  State<HalamanCari> createState() => _HalamanCariState();
}

class _HalamanCariState extends State<HalamanCari> {
  final _controller = TextEditingController();
  final _scrollController = ScrollController();

  @override
  void dispose() {
    // Tanpa dua baris ini, controller tetap tinggal di memori
    // setiap kali halaman dibuka-tutup (memory leak).
    _controller.dispose();
    _scrollController.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: TextField(controller: _controller)),
      body: ListView.builder(
        controller: _scrollController,
        itemCount: 100,
        itemBuilder: (context, i) => ListTile(title: Text('Hasil $i')),
      ),
    );
  }
}

Cara memeriksanya di tab Memory:

  1. Buka tab Memory, klik Take heap snapshot (snapshot A).
  2. Buka lalu tutup HalamanCari sebanyak 10 kali.
  3. Klik GC (paksa garbage collection), lalu ambil snapshot B.
  4. Bandingkan (Diff) snapshot B dengan A dan cari TextEditingController. Jika jumlahnya bertambah 10, ada leak.

Objek yang wajib di-dispose: TextEditingController, ScrollController, AnimationController, FocusNode, TabController, StreamSubscription (cancel), dan Timer (cancel).

⚠️ Kesalahan umum

  • Mengukur performa di mode debug lalu menyimpulkan “Flutter lambat”. Selalu ukur dengan flutter run --profile.
  • Membuat Future langsung di parameter FutureBuilder(future: ambilData()). Setiap rebuild memicu request baru; simpan Future di initState.
  • Lupa memanggil super.dispose() di akhir method dispose().
  • Membiarkan showPerformanceOverlay: true atau debugPaintSizeEnabled = true sampai build rilis.
