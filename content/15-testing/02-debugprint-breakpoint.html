Setelah tahu letak error, langkah berikutnya adalah memahami kenapa kode berperilaku salah. Ada dua cara: mencetak isi variabel ke console (logging), atau menghentikan aplikasi di baris tertentu lalu memeriksa semua variabel (breakpoint).

1. debugPrint: cara paling sederhana

print() memang bisa dipakai, tetapi lint bawaan Flutter (avoid_print) akan memberi peringatan. Gunakan debugPrint() dari package:flutter/foundation.dart. Bedanya, debugPrint membatasi kecepatan output sehingga log panjang tidak terpotong oleh Android.

import 'dart:developer' as developer;

import 'package:flutter/foundation.dart';
import 'package:flutter/material.dart';

class KeranjangDebug {
  final List<int> sks = [];

  void tambah(int nilaiSks) {
    debugPrint('tambah() dipanggil dengan sks=$nilaiSks');
    sks.add(nilaiSks);
    debugPrint('isi sekarang: $sks, total=${sks.fold(0, (a, b) => a + b)}');
  }
}

Output di Debug Console saat tambah(3) lalu tambah(4) dipanggil:

I/flutter ( 5123): tambah() dipanggil dengan sks=3
I/flutter ( 5123): isi sekarang: [3], total=3
I/flutter ( 5123): tambah() dipanggil dengan sks=4
I/flutter ( 5123): isi sekarang: [3, 4], total=7

Tulis log yang informatif: sebutkan nama fungsi dan nilai variabelnya, bukan sekadar debugPrint('masuk').

2. log dari dart:developer: log yang lebih terstruktur

developer.log() mendukung nama kategori (name), objek error, dan stack trace. Log ini tampil rapi di tab Logging DevTools dan bisa difilter berdasarkan nama.

Future<void> muatCatatan() async {
  developer.log('Mulai memuat catatan', name: 'catatan.repo');
  try {
    await Future.delayed(const Duration(seconds: 1));
    throw Exception('Timeout ke server');
  } catch (e, stackTrace) {
    developer.log(
      'Gagal memuat catatan',
      name: 'catatan.repo',
      error: e,
      stackTrace: stackTrace,
      level: 1000, // 1000 = SEVERE
    );
  }
}

Poin penting:

  • catch (e, stackTrace): parameter kedua menangkap stack trace, sehingga Anda tahu dari mana error berasal.
  • name: 'catatan.repo': kategori log. Di DevTools, ketik catatan di kolom filter untuk hanya melihat log ini.
  • level: 1000: tingkat keparahan (800 = INFO, 900 = WARNING, 1000 = SEVERE).

3. kDebugMode dan assert

Log dan pemeriksaan tambahan sebaiknya hanya aktif saat pengembangan. Flutter menyediakan konstanta kDebugMode dan pernyataan assert:

void catatDebug(String pesan) {
  // kDebugMode bernilai false di build release,
  // sehingga blok ini dibuang total oleh compiler.
  if (kDebugMode) {
    debugPrint('[DEBUG] $pesan');
  }
}

double hitungRataRata(List<int> nilai) {
  // assert hanya diperiksa di mode debug
  assert(nilai.isNotEmpty, 'List nilai tidak boleh kosong');
  return nilai.reduce((a, b) => a + b) / nilai.length;
}

assert sangat berguna untuk menangkap “hal yang seharusnya tidak pernah terjadi”. Di mode debug, hitungRataRata([]) langsung berhenti dengan pesan jelas, bukan menghasilkan NaN diam-diam.

4. Breakpoint di VS Code

Breakpoint menghentikan aplikasi tepat di satu baris sehingga Anda bisa melihat nilai semua variabel tanpa menulis debugPrint. Langkahnya:

  1. Jalankan aplikasi dengan mode debug: tekan F5 (atau menu Run → Start Debugging). Jangan pakai flutter run di terminal jika ingin breakpoint VS Code bekerja.
  2. Klik di sebelah kiri nomor baris sampai muncul titik merah.
  3. Lakukan aksi di aplikasi yang menjalankan baris tersebut. Aplikasi akan berhenti dan baris tersebut disorot kuning.
  4. Lihat panel Variables (nilai variabel lokal), Watch (ekspresi yang Anda pantau), dan Call Stack.
int hitungTotalSks(List<int> daftarSks) {
  var total = 0;
  for (final sks in daftarSks) {
    total += sks; // <- pasang breakpoint di baris ini (klik kiri nomor baris)
  }
  return total;
}

class TombolHitung extends StatelessWidget {
  const TombolHitung({super.key});

  @override
  Widget build(BuildContext context) {
    return FilledButton(
      onPressed: () {
        final total = hitungTotalSks([3, 4, 2, 3]);
        // Bisa juga berhenti lewat kode (hanya jika debugger terhubung)
        if (total > 10) developer.debugger(message: 'Total SKS > 10');
        ScaffoldMessenger.of(context).showSnackBar(
          SnackBar(content: Text('Total SKS: $total')),
        );
      },
      child: const Text('Hitung SKS'),
    );
  }
}

Saat berhenti di baris total += sks;, gunakan tombol kontrol debug:

TombolPintasanFungsi
ContinueF5Lanjut sampai breakpoint berikutnya
Step OverF10Jalankan baris ini, berhenti di baris berikutnya
Step IntoF11Masuk ke dalam fungsi yang dipanggil di baris ini
Step OutShift+F11Selesaikan fungsi saat ini, kembali ke pemanggil
RestartShift+Cmd/Ctrl+F5Hot restart aplikasi

Breakpoint bersyarat dan logpoint

Klik kanan titik merah lalu pilih Edit Breakpoint:

  • Expression: berhenti hanya jika kondisi benar, misalnya sks > 3. Berguna di dalam loop panjang.
  • Log Message (logpoint): tidak berhenti, hanya mencetak pesan seperti total sekarang {total}. Ini seperti debugPrint tanpa mengubah kode.

Konfigurasi launch.json

Jika aplikasi butuh argumen tambahan (misalnya file konfigurasi Supabase di Modul 16), buat .vscode/launch.json lewat menu Run → Add Configuration:

📄 .vscode/launch.json

{
  "version": "0.2.0",
  "configurations": [
    {
      "name": "Catatan Kuliah (debug)",
      "request": "launch",
      "type": "dart",
      "program": "lib/main.dart",
      "args": ["--dart-define-from-file=config/dev.json"]

    {
      "name": "Catatan Kuliah (profile)",
      "request": "launch",
      "type": "dart",
      "flutterMode": "profile",
      "args": ["--dart-define-from-file=config/dev.json"]
    }
  ]
}

⚠️ Kesalahan umum

  • Memasang breakpoint lalu menjalankan aplikasi dengan flutter run di terminal biasa. Debugger VS Code tidak terhubung, jadi aplikasi tidak pernah berhenti.
  • Meninggalkan puluhan debugPrint di kode yang dikumpulkan. Hapus atau bungkus dengan if (kDebugMode).
  • Mencetak data sensitif (password, token Supabase) ke log. Log Android bisa dibaca oleh siapa pun yang memegang HP lewat adb logcat.
  • Menulis catch (e) {} kosong. Error “tertelan” dan Anda tidak akan pernah tahu ada masalah. Minimal log errornya.
