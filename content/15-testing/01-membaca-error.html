Sebelum belajar alat debugging yang canggih, keterampilan paling penting adalah membaca pesan error. Hampir semua error Flutter sebenarnya sudah memberi tahu apa masalahnya, di file mana, dan sering kali juga cara memperbaikinya. Sayangnya, banyak mahasiswa langsung menyalin error ke mesin pencari tanpa membacanya.

Di mana error muncul?

  • Terminal / Debug Console VS Code: pesan lengkap beserta stack trace. Ini sumber informasi utama.
  • Layar aplikasi: pada mode debug, error saat build() menampilkan layar merah dengan teks kuning. Error layout menampilkan garis kuning-hitam.
  • Tab Problems VS Code: error kompilasi (salah tipe, salah nama) yang muncul sebelum aplikasi dijalankan.

Anatomi pesan error Flutter

Berikut contoh pesan asli yang muncul di Debug Console saat setState() dipanggil setelah halaman ditutup:

setState() called after dispose(): _ProfilSalahState#7b34c(lifecycle state: defunct, not mounted)

no longer appears in the widget tree ...

in the dispose() callback. Another solution is to check the "mounted" property of

When the exception was thrown, this was the stack:
#0      State.setState.<anonymous closure> (package:flutter/src/widgets/framework.dart:1163:9)
#1      State.setState (package:flutter/src/widgets/framework.dart:1200:6)
#2      _ProfilSalahState._muat (package:catatan_kuliah/demos/error_demos.dart:71:5)

Baca dengan urutan berikut:

  1. Judul (EXCEPTION CAUGHT BY ...): bagian Flutter mana yang menangkap error, misalnya WIDGETS LIBRARY (saat build) atau RENDERING LIBRARY (saat layout).
  2. Kalimat pertama: inti masalahnya. Di sini: setState() called after dispose().
  3. Paragraf penjelasan: Flutter sering langsung menyarankan solusi. Di sini: cek properti mounted.
  4. Stack trace: daftar pemanggilan fungsi, paling atas adalah yang terakhir dipanggil. Cari baris pertama yang berasal dari package proyek Anda (bukan package:flutter/). Pada contoh di atas itu baris #2: file error_demos.dart baris 71 kolom 5.

💡 Tips

Di Debug Console VS Code, nama file pada stack trace bisa di-klik (Cmd/Ctrl + klik) dan langsung membuka baris yang bermasalah.

Berikut lima error yang paling sering ditemui mahasiswa, lengkap dengan kode penyebab dan perbaikannya.

Error 1: A RenderFlex overflowed by ... pixels

Artinya: anak-anak Row/Column butuh ruang lebih besar daripada yang tersedia. Muncul garis kuning-hitam di sisi yang meluap.

// SALAH: teks panjang di dalam Row tidak punya batas lebar
class KartuMatkulSalah extends StatelessWidget {
  const KartuMatkulSalah({super.key});

  @override
  Widget build(BuildContext context) {
    return const Row(
      children: [
        Icon(Icons.book),
        SizedBox(width: 8),
        Text('Pemrograman Perangkat Bergerak Lanjut untuk Informatika Semester 5'),
      ],
    );
  }
}

Pesan di console: A RenderFlex overflowed by 173 pixels on the right. Perbaikannya, bungkus anak yang fleksibel dengan Expanded (atau Flexible) agar ukurannya mengikuti sisa ruang:

// BENAR: Expanded memberi Text sisa lebar yang tersedia
class KartuMatkulBenar extends StatelessWidget {
  const KartuMatkulBenar({super.key});

  @override
  Widget build(BuildContext context) {
    return const Row(
      children: [
        Icon(Icons.book),
        SizedBox(width: 8),
        Expanded(
          child: Text(
            'Pemrograman Perangkat Bergerak Lanjut untuk Informatika Semester 5',
            overflow: TextOverflow.ellipsis, // potong dengan "..."
          ),
        ),
      ],
    );
  }
}
Sebelum: teks meluap, muncul garis kuning-hitam di kanan
Sesudah: Expanded + TextOverflow.ellipsis

Untuk Column yang terlalu tinggi (misalnya form panjang saat keyboard muncul), solusinya biasanya membungkus Column dengan SingleChildScrollView.

Error 2: setState() called after dispose()

Artinya: proses async (ambil data, Future.delayed, timer) selesai setelah pengguna meninggalkan halaman, lalu kode mencoba memanggil setState() pada State yang sudah dibuang.

class ProfilSalah extends StatefulWidget {
  const ProfilSalah({super.key});

  @override
  State<ProfilSalah> createState() => _ProfilSalahState();
}

class _ProfilSalahState extends State<ProfilSalah> {
  String _nama = 'Memuat...';

  @override
  void initState() {
    super.initState();
    _muat();
  }

  Future<void> _muat() async {
    final nama = await ambilProfil(); // butuh 3 detik
    // Jika pengguna sudah menekan "Back" sebelum 3 detik,
    // State ini sudah di-dispose dan baris berikut memicu error.
    setState(() => _nama = nama);
  }

  @override
  Widget build(BuildContext context) => Text(_nama);
}

Perbaikannya: setiap kali ada await sebelum setState() atau sebelum memakai context, cek mounted dulu.

class ProfilBenar extends StatefulWidget {
  const ProfilBenar({super.key});

  @override
  State<ProfilBenar> createState() => _ProfilBenarState();
}

class _ProfilBenarState extends State<ProfilBenar> {
  String _nama = 'Memuat...';

  @override
  void initState() {
    super.initState();
    _muat();
  }

  Future<void> _muat() async {
    final nama = await ambilProfil();
    if (!mounted) return; // widget sudah tidak ada di layar, berhenti
    setState(() => _nama = nama);
  }

  @override
  Widget build(BuildContext context) => Text(_nama);
}

Untuk Timer dan StreamSubscription, batalkan di dispose() dengan timer.cancel() atau subscription.cancel().

Error 3: Null check operator used on a null value

Artinya: Anda memakai operator ! (“saya jamin tidak null”) pada nilai yang ternyata null. Ini error paling sering di aplikasi yang membaca data dari API atau database.

class KartuEmail extends StatelessWidget {
  const KartuEmail({super.key, this.mahasiswa});

  final Mahasiswa? mahasiswa;

  @override
  Widget build(BuildContext context) {
    // SALAH: crash jika mahasiswa atau email-nya null
    // return Text(mahasiswa!.email!);

    // BENAR 1: beri nilai cadangan dengan ?. dan ??
    final email = mahasiswa?.email ?? 'Email belum diisi';

    // BENAR 2: simpan ke variabel lokal, lalu cek null secara eksplisit
    final mhs = mahasiswa;
    if (mhs == null) {
      return const Text('Data mahasiswa tidak ditemukan');
    }
    return Text('${mhs.nama} - $email'); // mhs sudah pasti tidak null
  }
}
Versi salah (mahasiswa!.email!): layar merah di mode debug
Versi benar: email null diganti teks cadangan

Di build release, layar merah ini berubah menjadi area abu-abu kosong. Pengguna tidak melihat pesan apa pun, jadi bug seperti ini harus ditemukan saat debug atau lewat test.

Error 4: Vertical viewport was given unbounded height

Artinya: widget yang bisa di-scroll (ListView, GridView) diletakkan di dalam widget yang tidak membatasi tingginya (Column, atau ListView lain). ListView ingin setinggi mungkin, Column memberi tinggi tak terbatas, sehingga Flutter bingung.

// SALAH: ListView di dalam Column -> "Vertical viewport was given unbounded height"
class DaftarSalah extends StatelessWidget {
  const DaftarSalah({super.key});

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        const Text('Daftar Catatan'),
        ListView.builder(
          itemCount: 20,
          itemBuilder: (context, i) => ListTile(title: Text('Catatan $i')),
        ),
      ],
    );
  }
}

Pesan di console menunjuk langsung ke ListView yang bermasalah (The relevant error-causing widget was: ListView ...error_demos.dart:147:18). Perbaikannya:

// BENAR: Expanded memberi ListView tinggi = sisa ruang Column
class DaftarBenar extends StatelessWidget {
  const DaftarBenar({super.key});

  @override
  Widget build(BuildContext context) {
    return Column(
      children: [
        const Text('Daftar Catatan'),
        Expanded(
          child: ListView.builder(
            itemCount: 20,
            itemBuilder: (context, i) => ListTile(title: Text('Catatan $i')),
          ),
        ),
      ],
    );
  }
}
Sebelum: halaman kosong, error hanya terlihat di console
Sesudah: ListView dibungkus Expanded

Alternatif lain adalah ListView(shrinkWrap: true, physics: NeverScrollableScrollPhysics()), tetapi ini hanya cocok untuk daftar pendek karena semua item dibangun sekaligus.

Error 5: Could not find the correct Provider<T> above this Widget

Artinya: widget memanggil context.watch<T>() atau context.read<T>(), tetapi tidak ada Provider<T> di atasnya pada widget tree. Penyebab paling umum: provider dipasang di dalam satu halaman, lalu halaman lain yang dibuka dengan Navigator.push mencoba membacanya.

// SALAH: provider dipasang DI BAWAH MaterialApp, hanya untuk HalamanA.
// Halaman yang dibuka lewat Navigator.push tidak bisa melihatnya.
class AppSalah extends StatelessWidget {
  const AppSalah({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      home: ChangeNotifierProvider(
        create: (_) => CounterProvider(),
        child: const HalamanA(),
      ),
    );
  }
}

Halaman baru dari Navigator.push adalah “saudara” HalamanA di bawah MaterialApp, bukan anaknya, sehingga tidak bisa melihat provider tersebut. Pindahkan provider ke atas MaterialApp:

// BENAR: provider membungkus MaterialApp sehingga semua route bisa membacanya
class AppBenar extends StatelessWidget {
  const AppBenar({super.key});

  @override
  Widget build(BuildContext context) {
    return ChangeNotifierProvider(
      create: (_) => CounterProvider(),
      child: const MaterialApp(home: HalamanA()),
    );
  }
}
AppSalah: setelah membuka Halaman B, pesan error lengkap dengan daftar penyebab
AppBenar: Halaman B bisa membaca CounterProvider

Penyebab lain: lupa memberi tipe generik (context.read() tanpa <CounterProvider>), atau menambah provider baru di main.dart lalu hanya melakukan hot reload. Untuk kasus terakhir, lakukan hot restart (Shift+R atau tombol restart di VS Code).

⚠️ Kesalahan umum

  • Hanya membaca baris terakhir error, padahal inti masalah ada di kalimat pertama.
  • Mencari penyebab di file framework.dart. Baris dari package:flutter/ hampir tidak pernah salah; cari baris pertama dari proyek Anda.
  • Menambahkan ! di mana-mana agar error merah di editor hilang. Ini hanya memindahkan error dari waktu kompilasi ke waktu aplikasi berjalan.
  • Memperbaiki overflow dengan mengecilkan font. Di HP lain dengan layar lebih kecil, error akan muncul lagi.
