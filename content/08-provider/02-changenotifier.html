ChangeNotifier adalah class bawaan Flutter (bukan dari package provider) yang bisa "mengabari" siapa saja yang mendengarkan ketika datanya berubah. Inilah pondasi Provider.

Empat langkah membuat ChangeNotifier

  1. Buat class yang extends ChangeNotifier.
  2. Simpan state di field privat (diawali _).
  3. Sediakan getter untuk membaca state.
  4. Sediakan method untuk mengubah state, dan panggil notifyListeners() di akhir.

Contoh kecil: tanpa UI sama sekali

import 'package:flutter/foundation.dart';

class CounterModel extends ChangeNotifier {
  int _nilai = 0; // 1. state disimpan privat

  int get nilai => _nilai; // 2. dibaca lewat getter

  void tambah() {
    _nilai++; // 3. ubah state
    notifyListeners(); // 4. kabari semua pendengar
  }
}

void main() {
  final counter = CounterModel();

  // Daftarkan "pendengar": fungsi yang dipanggil setiap notifyListeners()
  counter.addListener(() {
    debugPrint('Nilai berubah menjadi ${counter.nilai}');
  });

  counter.tambah(); // Nilai berubah menjadi 1
  counter.tambah(); // Nilai berubah menjadi 2
}
  • addListener mendaftarkan fungsi yang akan dipanggil setiap notifyListeners().
  • Dari luar class, _nilai tidak bisa diubah langsung. Satu-satunya jalan adalah lewat tambah(). Ini menjaga aturan bisnis tetap di satu tempat.

Contoh lengkap: menghubungkan ke UI dengan ListenableBuilder

Sebelum memakai package provider, mari lihat bahwa ChangeNotifier sudah bisa dipakai dengan widget bawaan ListenableBuilder.

📄 lib/main.dart

// lib/main.dart — salin SELURUH kode ini untuk menggantikan isi lib/main.dart
// ChangeNotifier TANPA package provider, memakai ListenableBuilder bawaan Flutter
import 'package:flutter/material.dart';

class CounterModel extends ChangeNotifier {
  int _nilai = 0;
  int get nilai => _nilai;

  void tambah() {
    _nilai++;
    notifyListeners();
  }

  void reset() {
    _nilai = 0;
    notifyListeners();
  }
}

// Satu objek model untuk seluruh aplikasi (sementara, sebelum pakai Provider)
final counter = CounterModel();

void main() {
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const CounterPage(),
    );
  }
}

// Perhatikan: StatelessWidget, tidak ada setState sama sekali
class CounterPage extends StatelessWidget {
  const CounterPage({super.key});

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('ChangeNotifier dari Nol')),
      body: Center(
        // ListenableBuilder = addListener + rebuild otomatis
        child: ListenableBuilder(
          listenable: counter,
          builder: (context, child) {
            return Text(
              'Jumlah klik: ${counter.nilai}',
              style: Theme.of(context).textTheme.headlineMedium,
            );
          },
        ),
      ),
      floatingActionButton: Row(
        mainAxisSize: MainAxisSize.min,
        children: [
          FloatingActionButton(
            heroTag: 'reset',
            tooltip: 'Reset',
            onPressed: counter.reset,
            child: const Icon(Icons.refresh),
          ),
          const SizedBox(width: 12),
          FloatingActionButton(
            heroTag: 'tambah',
            tooltip: 'Tambah',
            onPressed: counter.tambah,
            child: const Icon(Icons.add),
          ),
        ],
      ),
    );
  }
}
Tiga kali Tambah tanpa setState

Penjelasan:

  • CounterPage adalah StatelessWidget, tetapi angkanya tetap berubah. Yang memicu rebuild adalah ListenableBuilder, bukan setState.
  • Hanya bagian di dalam builder yang di-build ulang. AppBar dan tombol tidak ikut.
  • Kelemahan contoh ini: counter adalah variabel global. Sulit diganti saat testing, dan tidak pernah di-dispose. Package provider menyelesaikan kedua masalah ini.

⚠️ Kesalahan umum

  • Lupa notifyListeners(). Data berubah di memori, tetapi layar tidak berubah sama sekali.
  • Memanggil notifyListeners() di dalam getter. Getter hanya membaca; memanggil notify di sana menyebabkan rebuild tanpa henti.
  • Membuat field publik (int nilai = 0;) lalu mengubahnya dari UI: model.nilai++. Tidak ada yang memanggil notify, dan aturan bisnis tersebar di UI.
