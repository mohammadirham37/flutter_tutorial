Kadang satu provider butuh data dari provider lain. Contoh: daftar catatan bergantung pada siapa yang sedang login. ChangeNotifierProxyProvider menyambungkan keduanya: setiap kali provider sumber berubah, provider tujuan diberi tahu.

Bentuk umumnya

ChangeNotifierProxyProvider<Sumber, Tujuan>(
  create: (_) => Tujuan(),                                  // dibuat sekali
  update: (_, sumber, tujuan) => tujuan!..perbarui(sumber), // dipanggil tiap Sumber berubah
)

Contoh lengkap: catatan per pengguna

📄 lib/main.dart

// lib/main.dart — salin SELURUH kode ini untuk menggantikan isi lib/main.dart
import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

class AuthProvider extends ChangeNotifier {
  String? _nim;
  String? get nim => _nim;

  void loginSebagai(String nim) {
    _nim = nim;
    notifyListeners();
  }
}

// CatatanProvider BERGANTUNG pada AuthProvider: catatan milik siapa?
class CatatanProvider extends ChangeNotifier {
  String? _nimAktif;
  final Map<String, List<String>> _catatanPerNim = {};

  List<String> get catatan => _catatanPerNim[_nimAktif] ?? const [];

  // Dipanggil oleh ProxyProvider setiap AuthProvider berubah
  void perbaruiPengguna(String? nim) {
    if (nim == _nimAktif) return;
    _nimAktif = nim;
    notifyListeners();
  }

  void tambah(String teks) {
    final nim = _nimAktif;
    if (nim == null) return;
    _catatanPerNim.putIfAbsent(nim, () => []).add(teks);
    notifyListeners();
  }
}

void main() {
  runApp(
    MultiProvider(
      providers: [
        // 1. Provider yang menjadi sumber harus didaftarkan LEBIH DULU
        ChangeNotifierProvider(create: (_) => AuthProvider()),
        // 2. ProxyProvider: <Sumber, Hasil>
        ChangeNotifierProxyProvider<AuthProvider, CatatanProvider>(
          create: (_) => CatatanProvider(),
          // update dipanggil di awal dan setiap AuthProvider notifyListeners
          update: (_, auth, catatan) => catatan!..perbaruiPengguna(auth.nim),
        ),
      ],
      child: const MyApp(),
    ),
  );
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.purple),
      home: const CatatanPage(),
    );
  }
}

class CatatanPage extends StatelessWidget {
  const CatatanPage({super.key});

  @override
  Widget build(BuildContext context) {
    final nim = context.watch<AuthProvider>().nim;
    final catatan = context.watch<CatatanProvider>().catatan;

    return Scaffold(
      appBar: AppBar(title: Text('Catatan milik: ${nim ?? '-'}')),
      body: Column(
        children: [
          Padding(
            padding: const EdgeInsets.all(12),
            child: Wrap(
              spacing: 8,
              children: [
                for (final n in ['H1D023001', 'H1D023002'])
                  ChoiceChip(
                    label: Text(n),
                    selected: nim == n,
                    onSelected: (_) => context.read<AuthProvider>().loginSebagai(n),
                  ),
              ],
            ),
          ),
          Expanded(
            child: ListView(
              children: [for (final c in catatan) ListTile(title: Text(c))],
            ),
          ),
        ],
      ),
      floatingActionButton: FloatingActionButton.extended(
        icon: const Icon(Icons.add),
        label: const Text('Tambah Catatan'),
        onPressed: nim == null
            ? null
            : () {
                final prov = context.read<CatatanProvider>();
                prov.tambah('Catatan ke-${prov.catatan.length + 1}');
              },
      ),
    );
  }
}
Catatan milik H1D023001
Ganti pengguna: CatatanProvider ikut diperbarui

Penjelasan:

  • AuthProvider wajib didaftarkan sebelum ProxyProvider yang membutuhkannya.
  • update menerima objek CatatanProvider yang sudah ada (catatan!) dan hanya memperbarui NIM-nya. Objek tidak dibuat ulang, jadi catatan yang tersimpan tidak hilang.
  • Di perbaruiPengguna, if (nim == _nimAktif) return; mencegah notify yang tidak perlu.
  • Pilih NIM pertama, tambah dua catatan, lalu pilih NIM kedua: daftar kosong. Kembali ke NIM pertama: dua catatan muncul lagi.

ℹ️ Seberapa sering dipakai?

Untuk proyek kuliah, ProxyProvider jarang wajib. Alternatif yang lebih sederhana: panggil context.read<CatatanProvider>().perbaruiPengguna(nim) tepat setelah login berhasil. Namun mengenal ProxyProvider membantu saat membaca kode proyek orang lain.

⚠️ Kesalahan umum

  • Membuat objek baru di update: update: (_, auth, __) => CatatanProvider(). Semua data hilang setiap kali auth berubah.
  • Urutan provider terbalik (ProxyProvider di atas AuthProvider) sehingga muncul ProviderNotFoundException.
