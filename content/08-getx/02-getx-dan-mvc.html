GetX (package get) adalah library Flutter yang menyediakan state management, dependency injection, dan navigasi dalam satu paket. Di kursus ini GetX selalu dipakai bersama pola MVC agar kode tetap rapi meskipun aplikasi membesar.

Tiga pilar GetX

PilarFungsinyaAPI yang akan sering dipakai
State managementMenyimpan state di controller dan membangun ulang UI ketika state berubahGetxController, .obs, Obx, GetBuilder + update()
Dependency managementMendaftarkan objek sekali lalu mengambilnya dari mana saja, tanpa constructor berantaiGet.put, Get.find, Get.lazyPut, Bindings
Route managementBerpindah halaman tanpa perlu BuildContextGet.to, Get.back, Get.off, Get.toNamed

Ketiganya bisa dipakai terpisah. Fokus modul ini adalah dua pilar pertama; navigasi GetX cukup dipakai seperlunya (Get.to dan Get.back).

Pola MVC: membagi tanggung jawab

MVC membagi kode menjadi tiga bagian dengan tugas yang jelas:

BagianTanggung jawabBoleh mengimporContoh
ModelBentuk data dan aturan kecil yang melekat pada data (mis. toJson, getter turunan)Dart murni sajaMataKuliah, Tugas, Mahasiswa
ViewMenampilkan state dan meneruskan aksi pengguna ke controller. Juga urusan tampilan: SnackBar, dialog, navigasimaterial.dart, get.dart, controllerKatalogKrsView, LoginView
ControllerMenyimpan state (reaktif), menjalankan logika bisnis, memanggil serviceget.dart, foundation.dart, model, serviceKrsController, AuthController

Untuk akses data (HTTP, database, Hive, Supabase) kita menambahkan satu lapisan lagi, yaitu Service. Arah ketergantungannya selalu satu arah:

View  ──►  Controller  ──►  Service  ──►  Model
(UI)       (state+logika)    (ambil/simpan data)  (bentuk data)

View mengenal Controller, Controller mengenal Service,
tetapi TIDAK sebaliknya: Controller tidak pernah mengimpor View.

Aturan penting: controller tanpa UI

Di kursus ini controller tidak mengimpor package:flutter/material.dart, tidak menyimpan BuildContext, dan tidak menampilkan SnackBar, dialog, atau berpindah halaman. Controller cukup mengembalikan hasil (misalnya bool atau pesan error), lalu View yang memutuskan cara menampilkannya.

// Controller: hanya mengembalikan hasil
bool tambahMatkul(MataKuliah mk) {
  if (totalSks + mk.sks > 24) return false;
  _matkul.add(mk);
  return true;
}

// View: memutuskan bagaimana memberi tahu pengguna
onPressed: () {
  if (!controller.tambahMatkul(mk)) {
    ScaffoldMessenger.of(context).showSnackBar(
      const SnackBar(content: Text('Kuota SKS penuh')),
    );
  }
},

Alasannya: controller yang bebas dari widget bisa di-unit test dengan Dart biasa, tanpa memompa widget dan tanpa emulator (dibahas di Modul 15). Selain itu, satu controller bisa dipakai beberapa View yang cara menampilkan pesannya berbeda.

ℹ️ Bagaimana dengan Get.snackbar?

GetX sebenarnya mengizinkan Get.snackbar(...), Get.dialog(...), dan Get.to(...) dipanggil langsung dari controller karena tidak butuh BuildContext. Kursus ini sengaja tidak melakukannya agar pemisahan tanggung jawab tetap jelas dan controller mudah diuji. Pemanggilan seperti itu kita letakkan di View.

Instalasi

flutter pub add get

Lalu impor di file yang membutuhkannya:

import 'package:get/get.dart';

GetMaterialApp

Ganti MaterialApp dengan GetMaterialApp. Parameternya sama (home, theme, debugShowCheckedModeBanner, dan seterusnya), ditambah fitur GetX seperti initialBinding dan getPages. GetMaterialApp wajib dipakai jika Anda memakai navigasi GetX (Get.to, Get.back) atau Get.snackbar.

return GetMaterialApp(
  debugShowCheckedModeBanner: false,
  theme: ThemeData(colorSchemeSeed: Colors.teal),
  home: const CounterView(),
);

Contoh lengkap: counter dengan pola MVC

Agar mudah dicoba, Model, Controller, dan View ditulis dalam satu file dan dipisahkan dengan komentar. Di section 6 kita memecahnya menjadi beberapa file sesuai folder MVC. Jangan khawatir dulu tentang .obs dan Obx; keduanya dibahas tuntas di section 3.

📄 lib/main.dart

// lib/main.dart — salin SELURUH kode ini untuk menggantikan isi lib/main.dart
// Pastikan sudah: flutter pub add get
import 'package:flutter/material.dart';
import 'package:get/get.dart';

// ================== MODEL ==================
// Data murni: tidak mengimpor Flutter maupun GetX.
class Hitungan {
  final int nilai;
  final int batas;

  const Hitungan({this.nilai = 0, this.batas = 10});

  bool get penuh => nilai >= batas;

  Hitungan tambahSatu() => Hitungan(nilai: nilai + 1, batas: batas);
}

// ================ CONTROLLER ================
// State + logika. Tidak memakai widget, BuildContext, atau SnackBar.
class CounterController extends GetxController {
  final hitungan = const Hitungan().obs; // state reaktif (dibahas di section 3)

  /// Mengembalikan false jika batas sudah tercapai. View yang memutuskan
  /// bagaimana memberi tahu pengguna.
  bool tambah() {
    if (hitungan.value.penuh) return false;
    hitungan.value = hitungan.value.tambahSatu();
    return true;
  }

  void reset() => hitungan.value = const Hitungan();
}

// =================== VIEW ===================
void main() {
  Get.put(CounterController()); // daftarkan controller sekali
  runApp(const MyApp());
}

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    // GetMaterialApp = MaterialApp + fitur GetX (navigasi, binding, dll)
    return GetMaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const CounterView(),
    );
  }
}

class CounterView extends StatelessWidget {
  const CounterView({super.key});

  @override
  Widget build(BuildContext context) {
    final c = Get.find<CounterController>(); // ambil controller

    return Scaffold(
      appBar: AppBar(title: const Text('Counter MVC dengan GetX')),
      body: Center(
        // Obx: bagian ini dibangun ulang otomatis saat hitungan berubah
        child: Obx(() {
          final h = c.hitungan.value;
          return Column(
            mainAxisSize: MainAxisSize.min,
            children: [
              Text(
                '${h.nilai} / ${h.batas}',
                style: Theme.of(context).textTheme.displayMedium,
              ),
              const SizedBox(height: 8),
              Text(h.penuh ? 'Batas tercapai' : 'Masih bisa ditambah'),
            ],
          );
        }),
      ),
      floatingActionButton: Row(
        mainAxisSize: MainAxisSize.min,
        children: [
          FloatingActionButton(
            heroTag: 'reset',
            tooltip: 'Reset',
            onPressed: c.reset,
            child: const Icon(Icons.refresh),
          ),
          const SizedBox(width: 12),
          FloatingActionButton(
            heroTag: 'tambah',
            tooltip: 'Tambah',
            onPressed: () {
              final berhasil = c.tambah();
              if (!berhasil) {
                // Urusan tampilan (SnackBar) tetap di View
                ScaffoldMessenger.of(context).showSnackBar(
                  const SnackBar(content: Text('Sudah mencapai batas 10')),
                );
              }
            },
            child: const Icon(Icons.add),
          ),
        ],
      ),
    );
  }
}
Setelah tiga kali Tambah, tanpa setState

Penjelasan:

  • Model Hitungan hanya berisi data dan aturan kecil (penuh, tambahSatu). Ia tidak tahu apa-apa tentang Flutter.
  • Controller CounterController menyimpan state hitungan dan memutuskan boleh/tidaknya menambah. Method tambah() mengembalikan bool, bukan menampilkan SnackBar.
  • View CounterView adalah StatelessWidget. Ia mengambil controller dengan Get.find, menampilkan state di dalam Obx, dan menampilkan SnackBar saat tambah() mengembalikan false.
  • Get.put(CounterController()) di main() mendaftarkan controller sekali sebelum aplikasi berjalan. Cara lain mendaftarkan controller dibahas di section 4.

⚠️ Kesalahan umum

  • Tetap memakai MaterialApp lalu memanggil Get.to atau Get.snackbar. Navigasi dan snackbar GetX butuh GetMaterialApp.
  • Mengimpor material.dart di controller supaya bisa memanggil showSnackBar atau menyimpan BuildContext. Kembalikan hasil saja, biarkan View yang menampilkan.
  • Menaruh logika bisnis di onPressed View (misalnya cek batas di tombol). Jika ada dua tombol di dua halaman, aturannya harus ditulis dua kali.
