Semakin besar aplikasi, semakin penting memisahkan kode berdasarkan tanggung jawabnya. Struktur MVC berikut sederhana, cukup untuk proyek kuliah, dan dipakai lagi di proyek CRUD + Auth (Modul 13–14).

lib/
├── main.dart              # runApp(GetMaterialApp(...)) + initialBinding
├── models/                # M: class data murni (User, Mahasiswa, Todo)
├── services/              # akses data: HTTP, database, Supabase, Hive
├── controllers/           # C: GetxController, state reaktif + logika bisnis

├── views/                 # V: halaman penuh, file xxx_view.dart, class XxxView

Arah ketergantungan: View → Controller → Service → Model. Panah hanya menunjuk satu arah: controller tidak boleh tahu tentang View. Itulah sebabnya controller tidak menampilkan SnackBar atau bernavigasi sendiri. Controller mengembalikan hasil (bool, pesan error), lalu View yang memutuskan reaksinya.

ℹ️ "Tapi GetX bisa Get.snackbar dari controller..."

Benar. Karena Get.snackbar, Get.to, dan Get.back tidak butuh BuildContext, GetX sebenarnya mengizinkan semua itu dipanggil dari controller. Kursus ini sengaja tidak melakukannya. Controller yang bebas UI bisa diuji dengan unit test biasa tanpa widget (Modul 15), dan logikanya bisa dipakai ulang oleh View yang berbeda.

Contoh lengkap: Auth gate dengan GetX

Auth gate adalah widget yang memilih menampilkan LoginView atau HomeView berdasarkan status sesi di AuthController. Login dan logout tidak memerlukan Get.to atau Get.off sama sekali.

import '../models/user.dart';

class AuthService {
  Future<User> login(String email, String password) async {
    await Future.delayed(const Duration(seconds: 1));
    if (password != '123456') {
      throw Exception('Email atau password salah');
    }
    return User(email: email, nama: email.split('@').first);
  }

  Future<void> logout() async {
    await Future.delayed(const Duration(milliseconds: 300));
  }
}

📄 lib/controllers/auth_controller.dart

// lib/controllers/auth_controller.dart
// Controller TIDAK mengimpor material.dart dan tidak memegang BuildContext.
import 'package:get/get.dart';

import '../models/user.dart';
import '../services/auth_service.dart';

class AuthController extends GetxController {
  AuthController(this._service);

  final AuthService _service;

  final _user = Rxn<User>(); // null = belum login
  final _isLoading = false.obs;
  final _error = RxnString();

  User? get user => _user.value;
  bool get isLoggedIn => _user.value != null;
  bool get isLoading => _isLoading.value;
  String? get error => _error.value;

  /// Mengembalikan true jika berhasil. View yang memutuskan cara
  /// menampilkan kegagalan (SnackBar, dialog, dll).
  Future<bool> login(String email, String password) async {
    _isLoading.value = true;
    _error.value = null;
    try {
      _user.value = await _service.login(email, password);
      return true;
    } catch (e) {
      _error.value = e.toString().replaceFirst('Exception: ', '');
      return false;
    } finally {
      _isLoading.value = false;
    }
  }

  Future<void> logout() async {
    await _service.logout();
    _user.value = null;
  }
}

📄 lib/views/login_view.dart

// lib/views/login_view.dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/auth_controller.dart';

// StatefulWidget karena TextEditingController adalah state LOKAL form ini
class LoginView extends StatefulWidget {
  const LoginView({super.key});

  @override
  State<LoginView> createState() => _LoginViewState();
}

class _LoginViewState extends State<LoginView> {
  final _auth = Get.find<AuthController>();
  final _emailController = TextEditingController(text: 'andi@mhs.unsoed.ac.id');
  final _passwordController = TextEditingController();

  @override
  void dispose() {
    _emailController.dispose();
    _passwordController.dispose();
    super.dispose();
  }

  Future<void> _login() async {
    FocusScope.of(context).unfocus(); // tutup keyboard
    final berhasil = await _auth.login(
      _emailController.text.trim(),
      _passwordController.text,
    );
    // Jika berhasil, AuthGate otomatis menampilkan HomeView.
    if (!berhasil && mounted) {
      ScaffoldMessenger.of(context).showSnackBar(
        SnackBar(content: Text(_auth.error ?? 'Login gagal')),
      );
    }
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Login')),
      body: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          children: [
            TextField(
              controller: _emailController,
              decoration: const InputDecoration(labelText: 'Email'),
            ),
            TextField(
              controller: _passwordController,
              obscureText: true,
              decoration: const InputDecoration(
                labelText: 'Password',
                helperText: 'Petunjuk: 123456',
              ),
            ),
            const SizedBox(height: 24),
            SizedBox(
              width: double.infinity,
              // Obx kecil: hanya tombol yang rebuild saat isLoading berubah
              child: Obx(
                () => FilledButton(
                  onPressed: _auth.isLoading ? null : _login,
                  child: _auth.isLoading
                      ? const SizedBox(
                          width: 20,
                          height: 20,
                          child: CircularProgressIndicator(strokeWidth: 2),
                        )
                      : const Text('Masuk'),
                ),
              ),
            ),
          ],
        ),
      ),
    );
  }
}

Penjelasan:

  • AuthController menyimpan user dalam Rxn<User>(), observable yang boleh null. null berarti belum login.
  • AuthGate membungkus pilihan halaman dengan Obx yang hanya membaca isLoggedIn. Begitu _user.value berubah, gate langsung berganti halaman. Saat isLoading berubah, gate tidak ikut rebuild.
  • login() mengembalikan bool. LoginView yang memutuskan cara menampilkan kegagalan (SnackBar, dengan cek mounted setelah await), sedangkan controller hanya menyimpan pesannya di error.
  • LoginView tetap StatefulWidget karena TextEditingController adalah state lokal milik form (ephemeral state, section 1). State global (siapa yang login) ada di controller.
  • Tombol Masuk dibungkus Obx kecil: dinonaktifkan dan diganti spinner selama isLoading, mencegah login ganda.
  • Logout cukup memanggil controller.logout. Begitu user menjadi null, AuthGate menampilkan LoginView lagi.
  • AppBinding mendaftarkan AuthController dengan permanent: true karena sesi login dibutuhkan selama aplikasi hidup.
  • auth_controller.dart hanya mengimpor package:get/get.dart, model, dan service. Coba cek: tidak ada material.dart.

💡 Dipakai lagi di Modul 13–14

Proyek CRUD + Auth nanti memakai nama yang sama: lib/controllers/auth_controller.dart (AuthController), AuthGate, LoginView, RegisterView, HomeView, ditambah NotesController. Bedanya, AuthService palsu di atas diganti Supabase Auth, dan status login didengarkan dari stream (StreamSubscription dibuat di onInit, dibatalkan di onClose).

⚠️ Kesalahan umum

  • Mengimpor material.dart di controller untuk memanggil ScaffoldMessenger, atau memanggil Get.snackbar/Get.to dari controller. Kembalikan hasil (bool/pesan) dan biarkan View yang bereaksi.
  • Mencampur AuthGate dengan Get.off(() => const HomeView()) manual setelah login. Pilih satu cara; jika memakai AuthGate, biarkan ia yang menentukan halaman.
  • Memanggil AuthService langsung dari LoginView. View hanya bicara dengan controller.
  • Menaruh semua class di main.dart sampai ratusan baris. Pecah sesuai struktur di atas sejak awal.
