Kadang satu controller butuh data dari controller lain. Contoh: daftar catatan bergantung pada siapa yang sedang login. Di GetX, controller cukup mengambil controller lain dengan Get.find, lalu memasang worker agar otomatis bereaksi setiap kali observable di controller sumber berubah.

Mengambil controller lain

class CatatanController extends GetxController {
  late final AuthController _auth;

  @override
  void onInit() {
    super.onInit();
    _auth = Get.find<AuthController>(); // controller yang SUDAH terdaftar
  }
}

Syaratnya: AuthController sudah didaftarkan sebelum CatatanController.onInit berjalan. Di binding, tulis Get.put(AuthController()) lebih dulu, atau daftarkan dengan Get.lazyPut sehingga urutan tidak lagi penting.

Worker: bereaksi terhadap perubahan observable

Worker adalah fungsi yang "mengawasi" sebuah observable dan menjalankan callback ketika nilainya berubah. Semuanya mengembalikan objek Worker yang harus dihentikan dengan dispose() di onClose.

WorkerCallback dijalankanContoh pemakaian
ever(rx, cb)Setiap kali nilai berubahPengguna berganti, muat ulang data miliknya
once(rx, cb)Hanya pada perubahan pertama, lalu berhenti sendiriMenampilkan tutorial saat pertama kali login
debounce(rx, cb, time: ...)Setelah nilai berhenti berubah selama time (bawaan 800 ms)Kotak pencarian: cari setelah pengguna selesai mengetik
interval(rx, cb, time: ...)Paling banyak satu kali per time (bawaan 1 detik), perubahan di antaranya diabaikanMembatasi tombol yang ditekan beruntun
 
final _workers = <Worker>[];

@override
void onInit() {
  super.onInit();
  _workers.addAll([
    ever<String?>(_auth.nimRx, (nim) => debugPrint('login sebagai $nim')),
    once<String?>(_auth.nimRx, (_) => debugPrint('login pertama kali')),
    debounce<String>(_kataKunci, (k) => debugPrint('cari $k'),
        time: const Duration(milliseconds: 500)),
    interval<int>(_jumlahKlik, (n) => debugPrint('klik ke-$n'),
        time: const Duration(seconds: 1)),
  ]);
}

@override
void onClose() {
  for (final w in _workers) {
    w.dispose(); // hentikan semua worker
  }
  super.onClose();
}

Contoh lengkap: catatan per pengguna + pencarian

AuthController menyimpan NIM yang sedang login. CatatanController memakai ever untuk mengganti daftar catatan setiap kali NIM berubah, dan debounce agar pencarian baru diterapkan setelah pengguna berhenti mengetik.

📄 lib/main.dart

// lib/main.dart — salin SELURUH kode ini untuk menggantikan isi lib/main.dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

// ================= CONTROLLER SUMBER =================
class AuthController extends GetxController {
  final _nim = RxnString();

  String? get nim => _nim.value;

  // Observable-nya dibuka (read-only lewat getter) agar controller lain
  // bisa memasang worker. Ubah nilainya HANYA lewat method di bawah.
  RxnString get nimRx => _nim;

  void loginSebagai(String nim) => _nim.value = nim;
}

// ================= CONTROLLER YANG BERGANTUNG =================
// CatatanController BERGANTUNG pada AuthController: catatan milik siapa?
class CatatanController extends GetxController {
  late final AuthController _auth;
  final _workers = <Worker>[];

  final Map<String, List<String>> _catatanPerNim = {};
  final _catatan = <String>[].obs; // catatan milik pengguna aktif
  final _kataKunci = ''.obs; // isi kotak pencarian (berubah tiap ketikan)
  final _kataTerapan = ''.obs; // kata kunci yang SUDAH diterapkan (setelah debounce)

  String get kataTerapan => _kataTerapan.value;
  int get jumlah => _catatan.length;

  List<String> get catatanTampil {
    final k = _kataTerapan.value.toLowerCase();
    if (k.isEmpty) return List.unmodifiable(_catatan);
    return _catatan.where((c) => c.toLowerCase().contains(k)).toList();
  }

  @override
  void onInit() {
    super.onInit();
    _auth = Get.find<AuthController>(); // ambil controller lain

    // ever: jalankan callback SETIAP kali nim berubah
    _workers.add(ever<String?>(_auth.nimRx, _gantiPengguna));

    // debounce: jalankan callback 500 ms setelah pengguna BERHENTI mengetik
    _workers.add(debounce<String>(
      _kataKunci,
      (kata) {
        debugPrint('mencari: "$kata"');
        _kataTerapan.value = kata;
      },
      time: const Duration(milliseconds: 500),
    ));

    _gantiPengguna(_auth.nim); // nilai awal
  }

  void _gantiPengguna(String? nim) {
    debugPrint('ever: pengguna berganti ke $nim');
    _catatan.assignAll(nim == null ? const [] : _catatanPerNim[nim] ?? const []);
  }

  void ubahKataKunci(String kata) => _kataKunci.value = kata;

  void tambah(String teks) {
    final nim = _auth.nim;
    if (nim == null) return;
    _catatanPerNim.putIfAbsent(nim, () => []).add(teks);
    _catatan.add(teks);
  }

  @override
  void onClose() {
    for (final w in _workers) {
      w.dispose(); // hentikan semua worker
    }
    super.onClose();
  }
}

// ================= BINDING =================
class AppBinding extends Bindings {
  @override
  void dependencies() {
    // AuthController didaftarkan LEBIH DULU karena dipakai di onInit CatatanController
    Get.put(AuthController());
    Get.put(CatatanController());
  }
}

void main() {
  runApp(const MyApp());
}

Perhatikan: walaupun ada lima ketikan (b, a, s, i, s), callback debounce hanya berjalan sekali. Jika pencarian memanggil server (Modul 09), ini menghemat empat request yang sia-sia.

Penjelasan:

  • AppBinding mendaftarkan AuthController lebih dulu karena CatatanController.onInit langsung memanggil Get.find<AuthController>().
  • AuthController membuka observable-nya lewat getter nimRx supaya bisa diawasi worker. Nilainya tetap hanya diubah lewat method loginSebagai.
  • ever<String?>(_auth.nimRx, _gantiPengguna): setiap kali NIM berubah, _gantiPengguna mengisi ulang _catatan dari map. Data per NIM tetap tersimpan, jadi kembali ke H1D023001 memunculkan tiga catatannya lagi.
  • ever tidak dijalankan untuk nilai awal, hanya untuk perubahan. Karena itu _gantiPengguna(_auth.nim) dipanggil sekali secara manual di akhir onInit (baris log pertama, NIM masih null).
  • Pencarian memakai dua observable: _kataKunci berubah setiap ketikan, sedangkan _kataTerapan baru berubah 500 ms setelah pengguna berhenti mengetik. catatanTampil hanya membaca _kataTerapan, jadi daftar tidak berkedip di setiap huruf.
  • Semua worker disimpan di _workers dan dihentikan di onClose. Controller di contoh ini hidup sepanjang aplikasi, tetapi kebiasaan ini wajib untuk controller per halaman (section 7).
  • onChanged: catatan.ubahKataKunci mengoper method sebagai callback (tear-off), tanpa membuat fungsi anonim.

ℹ️ Seberapa sering dipakai?

Untuk proyek kuliah, cara yang lebih sederhana juga sah: View memanggil Get.find<CatatanController>().gantiPengguna(nim) tepat setelah login berhasil. Worker ever lebih aman ketika status login bisa berubah dari banyak tempat (login, logout, sesi kedaluwarsa), karena controller tujuan pasti ikut bereaksi. Pola ever + auth ini muncul lagi di proyek Modul 14. Jika Anda pernah melihat ProxyProvider di package Provider, worker inilah padanannya di GetX.

⚠️ Kesalahan umum

  • Memasang worker di build() View. Setiap rebuild menambah worker baru, sehingga callback dipanggil berkali-kali. Worker selalu dibuat di onInit controller.
  • Lupa dispose() worker di onClose. Worker tetap mendengarkan observable milik controller lain yang masih hidup, sehingga callback berjalan pada controller yang sudah dihapus.
  • Urutan pendaftaran terbalik: Get.put(CatatanController()) sebelum Get.put(AuthController()) menghasilkan error "AuthController" not found di onInit.
  • Mengira ever langsung dijalankan untuk nilai awal. Panggil callback-nya sekali secara manual jika perlu.
