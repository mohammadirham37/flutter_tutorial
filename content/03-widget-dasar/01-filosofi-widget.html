Di dalam Flutter, hampir segala sesuatu adalah Widget. Bukan hanya tombol atau gambar, tetapi struktur layout (Padding, Center), tema warna (Theme), hingga pendeteksi sentuhan (GestureDetector) semuanya adalah widget.

Di balik layar, Flutter mengelola tiga pohon paralel untuk mencapai performa render 60-120 FPS yang mulus:

1. WIDGET TREE

Konfigurasi Blueprint (Ringan & Cepat dihancurkan/dibuat ulang). Bersifat immutable.

2. ELEMENT TREE

Struktur Skeletal (Persisten di memori). Mengaitkan widget dengan objek render riil dan memegang State.

3. RENDER TREE

Penggambar Piksel (Komputasi berat). Menghitung kalkulasi ukuran (layouting) dan melukis (paint) piksel ke layar.

Widget adalah "resep", bukan tampilan

Bayangkan widget seperti resep masakan. Resep hanya berisi keterangan: bahan apa, berapa banyak, dimasak bagaimana. Flutter yang "memasak" resep itu menjadi piksel di layar. Karena widget hanya resep, membuat ulang widget itu murah sekali. Flutter boleh membuat ulang ribuan widget setiap detik tanpa membuat aplikasi lambat.

Widget disusun bersarang seperti pohon. Setiap widget punya parent (induk) dan bisa punya child (satu anak) atau children (banyak anak). Lihat contoh kecil berikut:

// Pohon widget sederhana: Center -> Column -> [Icon, Text]
Center(
  child: Column(
    mainAxisSize: MainAxisSize.min,
    children: const [
      Icon(Icons.school, size: 48),
      Text('Halo, Mahasiswa UNSOED!'),
    ],
  ),
)
Pohon widget Center → Column → Icon + Text

Jika digambar sebagai pohon, susunannya menjadi seperti ini:

Center
 └── Column
      ├── Icon (school)
      └── Text ("Halo, Mahasiswa UNSOED!")

Program Flutter paling kecil

Program Flutter selalu dimulai dari fungsi main() yang memanggil runApp(). Widget yang diberikan ke runApp() menjadi akar (root) pohon widget. Coba jalankan kode ini untuk melihat bahwa satu widget Text pun sudah bisa menjadi aplikasi.

📄 lib/main.dart

// lib/main.dart — salin SELURUH kode ini untuk menggantikan isi lib/main.dart
import 'package:flutter/material.dart';

void main() {
  // runApp menerima satu widget sebagai akar pohon widget.
  runApp(
    const Center(
      child: Text(
        'Halo, Flutter!',
        // Tanpa MaterialApp, arah teks wajib ditentukan sendiri.
        textDirection: TextDirection.ltr,
        style: TextStyle(fontSize: 32, color: Colors.white),
      ),
    ),
  );
}
Program terkecil: satu Text tanpa MaterialApp, latar hitam

Hasilnya adalah layar hitam dengan tulisan putih di tengah. Perhatikan bahwa kita harus menulis textDirection sendiri karena belum ada MaterialApp yang menyediakan pengaturan bawaan (arah teks, tema, font). Di section berikutnya kita akan memakai MaterialApp supaya hal-hal seperti ini diurus otomatis.

💡 Cara membaca kode Flutter

Baca kode widget dari luar ke dalam: widget paling luar adalah pembungkus, lalu turun ke child atau children. Biasakan memberi koma di akhir setiap argumen (trailing comma) agar format otomatis (Shift+Alt+F di VS Code) menyusun kode menjadi bertingkat rapi.

⚠️ Kesalahan umum

  • Lupa memanggil runApp() di main() sehingga layar tetap kosong.
  • Menganggap widget sebagai objek yang "diubah-ubah". Widget bersifat immutable (tidak bisa diubah). Untuk mengubah tampilan, Flutter membuat widget baru dengan data baru.
  • Salah menaruh kurung tutup ) sehingga widget masuk ke induk yang salah. Gunakan trailing comma dan format otomatis.
