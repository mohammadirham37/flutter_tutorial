Objek State punya siklus hidup (lifecycle): ia dibuat, dipasang ke pohon, digambar berkali-kali, diperbarui, lalu dibuang. Flutter memanggil method tertentu di setiap tahap. Memahami urutannya adalah kunci menghindari kebocoran memori (memory leak) dan error saat aplikasi berjalan.

createState()
     │
     ▼
initState()               ← sekali, saat State pertama kali dibuat
     │
     ▼
didChangeDependencies()   ← setelah initState, dan tiap kali Theme/MediaQuery yang dipakai berubah
     │
     ▼
build()  ◄───────────────┐  ← berkali-kali
     │                   │
     ├── setState() ─────┤
     ├── didUpdateWidget()┤ ← induk membangun ulang dengan parameter baru
     │                   │
     ▼
dispose()                 ← sekali, saat widget dibuang dari pohon selamanya
  1. createState(): Dipanggil saat framework membuat elemen baru di pohon elemen. Isinya hanya membuat objek State.
  2. initState(): Dipanggil tepat SATU KALI saat objek state pertama kali dimasukkan ke tree. Cocok untuk inisialisasi controller, controller animasi, timer, atau mengambil data awal.
  3. didChangeDependencies(): Dipanggil setelah initState() dan setiap kali objek yang dibaca lewat context (seperti Theme.of atau MediaQuery) berubah.
  4. build(): Mengembalikan struktur widget tree yang akan digambar. Dipanggil setiap kali ada setState(), didUpdateWidget(), atau perubahan dependensi.
  5. didUpdateWidget(oldWidget): Dipanggil saat induk membangun ulang widget ini dengan parameter baru. Kita bisa membandingkan oldWidget dengan widget.
  6. setState(): Memberi sinyal ke framework bahwa ada data internal yang berubah, memicu pemanggilan ulang build().
  7. dispose(): Dipanggil saat widget dihapus secara permanen dari layar. Wajib menutup stream, timer, AnimationController, dan TextEditingController di sini agar tidak bocor di memori!

Contoh kecil: pola initState dan dispose

class KolomNama extends StatefulWidget {
  const KolomNama({super.key});

  @override
  State<KolomNama> createState() => _KolomNamaState();
}

class _KolomNamaState extends State<KolomNama> {
  late final TextEditingController _controller;

  @override
  void initState() {
    super.initState(); // selalu panggil super.initState() PALING AWAL
    _controller = TextEditingController(text: 'Mahasiswa');
  }

  @override
  void dispose() {
    _controller.dispose(); // bersihkan resource milik kita dulu
    super.dispose();       // super.dispose() PALING AKHIR
  }

  @override
  Widget build(BuildContext context) {
    return TextField(controller: _controller);
  }
}

Contoh lengkap: demo log lifecycle

Jalankan kode berikut, buka Debug Console (VS Code) atau terminal tempat flutter run berjalan, lalu tekan tombol-tombolnya satu per satu sambil membaca log yang muncul.

📄 lib/main.dart

// lib/main.dart — salin SELURUH kode ini untuk menggantikan isi lib/main.dart
import 'dart:async';

import 'package:flutter/material.dart';

void main() {
  runApp(const DemoLifecycleApp());
}

/// Induk: menyimpan 3 state yang mempengaruhi anak.
class DemoLifecycleApp extends StatefulWidget {
  const DemoLifecycleApp({super.key});

  @override
  State<DemoLifecycleApp> createState() => _DemoLifecycleAppState();
}

class _DemoLifecycleAppState extends State<DemoLifecycleApp> {
  bool _tampilkanAnak = true; // untuk memicu initState / dispose
  int _nomorPertemuan = 1;    // untuk memicu didUpdateWidget
  bool _modeGelap = false;    // untuk memicu didChangeDependencies

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      // Matikan animasi pergantian tema agar log tidak tercetak berkali-kali
      themeAnimationDuration: Duration.zero,
      theme: ThemeData(
        colorSchemeSeed: Colors.indigo,
        brightness: _modeGelap ? Brightness.dark : Brightness.light,
      ),
      home: Scaffold(
        appBar: AppBar(title: const Text('Demo Lifecycle')),
        body: Padding(
          padding: const EdgeInsets.all(16),
          child: Column(
            crossAxisAlignment: CrossAxisAlignment.stretch,
            children: [
              FilledButton(
                onPressed: () => setState(() => _tampilkanAnak = !_tampilkanAnak),
                child: Text(_tampilkanAnak ? 'Sembunyikan anak (dispose)' : 'Tampilkan anak (initState)'),
              ),
              const SizedBox(height: 8),
              OutlinedButton(
                onPressed: () => setState(() => _nomorPertemuan++),
                child: const Text('Ganti parameter (didUpdateWidget)'),
              ),
              const SizedBox(height: 8),
              OutlinedButton(
                onPressed: () => setState(() => _modeGelap = !_modeGelap),
                child: const Text('Ganti tema (didChangeDependencies)'),
              ),
              const SizedBox(height: 24),
              if (_tampilkanAnak) KartuLifecycle(nomorPertemuan: _nomorPertemuan),
            ],
          ),
        ),
      ),
    );
  }
}

/// Anak: mencetak log di setiap tahap lifecycle.
class KartuLifecycle extends StatefulWidget {
  final int nomorPertemuan;

  const KartuLifecycle({super.key, required this.nomorPertemuan});

  @override
  // ignore: no_logic_in_create_state
  State<KartuLifecycle> createState() {
    debugPrint('1. createState()');
    return _KartuLifecycleState();
  }
}

class _KartuLifecycleState extends State<KartuLifecycle> {
  Timer? _timer;
  int _detik = 0;

  @override
  void initState() {
    super.initState();
    debugPrint('2. initState()  -> timer dimulai');
    // Timer berjalan tiap detik. WAJIB dibatalkan di dispose().
    _timer = Timer.periodic(const Duration(seconds: 1), (_) {
      setState(() => _detik++);
    });
  }

  @override
  void didChangeDependencies() {
    super.didChangeDependencies();
    final gelap = Theme.of(context).brightness == Brightness.dark;
    debugPrint('3. didChangeDependencies()  -> tema gelap: $gelap');
  }

  @override
  void didUpdateWidget(covariant KartuLifecycle oldWidget) {
    super.didUpdateWidget(oldWidget);
    debugPrint(
      '5. didUpdateWidget()  -> pertemuan ${oldWidget.nomorPertemuan} '
      'menjadi ${widget.nomorPertemuan}',
    );
  }

  @override
  void dispose() {
    _timer?.cancel();
    debugPrint('6. dispose()  -> timer dibatalkan setelah $_detik detik');
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    // Dicetak hanya pada build pertama agar log tidak penuh oleh timer
    if (_detik == 0) debugPrint('4. build()');

    return Card(
      child: Padding(
        padding: const EdgeInsets.all(24),
        child: Column(
          children: [
            // Akses parameter widget dari State lewat "widget."
            Text(
              'Pertemuan ke-${widget.nomorPertemuan}',
              style: Theme.of(context).textTheme.titleLarge,
            ),
            const SizedBox(height: 8),
            Text('Sudah tampil selama $_detik detik'),
          ],
        ),
      ),
    );
  }
}

Contoh log yang muncul

// Saat aplikasi dibuka
1. createState()
2. initState()  -> timer dimulai
3. didChangeDependencies()  -> tema gelap: false
4. build()

// Tekan "Ganti parameter"
5. didUpdateWidget()  -> pertemuan 1 menjadi 2

// Tekan "Ganti tema": induk membangun ulang (didUpdateWidget),
// lalu Theme yang dibaca anak berubah (didChangeDependencies)
5. didUpdateWidget()  -> pertemuan 2 menjadi 2
3. didChangeDependencies()  -> tema gelap: true

// Tekan "Sembunyikan anak"
6. dispose()  -> timer dibatalkan setelah 12 detik

// Tekan "Tampilkan anak" lagi: State BARU dibuat, detik mulai dari 0
1. createState()
2. initState()  -> timer dimulai
3. didChangeDependencies()  -> tema gelap: true
4. build()

Penjelasan kode

  • widget.nomorPertemuan: dari dalam class State, parameter milik widget diakses lewat properti widget.
  • initState tidak boleh memakai Theme.of(context) atau MediaQuery.of(context). Hal yang bergantung pada context diletakkan di didChangeDependencies atau build.
  • Jika baris _timer?.cancel() dihapus, timer tetap berjalan setelah widget hilang dan memanggil setState pada State yang sudah dibuang. Hasilnya error "setState() called after dispose()".
  • didUpdateWidget dipanggil setiap kali induk memanggil setState, walaupun nilainya sama (lihat "pertemuan 2 menjadi 2"). Karena itu, di dalamnya biasanya kita membandingkan dulu: if (oldWidget.nomorPertemuan != widget.nomorPertemuan) { ... }.
  • Saat anak ditampilkan lagi, _detik kembali ke 0. Ini membuktikan State lama sudah dibuang dan State baru dibuat.

Pengecekan mounted setelah await

Jika kamu menunggu proses lama (misalnya request API) lalu memanggil setState, cek dulu apakah widget masih terpasang:

Future<void> _muatData() async {
  await Future.delayed(const Duration(seconds: 2)); // pura-pura request API
  if (!mounted) return; // widget sudah ditutup? jangan setState
  setState(() {
    // perbarui data di sini
  });
}

⚠️ Kesalahan umum

  • Lupa memanggil super.initState() di awal atau super.dispose() di akhir.
  • Membuat controller (TextEditingController, AnimationController) di dalam build(). Controller akan dibuat ulang setiap build dan isinya hilang. Buat di initState.
  • Tidak membatalkan Timer atau StreamSubscription di dispose().
  • Memanggil setState di dispose(), atau setelah await tanpa cek mounted.
