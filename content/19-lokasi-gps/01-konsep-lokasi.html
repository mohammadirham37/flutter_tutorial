Aplikasi ojek online, presensi kantor, pelacak lari, dan peta kampus punya satu kebutuhan yang sama: mengetahui di mana pengguna berada. Di bab ini kamu belajar mengambil posisi perangkat, memantaunya secara real-time, mengubahnya menjadi alamat, menampilkannya di peta, lalu membangun aplikasi presensi kampus berbasis lokasi dengan GetX MVC.

Dalam percakapan sehari-hari (dan di modul ini) kata "GPS" tetap dipakai untuk menyebut layanan lokasi secara umum.

Fused Location Provider

Di Android, Google Play services menyediakan Fused Location Provider (FusedLocationProviderClient). Modul lama yang berbasis Kotlin memanggilnya langsung. Provider ini menggabungkan ("fuse") GNSS, Wi-Fi, seluler, dan sensor gerak, lalu memilih kombinasi terbaik sesuai prioritas yang diminta aplikasi. Kita tidak perlu memanggilnya sendiri: package geolocator yang dipakai di bab ini memakai Fused Location Provider secara otomatis di Android (dan Core Location di iOS).

Akurasi vs baterai

Makin tinggi akurasi yang diminta, makin sering chip GNSS dinyalakan, makin cepat baterai habis. Di geolocator pilihan ini diatur lewat enum LocationAccuracy:

⚠️ lowest bukan berarti "paling cepat"

Di Android, LocationAccuracy.lowest berarti pasif: aplikasimu tidak meminta lokasi baru sama sekali, hanya menerima jika aplikasi lain kebetulan memintanya. Akibatnya posisi bisa tidak pernah datang. Untuk kebutuhan biasa pakai medium atau high.

Sejak Android 12, dialog izin selalu memberi pengguna pilihan Akurat atau Perkiraan, walaupun aplikasi meminta ACCESS_FINE_LOCATION. iOS 14 ke atas juga punya sakelar Precise. Artinya aplikasi harus siap menerima lokasi yang kasar. Kamu bisa mengeceknya dengan Geolocator.getLocationAccuracy():

import 'package:flutter/foundation.dart';
import 'package:geolocator/geolocator.dart';

Future<void> cekPresisi() async {
  final status = await Geolocator.getLocationAccuracy();
  if (status == LocationAccuracyStatus.reduced) {
    // Pengguna memilih "Perkiraan" (approximate): posisi bisa meleset
    // hingga beberapa kilometer persegi. Jelaskan kenapa butuh "Akurat".
    debugPrint('Lokasi hanya perkiraan');
  }
}

Foreground vs background location

  • Foreground (while in use): lokasi hanya diambil selama aplikasi terbuka di layar. Ini cukup untuk hampir semua kasus, termasuk presensi kampus di bab ini.
  • Background (always): lokasi tetap diambil saat aplikasi diminimalkan, misalnya aplikasi pelacak armada. Di Android butuh izin ACCESS_BACKGROUND_LOCATION yang diminta terpisah, notifikasi foreground service, dan alasan tertulis saat rilis ke Play Store. Di iOS butuh izin "Always" dan Background Mode.

💡 Prinsip minimal

Minta izin paling rendah yang cukup untuk fitur yang kamu bangun. Aplikasi yang meminta lokasi background tanpa alasan kuat biasanya ditolak Google Play dan App Store, dan pengguna juga cenderung mencopotnya.

ℹ️ Kenapa tidak memakai permission_handler?

Di Modul 17 kamu memakai permission_handler untuk berbagai izin. Untuk lokasi, geolocator sudah punya API izin sendiri (checkPermission, requestPermission) yang sekaligus memahami status layanan GPS. Memakai satu package untuk satu fitur membuat kode lebih sederhana. Polanya tetap sama dengan Modul 17: cek, minta, tangani ditolak, tangani ditolak permanen.
