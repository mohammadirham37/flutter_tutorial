Sebelum menulis kode, aplikasi harus "mendaftarkan" kebutuhan lokasinya ke sistem operasi. Setelah itu, saat aplikasi berjalan, kita memeriksa dua hal secara berurutan: apakah layanan lokasi menyala, dan apakah izin sudah diberikan.

Langkah 1: Pasang package

flutter create --org id.ac.kampus lokasi_app
cd lokasi_app
flutter pub add geolocator geocoding flutter_map latlong2 get

Langkah 2: AndroidManifest.xml

Buka android/app/src/main/AndroidManifest.xml dan tambahkan izin sebagai anak langsung tag <manifest>, di atas <application>:

📄 android/app/src/main/AndroidManifest.xml

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- Lokasi perkiraan (wajib dideklarasikan bersama FINE sejak Android 12) -->
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
    <!-- Lokasi akurat: dibutuhkan untuk presensi berbasis radius -->
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
    <!-- Internet: untuk geocoding dan ubin peta pada build rilis -->
    <uses-permission android:name="android.permission.INTERNET" />

    <application ...>
        ...
    </application>
</manifest>
  • COARSE dan FINE dideklarasikan berdua. Sejak Android 12, pengguna boleh memilih "Perkiraan" walau aplikasi meminta FINE, jadi keduanya harus ada di manifest. geolocator akan meminta keduanya dalam satu dialog.
  • INTERNET sudah ada di manifest debug dan profile bawaan Flutter, tetapi tidak di main. Tanpa baris ini, peta dan geocoding berjalan saat flutter run tetapi kosong di APK rilis (Modul 16).

Hanya jika aplikasimu benar-benar butuh lokasi saat diminimalkan (misalnya pelacak rute), tambahkan juga:

<!-- HANYA untuk lokasi di latar belakang -->
<uses-permission android:name="android.permission.ACCESS_BACKGROUND_LOCATION" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_LOCATION" />

⚠️ Jangan menyalin izin background "untuk jaga-jaga"

Google Play memeriksa izin ACCESS_BACKGROUND_LOCATION dan foreground service lokasi. Aplikasi yang mendeklarasikannya tanpa fitur yang jelas akan ditolak saat review. Aplikasi presensi di bab ini tidak membutuhkannya.

Langkah 3: Info.plist (iOS)

Di iOS, setiap izin wajib disertai kalimat alasan yang tampil di dialog. Tanpa kunci ini aplikasi langsung crash saat meminta izin. Buka ios/Runner/Info.plist dan tambahkan di dalam <dict>:

📄 ios/Runner/Info.plist

<key>NSLocationWhenInUseUsageDescription</key>
<string>Lokasi dipakai untuk memastikan kamu berada di area kampus saat presensi.</string>

Karena aplikasi kita tidak memakai lokasi "Always", README geolocator menyarankan menambahkan makro BYPASS_PERMISSION_LOCATION_ALWAYS=1 agar App Store tidak menanyakan kunci NSLocationAlwaysAndWhenInUseUsageDescription. Untuk proyek yang memakai CocoaPods, tambahkan di ios/Podfile:

📄 ios/Podfile (bagian post_install)

post_install do |installer|
  installer.pods_project.targets.each do |target|
    flutter_additional_ios_build_settings(target)
    if target.name == "geolocator_apple"
      target.build_configurations.each do |config|
        config.build_settings['GCC_PREPROCESSOR_DEFINITIONS'] ||= ['$(inherited)', 'BYPASS_PERMISSION_LOCATION_ALWAYS=1']
      end
    end
  end
end

Jika proyek iOS-mu memakai Swift Package Manager, gunakan variabel lingkungan saat build: BYPASS_PERMISSION_LOCATION_ALWAYS=1 flutter build ios. Aplikasi yang memang butuh lokasi background di iOS harus menambahkan NSLocationAlwaysAndWhenInUseUsageDescription dan UIBackgroundModes berisi location.

Langkah 4: Alur pemeriksaan saat runtime

Urutan yang benar sebelum mengambil posisi:

  1. Geolocator.isLocationServiceEnabled(): apakah sakelar Lokasi/GPS di perangkat menyala? Jika mati, izin apa pun tidak berguna. Arahkan pengguna ke Geolocator.openLocationSettings().
  2. Geolocator.checkPermission(): cek status izin tanpa menampilkan dialog.
  3. Jika denied, panggil Geolocator.requestPermission() untuk menampilkan dialog sistem.
  4. Jika hasilnya deniedForever, dialog tidak akan muncul lagi. Satu-satunya jalan: Geolocator.openAppSettings().
LocationPermissionArtiTindakan aplikasi
deniedBelum diizinkan (juga status awal). Masih boleh diminta lagi.Jelaskan manfaatnya, sediakan tombol "Coba lagi"
deniedForeverDitolak permanen, dialog tidak akan tampil lagiTombol "Buka pengaturan aplikasi"
whileInUseDiizinkan saat aplikasi dipakaiLanjut ambil posisi
alwaysDiizinkan termasuk di latar belakangLanjut ambil posisi
unableToDetermineStatus tidak bisa ditentukan (praktis hanya di web)Perlakukan seperti denied

Contoh lengkap: memeriksa izin lokasi

📄 lib/main.dart

// lib/main.dart
import 'package:flutter/material.dart';
import 'package:geolocator/geolocator.dart';

void main() => runApp(const MyApp());

class MyApp extends StatelessWidget {
  const MyApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.teal),
      home: const CekIzinPage(),
    );
  }
}

class CekIzinPage extends StatefulWidget {
  const CekIzinPage({super.key});

  @override
  State<CekIzinPage> createState() => _CekIzinPageState();
}

class _CekIzinPageState extends State<CekIzinPage> {
  String _pesan = 'Tekan tombol untuk memeriksa izin lokasi.';
  bool _ditolakPermanen = false;
  bool _layananMati = false;

  Future<void> _periksa() async {
    // 1. Apakah layanan lokasi (GPS) di perangkat menyala?
    final layananAktif = await Geolocator.isLocationServiceEnabled();
    if (!mounted) return;
    if (!layananAktif) {
      setState(() {
        _layananMati = true;
        _ditolakPermanen = false;
        _pesan = 'Layanan lokasi mati. Nyalakan GPS terlebih dahulu.';
      });
      return;
    }

    // 2. Cek izin yang sudah ada, minta jika masih denied
    var izin = await Geolocator.checkPermission();
    if (izin == LocationPermission.denied) {
      izin = await Geolocator.requestPermission();
    }
    if (!mounted) return;

    // 3. Terjemahkan hasilnya menjadi pesan untuk pengguna
    setState(() {
      _layananMati = false;
      _ditolakPermanen = izin == LocationPermission.deniedForever;
      _pesan = switch (izin) {
        LocationPermission.whileInUse =>
          'Izin diberikan (hanya saat aplikasi dipakai).',
        LocationPermission.always => 'Izin diberikan (selalu).',
        LocationPermission.denied =>
          'Izin ditolak. Kamu bisa menekan tombol lagi untuk meminta ulang.',
        LocationPermission.deniedForever =>
          'Izin ditolak permanen. Buka pengaturan aplikasi untuk mengizinkan.',
        LocationPermission.unableToDetermine =>
          'Status izin tidak dapat ditentukan di platform ini.',
      };
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Izin Lokasi')),
      body: Center(
        child: Padding(
          padding: const EdgeInsets.all(24),
          child: Column(
            mainAxisSize: MainAxisSize.min,
            children: [
              const Icon(Icons.location_on, size: 64),
              const SizedBox(height: 16),
              Text(_pesan, textAlign: TextAlign.center),
              const SizedBox(height: 24),
              FilledButton.icon(
                onPressed: _periksa,
                icon: const Icon(Icons.refresh),
                label: const Text('Periksa izin'),
              ),
              if (_layananMati)
                TextButton(
                  onPressed: Geolocator.openLocationSettings,
                  child: const Text('Buka pengaturan lokasi'),
                ),
              if (_ditolakPermanen)
                TextButton(
                  onPressed: Geolocator.openAppSettings,
                  child: const Text('Buka pengaturan aplikasi'),
                ),
            ],
          ),
        ),
      ),
    );
  }
}
  • Layanan dulu, izin kemudian. Jika GPS mati, kita berhenti dan menampilkan tombol yang membuka pengaturan lokasi, bukan pengaturan aplikasi.
  • requestPermission() hanya dipanggil saat status denied. Memanggilnya saat sudah whileInUse tidak berbahaya, tetapi tidak perlu.
  • if (!mounted) return; setelah setiap await: pengguna bisa saja menutup halaman saat dialog izin tampil, dan setState pada widget yang sudah dibuang akan memicu error.
  • Ekspresi switch pada enum harus mencakup semua nilai, termasuk unableToDetermine. Analyzer akan memberi error jika ada yang terlewat, sehingga tidak ada status yang tidak tertangani.

ℹ️ Android tidak bisa melaporkan deniedForever dari checkPermission

Menurut dokumentasi geolocator, di Android status ditolak permanen hanya diketahui sebagai hasil requestPermission(). checkPermission() akan mengembalikan denied. Karena itu alur di atas selalu memanggil requestPermission() saat denied: jika ternyata sudah permanen, dialog tidak tampil dan hasilnya langsung deniedForever.

💡 Setelah kembali dari Pengaturan

openAppSettings() hanya membuka halaman pengaturan; hasilnya tidak dikirim balik ke aplikasi. Sediakan tombol "Coba lagi" atau periksa ulang izin saat aplikasi kembali aktif (misalnya dengan AppLifecycleListener pada callback onResume).
