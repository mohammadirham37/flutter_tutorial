Foto yang hanya ada di HP akan hilang saat aplikasi di-uninstall dan tidak bisa dilihat dari perangkat lain. Untuk foto profil yang tampil di mana saja, unggah ke Supabase Storage. Bagian ini melanjutkan pengenalan Storage di Modul 12 bagian 10 dan memakai login dari Modul 13.

Langkah 1: buat bucket dan policy

Buka dashboard Supabase → Storage → New bucket, beri nama foto-profil. Centang Public bucket jika foto boleh dilihat siapa saja yang tahu URL-nya (cocok untuk foto profil). Di pengaturan bucket, batasi juga ukuran file (misalnya 2 MB) dan jenis file (image/jpeg, image/png). Lalu buat policy di SQL Editor agar setiap user hanya bisa mengelola foldernya sendiri:

-- Unggah ke folder milik sendiri: foto-profil/<id user>/...
create policy "Unggah foto profil sendiri"
on storage.objects for insert to authenticated
with check (
  bucket_id = 'foto-profil'
  and (storage.foldername(name))[1] = (select auth.uid())::text
);

-- Menimpa (upsert) foto sendiri
create policy "Ganti foto profil sendiri"
on storage.objects for update to authenticated
using (
  bucket_id = 'foto-profil'
  and (storage.foldername(name))[1] = (select auth.uid())::text
);

-- Menghapus foto sendiri
create policy "Hapus foto profil sendiri"
on storage.objects for delete to authenticated
using (
  bucket_id = 'foto-profil'
  and (storage.foldername(name))[1] = (select auth.uid())::text
);

-- Hanya untuk bucket PRIVATE: izinkan membaca foto sendiri
create policy "Lihat foto profil sendiri"
on storage.objects for select to authenticated
using (
  bucket_id = 'foto-profil'
  and (storage.foldername(name))[1] = (select auth.uid())::text
);

Pada bucket public, siapa pun bisa membaca file lewat URL publik, tetapi menulis, menimpa, dan menghapus tetap dijaga policy di atas. upsert butuh policy update (dan biasanya select) karena file lama ditimpa.

Langkah 2: service untuk Storage

Seperti Modul 13–14, semua akses Supabase dibungkus di satu service. Inisialisasi Supabase.initialize(url:, publishableKey:) tetap dilakukan di main() seperti di Modul 12.

📄 lib/services/foto_cloud_service.dart

// lib/services/foto_cloud_service.dart
import 'dart:io';

import 'package:path/path.dart' as p;
import 'package:supabase_flutter/supabase_flutter.dart';

class FotoCloudService {
  FotoCloudService(this._client);
  final SupabaseClient _client;

  static const String bucket = 'foto-profil';

  // Path di bucket: <id user>/profil.jpg (satu foto per user).
  String _pathProfil(String ekstensi) {
    final user = _client.auth.currentUser;
    if (user == null) {
      throw const StorageException('Silakan login terlebih dahulu.');
    }
    return '${user.id}/profil$ekstensi';
  }

  /// Mengunggah file foto dan mengembalikan path-nya di bucket.
  Future<String> unggah(File file) async {
    final ekstensi = p.extension(file.path).toLowerCase(); // .jpg / .png
    final path = _pathProfil(ekstensi);

    await _client.storage
        .from(bucket)
        .upload(
          path,
          file,
          fileOptions: FileOptions(
            contentType: ekstensi == '.png' ? 'image/png' : 'image/jpeg',
            upsert: true, // timpa foto lama dengan path yang sama
          ),
        );
    return path;
  }

  /// URL untuk bucket PUBLIC. cacheNonce membuat URL berbeda setiap
  /// versi foto, sehingga CDN dan cache gambar tidak menampilkan foto lama.
  String urlPublik(String path, {required String versi}) {
    return _client.storage.from(bucket).getPublicUrl(path, cacheNonce: versi);
  }

  /// URL sementara untuk bucket PRIVATE (berlaku 1 jam).
  Future<String> urlBertanda(String path) {
    return _client.storage.from(bucket).createSignedUrl(path, 60 * 60);
  }

  Future<void> hapus(String path) async {
    await _client.storage.from(bucket).remove([path]);
  }
}
MethodKegunaan
upload(path, File, fileOptions:)Mengunggah File dari dart:io (Android/iOS)
uploadBinary(path, Uint8List, fileOptions:)Mengunggah byte, misalnya dari await xfile.readAsBytes(). Juga jalan di Flutter Web
getPublicUrl(path)URL permanen, hanya untuk bucket public. Tidak memanggil jaringan (bukan Future)
createSignedUrl(path, detik)URL sementara untuk bucket private, kedaluwarsa setelah sekian detik
remove([path, ...])Menghapus satu atau beberapa file
  • Path diawali user.id agar cocok dengan policy storage.foldername(name)[1].
  • FileOptions(contentType:, upsert: true): contentType membuat browser dan Image.network tahu jenis file, upsert menimpa file lama alih-alih error "already exists".
  • Karena path-nya selalu sama, CDN Supabase dan Image.network bisa menyimpan versi lama. Parameter cacheNonce menambahkan penanda versi ke URL sehingga foto baru langsung terlihat.
  • Kesalahan dari Storage dilempar sebagai StorageException yang berisi message dan statusCode. Status 403 hampir selalu berarti policy belum dibuat atau path tidak diawali id user.

Langkah 3: memakai service dan menampilkan foto online

import 'dart:io';

import 'package:flutter/material.dart';
import 'package:supabase_flutter/supabase_flutter.dart';

import 'services/foto_cloud_service.dart';

final service = FotoCloudService(Supabase.instance.client);

Future<String?> unggahDanAmbilUrl(File foto) async {
  try {
    final path = await service.unggah(foto);
    final versi = DateTime.now().millisecondsSinceEpoch.toString();
    return service.urlPublik(path, versi: versi);
  } on StorageException catch (e) {
    debugPrint('Gagal unggah: ${e.message} (status ${e.statusCode})');
    return null;
  }
}

class FotoOnline extends StatelessWidget {
  const FotoOnline({super.key, required this.url});
  final String url;

  @override
  Widget build(BuildContext context) {
    return Image.network(
      url,
      width: 120,
      height: 160,
      fit: BoxFit.cover,
      loadingBuilder: (context, child, progress) => progress == null
          ? child
          : const SizedBox(
              width: 120,
              height: 160,
              child: Center(child: CircularProgressIndicator()),
            ),
      errorBuilder: (context, error, stackTrace) =>
          const Icon(Icons.broken_image, size: 48),
    );
  }
}
  • Simpan path foto (misalnya di kolom foto_path tabel profiles), bukan URL lengkap. URL bisa dibentuk ulang kapan saja, dan signed URL memang kedaluwarsa.
  • loadingBuilder dan errorBuilder membuat tampilan tetap rapi saat jaringan lambat atau file tidak ditemukan.
  • Kompres foto sebelum diunggah (maxWidth dan imageQuality di bagian 3). Mengunggah foto 6 MB lewat data seluler itu lambat dan memakan kuota Storage.

⚠️ Kesalahan umum

  • StorageException ... new row violates row-level security policy (403): policy belum ada, atau path tidak diawali auth.uid().
  • Memakai getPublicUrl pada bucket private: URL terbentuk tetapi gambarnya gagal dimuat (400/404). Gunakan createSignedUrl.
  • Mengunggah sebelum login: currentUser bernilai null. Pastikan halaman ini hanya bisa diakses setelah AuthGate Modul 13.
  • Menyimpan secret key/service_role di aplikasi agar "bisa unggah tanpa policy". Jangan pernah, seperti yang ditegaskan di Modul 12.
