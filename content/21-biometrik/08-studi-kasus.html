Studi kasus kita: Kunci Aplikasi Catatan Kuliah. Mahasiswa sering meminjamkan HP ke teman, padahal di dalamnya ada catatan kuliah, draf tugas, dan sesi login akun kampus. Kita menambahkan fitur yang biasa ada di aplikasi catatan: pengaturan on/off kunci biometrik, layar kunci saat aplikasi dibuka atau kembali dari background, dan fallback ke login ulang.

Kebutuhan

  1. Pengguna login dengan email dan kata sandi (versi demo; di Modul 13 memakai Supabase).
  2. Di halaman Pengaturan ada sakelar Kunci dengan biometrik. Saat dinyalakan, pengguna harus lolos autentikasi sekali sebagai konfirmasi.
  3. Jika kunci aktif: layar kunci muncul saat aplikasi dibuka, dan saat kembali dari background lebih dari 30 detik, di atas halaman apa pun yang sedang terbuka.
  4. Layar kunci menerima sidik jari, wajah, atau PIN HP. Jika gagal terus, pengguna bisa keluar dan login ulang.
  5. Logout menghapus token dan pengaturan kunci.

// lib/controllers/sesi_controller.dart
import 'package:get/get.dart';

import '../services/sesi_service.dart';

/// Status login. Pada proyek Modul 13, isi login() diganti dengan
/// pemanggilan AuthService Supabase; sisanya tetap sama.
class SesiController extends GetxController {
  SesiController(this._service, {String? tokenAwal, String? emailAwal})
    : _token = RxnString(tokenAwal),
      _email = RxnString(emailAwal);

  final SesiService _service;

  final RxnString _token;
  final RxnString _email;
  final _isLoading = false.obs;
  final _errorMessage = RxnString();

  bool get sudahLogin => _token.value != null;
  String get email => _email.value ?? '';
  bool get isLoading => _isLoading.value;
  String? get errorMessage => _errorMessage.value;

  /// Dipakai controller lain untuk worker ever().
  RxnString get tokenRx => _token;

  Future<bool> login({required String email, required String password}) async {
    _isLoading.value = true;
    _errorMessage.value = null;
    try {
      // DEMO: pura-pura menghubungi server.
      await Future<void>.delayed(const Duration(milliseconds: 600));
      if (!email.contains('@') || password.length < 6) {
        _errorMessage.value = 'Email atau kata sandi tidak valid.';
        return false;
      }
      // Di Modul 13: token = session.refreshToken dari Supabase.
      final token = 'demo-${DateTime.now().millisecondsSinceEpoch}';
      await _service.simpanSesi(email: email.trim(), token: token);
      _email.value = email.trim();
      _token.value = token;
      return true;
    } finally {
      _isLoading.value = false;
    }
  }

  Future<void> logout() async {
    await _service.hapusSemua();
    _email.value = null;
    _token.value = null; // AppGate otomatis menampilkan LoginView
  }
}
  • Konstruktor menerima tokenAwal dan emailAwal yang sudah dibaca di main(). RxnString(tokenAwal) membuat observable nullable dengan nilai awal tersebut.
  • tokenRx sengaja dibuka agar LockController bisa memasang worker ever, sama seperti nimRx di Modul 08.
  • login() versi demo menerima email apa pun yang mengandung @ dan kata sandi minimal 6 karakter, lalu membuat token palsu. Bagian ini yang diganti saat digabung dengan Modul 13.

Langkah 3: LoginView

📄 lib/views/login_view.dart

// lib/views/login_view.dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/sesi_controller.dart';

class LoginView extends StatefulWidget {
  const LoginView({super.key});

  @override
  State<LoginView> createState() => _LoginViewState();
}

class _LoginViewState extends State<LoginView> {
  final _emailController = TextEditingController();
  final _passwordController = TextEditingController();
  final _sesi = Get.find<SesiController>();

  @override
  void dispose() {
    _emailController.dispose();
    _passwordController.dispose();
    super.dispose();
  }

  Future<void> _masuk() async {
    await _sesi.login(
      email: _emailController.text,
      password: _passwordController.text,
    );
    // Tidak perlu navigasi: AppGate bereaksi saat token berubah.
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Masuk')),
      body: ListView(
        padding: const EdgeInsets.all(24),
        children: [
          TextField(
            controller: _emailController,
            keyboardType: TextInputType.emailAddress,
            decoration: const InputDecoration(labelText: 'Email kampus'),
          ),
          const SizedBox(height: 12),
          TextField(
            controller: _passwordController,
            obscureText: true,
            decoration: const InputDecoration(labelText: 'Kata sandi'),
          ),
          const SizedBox(height: 12),
          Obx(() {
            final error = _sesi.errorMessage;
            return error == null
                ? const SizedBox.shrink()
                : Text(
                    error,
                    style: TextStyle(
                      color: Theme.of(context).colorScheme.error,
                    ),
                  );
          }),
          const SizedBox(height: 12),
          Obx(
            () => FilledButton(
              onPressed: _sesi.isLoading ? null : _masuk,
              child: Text(_sesi.isLoading ? 'Memproses...' : 'Masuk'),
            ),
          ),
        ],
      ),
    );
  }
}

LoginView memakai StatefulWidget karena memiliki dua TextEditingController yang harus di-dispose. Setelah login berhasil tidak ada navigasi: AppGate bereaksi sendiri saat token berubah (pola AuthGate dari Modul 13).

📄 lib/views/pengaturan_view.dart

// lib/views/pengaturan_view.dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/lock_controller.dart';
import '../controllers/sesi_controller.dart';

class PengaturanView extends GetView<LockController> {
  const PengaturanView({super.key});

  Future<void> _ubahKunci(BuildContext context, bool aktif) async {
    final error = await controller.aturKunci(aktif);
    if (!context.mounted) return; // context dipakai setelah await
    ScaffoldMessenger.of(context).showSnackBar(
      SnackBar(
        content: Text(
          error ??
              (aktif
                  ? 'Kunci biometrik diaktifkan.'
                  : 'Kunci biometrik dimatikan.'),
        ),
      ),
    );
  }

  Future<void> _keluar(BuildContext context) async {
    await Get.find<SesiController>().logout();
    if (!context.mounted) return;
    // Tutup halaman Pengaturan; AppGate di bawahnya sudah menampilkan LoginView.
    Navigator.of(context).popUntil((route) => route.isFirst);
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Pengaturan')),
      body: ListView(
        children: [
          Obx(
            () => SwitchListTile(
              secondary: const Icon(Icons.fingerprint),
              title: const Text('Kunci dengan biometrik'),
              subtitle: Text(
                'Minta sidik jari/wajah saat aplikasi dibuka atau kembali '
                'dari background lebih dari '
                '${LockController.masaTenggang.inSeconds} detik.',
              ),
              value: controller.kunciAktif,
              onChanged: controller.sedangMemproses
                  ? null
                  : (aktif) => _ubahKunci(context, aktif),
            ),
          ),
          const Divider(),
          ListTile(
            leading: const Icon(Icons.logout),
            title: const Text('Keluar'),
            subtitle: const Text('Menghapus sesi dan pengaturan kunci'),
            onTap: () => _keluar(context),
          ),
        ],
      ),
    );
  }
}
  • SwitchListTile membaca controller.kunciAktif di dalam Obx. Sakelar tidak langsung berpindah saat diketuk; ia baru berubah setelah aturKunci berhasil dan state controller diperbarui. Jika autentikasi konfirmasi dibatalkan, sakelar tetap mati.
  • onChanged: null selama dialog tampil membuat sakelar nonaktif sementara.
  • if (!context.mounted) return; dipakai di _ubahKunci dan _keluar karena context dipakai lagi setelah await.

Langkah 5: AppGate dan KunciOverlay

Ada dua keputusan tampilan yang dipisah:

  • Sudah login atau belum? Diputuskan AppGate, halaman pertama di Navigator.
  • Sedang terkunci atau tidak? Diputuskan KunciOverlay, yang membungkus seluruh Navigator lewat GetMaterialApp.builder.

Kenapa tidak cukup di AppGate saja? Jika pengguna sedang di halaman Pengaturan lalu aplikasi terkunci, halaman Pengaturan berada di atas AppGate dan tetap terlihat. Overlay di atas Navigator menutupi halaman apa pun, tanpa menghapus isi halaman di bawahnya.

📄 lib/views/app_gate.dart

// lib/views/app_gate.dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/sesi_controller.dart';
import 'catatan_view.dart';
import 'login_view.dart';

/// Halaman pertama: memilih LoginView atau CatatanView sesuai status login.
/// Urusan kunci biometrik ditangani KunciOverlay, bukan di sini.
class AppGate extends GetView<SesiController> {
  const AppGate({super.key});

  @override
  Widget build(BuildContext context) {
    return Obx(
      () => controller.sudahLogin ? const CatatanView() : const LoginView(),
    );
  }
}

📄 lib/views/kunci_overlay.dart

// lib/views/kunci_overlay.dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

import '../controllers/lock_controller.dart';
import '../controllers/sesi_controller.dart';
import 'lock_view.dart';

/// Membungkus SELURUH Navigator. Saat terkunci, LockView menutupi halaman
/// apa pun yang sedang terbuka tanpa menghapus state halaman tersebut.
class KunciOverlay extends StatelessWidget {
  const KunciOverlay({super.key, required this.child});

  final Widget child;

  @override
  Widget build(BuildContext context) {
    final sesi = Get.find<SesiController>();
    final kunci = Get.find<LockController>();

    return Obx(
      () => Stack(
        fit: StackFit.expand,
        children: [
          child, // selalu di posisi pertama agar state Navigator tidak hilang
          if (sesi.sudahLogin && kunci.terkunci)
            const Positioned.fill(child: LockView()),
        ],
      ),
    );
  }
}
  • Stack selalu dibuat, dan child (Navigator) selalu berada di posisi pertama. Jika kita menulis terkunci ? LockView() : child, Navigator akan dibuang dan dibuat ulang setiap kali terkunci, sehingga semua halaman yang terbuka hilang.
  • Positioned.fill membuat LockView menutupi seluruh layar dan menahan semua sentuhan ke halaman di bawahnya.

Langkah 6: main.dart

📄 lib/main.dart

// lib/main.dart
import 'package:flutter/material.dart';
import 'package:get/get.dart';

import 'controllers/catatan_controller.dart';
import 'controllers/lock_controller.dart';
import 'controllers/sesi_controller.dart';
import 'services/biometric_service.dart';
import 'services/sesi_service.dart';
import 'views/app_gate.dart';
import 'views/kunci_overlay.dart';

Future<void> main() async {
  WidgetsFlutterBinding.ensureInitialized();

  // Baca state awal SEBELUM UI muncul, agar catatan tidak sempat terlihat.
  final sesiService = SesiService();
  final token = await sesiService.bacaToken();
  final email = await sesiService.bacaEmail();
  final kunciAktif = await sesiService.kunciBiometrikAktif();

  final sesi = Get.put(
    SesiController(sesiService, tokenAwal: token, emailAwal: email),
  );
  Get.put(
    LockController(
      BiometricService(),
      sesiService,
      sesi,
      kunciAktifAwal: kunciAktif,
    ),
  );
  Get.put(CatatanController());

  runApp(const CatatanKuliahApp());
}

class CatatanKuliahApp extends StatelessWidget {
  const CatatanKuliahApp({super.key});

  @override
  Widget build(BuildContext context) {
    return GetMaterialApp(
      title: 'Catatan Kuliah',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),
      // builder membungkus Navigator: layar kunci menutupi semua halaman.
      builder: (context, child) => KunciOverlay(child: child!),
      home: const AppGate(),
    );
  }
}
  • Token, email, dan status kunci dibaca dengan await sebelum runApp. Akibatnya frame pertama sudah tahu harus menampilkan layar kunci, sehingga tidak ada "kedipan" isi catatan.
  • Get.put(SesiController(...)) mengembalikan instance yang langsung diteruskan ke LockController. Urutan pendaftaran penting: SesiController harus ada lebih dulu.
  • builder: (context, child) => KunciOverlay(child: child!) menempatkan overlay di atas Navigator.

Menggabungkan dengan proyek Modul 13/14

Di proyek Catatan Kuliah yang memakai Supabase, Anda tidak perlu SesiController demo. Supabase sudah menyimpan sesinya sendiri secara persisten. Yang perlu diubah:

  • LockController menerima AuthController dari Modul 13 sebagai pengganti SesiController: sudahLogin menjadi currentSession != null, worker ever dipasang pada observable sesi, dan loginUlang() memanggil signOut().
  • SesiService cukup menyimpan pengaturan kunci_biometrik_aktif. Saat logout, hapus pengaturan itu juga.
  • KunciOverlay dan LockView dipakai tanpa perubahan.

⚠️ Kesalahan umum di studi kasus

  • Lupa mengganti MainActivity menjadi FlutterFragmentActivity: layar kunci muncul tetapi dialog tidak pernah tampil, dan pesan berisi uiUnavailable.
  • Menaruh layar kunci sebagai home atau memakai Get.to(LockView()). Pengguna bisa menekan tombol kembali dan melewati kunci.
  • Memanggil bukaKunci() dari build() view. Setiap rebuild memunculkan dialog baru.
