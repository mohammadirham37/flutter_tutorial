Dialog biometrik saja belum membuat aplikasi aman. Yang perlu dipikirkan: apa yang dilindungi dan kapan aplikasi harus terkunci lagi. Section ini membahas pola yang dipakai aplikasi perbankan dan catatan pribadi: token sesi disimpan aman, biometrik menjadi gerbang untuk membuka aplikasi, dan aplikasi terkunci ulang setelah ditinggal ke background.

Kita bungkus flutter_secure_storage dalam satu service. Pada proyek Modul 13, Supabase sudah menyimpan sesinya sendiri; service ini menyimpan pengaturan kunci, dan pola yang sama berlaku untuk token dari backend lain (REST API Modul 09).

📄 lib/services/sesi_service.dart

// lib/services/sesi_service.dart
import 'package:flutter_secure_storage/flutter_secure_storage.dart';

/// Menyimpan sesi login dan pengaturan kunci di Keystore/Keychain.
class SesiService {
  SesiService({FlutterSecureStorage? storage})
    : _storage = storage ?? const FlutterSecureStorage();

  final FlutterSecureStorage _storage;

  static const _kunciToken = 'refresh_token';
  static const _kunciEmail = 'email';
  static const _kunciBiometrik = 'kunci_biometrik_aktif';

  Future<String?> bacaToken() => _storage.read(key: _kunciToken);

  Future<String?> bacaEmail() => _storage.read(key: _kunciEmail);

  Future<void> simpanSesi({
    required String email,
    required String token,
  }) async {
    await _storage.write(key: _kunciEmail, value: email);
    await _storage.write(key: _kunciToken, value: token);
  }

  Future<bool> kunciBiometrikAktif() async =>
      await _storage.read(key: _kunciBiometrik) == 'true';

  Future<void> aturKunciBiometrik(bool aktif) =>
      _storage.write(key: _kunciBiometrik, value: aktif.toString());

  /// Dipanggil saat logout: token DAN pengaturan kunci ikut dihapus.
  Future<void> hapusSemua() => _storage.deleteAll();
}
  • Semua nama kunci penyimpanan ditulis sekali sebagai konstanta privat, sehingga tidak ada salah ketik di tempat lain.
  • Secure storage hanya menyimpan String, jadi nilai bool disimpan sebagai 'true'/'false'.
  • hapusSemua() menghapus token dan pengaturan sekaligus. Setelah logout, pengguna berikutnya di HP yang sama tidak mewarisi pengaturan kunci.

Kapan aplikasi harus terkunci?

  1. Saat aplikasi dibuka (cold start) jika pengguna sudah login dan fitur kunci aktif.
  2. Saat kembali dari background setelah ditinggal lebih lama dari masa tenggang (misalnya 30 detik). Tanpa masa tenggang, pengguna yang hanya membuka notifikasi sebentar akan diminta sidik jari terus, dan itu menjengkelkan.

Untuk mendeteksi poin 2, Flutter menyediakan AppLifecycleListener (pengganti modern untuk WidgetsBindingObserver.didChangeAppLifecycleState). Urutan state saat aplikasi ditinggal lalu dibuka lagi:

resumed → inactive → hidden → paused     (pengguna menekan Home)
paused → hidden → inactive → resumed     (pengguna kembali ke aplikasi)

inactive juga terjadi saat notifikasi ditarik turun atau dialog sistem tampil, jadi momen yang aman untuk dicatat adalah onPause (benar-benar di background) dan onResume (aktif kembali).

Contoh lengkap: kunci otomatis setelah background

Contoh ini belum memakai biometrik, agar fokus pada lifecycle. Masa tenggang dibuat 5 detik supaya mudah dicoba: tekan Home, tunggu lebih dari 5 detik, lalu buka lagi aplikasinya.

📄 lib/main.dart

import 'package:flutter/material.dart';

void main() => runApp(const MaterialApp(home: DemoKunciOtomatis()));

class DemoKunciOtomatis extends StatefulWidget {
  const DemoKunciOtomatis({super.key});

  @override
  State<DemoKunciOtomatis> createState() => _DemoKunciOtomatisState();
}

class _DemoKunciOtomatisState extends State<DemoKunciOtomatis> {
  static const _masaTenggang = Duration(seconds: 5); // kecil agar mudah dicoba

  late final AppLifecycleListener _listener;
  DateTime? _waktuKeBackground;
  bool _terkunci = false;
  final _log = <String>[];

  @override
  void initState() {
    super.initState();
    _listener = AppLifecycleListener(
      onStateChange: (state) => setState(() => _log.insert(0, state.name)),
      onPause: () => _waktuKeBackground = DateTime.now(),
      onResume: _saatKembali,
    );
  }

  void _saatKembali() {
    final sejak = _waktuKeBackground;
    _waktuKeBackground = null;
    if (sejak == null) return;
    if (DateTime.now().difference(sejak) >= _masaTenggang) {
      setState(() => _terkunci = true);
    }
  }

  @override
  void dispose() {
    _listener.dispose(); // wajib, sama seperti StreamSubscription
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    if (_terkunci) {
      return Scaffold(
        body: Center(
          child: FilledButton.icon(
            // Di section berikutnya tombol ini memanggil local_auth.
            onPressed: () => setState(() => _terkunci = false),
            icon: const Icon(Icons.lock_open),
            label: const Text('Terkunci - ketuk untuk membuka'),
          ),
        ),
      );
    }
    return Scaffold(
      appBar: AppBar(title: const Text('Riwayat Lifecycle')),
      body: ListView(
        children: [
          for (final item in _log) ListTile(dense: true, title: Text(item)),
        ],
      ),
    );
  }
}

Penjelasan:

  • AppLifecycleListener dibuat di initState dan wajib di-dispose. Jika lupa, callback tetap dipanggil setelah widget dibuang.
  • onPause hanya mencatat waktu. Keputusan mengunci diambil di onResume dengan membandingkan selisih waktu terhadap masa tenggang.
  • onStateChange mencatat setiap perubahan state ke daftar, berguna untuk melihat urutan inactive, hidden, paused dengan mata sendiri.

⚠️ Jebakan: dialog biometrik juga memicu lifecycle

Di beberapa perangkat, munculnya dialog biometrik membuat aplikasi sempat berpindah state. Jika logika kunci tidak hati-hati, aplikasi bisa terkunci lagi tepat setelah berhasil dibuka, berulang tanpa henti. Solusinya: simpan flag "sedang autentikasi" dan abaikan event lifecycle selama flag itu aktif. Pola ini dipakai di LockController section 7.

Lanjutan: kunci Keystore yang terikat biometrik

Pola di atas memakai biometrik sebagai gerbang UI: token tetap bisa dibaca kode aplikasi tanpa sidik jari, hanya tampilannya yang ditahan. Untuk data yang sangat sensitif, Android mendukung kunci enkripsi yang baru bisa dipakai setelah pengguna lolos biometrik (konsep CryptoObject pada BiometricPrompt di modul Kotlin lama). flutter_secure_storage menyediakannya lewat AndroidOptions.biometric:

import 'package:flutter_secure_storage/flutter_secure_storage.dart';

// Lanjutan (khusus Android): kunci enkripsi di Keystore hanya bisa
// dipakai setelah pengguna lolos biometrik/PIN.
const storageTerikatBiometrik = FlutterSecureStorage(
  aOptions: AndroidOptions.biometric(
    enforceBiometrics: true,
    biometricPromptTitle: 'Buka data rahasia',
    biometricPromptSubtitle: 'Gunakan sidik jari atau PIN',
  ),
);

Future<String?> bacaTokenTerlindungi() =>
    storageTerikatBiometrik.read(key: 'refresh_token');

Dengan opsi ini, operasi baca/tulis memunculkan dialog biometrik dari plugin storage itu sendiri (Android 9 ke atas). Pilihan biometricType: AndroidBiometricType.strongBiometricOnly membatasi hanya ke Class 3. Untuk proyek kuliah, pola gerbang UI dengan local_auth sudah cukup dan lebih mudah diuji; pakai opsi ini jika dosen meminta tingkat keamanan lebih tinggi.
