Kabar baiknya, biometrik bisa diuji tanpa HP fisik. Android Emulator punya sensor sidik jari virtual, dan iOS Simulator punya Face ID/Touch ID tiruan. Section ini juga merangkum kesalahan yang paling sering terjadi dan hal-hal yang perlu diperhatikan soal keamanan dan privasi.

Menguji di Android Emulator

  1. Pakai AVD dengan image Google APIs atau Google Play (Android 10 ke atas disarankan).
  2. Pasang kunci layar dulu: Settings → Security (atau Security & privacy) → Screen lock → PIN. Sidik jari tidak bisa didaftarkan tanpa kunci layar.
  3. Pilih Fingerprint Unlock (namanya bisa "Pixel Imprint" atau "Fingerprint"). Saat diminta menempelkan jari, buka Extended Controls emulator (tombol ... di panel samping) → Fingerprint.
  4. Pilih Finger 1 lalu klik Touch sensor. Ulangi beberapa kali sampai pendaftaran 100%.
  5. Jalankan aplikasi. Saat dialog biometrik muncul, buka lagi Extended Controls → Fingerprint → Touch sensor dengan Finger 1 untuk berhasil.
  6. Untuk menguji jari yang salah, pilih Finger 2 (yang tidak didaftarkan) lalu klik Touch sensor. Ulangi 5 kali untuk memicu temporaryLockout.

Cara alternatif lewat terminal saat emulator menyala:

adb -e emu finger touch 1   # menempelkan Finger 1 (terdaftar)
adb -e emu finger touch 2   # menempelkan Finger 2 (tidak terdaftar)

Menguji di iOS Simulator (macOS)

  • Menu Features → Face ID → Enrolled untuk mengaktifkan Face ID tiruan.
  • Saat dialog muncul: Features → Face ID → Matching Face (berhasil) atau Non-matching Face (gagal).
  • Untuk menguji izin ditolak, jawab "Don't Allow" pada dialog izin Face ID pertama, lalu periksa bahwa aplikasi mendapat noBiometricHardware dan tombol "Buka Pengaturan" muncul.

ℹ️ Batasan emulator

Emulator Android hanya menyediakan sensor sidik jari; pengenalan wajah tidak bisa diuji. Perilaku Class 2 (wajah 2D) dan konfirmasi sensitiveTransaction hanya bisa dilihat di HP fisik yang memilikinya. Di iOS Simulator, dialog kode sandi fallback juga tidak sepenuhnya sama dengan perangkat asli.

Pertimbangan keamanan dan privasi

  • Data biometrik tidak pernah sampai ke aplikasi. Jangan pernah meminta pengguna memotret sidik jari atau wajahnya untuk "verifikasi" buatan sendiri. Selain berbahaya, itu melanggar prinsip minimisasi data pribadi (UU No. 27 Tahun 2022 tentang Pelindungan Data Pribadi menggolongkan data biometrik sebagai data pribadi yang bersifat spesifik).
  • Biometrik tidak menggantikan otorisasi server. Server tetap memeriksa token pada setiap request. Hasil true dari authenticate tidak boleh dikirim ke server sebagai bukti login, karena nilai itu mudah dipalsukan oleh aplikasi yang dimodifikasi.
  • Gerbang UI vs kunci kriptografi. Pola di modul ini (gerbang UI) cukup untuk melindungi dari orang yang meminjam HP. Untuk melindungi dari HP yang di-root, data harus dienkripsi dengan kunci yang terikat biometrik (AndroidOptions.biometric, section 6).
  • Siapa pun yang sidik jarinya terdaftar di HP bisa membuka aplikasi. Jika pemilik HP mendaftarkan jari pasangannya, aplikasi tidak bisa membedakan. Sebutkan hal ini di teks pengaturan bila datanya sangat pribadi.
  • Pratinjau di daftar aplikasi terbaru. Layar kunci tidak menyembunyikan tangkapan layar yang dibuat sistem saat aplikasi masuk background. Aplikasi perbankan biasanya menambahkan FLAG_SECURE di Android atau tampilan penutup di iOS; ini di luar cakupan modul.
  • Keychain iOS tidak terhapus saat uninstall. Token di flutter_secure_storage bisa tetap ada setelah aplikasi dipasang ulang. Jika itu tidak diinginkan, simpan penanda "sudah pernah dibuka" di SharedPreferences (yang terhapus saat uninstall) dan panggil hapusSemua() pada pembukaan pertama.
