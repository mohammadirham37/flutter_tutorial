Pernahkah Anda membuka aplikasi m-banking hanya dengan menempelkan jari? Aplikasi itu tidak mengirim sidik jari Anda ke bank. HP-lah yang mencocokkan sidik jari, lalu cuma memberi tahu aplikasi "cocok" atau "tidak cocok". Di modul ini kita membuat fitur serupa dengan Flutter: kunci aplikasi memakai sidik jari, wajah, atau PIN HP.

Biometrik sebagai faktor autentikasi

Dalam keamanan, ada tiga jenis bukti identitas (faktor):

FaktorContohKelemahan
Sesuatu yang Anda ketahuiKata sandi, PINBisa ditebak, diintip, atau lupa
Sesuatu yang Anda milikiHP yang sudah login, kartu, kode OTPBisa hilang atau dicuri
Sesuatu yang melekat pada AndaSidik jari, wajah, irisTidak bisa diganti jika bocor

Saat aplikasi Anda memakai biometrik, sebenarnya ada dua faktor sekaligus: HP yang menyimpan sesi login (dimiliki) dan sidik jari pemiliknya (melekat). Itu sebabnya biometrik cocok untuk membuka kunci sesi yang sudah ada di perangkat.

Tingkat keamanan biometrik di Android

Android Compatibility Definition membagi sensor biometrik menjadi tiga kelas berdasarkan seberapa sulit sensor itu ditipu (misalnya dengan foto atau cetakan jari palsu):

KelasNama di APIContohBisa dipakai aplikasi?
Class 3 (Strong)BIOMETRIC_STRONGSensor sidik jari, pemindai wajah 3DYa, termasuk untuk membuka kunci kriptografi di Keystore
Class 2 (Weak)BIOMETRIC_WEAKPengenalan wajah dari kamera depan 2D biasaYa, tetapi hanya sebagai konfirmasi, tidak untuk kunci Keystore
Class 1 (Convenience)tidak adaFace unlock sederhana di HP murahTidak. Hanya untuk membuka layar HP

Selain biometrik, Android punya device credential (DEVICE_CREDENTIAL): PIN, pola, atau sandi kunci layar. Kredensial ini biasanya menjadi fallback ketika sensor gagal membaca atau sedang terkunci karena terlalu banyak percobaan.

Di iOS: Face ID dan Touch ID

iPhone dan iPad memakai Face ID (kamera TrueDepth 3D) atau Touch ID (sensor sidik jari). Keduanya setara Class 3. Fallback-nya adalah kode sandi (passcode) perangkat. Bedanya dengan Android, iOS meminta izin pengguna saat aplikasi pertama kali memakai Face ID, sehingga aplikasi wajib menulis alasan pemakaian di Info.plist.

Biometrik hanya membuka kunci lokal

Ini konsep terpenting di modul ini. Bandingkan dua alur berikut:

LOGIN (Modul 13)                        BUKA KUNCI BIOMETRIK (modul ini)
----------------                        --------------------------------
email + kata sandi                      sidik jari / wajah / PIN HP
      |                                       |
      v                                       v
server Supabase memeriksa               HP memeriksa di chip aman (TEE)
      |                                       |
      v                                       v
server memberi token sesi               aplikasi hanya menerima true/false
      |                                       |
      v                                       v
token disimpan di secure storage        jika true: tampilkan isi aplikasi
  • Server tidak tahu pengguna memakai sidik jari. Server hanya melihat token sesi yang sah.
  • Biometrik bukan pengganti login. Pengguna tetap harus login dengan email dan kata sandi minimal sekali di perangkat itu. Setelah itu, biometrik menjaga agar orang lain yang meminjam HP tidak bisa membuka aplikasi.
  • Jika biometrik gagal terus, harus selalu ada jalan keluar: login ulang dengan email dan kata sandi.

ℹ️ Data biometrik tidak pernah sampai ke aplikasi

Template sidik jari dan wajah disimpan di area terisolasi milik prosesor (Trusted Execution Environment di Android, Secure Enclave di iOS). Aplikasi Flutter, termasuk kode yang kita tulis, tidak bisa membaca gambar sidik jari atau foto wajah. Yang kita terima hanyalah hasil true, false, atau kode error. Karena itu, aplikasi juga tidak bisa tahu jari yang mana yang dipakai, atau siapa pemiliknya.
