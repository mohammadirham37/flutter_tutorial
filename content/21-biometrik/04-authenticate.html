Inti local_auth adalah satu method: authenticate(). Method ini menampilkan dialog sistem, menunggu pengguna menempelkan jari atau menatap kamera, lalu mengembalikan hasilnya. Tampilan dialog sepenuhnya milik sistem operasi, sehingga aplikasi lain tidak bisa memalsukannya.

ℹ️ API berubah di local_auth versi 3

Banyak tutorial lama menulis authenticate(options: const AuthenticationOptions(biometricOnly: true, stickyAuth: true)) dan menangkap PlatformException. Sejak versi mayor 3, kelas AuthenticationOptions dihapus dari authenticate; opsinya menjadi parameter langsung (stickyAuth berganti nama menjadi persistAcrossBackgrounding, useErrorDialogs dihapus), dan error dilempar sebagai LocalAuthException dengan kode berupa enum. Modul ini memakai API baru tersebut.

Contoh kecil

final auth = LocalAuthentication();
final berhasil = await auth.authenticate(
  localizedReason: 'Verifikasi untuk melihat transkrip nilai',
);

localizedReason wajib diisi dan tidak boleh kosong. Teks ini muncul di dialog, jadi jelaskan untuk apa autentikasi diminta.

Parameter authenticate()

ParameterDefaultFungsi
localizedReasonwajibAlasan yang ditampilkan di dialog.
biometricOnlyfalsefalse: pengguna boleh memakai PIN/pola/sandi HP sebagai fallback. true: hanya biometrik, dan dialog Android menampilkan tombol Batal.
persistAcrossBackgroundingfalseJika aplikasi masuk background saat dialog tampil (misalnya ada telepon), plugin menunggu lalu mengulang autentikasi saat aplikasi kembali, bukan langsung gagal.
sensitiveTransactiontrueDi Android: setelah wajah dikenali, pengguna masih harus menekan tombol konfirmasi. Ini mencegah aplikasi terbuka hanya karena pengguna kebetulan melihat layar.
authMessagesteks bawaanMengganti judul, petunjuk, dan teks tombol dialog per platform.

Hasil: true, false, atau exception

  • true: pengguna berhasil diverifikasi.
  • false: verifikasi gagal tanpa efek samping (misalnya di iOS wajah tidak dikenali). Di Android, jari yang salah tidak menutup dialog; sistem hanya menampilkan "Tidak dikenali" dan pengguna bisa mencoba lagi.
  • LocalAuthException: semua kasus lain, termasuk pengguna menekan Batal (userCanceled), sensor terkunci, atau belum ada sidik jari. Rinciannya di section 5.

Contoh lengkap: membuka transkrip nilai

Aplikasi berikut menyembunyikan IPK sampai pengguna lolos verifikasi. Sakelar di atas mengatur apakah PIN HP boleh dipakai.

📄 lib/main.dart

import 'package:flutter/material.dart';
import 'package:local_auth/local_auth.dart';

void main() => runApp(const MaterialApp(home: NilaiRahasiaPage()));

class NilaiRahasiaPage extends StatefulWidget {
  const NilaiRahasiaPage({super.key});

  @override
  State<NilaiRahasiaPage> createState() => _NilaiRahasiaPageState();
}

class _NilaiRahasiaPageState extends State<NilaiRahasiaPage> {
  final _auth = LocalAuthentication();

  bool _hanyaBiometrik = false;
  bool _sedangProses = false;
  bool _terbuka = false;
  String _status = 'Transkrip nilai masih tersembunyi.';

  Future<void> _bukaTranskrip() async {
    setState(() => _sedangProses = true);
    String status;
    bool terbuka = false;

    try {
      terbuka = await _auth.authenticate(
        localizedReason: 'Verifikasi untuk melihat transkrip nilai',
        biometricOnly: _hanyaBiometrik,
      );
      status = terbuka
          ? 'Berhasil diverifikasi.'
          : 'Tidak dikenali, coba lagi.';
    } on LocalAuthException catch (e) {
      // Kode error dibahas lengkap di section berikutnya.
      status = 'Gagal: ${e.code.name}';
    }

    if (!mounted) return;
    setState(() {
      _sedangProses = false;
      _terbuka = terbuka;
      _status = status;
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Transkrip Nilai')),
      body: ListView(
        padding: const EdgeInsets.all(16),
        children: [
          SwitchListTile(
            title: const Text('Hanya biometrik'),
            subtitle: const Text('Matikan agar PIN/pola HP boleh dipakai'),
            value: _hanyaBiometrik,
            onChanged: (nilai) => setState(() => _hanyaBiometrik = nilai),
          ),
          const SizedBox(height: 16),
          Card(
            child: ListTile(
              leading: Icon(_terbuka ? Icons.lock_open : Icons.lock),
              title: Text(_terbuka ? 'IPK: 3,72' : 'IPK: ****'),
              subtitle: Text(_status),
            ),
          ),
          const SizedBox(height: 16),
          FilledButton.icon(
            onPressed: _sedangProses ? null : _bukaTranskrip,
            icon: const Icon(Icons.fingerprint),
            label: Text(_sedangProses ? 'Menunggu...' : 'Lihat Transkrip'),
          ),
          if (_terbuka)
            TextButton(
              onPressed: () => setState(() {
                _terbuka = false;
                _status = 'Transkrip disembunyikan lagi.';
              }),
              child: const Text('Sembunyikan'),
            ),
        ],
      ),
    );
  }
}

Penjelasan:

  • _sedangProses menonaktifkan tombol selama dialog tampil. Memanggil authenticate dua kali bersamaan menghasilkan error authInProgress.
  • Hasil try/catch ditampung dulu di variabel lokal status dan terbuka, baru kemudian satu setState dipanggil setelah pengecekan mounted. Pola ini menghindari setState setelah widget dibuang.
  • e.code bertipe enum LocalAuthExceptionCode, jadi e.code.name memberi teks seperti userCanceled. Untuk pengguna, teks ini harus diterjemahkan (section 5).
  • Coba matikan dan nyalakan sakelar "Hanya biometrik". Saat mati, dialog Android menampilkan pilihan "Gunakan PIN". Saat menyala, pilihan itu hilang dan muncul tombol Batal.

Mengganti teks dialog (opsional)

Teks bawaan dialog mengikuti bahasa sistem. Jika ingin teks sendiri, pakai authMessages. Kelas pesannya ada di package implementasi platform, jadi package tersebut perlu ditambahkan ke pubspec.yaml:

flutter pub add local_auth_android local_auth_darwin

import 'package:local_auth/local_auth.dart';
import 'package:local_auth_android/local_auth_android.dart';
import 'package:local_auth_darwin/local_auth_darwin.dart';

final _auth = LocalAuthentication();

Future<bool> verifikasiDenganPesanSendiri() {
  return _auth.authenticate(
    localizedReason: 'Verifikasi untuk melihat transkrip nilai',
    authMessages: const <AuthMessages>[
      AndroidAuthMessages(
        signInTitle: 'Verifikasi Identitas',
        signInHint: 'Sentuh sensor sidik jari',
        cancelButton: 'Batal',
      ),
      IOSAuthMessages(
        cancelButton: 'Batal',
        localizedFallbackTitle: 'Pakai Kode Sandi',
      ),
    ],
  );
}

AndroidAuthMessages mengatur judul (signInTitle), petunjuk (signInHint), dan tombol Batal (cancelButton, hanya tampil jika biometricOnly: true). IOSAuthMessages mengatur tombol Batal dan tombol fallback ke kode sandi.

⚠️ Kesalahan umum

  • Memanggil authenticate di initState halaman pertama. Pada saat itu Activity belum tentu siap menampilkan dialog, dan hasilnya error uiUnavailable. Panggil setelah frame pertama (misalnya dari tombol, atau dari onReady controller GetX seperti di section 7).
  • Menganggap false berarti "dibatalkan". Di Android, Batal dilempar sebagai exception userCanceled, bukan false.
  • Menulis localizedReason: ''. Teks kosong ditolak.
