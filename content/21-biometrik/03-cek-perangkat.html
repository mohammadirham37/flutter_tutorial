Sebelum menawarkan fitur "kunci dengan sidik jari", aplikasi perlu tahu apakah perangkat mampu. Ada HP tanpa sensor, ada HP yang sensornya ada tetapi belum ada jari yang didaftarkan, dan ada HP yang bahkan belum memakai PIN layar. local_auth menyediakan tiga pemeriksaan untuk membedakannya.

Tiga pemeriksaan dasar

APIHasilArti
isDeviceSupported()Future<bool>Perangkat bisa melakukan autentikasi lokal: biometrik atau PIN/pola/sandi.
canCheckBiometrics (getter)Future<bool>Ada perangkat keras biometrik. Belum tentu sudah ada jari/wajah terdaftar.
getAvailableBiometrics()Future<List<BiometricType>>Biometrik yang sudah terdaftar dan boleh dipakai aplikasi.

Contoh kecil, langsung di dalam fungsi async:

final auth = LocalAuthentication();
final bisaAutentikasi = await auth.canCheckBiometrics || await auth.isDeviceSupported();
final terdaftar = await auth.getAvailableBiometrics();
debugPrint('bisa: $bisaAutentikasi, terdaftar: $terdaftar');

Contoh lengkap: halaman diagnosa biometrik

Program berikut menampilkan hasil ketiga pemeriksaan. Jalankan di emulator sebelum dan sesudah mendaftarkan sidik jari (caranya di section 9) untuk melihat perbedaannya.

📄 lib/main.dart

import 'package:flutter/material.dart';
import 'package:local_auth/local_auth.dart';

void main() => runApp(const MaterialApp(home: CekBiometrikPage()));

class CekBiometrikPage extends StatefulWidget {
  const CekBiometrikPage({super.key});

  @override
  State<CekBiometrikPage> createState() => _CekBiometrikPageState();
}

class _CekBiometrikPageState extends State<CekBiometrikPage> {
  final _auth = LocalAuthentication();

  bool? _perangkatMendukung;
  bool? _adaSensor;
  List<BiometricType> _terdaftar = [];

  @override
  void initState() {
    super.initState();
    _periksa();
  }

  Future<void> _periksa() async {
    final mendukung = await _auth.isDeviceSupported();
    final adaSensor = await _auth.canCheckBiometrics;
    final terdaftar = await _auth.getAvailableBiometrics();

    if (!mounted) return; // widget mungkin sudah ditutup selama await
    setState(() {
      _perangkatMendukung = mendukung;
      _adaSensor = adaSensor;
      _terdaftar = terdaftar;
    });
  }

  String _teks(bool? nilai) => switch (nilai) {
    null => 'memeriksa...',
    true => 'Ya',
    false => 'Tidak',
  };

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Cek Biometrik')),
      body: ListView(
        children: [
          ListTile(
            leading: const Icon(Icons.phonelink_lock),
            title: const Text('isDeviceSupported()'),
            subtitle: const Text('Biometrik ATAU PIN/pola/sandi tersedia'),
            trailing: Text(_teks(_perangkatMendukung)),
          ),
          ListTile(
            leading: const Icon(Icons.sensors),
            title: const Text('canCheckBiometrics'),
            subtitle: const Text('Ada perangkat keras biometrik'),
            trailing: Text(_teks(_adaSensor)),
          ),
          ListTile(
            leading: const Icon(Icons.fingerprint),
            title: const Text('getAvailableBiometrics()'),
            subtitle: Text(
              _terdaftar.isEmpty
                  ? 'Belum ada biometrik yang terdaftar'
                  : _terdaftar.map((b) => b.name).join(', '),
            ),
          ),
          Padding(
            padding: const EdgeInsets.all(16),
            child: FilledButton.icon(
              onPressed: _periksa,
              icon: const Icon(Icons.refresh),
              label: const Text('Periksa ulang'),
            ),
          ),
        ],
      ),
    );
  }
}

Penjelasan:

  • LocalAuthentication() adalah pintu masuk plugin. Membuat objek ini murah, tidak ada proses berat di konstruktornya.
  • Ketiga pemeriksaan bersifat async karena harus bertanya ke sistem operasi lewat platform channel. Karena itu _periksa() dipanggil dari initState tanpa await, lalu hasilnya ditampilkan lewat setState.
  • if (!mounted) return; wajib ada setelah await. Jika pengguna menutup halaman sebelum pemeriksaan selesai, setState pada widget yang sudah dibuang akan memicu error.
  • bool? dengan nilai awal null dipakai untuk membedakan "belum diperiksa" dari "tidak".

Nilai BiometricType berbeda antara Android dan iOS

PlatformNilai yang mungkin munculKeterangan
Androidweak, strongAndroid tidak memberi tahu jenis sensornya, hanya kelasnya. Sidik jari Class 3 biasanya muncul sebagai [weak, strong] karena sensor Strong juga memenuhi syarat Weak.
iOSface atau fingerprintFace ID atau Touch ID. Jika izin Face ID ditolak, daftar ini kosong walaupun wajah sudah terdaftar.

💡 Tips

Jangan menulis logika seperti "jika ada BiometricType.fingerprint maka tampilkan ikon sidik jari". Di Android nilai itu hampir tidak pernah muncul. Cukup cek daftar.isNotEmpty untuk tahu bahwa ada biometrik yang siap dipakai, dan pakai ikon umum seperti Icons.fingerprint atau teks "biometrik".

⚠️ Perhatian

canCheckBiometrics == true tidak berarti pengguna sudah mendaftarkan sidik jari. Untuk fitur kunci aplikasi yang boleh memakai PIN sebagai fallback, pemeriksaan yang paling tepat adalah isDeviceSupported(). Untuk fitur yang hanya menerima biometrik, pastikan getAvailableBiometrics() tidak kosong.
