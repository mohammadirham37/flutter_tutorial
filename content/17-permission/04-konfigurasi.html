Package permission_handler adalah plugin paling populer untuk memeriksa dan meminta izin di Android dan iOS dengan satu API Dart. Sebelum menulis kode, konfigurasi platformnya harus beres dulu, karena hampir semua masalah izin berasal dari konfigurasi yang terlewat.

Langkah 1: pasang package

flutter pub add permission_handler get

Package get ikut dipasang karena section 7 dan studi kasus memakai GetX (Modul 08).

Langkah 2: Android, compileSdk

Versi terbaru permission_handler dikompilasi terhadap Android SDK yang lebih baru daripada nilai bawaan proyek Flutter. Jika flutter run gagal dengan pesan seperti di bawah, naikkan compileSdk sesuai angka yang diminta di pesan tersebut.

Your project is configured to compile against Android SDK 36, but the following
plugin(s) require to be compiled against a higher Android SDK version:
- permission_handler_android compiles against Android SDK 37
...
Dependency ':permission_handler_android' requires libraries and applications that
depend on it to compile against version 37 or later of the Android APIs.
:app is currently compiled against android-36.

📄 android/app/build.gradle.kts (potongan)

android {
    namespace = "id.ac.kampus.contoh_hardware"
    // Semula: compileSdk = flutter.compileSdkVersion
    compileSdk = 37
    // ...
    defaultConfig {
        // minSdk dan targetSdk biarkan memakai nilai bawaan Flutter
        minSdk = flutter.minSdkVersion
        targetSdk = flutter.targetSdkVersion
        // ...
    }
}

Pastikan SDK Platform versi tersebut sudah terpasang (Android Studio → SDK Manager → SDK Platforms). compileSdk hanya menentukan API yang boleh dipakai saat kompilasi; perilaku aplikasi di perangkat tetap ditentukan oleh targetSdk. Angka di pesan error bisa berbeda seiring rilis package, jadi selalu ikuti pesan error dan README package.

Langkah 3: Android, deklarasi izin di manifest

Tulis semua izin yang mungkin diminta aplikasi di manifest main (bukan debug), di luar tag <application>. Untuk studi kasus Pusat Izin, kita butuh kamera, lokasi, mikrofon, dan notifikasi.

📄 android/app/src/main/AndroidManifest.xml (potongan)

<manifest xmlns:android="http://schemas.android.com/apk/res/android">
    <!-- Izin normal: otomatis diberikan saat instal -->
    <uses-permission android:name="android.permission.INTERNET" />

    <!-- Izin runtime (dangerous): tetap harus diminta saat aplikasi berjalan -->
    <uses-permission android:name="android.permission.CAMERA" />
    <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
    <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
    <uses-permission android:name="android.permission.RECORD_AUDIO" />
    <!-- Android 13+ (API 33). Di versi lebih lama baris ini diabaikan -->
    <uses-permission android:name="android.permission.POST_NOTIFICATIONS" />

    <!-- Kamera tidak wajib: aplikasi tetap bisa dipasang di perangkat tanpa kamera -->
    <uses-feature android:name="android.hardware.camera" android:required="false" />

    <application
        android:label="Aplikasi Kampus"
        ...>
        ...
    </application>
</manifest>

Langkah 4: iOS, kalimat alasan di Info.plist

📄 ios/Runner/Info.plist (potongan, di dalam <dict> utama)

<key>NSCameraUsageDescription</key>
<string>Kamera dipakai untuk memindai QR presensi dan memotret bukti kegiatan.</string>
<key>NSLocationWhenInUseUsageDescription</key>
<string>Lokasi dipakai untuk memastikan kamu berada di area kampus saat presensi.</string>
<key>NSMicrophoneUsageDescription</key>
<string>Mikrofon dipakai untuk merekam catatan suara saat perkuliahan.</string>

Tulis kalimat yang jujur dan spesifik: untuk apa data itu dipakai. Kalimat umum seperti "Aplikasi butuh kamera" sering menjadi alasan penolakan review App Store.

Langkah 5: iOS, mengaktifkan izin di plugin

Agar aplikasi tidak membawa kode izin yang tidak dipakai (yang bisa memicu penolakan App Store), permission_handler hanya mengaktifkan izin yang kamu pilih. Caranya bergantung pada sistem dependensi iOS proyekmu:

  • Swift Package Manager (bawaan proyek Flutter baru; folder ios/ tidak berisi Podfile): izin otomatis diaktifkan berdasarkan kunci yang ada di Info.plist. Jadi Langkah 4 sudah cukup. Izin notifikasi aktif secara bawaan. Setelah menambah kunci baru, hapus cache Xcode sekali (rm -rf ~/Library/Developer/Xcode/DerivedData) lalu build ulang.
  • CocoaPods (proyek lama yang punya ios/Podfile): aktifkan lewat macro di blok post_install. Izin yang tidak ditulis bernilai 0 (nonaktif).

📄 ios/Podfile (potongan, hanya untuk proyek CocoaPods)

post_install do |installer|
  installer.pods_project.targets.each do |target|
    flutter_additional_ios_build_settings(target)

    target.build_configurations.each do |config|
      config.build_settings['GCC_PREPROCESSOR_DEFINITIONS'] ||= [
        '$(inherited)',

        ## dart: PermissionGroup.camera
        'PERMISSION_CAMERA=1',

        ## dart: PermissionGroup.microphone
        'PERMISSION_MICROPHONE=1',

        ## dart: PermissionGroup.locationWhenInUse
        ## (cukup macro ini jika tidak butuh lokasi "always")
        'PERMISSION_LOCATION_WHENINUSE=1',

        ## dart: PermissionGroup.notification
        'PERMISSION_NOTIFICATIONS=1',
      ]
    end
  end
end

Setelah mengubah Podfile, jalankan flutter clean lalu build ulang. Daftar lengkap macro dan kunci Info.plist ada di README permission_handler bagian Setup.

💡 Satu sumber kebenaran

Buat tabel kecil di README proyekmu: fitur → izin Android → kunci iOS → macro Podfile. Setiap kali menambah fitur hardware, isi satu baris. Cara sederhana ini mencegah lupa salah satu dari tiga tempat tersebut.

⚠️ Kesalahan umum

  • Menulis <uses-permission> di dalam <application> atau di manifest debug. Izin harus di manifest main, sebagai anak langsung <manifest>.
  • Mengubah manifest, Info.plist, atau Podfile lalu hanya hot reload. Perubahan native butuh build ulang (stop lalu flutter run).
  • Di iOS (CocoaPods) semua status izin selalu denied walau dialog tidak pernah muncul: macro izinnya belum diaktifkan di Podfile.
