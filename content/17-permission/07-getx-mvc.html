Langkah 1: Model

Kita membuat enum status sendiri alih-alih memakai PermissionStatus langsung. Alasannya: view dan controller tidak perlu tahu package apa yang dipakai. Jika suatu hari package diganti, cukup service yang berubah.

📄 lib/models/izin.dart

// lib/models/izin.dart
// MODEL: data murni, tanpa import Flutter, GetX, maupun permission_handler.

/// Fitur hardware yang butuh izin di aplikasi kampus.
enum JenisIzin {
  kamera(
    'Kamera',
    'Memindai QR presensi dan memotret bukti kegiatan.',
  ),
  lokasi(
    'Lokasi',
    'Memastikan kamu berada di area kampus saat presensi.',
  ),
  notifikasi(
    'Notifikasi',
    'Mengingatkan jadwal kuliah dan pengumuman penting.',
  ),
  mikrofon(
    'Mikrofon',
    'Merekam catatan suara saat perkuliahan.',
  );

  const JenisIzin(this.label, this.alasan);

  final String label;
  final String alasan;
}

/// Status izin versi aplikasi kita (bukan enum milik package).
enum StatusIzin {
  belumDiketahui('Memeriksa...'),
  diizinkan('Diizinkan'),
  terbatas('Diizinkan sebagian'),
  ditolak('Belum diizinkan'),
  ditolakPermanen('Ditolak permanen'),
  dibatasiSistem('Dibatasi sistem');

  const StatusIzin(this.label);

  final String label;

  bool get bolehDipakai => this == diizinkan || this == terbatas;
  bool get perluPengaturan => this == ditolakPermanen || this == dibatasiSistem;
}
  • Enhanced enum (Dart 2.17+) bisa punya field dan constructor. Label dan alasan setiap izin ditulis sekali di sini dan dipakai di dialog maupun kartu.
  • bolehDipakai dan perluPengaturan adalah aturan yang dipakai di banyak tempat, jadi diletakkan di model agar tidak ditulis ulang.

Langkah 2: Service

📄 lib/services/permission_service.dart

// lib/services/permission_service.dart
// SERVICE: satu-satunya file yang mengimpor permission_handler.
import 'package:permission_handler/permission_handler.dart';

import '../models/izin.dart';

class PermissionService {
  /// Pemetaan fitur aplikasi ke izin milik permission_handler.
  Permission _izinDari(JenisIzin jenis) {
    switch (jenis) {
      case JenisIzin.kamera:
        return Permission.camera;
      case JenisIzin.lokasi:
        return Permission.locationWhenInUse;
      case JenisIzin.notifikasi:
        return Permission.notification;
      case JenisIzin.mikrofon:
        return Permission.microphone;
    }
  }

  StatusIzin _konversi(PermissionStatus status) {
    switch (status) {
      case PermissionStatus.granted:
      case PermissionStatus.provisional:
        return StatusIzin.diizinkan;
      case PermissionStatus.limited:
        return StatusIzin.terbatas;
      case PermissionStatus.denied:
        return StatusIzin.ditolak;
      case PermissionStatus.permanentlyDenied:
        return StatusIzin.ditolakPermanen;
      case PermissionStatus.restricted:
        return StatusIzin.dibatasiSistem;
    }
  }

  /// Membaca status tanpa memunculkan dialog.
  /// Catatan: di Android, hasilnya tidak pernah ditolakPermanen.
  Future<StatusIzin> cekStatus(JenisIzin jenis) async {
    final status = await _izinDari(jenis).status;
    return _konversi(status);
  }

  /// Memunculkan dialog sistem (jika masih boleh) dan mengembalikan hasilnya.
  Future<StatusIzin> minta(JenisIzin jenis) async {
    final status = await _izinDari(jenis).request();
    return _konversi(status);
  }

  /// Meminta beberapa izin sekaligus dalam satu antrean dialog.
  Future<Map<JenisIzin, StatusIzin>> mintaBeberapa(
    List<JenisIzin> daftar,
  ) async {
    final hasil = await daftar.map(_izinDari).toList().request();
    return {
      for (final jenis in daftar)
        jenis: _konversi(hasil[_izinDari(jenis)] ?? PermissionStatus.denied),
    };
  }

  /// Android saja: true jika pengguna pernah menolak sekali.
  /// Di iOS selalu false.
  Future<bool> perluPenjelasan(JenisIzin jenis) =>
      _izinDari(jenis).shouldShowRequestRationale;

  /// Mengecek apakah GPS/layanan lokasi di perangkat menyala.
  Future<bool> layananLokasiAktif() =>
      Permission.locationWhenInUse.serviceStatus.isEnabled;

  /// Membuka halaman pengaturan aplikasi ini di sistem.
  Future<bool> bukaPengaturan() => openAppSettings();
}
  • _izinDari memetakan fitur aplikasi ke izin plugin. Lokasi memakai locationWhenInUse karena aplikasi kampus hanya butuh lokasi saat aplikasi dibuka.
  • _konversi memakai switch tanpa default. Jika versi package berikutnya menambah status baru, analyzer langsung memberi tahu ada kasus yang belum ditangani.
  • provisional (notifikasi "diam" di iOS) dianggap diizinkan karena notifikasi tetap bisa dikirim.
  • Service tidak mengimpor GetX maupun Flutter. Ia bisa diganti dengan versi palsu saat pengujian.

Langkah 3: Controller

📄 lib/controllers/permission_controller.dart

// lib/controllers/permission_controller.dart
// CONTROLLER: state reaktif per izin. Tidak mengimpor material.dart.
import 'package:flutter/widgets.dart' show AppLifecycleListener;
import 'package:get/get.dart';

import '../models/izin.dart';
import '../services/permission_service.dart';

class PermissionController extends GetxController {
  PermissionController(this._service);
  final PermissionService _service;

  // State reaktif privat: satu status untuk setiap jenis izin
  final _status = {
    for (final jenis in JenisIzin.values) jenis: StatusIzin.belumDiketahui,
  }.obs;
  final _lokasiAktif = true.obs;
  final _sedangMemproses = Rxn<JenisIzin>();

  // Android tidak bisa memberi tahu "ditolak permanen" lewat status,
  // jadi kita ingat sendiri dari hasil request().
  final _pernahDitolakPermanen = <JenisIzin>{};

  late final AppLifecycleListener _lifecycle;

  // Getter publik read-only
  StatusIzin statusDari(JenisIzin jenis) =>
      _status[jenis] ?? StatusIzin.belumDiketahui;
  bool get lokasiAktif => _lokasiAktif.value;
  bool sedangMemproses(JenisIzin jenis) => _sedangMemproses.value == jenis;
  int get jumlahDiizinkan =>
      _status.values.where((s) => s.bolehDipakai).length;

  @override
  void onInit() {
    super.onInit();
    // Pengguna bisa mengubah izin dari Pengaturan lalu kembali ke aplikasi.
    // Saat aplikasi aktif lagi (resume), baca ulang semua status.
    _lifecycle = AppLifecycleListener(onResume: muatUlang);
    muatUlang();
  }

  @override
  void onClose() {
    _lifecycle.dispose();
    super.onClose();
  }

  Future<void> muatUlang() async {
    for (final jenis in JenisIzin.values) {
      final dariSistem = await _service.cekStatus(jenis);
      _status[jenis] = _gabungkan(jenis, dariSistem);
    }
    _lokasiAktif.value = await _service.layananLokasiAktif();
  }

  /// Dipanggil View setelah pengguna setuju di dialog penjelasan.
  Future<StatusIzin> minta(JenisIzin jenis) async {
    _sedangMemproses.value = jenis;
    try {
      final hasil = await _service.minta(jenis);
      _status[jenis] = _gabungkan(jenis, hasil);
      return statusDari(jenis);
    } finally {
      _sedangMemproses.value = null;
    }
  }

  Future<bool> perluPenjelasan(JenisIzin jenis) =>
      _service.perluPenjelasan(jenis);

  Future<void> bukaPengaturan() => _service.bukaPengaturan();

  StatusIzin _gabungkan(JenisIzin jenis, StatusIzin baru) {
    if (baru == StatusIzin.ditolakPermanen) {
      _pernahDitolakPermanen.add(jenis);
      return baru;
    }
    if (baru.bolehDipakai) {
      _pernahDitolakPermanen.remove(jenis);
      return baru;
    }
    // Status "ditolak" dari Android bisa berarti ditolak permanen.
    return _pernahDitolakPermanen.contains(jenis)
        ? StatusIzin.ditolakPermanen
        : baru;
  }
}

Penjelasan baris penting:

  • _status adalah RxMap<JenisIzin, StatusIzin> yang dibuat dari collection-for. Mengubah _status[jenis] = ... otomatis membangun ulang setiap Obx yang membaca map tersebut.
  • _sedangMemproses (Rxn, boleh null) mencatat izin yang sedang diminta, sehingga view bisa menampilkan loading dan menonaktifkan tombol. Ini mencegah request() dipanggil dua kali bersamaan.
  • _pernahDitolakPermanen menutupi keterbatasan Android dari section 5: hasil request() yang ditolakPermanen diingat, sehingga saat muatUlang() membaca status ditolak dari sistem, kartu tetap menampilkan "Ditolak permanen". Tanda ini dihapus begitu izin diberikan. Set ini hanya hidup selama aplikasi berjalan; setelah aplikasi dibuka ulang, alur "minta dulu, lihat hasilnya" tetap bekerja karena request izin yang ditolak permanen langsung kembali tanpa dialog.
  • AppLifecycleListener(onResume: muatUlang) membaca ulang semua status setiap kali aplikasi kembali ke depan (misal dari Pengaturan). Listener ini wajib di-dispose() di onClose. Import flutter/widgets.dart dengan show hanya mengambil kelas itu, sehingga controller tetap tidak bergantung pada material.dart.
  • minta() memakai try/finally agar indikator loading pasti dimatikan walaupun plugin melempar error.
  • Controller tidak menampilkan dialog. Keputusan "tampilkan penjelasan" atau "ajak ke Pengaturan" ada di view, karena keduanya butuh BuildContext.

Bonus: controller bisa diuji tanpa perangkat

Karena controller hanya bergantung pada PermissionService, kita bisa memberinya service palsu dan menguji logikanya dengan flutter test (Modul 15). Ganti pusat_izin dengan nilai name di pubspec.yaml proyekmu.

📄 test/permission_controller_test.dart

// test/permission_controller_test.dart
import 'package:flutter_test/flutter_test.dart';
import 'package:get/get.dart';
import 'package:pusat_izin/controllers/permission_controller.dart';
import 'package:pusat_izin/models/izin.dart';
import 'package:pusat_izin/services/permission_service.dart';

/// Service palsu: tidak menyentuh plugin, hasilnya kita atur sendiri.
class FakePermissionService implements PermissionService {
  final status = {for (final j in JenisIzin.values) j: StatusIzin.ditolak};
  StatusIzin hasilMinta = StatusIzin.diizinkan;

  @override
  Future<StatusIzin> cekStatus(JenisIzin jenis) async => status[jenis]!;

  @override
  Future<StatusIzin> minta(JenisIzin jenis) async {
    status[jenis] = hasilMinta == StatusIzin.ditolakPermanen
        ? StatusIzin.ditolak // meniru Android: status tidak pernah "permanen"
        : hasilMinta;
    return hasilMinta;
  }

  @override
  Future<Map<JenisIzin, StatusIzin>> mintaBeberapa(
    List<JenisIzin> daftar,
  ) async =>
      {for (final j in daftar) j: await minta(j)};

  @override
  Future<bool> perluPenjelasan(JenisIzin jenis) async => false;

  @override
  Future<bool> layananLokasiAktif() async => true;

  @override
  Future<bool> bukaPengaturan() async => true;
}

void main() {
  TestWidgetsFlutterBinding.ensureInitialized();

  late FakePermissionService service;
  late PermissionController controller;

  setUp(() async {
    service = FakePermissionService();
    controller = Get.put(PermissionController(service));
    await controller.muatUlang();
  });

  tearDown(Get.reset);

  test('status awal dibaca dari service', () {
    expect(controller.statusDari(JenisIzin.kamera), StatusIzin.ditolak);
    expect(controller.jumlahDiizinkan, 0);
  });

  test('minta() yang diizinkan memperbarui state', () async {
    final hasil = await controller.minta(JenisIzin.kamera);
    expect(hasil, StatusIzin.diizinkan);
    expect(controller.jumlahDiizinkan, 1);
  });

  test('ditolak permanen tetap diingat setelah muat ulang', () async {
    service.hasilMinta = StatusIzin.ditolakPermanen;
    await controller.minta(JenisIzin.mikrofon);
    await controller.muatUlang(); // service melaporkan "ditolak" saja
    expect(
      controller.statusDari(JenisIzin.mikrofon),
      StatusIzin.ditolakPermanen,
    );
  });

  test('izin dari Pengaturan menghapus tanda permanen', () async {
    service.hasilMinta = StatusIzin.ditolakPermanen;
    await controller.minta(JenisIzin.lokasi);
    service.status[JenisIzin.lokasi] = StatusIzin.diizinkan;
    await controller.muatUlang();
    expect(controller.statusDari(JenisIzin.lokasi), StatusIzin.diizinkan);
  });
}

Tes ketiga membuktikan logika terpenting: walaupun "sistem" hanya melaporkan ditolak, controller tetap ingat bahwa izin mikrofon ditolak permanen. Uji seperti ini sulit dilakukan secara manual di emulator.

⚠️ Kesalahan umum

  • Memanggil Permission.camera.request() langsung dari view atau dari controller lain. Semua akses izin lewat PermissionService/PermissionController, agar status di layar selalu sinkron.
  • Menampilkan Get.dialog atau showDialog dari dalam controller. Biarkan controller mengembalikan hasil, view yang memutuskan tampilannya.
  • Lupa _lifecycle.dispose() di onClose, sehingga listener tetap terpasang setelah controller dihapus.
  • Memanggil Get.put(PermissionController(...)) di dalam build(). Daftarkan sekali di main().
