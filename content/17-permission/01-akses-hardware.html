Mulai modul ini kita masuk ke kelompok materi Integrasi Hardware: kamera, lokasi, sensor, biometrik, dan konektivitas. Sebelum menyentuh hardware mana pun, ada dua hal yang harus dipahami lebih dulu: bagaimana kode Dart bisa sampai ke hardware, dan izin apa yang harus dimiliki aplikasi agar sistem operasi mengizinkannya.

Dart tidak bisa langsung menyentuh hardware

Kode Flutter kita berjalan di Dart VM/AOT di dalam engine Flutter. Engine ini menggambar UI sendiri (Modul 01), tetapi tidak punya akses langsung ke kamera, GPS, sensor, atau Bluetooth. Semua hardware itu hanya bisa diakses lewat API milik sistem operasi: Android SDK (Kotlin/Java) dan iOS SDK (Swift/Objective-C). Jadi selalu ada "jembatan" antara Dart dan kode native.

┌──────────────────────────────────────────────┐
│  Kode Dart kamu (lib/)                       │
│  View  →  Controller  →  Service             │
└───────────────────────┬──────────────────────┘

Lapisan paling bawah selalu dijaga oleh sistem operasi. Walaupun jembatannya sudah ada, sistem operasi tetap menolak akses ke kamera atau lokasi jika aplikasi belum mendapat izin (permission) dari pengguna. Itulah sebabnya modul tentang izin ini menjadi fondasi untuk Modul 18 sampai 22.

Plugin itu sebenarnya apa?

Plugin hanyalah package Dart yang juga membawa folder android/ dan ios/. Saat kamu menjalankan flutter pub add permission_handler, Flutter otomatis mendaftarkan kode Kotlin/Swift plugin itu ke proyekmu (lewat file GeneratedPluginRegistrant yang dibuat otomatis). Di dalamnya, plugin memakai platform channel yang sama seperti yang akan kita tulis sendiri di section berikutnya.

ℹ️ Federated plugin

Banyak plugin besar dipecah menjadi beberapa package: satu package "wajah" yang kamu pasang (misal permission_handler), satu platform interface, dan satu package per platform (permission_handler_android, permission_handler_apple, ...). Kamu cukup memasang package utamanya; sisanya ikut terpasang otomatis. Kalau melihat nama-nama itu di pubspec.lock, itu normal.

Kapan memakai plugin, kapan menulis sendiri?

  • Cari plugin dulu. Di pub.dev perhatikan label Flutter Favorite atau penerbit terverifikasi (misal flutter.dev, fluttercommunity.dev, baseflow.com), skor "likes/points", tanggal rilis terakhir, dan platform yang didukung (Android, iOS).
  • Baca README bagian setup. Hampir semua plugin hardware butuh konfigurasi AndroidManifest.xml dan Info.plist. Melewatkan bagian ini adalah penyebab crash nomor satu.
  • Tulis platform channel sendiri hanya jika fitur yang kamu butuhkan memang tidak ada, atau cukup kecil (satu-dua method) sehingga menambah dependensi tidak sepadan.

💡 Perangkat fisik vs emulator

Sebagian besar materi hardware bisa dicoba di Android Emulator. Panel Extended Controls (tombol ... di samping emulator) menyediakan simulasi Location, Virtual sensors, Fingerprint, dan Camera. Untuk modul ini, semua dialog izin juga muncul di emulator. Bluetooth tidak tersedia di emulator, jadi Modul 22 butuh HP sungguhan.
